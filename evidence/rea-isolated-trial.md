# REA isolated trial — 2026-10-16

**Result: useful additional inspection tool; native NWN query and MCP smoke
checks passed.** This was a separate tooling experiment. The main spellcasting /
combat / campaign goal remains paused, and no replacement-client code changed.

## Scope and isolation

- Used official npm `rea-agents@6.5.0`. The downloaded tarball's SHA512 matches
  the npm registry metadata. This is an integrity comparison, not an independent
  package-security audit or signature/provenance attestation verification.
- Installed only under `backups/rea-trial/runner`, with lifecycle scripts
  disabled, its own npm cache and empty trial npm configuration. No global
  installation, agent registration, skill installation, or normal setup command.
- Existing Ghidra12.1.4 and Liberica JDK21 were used read-only. The open original
  Ghidra11.3.2 project was not passed to REA. It remained running.
- A child-only temporary Windows profile and OS-temp root held REA/Ghidra
  state. REA used ephemeral read-only headless imports and its packaged Windows
  private-directory / Job Object controls. Proprietary target snapshots stayed
  outside the repository and were removed by provider cleanup. The trial never
  executed the game or the authored fixture, injected into a process, or changed
  permissions to access an existing project.
- This is controlled local process/profile isolation, **not** a VM, network
  sandbox, or certification for examining hostile binaries. External package
  dependencies and native tooling still execute with the invoking user's rights.
- Before/after SHA256 controls cover `nwmain.exe`, the original `.gpr`, regular
  Codex configuration, and the client package/lock files. All stayed unchanged.
  This is not a bytewise audit of every open Ghidra database file.
- The reusable launcher admits only version/help, scoped diagnostics, and static
  function queries. Setup/registration/snapshot/execution requests are refused;
  an explicit negative setup test passes before REA is launched.

## Measurements and independent checks

`scripts/verify-rea-trial.mjs` produces
`backups/rea-trial/verification.json`, **PASS**.

1. Scoped `doctor --provider ghidra` passes, including Windows native authority.
   Its broader informational environment report lists unused missing providers;
   those do not invalidate the selected Ghidra scope and were not installed.
2. `mcp doctor --json` performs a real temporary production-stdio startup:
  207/207 expected tools,6/6 prompts, matching package/catalog identity, and a
   successful `binary_session` request. It installs no persistent connection in
   this agent and does not establish every advertised tool's functionality.
3. An owned9-byte PE fixture, generated by `scripts/rea-trial-fixture.mjs`, is
   inspected but never executed. REA recovers its three instructions, complete
   function range, and `(x + 2*y) XOR 0x13579bdf` expression. The complete cold
   query, including import and cleanup, took14,957ms.
4. Real NWN executable SHA256
   `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`:
   static function query at **0x14022f690**, returned exported name **Yaw**,
   contiguous62-byte body through0x14022f6cd. All **17 instructions and their
   operands** match the pre-existing independent disassembly in
   `backups/animations/map-player-heading-angle-v1.txt`, after resolving RIP
   operands and normalizing equivalent JZ/JE and JNZ/JNE spellings.
   The known map call site **0x140894c88**, helper **0x140c8f29c**, sign-mask
   reference **0x140d81990**, and degree-factor reference **0x140d81948** also
   match. The complete cold query took **482,471ms (about8m2s)**.

The returned pseudocode agrees with the known zero-XY branch and sign-bit /
atan2 / degrees path, but still requires interpreting inferred types and the
integer XOR as a FLOAT sign-bit operation. It must not be transliterated into
replacement code without the original instruction/ABI checks. Constant address
references were checked here; the numerical values retain their independent
earlier native-data evidence. This was static analysis, not a new native
execution comparison of Yaw or a whole-engine correctness test.

Default Ghidra analysis logged overlap repairs, unavailable-read warnings and
stack-variable/type-analysis warnings elsewhere in the binary. A bounded
progress excerpt is retained; the successful function query does not certify
those other functions. REA preserved evidence provenance and limitations.

## Cleanup and adoption assessment

`backups/rea-trial/cleanup.json` records **zero remaining owned Java/MCP
processes and zero temporary Ghidra project directories**, with the original
Ghidra process still alive. The trial profile contains only residual local state
and metadata; downloads/dependencies and reproducibility records remain under
the trial folder. No binary was uploaded by a requested analysis operation.

REA is worth using for assembly/pseudocode, exported names, callers and data
references. A persistent MCP session would avoid the documented re-import cost
of independent CLI invocations. Its compatibility with this Windows/Ghidra/NWN
combination is now measured, rather than inferred from documentation. Existing
native oracles, type/ABI reconstruction, game-data interpretation and gameplay
parity tests remain necessary. No persistent integration was configured here.

Raw outputs: `doctor.json`, `mcp-doctor.json`, `owned-function.json`,
`nwn-heading.json`; `.run.json` files capture timings and unchanged controls.
`registry-metadata.json`, the isolated runner lockfile, source scripts and
`baseline.json` make the package/configuration choices reviewable. The small
trial evidence archive excludes package caches, dependencies and proprietary
binary data; consult its verification report for the final manifest result.
