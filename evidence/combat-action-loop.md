## Connected behavior and boundaries

ModuleSession now supplies the shared clock and reputation mutations. World updates drain canonical object actions through `RunActions` into the attack owner; self-target completion, target cleanup, mode switching, round startup and ordinary strike dispatch are connected. Native geometry remains a required provider. Missing LOS, approach, replacement search or movement does not manufacture success. In particular, missing combat-step callbacks fail **before dequeueing** the due round action, preserving both the enclosing object attack and its round action.

Local world-clock ownership is not the complete area-timer lifecycle. Native AI uses area-owned timer state; exact area cloning/pause/save synchronization and the full AI frame's height/trap/perception operations remain open. The local monotonic host clock supplies RunActions' microsecond budget. Its epoch and session RNG startup seed are not asserted identical to the original process.

Oversized action/effect lists issue persistent diagnostics. Native cleanup beyond500 actions or1000 effects is not mapped and fails explicitly. Other object action types remain recorded as unsupported before removal. Mode11 activation and active stance cleanup remain blocked before mutation where the current dependency is known. Saved effect import, equipment mutation and handler-specific effect removal still require implementation.

Damage party-state/initiative broadcasts, default event15 attack copies and events20/22 damage delivery, live modifier/AC/save/skill/feat-use queries and shared dice/animation RNG are connected from prior work. On-hit handlers/item spells/type30, event19 spell impact, advanced defenses/status/death/XP, ranged projectiles and presentation remain open. Attack radial is still a placeholder; there is no successful full replacement encounter capture.
