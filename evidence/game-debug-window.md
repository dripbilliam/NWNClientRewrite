# Separate debug window

The connected multiplayer client switches the outer document to `game-only` during area loading/playing. The viewport fills the content area; the model-lab header, toolbar, inspector, metrics and viewport caption are hidden. Existing ResizeObserver resizes the renderer and game overlays. Disconnect restores the lab layout. Pregame character/content screens keep their own existing presentation. No change to server admission, movement or simulation.

Options in the multiplayer panel, Main Menu and local fallback panel include **Show debug window**. Default is off; the preference lives in the renderer profile. Turning it on opens one nonmodal Electron window with Performance, Gameplay, Diagnostics, Inspector and Resources tabs. The selected tab projects the existing live debug DOM as bounded typed text/control data, without starting a second renderer/world or transferring resource image data. Live controls proxy to their original source elements. Only the selected tab updates at 500ms while visible; minimizing/closing stops updates. Closing via X updates the Options checkbox/preference. The child closes with its owning game window.

The child has a separate sandboxed/context-isolated preload without the multiplayer, credentials, filesystem or runtime-log bridges. IPC attests the owning main frame and exact local page. Child navigation/popups are blocked. Display data uses whitelisted DOM tags/textContent, never server-provided HTML. Commands resolve only to currently projected, connected controls in the selected source roots; sensitive/file/hidden inputs and resource images are excluded. Resource browse buttons retain their source handlers; file-picker activation from a separate window has not been verified.
