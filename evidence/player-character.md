## Observed native behavior

| Native entry | Address / call site | Verified behavior |
| --- | --- | --- |
| `CNWSPlayer::LoadCreatureData` | `0x1404bb450` | Opens a `BIC ` GFF resource, calls `CNWSCreatureStats::ReadStatsFromGff`, then sets the PC flag. This is one import path, not a complete admission/lifecycle map. |
| `ReadStatsFromGff` | `0x14040f7f0`; XP read/write `0x140410110..0x140410159` | Reads serialized `Experience`; excludes a DM recipient from the XP write. Full assembly was inspected because the decompiler stops at a misidentified non-returning cleanup call. |
| Player HP restoration | `0x140411656..0x1404116dc` | Reads signed-short base `HitPoints` and `CurrentHitPoints`; the PC branch adds `GetMaxHitPoints(1) - baseHP` to saved current HP. Serialized `MaxHitPoints` is not the calculation's authority. |
| `GetMaxHitPoints` | `0x140391850` | PC path sums per-level `max(1, hitDie + CON modifier)`, optionally adds Toughness per level, highest Epic Toughness tier, and Pale Master/Deathless Vigor bonuses. The NPC path differs. Default feat/ruleset constants are observed; custom ruleset overrides remain open in the replacement. |
| `GetCONStat`, class ability adjustments | `0x1403fa0f0`, `0x1403fa6b0`, `0x140299710` | Adds stored base, racial adjustment, class stat-gain table and effect bonus. Current CON has a minimum of 3 and an unsigned-byte result. Per-class gains sum levels 1..N, returning signed bytes; the class aggregate clamps to signed-byte range. Other current stat getters confirm the same minimum/result convention (`DEX 0x1403fd3e0`, `INT 0x140402d10`, `WIS 0x14040b5e0`, `CHA 0x1403fa050`). DEX also has incapacitation checks which require the future effect/combat engine. |
| Item ability increase/decrease handlers | `0x14046dcd0`, `0x14046fbb0`; increase value read `0x14046dd6d` and effect attachment `0x14046de53` | Resolve native cost tables 1/21; use property subtype as ability selector and cost-row `Value` as magnitude. |
| Ability effect aggregation | `0x140393340`, ability case around `0x140395993..0x140395bdd` | Keeps strongest increase/decrease per source item, sums distinct sources, caps each independently, then subtracts. Calls to server limit providers at `0x140395b13` / `0x140395b28`. |
| Server limit defaults | Constructor `0x14055c300`, writes `0x14055c656` / `0x14055c660` | Default ability increase limit 12 and decrease limit 30. Runtime overrides are not implemented. |
| `ExecuteCommandGiveXPToCreature` | `0x140532cf0` | Pops object then amount, ignores nonpositive awards and non-creature recipients, calls stats `AddExperience`. |
| `AddExperience` | `0x1403eef50`; `SetExperience` call `0x1403ef156` | Ignores associates. With multiple classes, resolves racial favored class (or first highest class without a prerequisite table), excludes favored and XP-exempt classes, and deducts 20% per class more than one level below the highest eligible class. Truncates the double result; addition is uint32. Constants at `0x140ee45f8` / `0x140dd3050` are 1.0 / 0.2. |
| `SetExperience` | `0x140415640..0x140415956`; XP store `0x140415756` | Ignores DM state; emits gain/loss feedback, writes XP, handles stored level-history changes and level-up availability. The replacement implements positive awards and eligibility, not automatic replay of future level history or native feedback/event messages. |
| XP/class/race/HP script getters | `0x140532b40`, `0x140520d50`, `0x14052f6a0`, `0x140525d00`, `0x140525db0`, `0x14051e470` | XP/default-invalid behavior; 1-based class position; total class levels; base/current ability selector; object HP virtual dispatch. |
| Inventory script accessors | `0x140528960`, `0x140528d40`, `0x140525090` | Converts script equipment index to `1 << index`; returns item object ID; item possession follows canonical owner IDs (optional immediate owner); creature gold is a field, placeable gold comes from its gold-stack item. |

`scripts/inspect-character.py` verifies the binary hash and decodes complete PE unwind function ranges with Capstone. This avoids relying on Ghidra's incorrectly truncated function bodies; it never changes the database. Full local traces are in `backups/animations/bic-native-full.txt`.

## Implemented slice

- `character.js` validates BIC/GFF type and PC state, native-sized fields, classes, level history and equipment struct masks. DM, polymorph and saved active-effect imports are explicitly unsupported. Rules and names resolve from module/HAK/base 2DA/TLK precedence.
- `ModuleSession.loadCharacter` populates the existing canonical player record. Its object ID and current area membership survive an initial preview upgrade. A BIC selected before opening a module is loaded before lifecycle scripts. Upgrading a running preview is a development convenience: failed startup scripts are not replayed.
- Carried/equipped items and nested contents receive fresh IDs from the shared object array, native equipment masks and owner IDs. Serialized `ObjectId`, `AreaId`, perception/combat references and quickbar references do not become live IDs. BIC object locals only remap uniquely imported player/owned-item identities; invalid or ambiguous IDs and other foreign references remain invalid. Location locals are rejected with a diagnostic. Allocation failure rolls back imported objects without recycling IDs.
- Character stats retain authored BIC data separately from live XP. Current stat calculation includes racial/class gains and equipped ability increase/decrease properties. PC HP follows the mapped level-history/feat path under default rules; other effects/item properties are not simulated. Current effect-dependent state cannot be restored from a save.
- Script adapters now include XP awards/getter, race, hit dice, class/level lookup, base/equipped abilities, PC HP, equipment/owner accessors and gold. NPC stat construction is pending and emits explicit diagnostics when a stat provider is required. Positive XP awards update the canonical stats record and UI; no class or level is invented.
- HUD loads the BIC portrait and HP. Character/Skills/Feats panels display actual fields and TLK names. Inventory separates carried items/equipment and uses canonical IDs for examination. Spellbook preserves per-class known spells and each memorized slot's readiness/metamagic. Spell/feat use remains structured placeholders.
- The PC model uses existing creature assembly and inherited idle animations, with body/head palettes and chest armor parts/colors. Weapon/shield/cloak/helmet/robe overrides, equipment visual precedence and gameplay walk/run animation selection are not complete.

### Head texture orientation correction, 2026-10-11

Observed: the installed wizard's `pme0` head anchor remains upright in rest, `pause1` and `walk` poses. The upside-down facial features came from the PLT upload path, which applied `flipY=true` to pixels already stored bottom-to-top. Local reference `references/xoreos/src/graphics/aurora/pltfile.cpp` preserves PLT pixel order when rebuilding the texture. This is asset/renderer evidence; no new native attachment semantics or Ghidra annotations are claimed.

`decodeBioWarePlt` now declares `flipY=false`, and the shared renderer uses that value for PC/NPC heads and all other palette textures. Palette color-row lookup remains independent of image orientation. TGA and DDS decoding retain their own upload conventions.

Validation: the asymmetric two-row decoder fixture checks upload orientation and unchanged palette selection. `node scripts/smoke-plt.mjs <install> <module>` samples the installed `pme0_head001` face UVs with layer IDs encoded as colors: hair samples average Z=0.1502, skin Z=0.0720. Reversing image rows maps hair below the face and fails the regression. No installed textures are extracted. `--focus-character` in the Electron harness frames the loaded PC for visual inspection.
- Loading another BIC while a real PC is active stages it for the next module. Active-PC replacement and BIC writing are pending. No native admission/server legality checks, saves, multiplayer packets or external object replication are claimed.
