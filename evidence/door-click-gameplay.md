# Door clicks and the first gameplay layer

Target: NWN:EE `89.8193.37-17`, executable SHA-256 `3B7CB1252E0EDB2CE22D7971F333AADE027039AE30A45B4BC64732C3E6BEC73A`. Research uses the existing executable and live Ghidra bridge. No game files or Ghidra annotations were changed.

## Observed in the target

- `FUN_1406f02c0` identifies itself in logging as `PerformLButtonDownAction` (`game/clientcore/clientinput.cpp`). GUI handling precedes world picking. `FUN_1406eae20` performs hit selection; `FUN_1406efec0` dispatches by object type, including door type 10. The picker has filters and priorities beyond a single nearest triangle.
- The door dispatch checks client fields and input modes. At `0x1406eff59` it calls `FUN_14086df30`, which returns byte `door+0x19c`. If that byte and `door+0x1c0` are nonzero, call site `0x1406effd5` sends a movement/target request through `FUN_1407c0970`. Otherwise, call site `0x1406f0002` invokes `FUN_14086e810`. The semantic interpretation of these fields as open/transition eligibility remains an inference pending their replication setters.
- `FUN_14086e810` inspects animation ID: closed `0x16` sends action `0x15` at tail call `0x14086e843`; open `0x32/0x33` sends action `0x16` at `0x14086e863`. It does not start an animation directly or inspect the custom OnClick script. `FUN_1407bf860` serializes target ID and action word in input message `(6,3)`.
- `CNWSMessage::HandlePlayerToServerInputMessage` (`0x1404531b0`), case 3, reads that object ID/action word and queues `AddOpenDoorAction` or `AddCloseDoorAction` for the controlled creature.
- `CNWSObject::AIActionOpenDoor` (`0x1404a2fb0`) and `AIActionCloseDoor` (`0x14049eb30`) check actor/target validity and use range. An actor outside range receives movement and a retry action. In range, the routines schedule door events; additional trap/death/rule branches exist.
- `CNWSCreature::GetUseRange` (`0x140396480`) uses `CNWSDoor::GetNearestActionPoint` and adds `0.75` to an actor field. `GetIsInUseRange` (`0x140391310`) requires the same area, line of sight and horizontal range, including a `0.1` tolerance. Constants were checked against executable data bytes.
- `CNWDoorSurfaceMesh::LoadWalkMesh` (`0x1402cf720`) loads `_DWK_dp_closed/open1/open2_NN` dummy positions separately from collision geometry. `GetActionPoint` (`0x1404201e0`) transforms those positions; `GetNearestActionPoint` (`0x140420360`) also considers closed points while open.
- `CNWSArea::LoadDoors` (`0x1403608f0`, `SetOrientation` call at `0x140360b9e`) derives a direction from Bearing. Its quaternion calculation yields native `[-sin(bearing), cos(bearing), 0]`; in Three coordinates this is `[-sin(bearing), 0, -cos(bearing)]`.
- `CNWSDoor::EventHandler` (`0x14041e760`) chooses opening side from actor-minus-door position dotted with that direction, applies state 1 or 2, records actor IDs, mirrors linked-door state when resolved, and dispatches OnOpen/OnClosed scripts. `SetOpenState` (`0x140423230`) controls resting animation and collision. These are gameplay consequences, not an autonomous animation loop.

## Implemented replacement foundation

`WorldObjects` is an area membership/render-binding view of the module-wide numeric object registry, sharing simulation records and persistent OBJECT_IDs. Render objects carry picking IDs. Pointer picking selects visible object geometry and stops at visible scenery; player helpers are excluded from default use but selectable by right-click. A bounded closed-DWK region keeps an open doorway selectable when its leaf swings into a wall. This is a conservative approximation of the target's hit priorities.

`ActionQueue` captures use intent, validates the target, approaches an authored use point, rechecks rules on arrival, emits object events and waits for a transition to settle. A click does not immediately toggle state. Duplicate requests for the active target are ignored; movement keys/Escape cancel approach. Doors check usability, destruction, locks, available collision states and actor overlap, choose opening side and dispatch state/failure events. Animation and collision follow the state event. Normal module startup holds doors in resting poses; diagnostic animation tools are opt-in.

The shared walkmesh planner uses A* over face centroids and sampled shared-edge portals, then sweep-validated smoothing. A spatial corridor limits triangle work during searches. Every route segment and actor step uses capsule/floor checks. This is a replacement planner, not a reconstruction of the native pathfinder: exact-edge matching, finite portal samples, no dynamic replanning and incomplete walkmeshes can prevent valid routes. The capsule radius substitutes for the unmapped actor use-range field; walkable visibility approximates native line of sight.

Visible models still resolve with UTD defaults, while the session uses complete authored GIT instances for gameplay state and locals. The [script/object runtime](script-object-runtime.md) now executes authored door events, mirrors linked-door state, and runs the actual transition script through deferred commands. Its explicit [radial Close](radial-menu.md) enters the shared queue without invoking the transition-click script. Keys, traps, full campaign startup, multiplayer authority and broader creature/placeable simulation remain unfinished. Cancellation after a state event does not undo a committed door transition.
