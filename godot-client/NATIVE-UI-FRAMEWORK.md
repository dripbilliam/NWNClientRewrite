# Shared native menu framework

Immediate priority: [complete level-up UI parity](NATIVE-LEVEL-UP-PARITY-GOAL.md).
Original presentation, complete action behavior and original-local-server
acceptance are required; the rest of this framework's unfinished scope remains.

The [current first-level creation checkpoint](NATIVE-CREATION.md) now connects
the shared source controls through class-dependent Package children,
Appearance/Information and the native BIC worker. Active class records privately
apply original legacy initialization before server overrides. Immutable feat
metadata survives within-draft transitions, with fresh post-Skills eligibility.
Source-automatic feat recommendations carry a compact receipt replayed in the
existing worker; manual completion stays separate. Level-up now owns its own
transaction-scoped class publication and accepted-resource observer; it reuses
only the original field compiler, never a first-level creature snapshot.
See [the mode1 publication checkpoint](NATIVE-LEVEL-UP-CLASS-PUBLICATION.md).
Older staged descriptions below are historical within those scopes. Full
level-up, original pixels and the complete UI/client objective remain unaccepted.

[Quickbar contexts](NATIVE-QUICKBAR-CONTEXT.md) reuse the source information and
generic-edit owners lazily, with actual slot/binding/session lifetimes. Native
LineEdit submission retains editing across reentrant two-stage macro prompts.
Quickbar items borrow the item wheel with an independent origin; attachment
changes retire old input, while received protocol equipment caches remain
separate from last-disclosed GUI positions. Scoped original-server outcomes
pass; complete role/bound-type availability and original pixels remain open.

Rule ownership is separate from pregame artwork. Creation and level-up always
read the base or active server's resolved `.2da` tables, referenced class/race/
feat/spell/skill resources and custom TLK. Shared widgets must not bring stock
choice lists or cached rules from another connection. The [skill allocator](NATIVE-CREATION-SKILLS.md)
is shared native code with caller-supplied rule context and original byte/word
semantics; the specific creation/level-up controller still owns its draft.

[Feat-slot counters](NATIVE-CREATION-FEATS.md) now share one active-table core
between actual creation and level-up owners. Original BYTE widths and physical
bonus rows/defaults are checked separately from the still-unbound Feats screen.
The staged `native_feats_chooser.gd` now also reuses the source modal/painter
for original list rows and separate group/info popups. Physical input checks do
not replace its pending live draft/rule binding or original-pixel acceptance.

[Skills creation](NATIVE-CREATION-SKILLS.md) now reuses the source modal/painter,
help/scrollbar and strict GUI repeat timer. Its layout keeps the original frame
and nested label offsets, while separate metadata/numeric models retain row
controls during held edits. The caller owns active data, recommendation/reset,
mask commit and the transferred Package callback. Feats/class-dependent source
continuations, complete creator/level-up and original pixels remain open.

[Package](NATIVE-CREATION-PACKAGE.md) now reuses `native_creation_choice.gd`,
source help/modal/painter and native scrollbars. Its selection state keeps
Package-specific general help, physical ordering and Cancel3 separate from the
other choosers. Caller-owned native entry/async commit handles table loading,
live draft metadata, automatic8008 and the transferred configuration child.
Skills now owns that child. Its later Feats/class-dependent continuation, name
generation and complete original helper parity remain open.

[Abilities creation](NATIVE-CREATION-ATTRIBUTES.md) reuses the source modal,
painter, help region and original GUI repeat timer. `native_source_help.gd`
accepts a scoped numeric prefix while preserving Race/Class/Alignment caching.
The parent owns active rules/text, exact live allocation and result8003. Own
edits preserve a held arrow; external context changes retire it. Full creator,
level-up variants and original pixels remain unaccepted.

[Alignment creation](NATIVE-CREATION-ALIGNMENT.md) now uses the shared original
modal/painter and `native_source_help.gd`. Race and Class reuse that same
readonly help component. The parent owns active class/rules/TLK context and
draft commits; native restrictions, radio input and result lifetime stay scoped.
The complete source creator and original-client visual acceptance remain open.

[Class creation](NATIVE-CREATION-CLASS.md) extracts the original list/help/radio
presentation and hook validation into `native_creation_choice.gd` and
`creation_choice_layout.gd`, shared with Race. Active rules/text and scoped
draft commits remain caller-owned. This accepts neither level-up variants nor
the still-staged complete original creator.

[Race/Subrace creation](NATIVE-CREATION-RACE.md) adds
`native_source_modal.gd` for shared original-resource preparation, source
buttons, held input and retirement. `native_generic_edit.gd` reuses the original
UTIL_EDITPOPUP with scoped text/limit/OK/Cancel behavior. Callers own their
draft rules and active data, while pregame frames retain their independent
catalog. This does not accept every generic-edit consumer or the full creator.

[Original Gender creation](NATIVE-CREATION-GENDER.md) now reuses the source
painter/buttons/fonts/animated scrollbar and the parent's scoped child tickets.
The native draft owner commits its result; no new view-side BIC/network writer
is introduced. Remaining child workflows and complete creation parity stay open.

Creation summary lists: [live Feats and Spells](NATIVE-CREATION-SUMMARY-LISTS.md)
reuse one source list view with scope/availability providers rather than a
picker-specific copy. The real draft and typed-BIC picker keep distinct data
projections; original live and imported Spells callbacks have different rules.
The source creator remains staged pending its remaining original children.

The [live Skills summary](NATIVE-CREATION-SKILL-SUMMARY.md) now uses that same
view. Its native draft owner preserves the original committed eligibility mask
through rank edits and clears/rebuilds it only on the relevant reset/acceptance
routes. Sharing geometry does not substitute BIC import state for a live draft.

Accounts: [saved login profiles](NATIVE-LOGIN-PROFILES.md) pairs player names
with Windows-protected keys, using one shared native manager from Options,
Player Name and the browser header. Credentials resolve at connection time.

Browser update: [automatic list loading and header refresh](NATIVE-BROWSER-REFRESH.md)
loads the first permitted Internet list automatically and enforces a two-second
refresh cooldown in both the native UI and data service.

Navigation fix: [character Cancel and browser return](NATIVE-MULTIPLAYER-NAVIGATION.md)
keeps native frontend ownership through disconnect and prevents retired lobby
fallbacks. Cancel returns to the native server list on the last active tab.

Game-value formatting: [whole-number display policy](NATIVE-GAME-NUMBER-DISPLAY.md)
fixes remaining JSON-float displays while retaining diagnostic and authored-text
precision. Its receipts cover the changed formatting paths, not full UI parity.

Follow-up: [server-browser responsiveness](NATIVE-BROWSER-RESPONSIVENESS.md)
retains original list rows/labels, updates changed records, skips duplicate views
and hidden fallback work, and formats JSON integer fields without `.0` suffixes.

This consolidates native UI construction and presentation. Controllers still
own their particular game rules, request signals and authoritative state.
It does not complete missing gameplay or certify the entire UI parity goal.

The [fixed character summary](NATIVE-CHARACTER-SUMMARY.md) now has one source
layout/view builder shared by the shipping character picker and in-progress
CG_MAIN parent. Caller-specific projections, availability and private input
tickets remain outside the view. The resizable in-game sheet remains a distinct
source variant; creation content/live integration and original pixels stay open.

The [creation data provider](NATIVE-CREATION-SUMMARY-BINDING.md) borrows that
pregame view while reading the actual connection-owned draft and active text.
Scope/generation guards protect hidden staged views as well as visible controls;
portrait commits update the real draft without replacing the committing ticket.
Remaining source content/children and complete activation stay open.

Startup follow-up: ordinary launches now receive `main-menu-open` instead of
the host's unconditional `browser-open`. The native owner hides lobby/browser
controls and presents the original Main Menu. Browser admission remains behind
the Multiplayer action; explicit owned local diagnostic harnesses retain their
browser entry. The complete launcher check `native-main-menu-startup-v2` observes
the ready main menu with both other surfaces hidden, then checks its existing
Options/Multiplayer routes. It exits cleanly with zero public connections.
The earlier `native-menu-framework-` receipts below precede this two-file
startup routing follow-up; they are not fresh whole-source receipts for it.

## Where to make changes

[Adjustable chat](NATIVE-CHAT-HUD.md) uses the same definition builder, shared
theme and DraggablePanel for its client settings. The gameplay HUD keeps original
chat model geometry/art. Options and the HUD acquire one viewport-scoped settings
window using the menu-layout file; they do not construct competing dialogs or
store chat preferences in the rendering-options file.

[Shared native tooltips](NATIVE-TOOLTIP-TIMING.md) use the same Client Options
builder. Its integer millisecond control persists microseconds in the Interface
preferences and applies the original default/range to engine and native item
tooltip consumers. Source-painter buttons and inventory/store/trade items now
share a viewport router, anchored source bubbles and original32-pixel movement
policy. The [active highlight key](NATIVE-HIGHLIGHT-TOOLTIPS.md) now drives world
labels and instant GUI hints with the original double-tap latch. Unsupported
controls, pregame key/resource-flag integration and full
graphical/modal acceptance remain open.

[HUD consumers](NATIVE-HUD-TOOLTIPS.md) explicitly borrow the live source
tooltip controller where they borrow artwork. `borrow_tooltips` does not take
ownership; painter close unregisters its decorated controls and closes only an
owned scope. Scripted widgets opt in through `native_tooltip_content`, preserving
their existing script and input signals. Retirement and live scope handoff finish
the old popup before control/resource ownership changes.

| --- | --- |
| Original-resource modal preparation, source buttons and held-input lifetime | `systems/native_source_modal.gd`; text-edit consumer `native_generic_edit.gd` |
| Construct standard controls or a whole definition tree | `systems/native_menu_builder.gd` |
| Shared source-button/item tooltip timing, foreground hit and scoped bubble views | `systems/native_tooltip_router.gd`, `native_item_tooltip.gd`, `native_data/tooltip_timing.gd` |

| Colors, fonts, original button/check/arrow/close images and picker variants | `systems/native_client_menu_style.gd` |
| Original GUI buttons, labels, edits, animated bounds and captions | `systems/native_gui_painter.gd` |
| Original GUI-model bounds and hooks | `systems/native_data/gui_model_geometry.gd` |
| A screen's network requests, pending operations and received state | Its existing controller |

Both Client Options and Game Options are constructed by the same
`MenuBuilder.build(content, definition)` entry point. The returned ID map binds
the controller's existing fields to the generated controls. The controller then
connects its action signals and supplies values. Definitions contain no file,
network or gameplay operations. Invalid kinds, duplicate IDs and unsupported
properties are rejected before a definition publishes any controls.

Original replicated menus keep their active catalog's GUI/MDL definitions and
source geometry. The same builder supplies their controls through the painter's
`create_button`, `create_label` and `create_edit` helpers. Existing controls can
still be decorated by `button` and `label`; this preserves specialized widgets
such as draggable inventory slots, scrollbars, portrait previews and map pins.
The original layout-specific parsers remain responsible for their source hooks.

The shared painter now extends Node directly. Inventory extends the painter,
adding its repository, container, equipment and expandable footer behavior.
The dependency previously ran in the opposite direction: unrelated menus
inherited the inventory implementation merely to paint a button. Source-model
geometry is also independent of equipment policy; the older equipment layout
entry point delegates to that common geometry implementation.

Native menus using the helpers include entry/Options/Multiplayer, original
character selection and record pages, connection/profile/password/confirmation
dialogs, key/video settings, examination, gold transfer, character-sheet,
spellbook, journal, player and trade controls. Source-specific actions, capture
revisions, cancellation and server acknowledgments stay with their owners.

## Theme and window lifetime

The active style publishes one tree-scoped Theme and updates registered
draggable windows. A window created later inherits that Theme immediately;
there is no requirement to subscribe each window separately. Closing the style
owner retires its publication. Original transparent panel overrides and their
authored close-button geometry are preserved during theme changes.

The retained experimental character picker has a distinct appearance and
immediate construction. It is now off in normal launches following the user's
request to restore the original-style chooser. Its controls use the common constructor; its primary,
ordinary, selected-row and unselected-row styles are named variants in the
shared style owner. Roster updates choose a variant instead of allocating four
new style boxes for every character on every update.

## Extending a menu

For a flexible menu, use the definition helpers to describe rows, columns,
tabs, labels, buttons, checks, choices, progress and scrolling regions. Give
controls stable IDs when the controller needs to update them. Construct once,
connect actions once, then update the same instances from received state.

For an original replicated menu, keep its source layout parser. Pass each
parsed entry to the painter's common helpers, or decorate a specialized existing
control. Preserve source dimensions and font metrics. Connect its signals to
the owning controller; the builder must not send game requests or predict
server outcomes.

Specialized content still has dedicated code. An item grid, world map or
three-dimensional portrait is not represented as a generic list of buttons.
Server-authored NUI retains its own schema interpreter and event semantics;
this refactor does not reinterpret it as an original GUI layout. Those are
intentional extensions of the shared controls, not a promise of one universal
function containing every screen's behavior.

## Verification

Current local native receipts use the `native-menu-framework-` prefix in
`reports/`. They cover definition publication/instance separation, preference
persistence, theme propagation to existing and late windows, source-frame
override preservation, and actual native input on the migrated menu routes.
The debugger wrapper checks source hashes, native exceptions, engine errors
and resource lifetime. Final accepted receipts are recorded by
`tools/audit-native-menu-framework.mjs`.

No public server connection or performance benchmark is part of this change.
Network-facing menu checks use authored replies and inspect the real typed
request signals. Earlier connected-server gameplay evidence remains a separate
scope. The broader parity goal, including unported original actions, is open.

Intermediate failures are retained: the first framework test incorrectly used
a script-resource method as a static call; a broader legacy settings fixture
loaded an unused complete protocol client and leaked that dependency graph at
exit. The fixture now omits that unused import and reports both its legacy
`passed` field and the wrapper's standard `success` field. Its 21 original
interaction checks remain intact. These failed runs are not acceptance evidence.

The desktop follow-up also found a real off-tree construction path: the store
calls window configuration before adding the window to its parent. Shared
styling now uses the base Theme off-tree and applies the active published Theme
on attachment. The actual late-window/style test covers this order. The broader
desktop fixture now chooses self-compatible cantrips and item powers from the
installed tables for its self-click scenarios; its older hardcoded selections
were rejected by current targeting validation. Gameplay targeting rules were
not loosened. A test invocation missing its required retained chooser oracle
was rerun with that oracle; it is not accepted as an executed test.
