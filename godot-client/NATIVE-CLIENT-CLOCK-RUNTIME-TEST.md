# Isolated native client clock runtime integration

The new runtime gate executes Root's actual `native_client_clock_runtime.gd`,
Services/Timer/Pause/ObjectClocks and explicitly loaded accepted Win32 clock DLL
in a copied headless project. It edits none of those producers. The copied
hidden `.cache/native-clock-source-v1` contains DLL SHA256
`497e483e44595a7518b860f92c55e3ab3cef9cd372b15c53a2ac31dfd2498190`
and byte-exact `Source.DESCRIPTOR_TEXT`. No extension list is authored and the
main project/extension list/clock installation/six outputs remain hash-guarded.
No DLL build, original client, server, credential, profile, visible/GPU action or
user-process manipulation occurs.

Picker's `native-clock-runtime-fixture.mjs` supplies17 batches/15 exact Bridge
frames from actual NetworkGameSession/NetworkWorld/private lifecycle/
RawCombatEvents/EntityDisclosure owners. Server DTO inputs are authored. The
last3/9 packet uses the actual native writer and decoder, not original server
capture. The generator forbids connecting/sending/resource loading, pins its
recursive source closure before/after, and exports detached raw rows/witnesses.
The runner generates it in an owned15s Node child before copying inputs.

The actual Runtime is configured with a thin fake client and passive Node GUI
holders, `native-overhead-clocks:true`, real absolute Win32 source samples and
actual engine frame numbers. Each engine frame performs prefix, exact ordered
fixture events, optional delayed received-row publication, then post_receive.
Query inputs use the actual `SpeechAnchor.witness(row)` and `Scope.context`
owners. Godot JSON numbers are FLOAT while owned witness/scope arrays are INT;
their values and raw fixture stay unchanged. A negative retains raw-array
rejection. Preserved v1 evidence has ten rejected raw-array queries, and the
production Runtime fences remain unchanged by this test-input correction.
No clock/frame duration, actor pose, model, result or constructor token is
injected. The received row publication is a detached unchanged fixture row.

Cases cover default/offline disabled paths; single process three-clock
construction; actual known pre-area OBJECT_INVALID scope; birth while raw/model
is absent; repeated A retaining physical identity; late first query from preceding
completed AI rather than birth/UI time; unknown other entity preserving T2 and
the certified actor; actual row dual-lifetime/token/scope checks; area transfer;
remove/ambiguous A invalidating even an older still-published row; reconnect and
old Bridge callbacks; and deliberate unsupported pause with no nominal fallback.
Actual samples advance only at the constructor/prefix, not raw publication,
protocol receipt, post_receive or queue/GUI queries. No assumed16ms delta is used.

Hot-method source guards reject full `state_view` calls in normal Runtime paths.
Only two explicitly cold test diagnostics inspect full state: early birth and
late-first-query basis. Area transfer enumerates thin refs only on a changed
scope. This is not a performance measurement or full-world benchmark.

The three GUI holders check actual Runtime Callable binding and explicit
availability only. They have no text/layout/model/renderer processing. Actual
ordinary/script/registry GUI-clock method execution belongs to separate tests;
this gate is not UI pixels or scene projection acceptance. Holder readers are
explicitly released at teardown. Runtime.close must break its Services/Pause/
acceptedLifecycle Callable cycles; unsupported clock history remains unknown.

The runtime intentionally lacks native pause scene/audio/profile/GUI lower
providers. A real received ON transition therefore fails before mutation, with
no zero or engine-delta substitution. Closing that unsupported state is tested;
actual partial Pause cleanup remains the separate Services165 component proof.
The test does not fabricate a live partial native transition to claim otherwise.

The private source is direct-Real only. It does not claim the original default
threaded-cache sampling phase, a remote full-frame/pause lower-provider admission,
original-server packet authority, or a live application/visual acceptance.
