# Direct-handoff semantic-chain integration

The dedicated driver accepts `canonicalCharacterContinuity`,
`compareCharacterChain`, and `compareRetryCharacter`. Root enables these only for
the owned direct check, using the actual parsed-BIC helper. Raw SHA/byte/upload
checks remain unchanged.

A configured roundtrip requires download A → download B → final original export
to match the helper's complete selected projection. The first installed read is
held as detached private canonical data and passed as an initial diagnostic with
`requireInitial:false`. Its changes are not hidden and do not silently become a
required edge. The capture retains comparison coverage, completeness and all
bounded differences. Missing or incomplete proof, bad provider results and
comparison errors cannot pass the configured check. Later evaluate options cannot
turn off the capture's constructor requirement.

Recovery has a different identity chain: after cancellation/failure, the UI
selects a fresh installed Wizard. Its retry read → final original A export and
initial read → retry read are diagnostic pairs. The abandoned, wiped download is
labeled separately and is never substituted as the fresh retry character. There
is no semantic gate added to recovery without another reviewed decision.

The [preparation receipt](reports/native-direct-handoff-semantic-chain-preparation-v1.json)
records 37 passing Node checks, including eight boundaries driven by actual parsed
and rewritten public Wizard BICs. Those tests used helper `3ef50102…d453a2`.
Character's later spellbook-coverage helper `44d2ba61…fb9d31` has separate focused
evidence, but the combined driver tests have not been rerun against it. The
requested manual user session froze the runtime before that combined run.

Driver and capture sources remain frozen. No engine, server, socket, key, GPU,
input, build or user-process action was performed here. Actual native pointer,
original-server semantic-chain/recovery acceptance and the broader stage matrix
remain separate work. Historical v8 raw/protocol acceptance is unchanged.
