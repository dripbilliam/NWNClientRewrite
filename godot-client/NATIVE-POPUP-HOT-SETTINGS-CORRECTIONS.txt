Popup hot settings: reviewed clock and visual-publication corrections

The first scoped checkpoint and its successful34 checks remain unchanged.
Read-only review found two additional paths not covered by that fixture.

1. A delayed native speech body may become ready after the Owner has already
   added the current GUI delta to request.elapsed. Transferring that record to
   the later Registry callback must not tick the same delta again. Every such
   elapsed update now records the actual Engine process frame on the pending
   request, including pre-firstscope requests. ANY later same-frame resolution
   propagates it to the shared record. The Registry skips that accounted delta
   once in the matching frame and clears the bookkeeping marker. Fresh text
   or an actual mode refit clears it; font/cache-only changes preserve it.
   accountedGuiFrame is local handoff bookkeeping, not a claimed native field,
   second timer, packet value or gameplay authority.

2. Enabling an inactive popup while its model/head anchor is unavailable used
   to lose its one-shot projection request. Eligible popup IDs now wait in a
   bounded exact-witness/scope set without ongoing idle processing. The actual
   NativeLiveWorld instance-ready/state-changed path stamps the visual first,
   then calls Gameplay.popup_visual_ready(id,visual_source,visual_scope) only
   for the accepted local connection/generation/area tuple. Gameplay forwards
   to the speech Owner, which validates both the current received source and
   the supplied visual source against the event's exact lifetime. It attempts
   synchronization once. Off, hidden, unknown-current-raw, removed, reused or
   retired sources cannot activate; scope closure clears candidates. No extra
   world/entity registry or per-frame world scan was added.
