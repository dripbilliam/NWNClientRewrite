# NWN-75: original model-resource storage branch

Original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This continues the model callback branch in `model-instance-branch.md`. These are demand-time resource operations; the static call tree does not prove they run each rendered frame. No worker handoff appears in these functions, so a call inherits its caller's thread. Dynamic thread identity is not established.

`CAuroraInterface::GetResource` `0x1400f63d0` chooses `CAuroraModel::LoadModel` `0x1400f4a70` for an MDL request. `CRes::Demand` `0x14018f300` calls `CExoResMan::Demand` `0x14018ef90`, which may reuse resident data or dispatch by storage class: 1 `ServiceFromResFile` `0x140193b80`, 2 `ServiceFromEncapsulated` `0x140192cf0`, 3 `ServiceFromDirectory` `0x140191e80`, 5 `ServiceFromManifest` `0x140193520`. Inputs include the resource ID, storage class, key entry and destination `CRes` buffer. The result is loaded model bytes plus service status, before model parsing. Evidence: REA `ev_5d7c92d55b6cd5dcc52fae8cadb9fc10e71b7c4d0aa03060a91a32c581d0f472`.

Classes 1 and 2 select an archive object from the table, call virtual `+0x8` to add a reference, virtual `+0x28` to get resource size, allocate the `CRes` buffer, then virtual `+0x40` to read resource bytes. The original constructors install CExoResFile vtable `0x140da1298` and CExoEncapsulatedFile vtable `0x140da12f8`. That marks the model bytes loaded and exposes data pointer/size. Short reads log and release the archive reference. Evidence: REA `ev_63e6a07d`, `ev_462ad7d6`, `ev_befe38c8`, `ev_6545f4ed`, original PE vtable bytes.

Both archive `ReadResource` implementations check open state, destination and resource index, seek to the stored offset, and choose either a plain `CExoFile::Read` `0x140166ca0` or compressed `CExoPackedFile::ReadNWCompressedBuffer` `0x14018c730`. `CExoFile::Read` forwards to `CExoFileInternal::Read` `0x140167c60`. A memory-backed file copies from its buffer and advances offset; a CRT-backed file calls `fread` `0x140c7e2a0` → `fread_s` `0x140c7e2c0` → `_fread_nolock_s` `0x140c7e010`. The latter either uses buffered `__acrt_stdio_refill_and_read_narrow_nolock` `0x140cafdc0` → `_read` `0x140ca7648`, or calls `_read_nolock` `0x140ca7764` directly for larger transfers. `_read_nolock` reaches imported `KERNEL32.DLL::ReadFile` on ordinary file handles; console alternatives use imported `GetConsoleMode` and `ReadConsoleW`, and failures use `GetLastError`. The ordinary file read path is therefore closed to an external OS API. Evidence: REA `ev_19121065`, `ev_1c8aec1d`, `ev_203ac148`, `ev_34aefe48`, `ev_d7558fd4`, `ev_47720f1e`, `ev_998effec`, `ev_3c7dede7`.
