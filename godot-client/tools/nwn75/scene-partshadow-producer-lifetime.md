# NWN-75: authored PartShadow creation, BSP admission and draw lifetime

Scope: installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This closes the PartShadow side of `BSPCreateStaticProjections` `0x1400d7f00`, which [the beam continuation](scene-beam-source-and-draw.md) left as an alternative. Shared projection, VDO, shader and GL implementations remain in their existing notes. Static evidence does not establish live authored subtype counts or draw frequency.

## Producer and subtype priority

`Scene::PostProcessLS` `0x1400cb200` and `Scene::RecomputeStaticProjections` `0x1400cbb20` call `BSPCreateStaticProjections` at `0x1400cb3ef` and `0x1400cbc37`, respectively, after traversing the Scene BSP with `RemoveShadows` and `RemoveBeams` callbacks. The projection builder itself returns unless `buildstaticshadows` is enabled. It scans candidate PartLights with radius `+0x74 >= 1000`, then BSP TriMesh Parts whose model node has authored `shadow +0x110` or `beaming +0x114` nonzero. A further source geometry/height test and TriMesh virtual `+0x108=WithinRange` at `0x1400d8258` must admit the mesh. When `beaming +0x114` is nonzero it selects **PartBeam**, even if `shadow` is also set. Only a zero `beaming` value selects **PartShadow**, which by the earlier OR gate requires nonzero `shadow`. This prevents counting one source mesh/light pair as both produced subtypes on this path. Evidence: builder `ev_f2c7e135f631952ab83176aa86238abe20b8a68d56f669c493ce68946dacc88f`; caller `ev_648ab72b157d03a99962c9d8a373e45a9c79c01d137eedc39596d5e4d2474ed3`; [authored flag parser](scene-beam-source-and-draw.md), [projection eligibility](dynamic-projection-eligibility-and-helpers.md).

The shadow branch allocates `0xb8` bytes, calls `PartProjection::PartProjection` `0x140087ed0` at `0x1400d8293`, **overwrites the base projection vtable** with `PartShadow::vftable` `0x140d8fe88` at `0x1400d82a0`, then calls `PartProjection::Init` `0x1400a2b30` at `0x1400d82ac`. The base constructor's `+0xc8` Draw slot is a guarded error trampoline; this derived table is installed before `Init` and before Scene publication. `Init` uses the derived `+0x80=AsPartShadow` result to choose the light's shadow radius/vertical displacement, then calls TriMesh `+0xb8=Project` to build projected geometry and, when faces are emitted, its VDO item. The common projection builder and its pool/GL buffer conditions are in [dynamic shadows](shadows-and-dynamic.md). A zero emitted face count `PartProjection+0xac` takes the virtual deleting destructor immediately at `0x1400d8311`. A positive face count calls `SceneBSPAddPart` `0x1400dcfd0` at `0x1400d831e` with null Model; allocation failure does not establish a valid object and is not treated as admission. Evidence: builder above; Init `ev_b99f859d89aa80b1e08a9556d2f0973478b46a757635ded9efb6b09cb241f3db`; [Part table census](part-draw-rtti-census.md).

## BSP queue to conditional GL leaf

With a nonnull Scene BSP, `SceneBSPAddPart` classifies the Part through `+0x78=AsPartProjection`, fits its `+0x88..+0x9c` bounds with `BSPFitBox`, and `+0x80=AsPartShadow` returns self for this table. It appends the pointer to the selected BSP node payload shadow list `+0x40/+0x48`. The visible BSP callback later requires `enableshadows && shadowstaticgeom`, culls each candidate with `PartOutside`, and appends survivors to `_staticshadowbucket`. `Scene::AddPartsToDrawBuckets` assigns each such Part to bucket 9 or 10 by `shadowfliporder` and an eight-corner camera-plane test. These are CPU preparation gates, not draw submissions. Evidence: membership `ev_d939045d5b0e98af6b4ec95068ecce22e2d76c44a8d4be3718e91c740718ba8d`; [visible BSP callback](scene-bsp-visible-callback.md); bucket body `ev_9b2776e75e9df7689deec134df0f62a5416d96a73218bc317ec5a36294648eb3`.

`Scene::RenderStaticShadows` `0x1400d2ca0` requires a selected first static shadow light that matches the LightManager's active shadow light and a usable `vs_shadowvol/fs_shadowvol` shader. It traverses bucket 9, then 10 with opposite stencil operations. For each nonnull item, Part virtual `+0x80=AsPartShadow` at `0x1400d2f5c` must return self and VDO `PartShadow+0xa0` must be nonnull. The next virtual `+0xc8` at `0x1400d2fcd` resolves to `PartShadow::Draw` `0x1400a2490` from the pinned table. That body calls `RenderInterface::RenderVertexData` `0x1400beec0` at `0x1400a24b5` with VDO `+0xa0`, **item ID** `+0xa8`, primitive `4` and default offsets. The selected VDO item's element count determines the later indexed draw; the shared `GLRender::RenderVertexData` route conditionally reaches imported `glDrawElementsBaseVertex` if program/VDO/stream state permits. No per-frame VDO rebuild is shown in this static-shadow draw body. Evidence: static pass `ev_10df1f7733b60aeecf039e74a43da7441e0b5efd08da1652d050cface9c4b624`, slot bytes `ev_f844fbfc408c5306aab29513229811897033f7b03f1dddcc9ad8c15c6aaef072`, Draw `ev_94b973dc79bec4b8f479511a16de80f03033d297af3a68323b96eaaf84e884d1`, [geometry/GL boundary](geometry-and-draw-boundary.md).

## Removal and remaining limits

`RemoveShadows` `0x1400dce70` walks each BSP node payload shadow list `+0x40` backward, invokes virtual deleting-destructor slot 0 on every nonnull pointer at `0x1400dcea8`, and decrements logical count `+0x48`. PartShadow's installed slot 0 is `FUN_1400d7390` `0x1400d7390`. With the observed delete flag 1, it calls `PartProjection::~PartProjection` `0x140089e00`, which calls `VertexDataObject::RemoveItem` `0x1400be140` for nonnull VDO `+0xa0` and valid item ID `+0xa8`, calls base `Part::~Part`, then frees the `0xb8`-byte object. Both explicit recomputation routes remove old projections before creating replacements. This is VDO item bookkeeping plus object release; the shared VDO manager controls eventual buffer repack/upload. Evidence: remover `ev_83c663f700124e56bbb216cdff2686be74534af1a6906df534c9b3e610ff3a98`, deleting thunk `ev_d899a99a0f2de66402db0152d16a03510e7bbdc696a61bcc17afc55c39b6fa1d`, destructor `ev_3ae388a4d2d85f38272507d8b2a6c05db57f846fff3d2a63f1a890278a4f2059`, slot bytes `ev_7118bedaf7118dbf841a34ce4e13b379009c86fddb0b3effb3d5453eecf623b1`.

The authored shadow/beaming flags, BSP visibility, selected light/shader, VDO item state and external GL admission remain conditional. Other inlined or external `PartProjection` constructors and the live Part subtype mix remain open; this note proves the one constructor-backed Shadow producer and its subsequent exact Draw target.
