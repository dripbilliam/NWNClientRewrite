## Backend selection and presentation

## Window destruction

The Aurora GL destructor, its deleting destructor, and `CAurInternalGL::ShutDown` each have a nonnull-window route to exported `SDL_DestroyWindow` `0x140ab1470`; the main client's second cleanup reaches the deleting destructor through `DestroyCAurora` when Aurora's final owner is released. The wrapper uses dynamic API cell `0x14129a808`. Its initial thunk `0x140aabf40` calls the same initializer and tail-dispatches through that cell. The built-in table assignment at `0x140ab0d43/0x140ab0d4a` installs `0x140acfaa0`. This function checks initialized video and a valid window, marks it destroyed, handles focus/grab/fullscreen state, and conditionally invokes video-device slots `+0x120`, `+0x108`, and `+0x1b0` while releasing window data. On the Windows device, constructor `0x140ab9cf0` installs `0x140af3d50`, `0x140af0040`, and `0x140af40e0` respectively. `0x140af3d50` deletes a memory DC/object; `0x140af0040` releases the window DC, removes SDL window data, and restores its window procedure or calls `USER32.DestroyWindow`; `0x140af40e0` frees a device-owned module. These callbacks run only under their individual guards and selected backend. The traced `SDL_DestroyWindow` function does not directly call built-in `SDL_GL_DeleteContext`. ## SDL quit and context deletion

After the client and renderer cleanup, `SDL_main` calls `SDL_WasInit` at `0x140046e7d` and, if nonzero, exported `SDL_Quit` `0x140ab2aa0` at `0x140046e86`. Built-in `SDL_Quit` is `0x140abdf10`, assigned through dynamic API cell `0x1412998c8`. It calls built-in `SDL_QuitSubSystem` `0x140abdd70` with mask `0x7231`. The included VIDEO bit `0x20` reaches video teardown `0x140ad50c0` only when the subsystem's final-reference/quit gate succeeds. That teardown releases touch and mouse state, destroys remaining windows via built-in `0x140acfaa0`, invokes the video-device shutdown slot `+0x10`, frees mode/display data, invokes device slot `+0x548`, and clears the global device. The three initial helpers `0x140ae51c0`, `0x140ad5da0`, and `0x140ace560` have no direct GL-context deletion call; neither does the Windows `+0x10` target `0x140aba6c0`. The Windows `+0x548` target `0x140aba5f0` unregisters the window class/icons through `0x140ab7f50`, frees two nonnull backend modules through `0x140ad5740`, then frees backend data and device; it also has no direct context-delete call. `SDL_DYNAMIC_API` can replace this built-in quit path. REA `SDL_main` `ev_833c7aa9adb229ef33dd413c495d7c0f61fbec645c741d6268e78b62f252dd65`, built-in quit `ev_1c73c65d5b459948c2107eda09b4295206205b78f93bb596c06e45bc1c96e815`, video teardown `ev_0235366165d1f4c23caa2ba0b1b2b79b46e28f0ffe27c3823ca1578e0e806230`, Windows final callback `ev_41b8abda437ef295572522adfef949654215416c80c6e9bcf3d26fcd0c0d0d19`.

Exported `SDL_GL_DeleteContext` `0x140ab15e0` jumps through dynamic API cell `0x14129a898`; the built-in table assignment at `0x140ab0e3f/0x140ab0e46` installs `0x140ad00a0`. The built-in function requires nonnull device and context, clears the current binding when deleting the current context, then calls video-device slot `+0x198` at `0x140ad00e5`. On the Windows backend that slot points to `0x140af2f80`, which returns if device `+0x530` is null, otherwise tail-dispatches through its GL table `+0x30`. Loader `0x140af3390` chooses the `SDL_OPENGL_LIBRARY` override or `OPENGL32.DLL`, creates the table at device `+0x530`, resolves `wglGetProcAddress` `+0x20`, `wglCreateContext` `+0x28`, **`wglDeleteContext` `+0x30`**, `wglMakeCurrent` `+0x38`, and `wglShareLists` `+0x40`, and rejects missing required entries. The `wglDeleteContext` string at `0x140e95560` is referenced at `0x140af3460`. Thus the built-in Windows context-deletion leaf is a dynamically loaded Win32 GL entry, conditional on all prior selections and gates.
