## Shadow eligibility before geometry work

After `PartTriMesh::WithinRange` accepts a candidate, `Scene::DoDynamicMeshProjections` transforms the light direction and calls the concrete TriMesh `+0xb8=Project` slot at `0x1400c7a7f`. `Project` requires source geometry, then calls `PartTriMesh::GetProjectsShadows` `0x14008f5f0` at `0x1400a37da` before classifying any faces. This predicate returns true immediately if `PartTriMesh+0x50` has no owning Gob, the Gob's primary `Model` at `+0x68` has bit `4` of byte `+0x92` set, or the global 32-bit control at `0x14128ec04` is zero. The pinned initial value of that control is `1`; live settings may change it. REA `Project` `ev_96f7c8a1c7a9b9b2f795a7d4fc47f3e5f131ddefb9a258bb78f04d23f775826d`, predicate `ev_7725f75a3b8e20d59ababedca6a9f1170db2d0920a34b461eebd9fbd157bfe6a`.

Otherwise the predicate reads the owner's `+0x450` behavior. At computed `0x14008f62c`, its `+0x30=AsBehaviorAttach` slot returns null for base `CAurBehavior` `0x140054a60`, or the attachment for `CAurBehaviorAttach` `0x140054a70`. For a nonnull attachment, its `+0x30` referenced Part is called at `0x14008f63b` through Part `+0x30=GetAurObject` `0x140061af0`; all 18 constructor-backed primary Part vtables use that target, reproducible with `audit-part-hitcheck-vtables.cjs` against the pinned PE. If this returns an owning Gob, eligibility is true. This is the same behavior/Part ownership chain independently identified in [draw-bucket population](geometry-and-draw-boundary.md). The installed behavior and referenced Part are runtime or authored choices.

The remaining case compares mesh alpha at `PartTriMesh+0xa8` with the float cutoff at `0x14128e640`. If owning Gob `+0xf6` is nonzero, it first multiplies by Gob alpha at `+0x108`. It accepts alpha greater than or equal to the cutoff. The pinned cutoff bytes `da ac 2a 3f` decode to approximately `0.6667`; this is the image's initial value, not a measured live setting. The predicate and its two virtual pointer checks contain no direct GL work. An ineligible mesh returns from `Project` before shadow index generation or publication.

## CPU helper and pool boundaries

For an eligible mesh, `Project` caps source faces at `0xfffe`, classifies faces, and emits at most `0x2aaa` shadow faces; zero emitted faces stop the path before any stream reservation. On its nonnull `PartProjection` branch, `MakeMatrix4x4` `0x14022d640` at `0x1400a3e1e` builds a quaternion/translation matrix, and the two calls at `0x1400a3e63/0x1400a3ed1` to `0x14022ad60` transform projected vectors. Both bodies are scalar CPU arithmetic leaves with no callees or GL calls. REA `ev_d79728d3a7d51ae67874817ff51b4995ca954c996799581894e488091696ac03`, `ev_f306bbb3ce3393982abdf70f66463442e833d031d46997dada77160da64beb21`.

`VertexDataObject::GetItemElementData` `0x1400bd7e0` calls `RenderInterface::LockPool` at `0x1400bd7ff` for the element handle `+0x1c`, offset by twice the item's element start from `+0x58`. `GetItemStaticData` `0x1400bd830` calls the same lock at `0x1400bd856` for static handle `+0x28`, offset by stride `+0x30` times the item's static start from `+0x48`. These return writable CPU pool pointers; [shared stream allocation](shared-stream-allocation.md) establishes that `LockPool` itself performs no GL map or upload. REA `ev_e1b3b68d052855ad654883b37c6115fdfba796ebf18806a07baaa2cd6617c4c7`, `ev_4e2e722cbedd43cbfeb279e076227b971d6dd83b56d35eeea985de84d3f2c72a`.

On the null `PartProjection` branch, `GetElementStreamSpaceAvailable` `0x1400bd770` at `0x1400a3f6d` obtains the maximum index capacity through `RenderInterface::GetVertexBufferMaxElementIndices` `0x1400bedb0`, subtracts current element count, and clamps at zero. That getter only calls imported `glGetIntegerv` on its cached-value `-1` path, as mapped in [VDO preparation](primitive-vdo-preparation.md). Insufficient space conditionally calls `Scene::RenderDynamicShadows` at `0x1400a3f7d`; that flushes/commits the prior shared element stream and reaches draw only under its shader, bucket and positive-index gates. `GetElementStreamData` then locks CPU element storage for the next span. On the nonnull branch, `CommitItemStaticData` and `CommitItemElementData` reach `RenderInterface::UnlockPool`, whose pool-state gates select GL buffer creation, storage allocation/orphaning, or subrange upload; the getters and math helpers above do not publish GPU data by themselves.
