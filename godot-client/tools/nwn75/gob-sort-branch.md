# NWN-75: original live-Gob bucket sort

Pinned `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This is an address-backed static branch; it does not measure the Gob count in an area.

`Scene::AddPartsToDrawBuckets` loads comparator address `0x1400c9bd0` at `0x1400c41fb` and calls `std::_Sort_unchecked<Gob**, bool(*)(Gob const*, Gob const*)>` `0x1400c0290` at `0x1400c4202` on the entire `_gobbucket`, before its per-Gob `ProcessGob`/Part traversal. The sort has an insertion branch below 33 items, a median/partition recursive branch above that threshold, and a heap branch when its depth budget is exhausted. It retains the comparator pointer through calls into `_Partition_by_median_guess_unchecked` `0x1400bf850`, `_Med3_unchecked` `0x1400bf510`, and `_Pop_heap_hole_by_index` `0x1400bfdc0`. Those helpers invoke the pointer at 5, 8, 3 and 2 distinct static instruction sites respectively; a site count does not establish runtime comparison count. The Gob sort-value producer is the BSP visibility callback `0x1400dc140`. For an admitted Gob it computes a transformed origin from adjusted pose, subtracts that position from `CurrentCamera+0xb0/+0xb4/+0xb8`, sums the three squared components, stores the result at Gob `+0x140`, then calls `Gob::SetLODModel`. Thus the final comparator key orders farther Gobs first within equal flag groups. Culling skips that write, and `Gob::Gob` initializes `+0x140` to `-1.0`; whether a particular culled Gob remains in `_gobbucket` for this sort is controlled by upstream membership. The semantic labels of the three model flag bits remain open.
