# Original Nui value/max progress callback

Pinned installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`; addresses are image VAs. This is the stored callback table `0x140e6e500` → `0x14095cab0` route for a programmatic progress Widget with **two** unsigned 64-bit DynamicValues. It is separate from the percentage-style callback `0x140e6e538` → `0x14095c970` already described in [JSON widgets](json-widget-callbacks.md). Exact branch edges are in [the ledger](nui-raw-progress-callback-ledger.json).

## Constructor and source values

`0x14095f360` allocates a refcounted `Nui::Layout::Widget`, retains/copies two `DynamicValue<unsigned __int64>` inputs and installs a stored function object with vtable `0x140e6e500` at `0x14095f48d`. Its observed direct callers are the programmatic `Nui::NWSync::Downloader` constructor `0x1408ac060` at `0x1408ad4d5` and `Nui::NWSync::Housekeeping` constructor `0x1408adcf0` at `0x1408ae04b`. The latter initializes one input to a literal 100 before calling the progress constructor; this does not prove all progress Widgets use a 100 maximum. Both caller paths eventually install window content, subject to the registry/open/visibility gates mapped in the existing [downloader branch](nui-downloader-status-label.md) and [registry ownership](nui-registry-ownership.md). Evidence constructor `ev_0311cfb4637237080df1b198c7722e09af9f3ef5b053423bf941329ad51ce347`, Downloader `ev_bacda11dfca5d965f6625b075c8957f5911c3a1eda7cb9d313f27011959fd95d`, Housekeeping `ev_55c39b7c77d45317220fdea0a1349d6a92fac818ef5ea45505f6a2ad88bc6907`.

The Widget render slot `0x1409528e0` invokes stored callback virtual `+0x10`. Table `0x140e6e500+0x10` resolves to `0x14095cab0`. That body reads both DynamicValues; each can be a direct value, a cached generated value or a fallback. It takes `min(first, second)` as the filled amount and passes the second as the maximum, then tail-jumps at `0x14095cb92` to `0x140a88a80` with mode zero. This caps the numerator before the progress helper's division. A missing or zero denominator is not specially handled in this wrapper; whether the resource data admits one is not established. Evidence `ev_4599d729ae3bcbd580def9bc5516cf84c0223df9ec923931d89a325b08bcf0f1`.

## Command leaves and open gates

`0x140a88a80` requires a nonnull Nui context, active window and valid row before calling `0x140a64610` at `0x140a88b2d`. The latter computes an inset progress rectangle and a fill width proportional to the unsigned value/max pair. It draws a background and a fill, each independently selected by style code: code 0 calls filled rectangle kind **5** and outlined rectangle kind **4**, code 1 calls image kind **17**, and code 2 calls nine-slice helper `0x140a7d2e0`, which emits textured slices under its own gates. Each producer is additionally subject to clipping and command allocation. Existing Nui conversion and a nonempty draw command are still required to reach imported `glDrawElements`; static reachability does not prove frame frequency. Evidence wrapper `ev_cd006aa92be8361ecbf7e76ad3ad28acee77712a8b954ade203df78e8530d966`, progress helper `ev_c4e21794555b6fa4105bb75694771fa805a5e90b8db2e363c19133a12ab0365c`.

The exact downloader/housekeeping DynamicValue generators and service data that supply the two values, style configuration, window open state and source content remain data-dependent. The route does not perform progress-value publication itself; it reads values and emits conditional display commands.
