# NWN-75: original TriMesh hit-test geometry continuation

Pinned installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This is a conditional CPU descendant of [Scene/Gob/Part hit checking](lens-flare-hitcheck.md). The same Scene hit-test can be reached by lens-flare occlusion and by admitted particle collision; neither caller's live frequency is established here. Addresses are original PE virtual addresses and the [ledger](original-hitcheck-geometry-ledger.json) records the direct sites.

`PartTriMesh::HitCheckGeom` `0x1400905b0` reads its model geometry and `CHitInfo` mode. When `CHitInfo+0x20` is nonzero, it expands/scales the mesh bounds and calls the output-point `BoxIntersect` `0x14022b7e0` at `0x140090764`. A miss returns immediately; a hit records the chosen point/normal and returns without locking the vertex pool or scanning faces. The exact body is Ghidra evidence `ev_90abc7c5927074437873c13688a68c095f93bed76fd5db0f0555d9323e499b94`. `BoxIntersect` has no direct calls in its complete body (`ev_33f6cbfa950582319aa055f63727e547b23fe55389e84de5809b1faf8d75f8c6`).

When that mode byte is zero, the routine first calls the no-output `BoxIntersect` `0x14022b400` at `0x14009086b`; a miss returns before the face loop. An admitted segment locks the selected vertex pool through `RenderInterface::LockPool` `0x1400bee30` at `0x14009089a`, using the mesh's pool ID at geometry `+0x280`. The wrapper reaches `GLRender::LockPool` `0x1400b4aa0`, which returns a CPU pointer into the pool and records its usage byte; it is not a GL map call (`ev_9d3dfd5e38819745ff67c37a956252bd78cdc6d78e218c6fa899b86c4652d6f1`). The no-output `BoxIntersect` body has no direct calls (`ev_803c57170127c1f6d1a52c58f5feda2db730d24da0a0740403d3f1b90fdb5461`).

For each mesh face, the routine reads three indexed vertices from that CPU pool, scales them when `param_5 != 1.0`, and calls `polyhit` `0x140231810` at `0x1400909ad` or `0x140090ad8`. `polyhit` tests the segment against the face plane, then the intersection against polygon edges and conditionally writes the hit point; its complete body has no direct calls (`ev_a21d6e7b7e5bf1ccc08b188f23ab7ee78660fa3bbaea18076df77dba747ab0b7`). On any admitted face, `HitCheckGeom` updates hit output and returns the accumulated result. The face count, index values, bounds and authored model subtype remain runtime data.

The face path locks through `RenderInterface::LockPool` at `0x14009089a` with mode `0x18` in R9D, then unlocks through `RenderInterface::UnlockPool` `0x1400bf3d0` at `0x140090b67` with arguments `(poolId, 0xffffffff, 0)`. `GLRender::LockPool` `0x1400b4aa0` writes that mode to pool descriptor `+0x11` for a valid pool. `GLRender::UnlockPool` `0x1400bbad0` prepends its manager pointer and forwards `(poolId, size=-1, offset=0)` to helper `0x1400bbaf0`; its size gate is therefore **nonzero**. The helper rejects descriptor modes with `+0x11 & 0x18`, so this read-mode hit-test lock cannot enter `glGenBuffers`, `glBufferData` or `glBufferSubData`. Sentinel pool ID `-1` also exits earlier.
