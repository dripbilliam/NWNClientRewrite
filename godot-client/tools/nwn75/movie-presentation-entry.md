# NWN-75: original movie presentation entry

Scope: installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This maps a static path from the normal `Update` entry to the movie renderer and existing window-swap boundary. It does not show that a movie plays in a gameplay frame.

`Update` `0x1400448b0` calls the client wrapper `0x1406ac690` at `0x1400450c8` (rel32 field `0x1400450c9`). The ordinary swap at `0x1400450a6` is permitted by a zero result from the `client+0x520` movie-pointer gate, while the direct movie wrapper is reached on a later nonzero test. Static code does not prove the pointer stays fixed between those tests. The wrapper's original bytes begin `48 8b 49 08 e9`, loading the internal client pointer from wrapper `+0x8` and tail-jumping at `0x1406ac694` to `0x1406dea40`. The pinned `.pdata` range for the latter is `0x1406dea40..0x1406deabe` (end exclusive). Its first body reads `client+0x520` into RCX, skips the movie call when that pointer is null, and otherwise calls the nonnull guard wrapper `0x140232200` at `0x1406dea55`. It tests the returned value and returns early when nonzero; the zero-result branch enters client follow-up/cleanup calls. These branch facts are backed by original bytes beginning `40 53 48 83 ec 20 48 8b d9 48 8b 89 20 05 00 00 48 85 c9 74 63 e8 a6 37 b5 ff 85 c0 75 5a` at `0x1406dea40`.

The guard wrapper at `0x140232200` loads `RCX=[RCX]`, tests it, and conditionally tail-jumps at `0x140232206` to `CExoMoviePlayerInternal::RenderFrame` `0x140233980`; a null inner pointer returns zero. Its byte sequence is `48 8b 09 48 85 c9 0f 85 74 17 00 00 33 c0 c3`. The movie frame body can decode/upload video, render the video quad, pace a frame and call `RenderInterface::SwapBuffers` at `0x140233a81`, as mapped in [GUI presentation](gui-presentation.md). That thunk reaches `GLRender::SwapBuffers` → `SDL_GL_SwapWindow`; the built-in Windows route reaches imported `GDI32.DLL::SwapBuffers(HDC)` under the [SDL swap gates](sdl-swap-boundary.md). The direct-reference census is reproducible with `scan-rip-references.cjs` against `0x1406ac690`, `0x1406dea40`, `0x140232200`, `0x140233980` and `0x1400bf390`; `.pdata` bounds come from `pe-function-range.cjs`. These are separate tests of the same pointer, not an unconditional double present; static analysis does not exclude mutation between tests.
