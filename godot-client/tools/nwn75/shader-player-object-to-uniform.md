# NWN-75: player object to shader uniform

This is a static continuation of [shader uniform dirty gates](shader-uniform-dirty-gates.md) for the installed `nwmain.exe`, SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are image virtual addresses. The [edge ledger](shader-player-object-to-uniform-ledger.json) records the sites and evidence. It maps the admitted object subtype to the conditional OpenGL uniform leaves; it does not establish that a player object or a particular shader is present in a live frame.

## Object identity and lookup

Original bytes independently show the constructor's type load from `0x140dc2a44` (`05`) and the vtable `+0x58` pointer at `0x140e47540` (`0x1407fd690`). The latter is a four-byte leaf, `mov rax, rcx; ret`: it returns the creature object without another call. ## Frame data and conditional GL leaves

For a nonnull returned creature, the GL frame updater reads six 32-bit values from object `+0x38..+0x4c`, grouped into two triples. It also reads the cutscene integer through `FUN_1406ac3d0` from the app-manager's client `+0x630`. It compares these seven values with globals `0x14128ea5c..0x14128ea70` and `0x14128eab0`. A difference copies the new values and increments generation `0x1413d2724`. If no type-5 object is returned, this specific block leaves the previous player globals/generation unchanged. Evidence frame updater `ev_7b869aaa5250832159935112c0849631946ee4d43dd082bac02054526a88c403`, cutscene read `ev_f991846bf273b02c45595856de820705cba74f189aac2295eba9c78fd5f15e0d`.

An admitted draw's `GLRender::SetProgram` `0x1400b7a40` tail-enters `GLRender::SetUniforms` `0x1400b8380` at `0x1400b7a85` or `0x1400b7aff`, even when the program ID is already bound. The selected program's cached generation `+0x34` is compared with `0x1413d2724`; only a mismatch enters this player group. Valid uniform locations at program `+0xb64`, `+0xb68`, `+0xb6c` (queried as `playerPosition`, `playerOrientation`, `playerInCutscene`) independently gate `glUniform3f` calls at `0x1400ba153` and `0x1400ba17b`, and `glUniform1i` at `0x1400ba191`. The pointer cells `0x141442628` and `0x1414425f8` are loaded through `wglGetProcAddress`; those APIs are the exact external boundary. A program switch can have a stale per-program generation even without a new frame-data change. Evidence SetProgram `ev_c2fa9ed1743a63b47c3b92d6a2cd636bdebff3734eddc2913bdeac583cee5a97`, retained SetUniforms `ev_1a4116233c92836c24653152acff91f84c48e7899cc3e2c69a0d2729deec3431`, [uniform locations](shader-uniform-location-map.json), [GL pointer names](gl-extension-pointers.json), and [exact callsites](shader-uniform-gl-callsites.json).

The synchronous Scene → GL call chain inherits the normal render caller described in [thread ownership](original-thread-ownership.md). This static map does not provide an OS thread ID or imply a separate player-uniform worker. Remaining boundaries are writers of the client's selected object ID and creature transform fields, runtime object subtype and validity, shader selection/location availability, and external GL driver execution. Other type-5 derived vtables are not excluded by the constructor-backed candidate.
