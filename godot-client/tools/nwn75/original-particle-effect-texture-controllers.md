# NWN-75: original particle-adjacent texture-controller image branch

Original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are original PE virtual addresses. These controllers are reached from the **shared Material texture bind** used by the emitter quad route; they are neither exclusive to emitters nor known to run for every emitter. The constructor-backed dispatch and API publication path are in [the emitter render branch](original-particle-effect-render.md). This supplement closes the image algorithms below the six `Control` targets. REA/Ghidra decompilation is static evidence; authored incidence and per-frame frequency are not inferred.

`ImageBuildPerlin` fills CPU octave arrays from the CRT thread-local RNG; `ImageGetPerlinPixel` interpolates and sums octave samples with `floorf` (`ev_db291f880432a2ea3d354f9e80a26179290774ffe5b40e715036c554e2d4d153`, `ev_273b14b16a79d7012168c9d9203522f3485086a049e6cc56cd77cb2b28d242b9`). `ImageLowpassBlur` allocates a temporary CPU image, applies weighted neighbor sampling and copies it back (`ev_06ac2a72152fef3a055e5c119de11617b0734492ec9cad9a8ce0b0a30643e06e`). `FloatInterpolate` does CPU bilinear arithmetic (`ev_1a9881316f7edf4b2a49606c9c39626175dfb1cc8d5de6574755f1bfeaf5e592`). None of these four helpers calls a graphics API; their CRT allocation/copy/free and RNG calls are CPU/runtime leaves.

`TextureController::Distort` `0x1400e2c00` reads Basic width/height/BPP through virtual `+0x70/+0x78/+0x80`, allocates or reuses a CPU scratch image, copies source bytes at wrapped offsets and optionally uses sine/cosine lookup tables (`ev_9db7d34123e02b9613531663feb99da97cc66c010a7dd45f2a4e4193a2f855e2`). `TextureController::Height2Channel` `0x1400e3000` reads those same Basic dimensions/BPP, allocates a CPU raster and remaps heights to channels using controller coefficients (`ev_466af851c99bf8863f0ad4ac32367f4cde29ca5671a4fe17bcb2bf17258a5a01`). Their Basic getter targets are `GetWidth` `0x1400ebba0`, `GetHeight` `0x1400eb880`, and `GetBPP` `0x1400eb6d0` (`ev_a3572cb5daaa440cc0eae923a9a0abd96869817877f94ba72e13102fef873ff8`, `ev_6e0a4d9ee4722e8f9aca4aa004dd592506b17196138e56294e74504378169fd4`, `ev_cf477b49526a0462cdba99f48d92573ec2d24d27f65da4b0832551fe982c6fd2`). These transforms and getters are CPU-only. The controller loop does not directly call GL; the image-writing variants hand the resulting raster to Basic texture publication.

## Publication to graphics API

The five image-writing controls call Basic texture vtable `+0xe8=CAurTexture::glImage` `0x1400ee130` → `CAurTextureBasic::glImageBasic` `0x1400ee1b0` (`ev_b2e85194d6b4aa14cefdd0f1e6976bc998fd394dd10df86b3e26f3215c2b706f`, `ev_6777a01a4f84262d4ab2615740bedc94f4ada8b876baf70f51518525885ebfb1`). The ordinary raster branch calls `RenderInterface::CreateTexture` `0x1400be960` or `DirectCreateTexture` `0x1400be9d0`, then `GLRender::CreateTexture` `0x1400af440` or `DirectCreateTexture` `0x1400b0150`. These reach imported `glTexImage2D` for new storage or `glTexSubImage2D` for a replaceable existing image (`ev_04d1f6fd237a993a5ed94fe19b75bfe50284e97c28882260e2fecceb7366a403`, `ev_01fe5e85fa31c00da7f0879d16971be710cb1075c2efe31b9bfed824af7c4680`, `ev_e1457697c281f0b9e795822e361fb5ff23463a3aee7d7f612d5a10add1480310`, `ev_3ebec5fb5b7ea67d757507906ef7b2b59a9479c1b10a838750fcc406dcadf529`). The Basic function also has a conditional cube-texture branch and a GPU palette-conversion branch that draws a shared quad into an FBO through `RenderInterface::RenderVertexData` `0x1400beec0`; those shared publication routes are mapped in [texture acquisition](texture-acquisition.md), [GUI presentation](gui-presentation.md), and [geometry/draw boundary](geometry-and-draw-boundary.md). This controller audit does not establish that a given authored controller selects those conditional Basic branches.

The direct image helpers above terminate at CPU memory, arithmetic or CRT runtime calls; the actual graphics boundary sits downstream of `glImageBasic`, and the CycleTID control selects a texture ID for the outer bind rather than uploading a new raster. No image-algorithm descendant remains unresolved within these six `Control` bodies. Remaining **shared** work is `GLRender::SetUniforms` `0x1400b8380` and shader compile/link (common shader branch), and conditional `glImageBasic` cube `0x1400be930` → `0x1400aeff0` and palette `0x1400beec0` branches (covered in the shared texture/geometry docs). Driver execution is beyond the binary. Exact live asset/controller population and frequency are runtime questions. No timing or client comparison was performed.
