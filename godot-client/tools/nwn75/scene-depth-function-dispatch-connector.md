# NWN-75: Scene render to depth-function API connector

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. The current reachability audit left `GLRender::SetDepthFunc` `0x1400b6f60` disconnected in `branch-ledger.json`, although its GL leaf was already mapped in [render-state boundaries](render-state-boundaries.md). This note joins it to the ordinary Scene render path. It is separate from the [export-only `SceneBSPUpdateGob` helper](scene-bsp-update-gob-export-root.md), for which no in-image frame caller was found.

The established [frame root](original-render-tree.md) reaches `Camera::RenderScene` and Scene virtual `+0x18=Scene::Render` `0x1400cc730` when a camera has a scene. Within that reached body, after `ManageSceneBSP` and `SetLightModel`, `Scene::Render` calls `RenderInterface::Enable(1)` and then `RenderInterface::SetDepthFunc(3)` at exact instruction `0x1400ccba0` (`e82b25ffff`). This is before the no-BSP/BSP split, so either Scene route passes this call if execution reaches that point. Earlier camera/scene admission and failures remain conditional. Evidence: Scene body `ev_17ec38a8462fe63e54833099ba8a0936b20e0b67c55d26a0bda6bf049d07a6a8`, decoded call `ev_0dadc71cdc67cee74bfb7898e3215f8c40c7c702442ffa996dbf29e326e5086b`.

`RenderInterface::SetDepthFunc` `0x1400bf0d0` is a five-byte thunk, `e98b7effff`, tail-jumping directly to `GLRender::SetDepthFunc` `0x1400b6f60`. The GLRender body indexes its constant comparison-function table at `0x140d8acc0` by the passed enum; entry 3 at `0x140d8accc` is numeric OpenGL value `0x203`. It then **unconditionally** tail-jumps at `0x1400b6f6d` through IAT cell `0x140d7ca98` to imported `glDepthFunc`; no changed-state cache or early return appears in this body. The API call is one GL state command per reached Scene render call on this route. Its driver cost, prior GL state and whether the command is redundant in a particular frame require runtime evidence. Evidence: wrapper `ev_375cbc19d3d0b5ff3428747dbfdae29846b3aad105e782c513bbc07cae458eb5`, tail bytes `ev_de5af8238e2f4daf315d9be74db517715cdb78737cd0ef924598947868734267`, GL body `ev_0918c4684f5603123d27212704d08e185ced9e804fd72d5f5be106bac8dbf74f`, value bytes `ev_6d6cbd711ece70eefe02b69eb05b9f362dd1fec5f122bb0058c8e4a32b47a23a`, imported boundary `ev_2b1fb5e1016a29052ec9651b18c26ebe4571bdebf63daf3b0e0cc545ddda152a`.

REA's incoming-reference set for the GL body names the wrapper's unconditional jump plus PE export DATA metadata; the wrapper's incoming set names the Scene call above plus its own export DATA metadata. The wrapper and GL body are therefore connected by actual code, independent of whether either export is used externally.
