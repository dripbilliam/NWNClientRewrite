# NWN-75: authored Skin Part through live Gob draw admission

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This closes the subtype-specific connector between authored `skin` model nodes and the visible Scene Gob bucket. Exact sites and REA IDs are in `scene-partskin-gob-draw-connector-ledger.json`. The [text Skin/AnimMesh](model-text-skin-animmesh.md), [Gob LOD and Scene publication](gob-lod-scene-publication.md) and [non-emitter animation/Skin draw](original-scene-animation-nonemitter.md) notes contain the already mapped parser, generic Gob and GPU draw descendants.

## Typed Part construction and ownership

Text `ParseNode` `0x1400a0d90` chooses `MdlNodeSkin::MdlNodeSkin` `0x140087790` for the `skin` token; the binary model decoder has the same typed node route. The constructor installs `+0x28=MdlNodeSkinCreateInstance` `0x140093000` at `0x140087827/0x14008782e`. `CreateInstanceTreeR` `0x14008dab0` calls this node function pointer at `0x14008dae0` and recursively stores each returned Part under its parent. The wrapper at `0x140093000` jumps to `MdlNodeSkin::InternalCreateInstance` `0x1400df1a0`, which allocates `0xc0` bytes, calls `PartTriMesh::PartTriMesh` at `0x1400df1d4` and installs `PartSkin::vftable` `0x140d88438` at `0x1400df1d9/0x1400df1e0`. Allocation failure returns null; no successful Part admission follows from that failure. Evidence: `ev_f493d499fe125ff3f25f7a89acfd513bc74dae76d5869dc6601856fb43d71666`, `ev_f7ea47f287ca07427ec0581de89cebf1200911646a4768b59bef961b587c89cc`, `ev_f77022cb6729c8a1db610ea915cf8084c28ce01942fc99830c35197e16cb36c6`.

`NewCAurObject` `0x1400931f0`, when it obtains a Model, constructs a Gob, retains its primary Model at `+0x68` and optional alternates at `+0x70/+0x78`, then calls `CreateInstanceTreeR` at `0x140093645/0x140093677/0x1400936a9`. It stores the respective root Part trees at Gob `+0x90/+0x98/+0xa0`, invokes each root's virtual `+0xd8=PostProcess`, creates references and initializes materials. A Skin Part may be the root or a descendant, and its `+0xd8` slot resolves to `PartSkin::PostProcess` `0x1400df860`; the heavy geometry/pool path is conditional on temporary Skin data and is already mapped. `CreateInstanceTreeR` writes Gob owner `Part+0x50` and parent/child links. `Gob::~Gob` later removes Scene membership, recursively destroys the Part tree and releases Model references; Skin Model-node pool deletion is a separate resource-lifetime branch. ## Scene admission and conditional draw

`Gob::SetScene` `0x140095250`, when a new Scene differs from the old one, stores Scene at Gob `+0x88` and invokes Scene virtual `+0x200` at `0x1400952c7`. The primary Scene table `0x140d8dd30` has `+0x200=Scene::ChildAdd` `0x1400c5990` (pointer bytes at `0x140d8df30`). For a model-backed Gob, `ChildAdd` calls `SceneBSPAddGob` `0x1400dcf70` at `0x1400c59a7`; that fits the Gob sphere and adds its pointer to BSP node payload Gob list `+0x10`. It also appends the Gob to Scene `+0x130` whether or not the Scene BSP exists. This is **Gob admission**, not an individual Skin Part insertion into the static TriMesh BSP list. The external/gameplay caller that chooses a particular Skin-bearing Gob and Scene remains data dependent. Evidence: `ev_28a6db585ee861d0a06c10a6679b3853b3f0825f3eb664abb1d2adca950b1781`, `ev_2bc13f9b3344976c5ba36740b215a8837402968a346caab9e659084a458c7526`, `ev_6b28523eef3201dc9117e17337c6a83ac7dea5eed4ce7f940c48e8c8b8ef8851`, `ev_f8ba87b0474d686e8a25bcdacfd5a63bd9aa38b43d064b93f0d0449100e1faeb`.

On a Scene BSP frame, `ManageSceneBSP` `0x1400db320` visits visible nodes, marks eligible Gobs in view, updates their LOD selection, and then appends a Gob to `_gobbucket` only if its `IsInViewVolume` result is true. `Scene::AddPartsToDrawBuckets` `0x1400c38f0` processes `_gobbucket`, calls `Gob::ProcessGob`, requires geometry flag Gob `+0x1a4` and positive fade/visibility `+0x108`, and passes the currently active root Part `Gob+0x90` to `Scene::AddPartsTreeToDrawBuckets` `0x1400c4620` at `0x1400c44ff`. A LOD switch can replace that active root with either prebuilt alternate; thus a Skin node in one authored model is not proof that the current frame uses that subtype. Evidence: `ev_09d80d9119302b831669f89420d3bae5e7a0578e74b2e20ff5ac6f593308b6a1`, `ev_9b2776e75e9df7689deec134df0f62a5416d96a73218bc317ec5a36294648eb3`, [Gob LOD and Scene publication](gob-lod-scene-publication.md).

The recursive collector rejects a Part with its geometry flag `+0x34` clear. Its Part virtual `+0x58=AsPartTriMesh` call at `0x1400c46a0` resolves to the self-returning `0x14008c4e0` for the constructor-backed Skin table (`0x140d88490` bytes). A Skin Part still needs `IsPartRenderable`, a nonempty primitive and material/bucket gates before `DrawBucketManager::AddPartToBucket` at `0x1400c47a6/0x1400c4801/0x1400c4879`. `Scene::RenderDrawBucket` later calls Part `+0xc8` at `0x1400cd8d1`; the Skin table slot at `0x140d88500` resolves to `PartSkin::Draw` `0x1400deb40`. That body conditionally calls `RenderSkinned` and `ExecuteSkinGPU`, reaching the already mapped primitive/GL submission. This connector proves the possible typed path, not its occurrence or cost in a recorded frame. ## Open boundaries

The live model's Skin node count and location, selected LOD root, visibility, renderability, material bucket, and bone count are runtime data. The no-BSP `Scene::RenderOnlyGobs` path is mapped separately in the generic Gob render tree; this branch is confined to Scene BSP/Gob bucket admission. No per-frame CPU skin deformation is inferred from the conditional `PostProcess` call.
