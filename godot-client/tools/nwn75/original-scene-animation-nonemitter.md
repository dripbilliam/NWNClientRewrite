## Clock and caller thread

## Scene, Gob and Part order

`Scene::Animate` sets global `currentscene`, walks Scene `+0x130/+0x138` Gob array in reverse index order, calls each Gob virtual `+0x28=Gob::Animate` `0x14004dbd0` with the animation delta, then clears `currentscene` (`ev_087a603bd75a32cbab3127f317f4678b5c7dfd904f3de29c83dc37d53a825e8a`, `ev_4baafc31359362e9a499ee231aa5e00ad33685483100da12ea17591bb12f594c`). The original Gob vtable at `0x140d88a00` fixes the dispatch target, as recorded in [scene animation/emitter branch](animation-and-emitter.md).

`Gob::Animate` first compares the current and previous Gob pose; under its wind/source gates it may add point-source wind, then copies current pose into previous-pose fields. It registers a safe-pointer guard, calls optional behavior object `+0x18=Control` at Gob `+0x450`, and admits animation only after Scene `IsAnimating`/Gob force/IsAnimating gates. Its optional `LookAtAnimation` at Gob `+0x1b0` can be controlled or removed; a visible/model/fade gate admits the animation-run loop. For each admitted `AnimRun`, the body advances time by `run_speed × animation_delta`, handles start/loop/done and reverse/wrap/weight branches, calls `AnimateHierarchy`, then `AnimateEvents`.
