# NWN-75: original scene animation and emitter branch

Pinned original `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This is an original-binary partial branch map. Earlier Ghidra evidence is stored in `tools/perf140/render/evidence/native-emitter-controller-and-simulation.json`, keyed by procedure and carrying original addresses/pseudocode; the vtable slots below were checked against original PE pointer bytes.

`CGuiMan::UpdateAndRender` calls scene virtual `+0x20=Scene::Animate` `0x1400c5210` before rendering each view. `Scene::Animate` (REA `ev_740e0fda`) sets `currentscene`, iterates its Gob array at Scene `+0x130/+0x138` in reverse index order and calls each Gob virtual slot `+0x28` with frame delta. `Gob::Gob` `0x1400869d0` references `Gob::vftable` `0x140d88a00`; original PE slot `+0x28=Gob::Animate` `0x14004dbd0`. It clears `currentscene` after the loop. This is a synchronous call chain on its inherited GUI/render caller thread; worker ownership of Gob descendants is not established by this edge.

`Gob::Animate` (REA `ev_82dc675e`) handles animation run timing/selection and calls `AnimateEvents` `0x14004fce0` and `AnimateHierarchy` `0x14004fe90`; it can remove completed `AnimRun` entries and add point-source wind. `AnimateHierarchy` (REA `ev_f539c179`) invokes the MdlNode controller function pointer at node `+0x18`, then recursively walks Part children with a depth cap of 1000. Controller branches include `MdlNode::InternalControl` `0x140051c50` and `MdlNodeEmitter::InternalControl` `0x140052400` in the saved evidence. Exact animation-run/error/controller branch coverage remains open.

The refreshed original REA bodies `Scene::Animate` `ev_9548f696`, `Gob::Animate` `ev_4baafc31`, `Part::Animate` `ev_981bd1d9`, `AnimateEvents` `ev_3c39cee2`, and `AnimateHierarchy` `ev_24de8218` give the following stage order and gates. Scene animation visits Gobs in reverse array order; each Gob caches its previous position/orientation, optionally adds point-source wind if moved, then enters animation only if the scene/force/visibility gates admit it. It advances/removes `AnimRun` entries, generates `start`/`loop`/`done` events via Gob virtual `+0x298=Gob::DoEvent` `0x140050d50`, calls `AnimateEvents` for authored timed events, and calls `AnimateHierarchy` for the selected animation run and its matched Part/node tree. `AnimateEvents` handles wrap and reverse traversal and dispatches each crossed event through the same Gob event slot. After run processing, Gob virtual `+0x2c8=Gob::GetMinimumSphere` `0x14008ee60` is invoked on its five-count cadence. Its active root Part at Gob `+0x90` receives virtual `+0xd0=Part::Animate` `0x14004e9e0`, whose child Part array recursively receives the same animation call. These branches are synchronous on the caller thread; the original binary does not establish separate worker execution for them.

The `Gob::Animate` computed-call census has 17 sites. Six named Gob vtable slots account for the repeated calls: `+0x10=GetName` `0x140048500` at `0x14004dd92/0x14004df13` (Tracy naming gate); `+0x260=IsAnimating` `0x140091ff0` at `0x14004e328`; `+0x298=DoEvent` `0x140050d50` at `0x14004e4aa/0x14004e587/0x14004e629/0x14004e6cd/0x14004e73a`; `+0x2a0=IsForceAnimated` `0x140092000` at `0x14004e314`; `+0x2b8=IsInViewVolume` `0x140049110` at `0x14004e431`; and `+0x2c8=GetMinimumSphere` `0x14008ee60` at `0x14004e8ee`. Scene `+0x280=IsAnimating` `0x1400cafe0` is called at `0x14004e304`. The LookAtAnimation object at Gob `+0x1b0` is established by `Gob::BeginLookAtAnimate` `0x140050000` (REA `ev_cf65f4b6`), which constructs vtable `0x140d81d40`: `+0x8=LookAtAnimation::IsActive` `0x140052570` at `0x14004e349`, `+0x18=LookAtAnimation::Control` `0x140050650` at `0x14004e35a`, and destructor slot `+0x0=FUN_14004d5e0` at `0x14004e41b`. The root Part animation at `0x14004e8b2` uses the Part vtable from `Part::Part` `0x140087d50`, `+0xd0=Part::Animate`. The remaining site `0x14004e2e7` calls `CAurBehavior::Control` or a subtype override through virtual `+0x18` on Gob `+0x450`: `Gob::SetBehavior` `0x140094890` writes that field from a `CAurBehavior*` (REA `ev_1d57ec5c`), and constructor-backed original PE vtables verify the base `0x140054ad0`, attach `0x140054cb0`, camera-follow `0x140055100` and subwindow `0x140202af0` targets. Which subtype is installed for a particular Gob is still open. These targets are from original vtable bytes, not Ghidra's unresolved-call labels.

`AnimateHierarchy` matches each Part child to an animation `MdlNode` child by the integer identifiers at Part `+0x30` and node `+0x34`, recursively, with `depth<1000`. For an unpaused Part (`+0x60==0`) it calls the node's **per-instance function pointer** `+0x18`, then Part virtual `+0x48=AsPartLight` (default `Part::AsPartLight` `0x1400616a0`; light override `0x14008c4a0`) and raises `AnimateStaticLight` on an eligible light through owner Gob `+0x298=DoEvent`. `MdlNodeEmitter::MdlNodeEmitter` `0x1400875a0` writes `MdlNodeEmitterControl` to its `+0x18` function field, leading to `MdlNodeEmitter::InternalControl` `0x140052400`. That control calls Part virtual `+0x68=AsPartEmitter`, then `MdlNode::InternalControl` `0x140051c50` and `PartEmitter::CalculateRadius` `0x140061710`. Base internal control visits its controller list, reads float/vector/quaternion keys through `NewController` helpers, blends values into the Part, and reports keys only when `AnimRun::m_pTraceRun` is set. This establishes the emitter-controller update route; emitter particle simulation is the separate render-stage branch below. The full set of node Control subclasses and CAurBehavior subtype descendants remain open.

`Part::Animate`'s three computed sites are `0x14004eb6d/0x14004ece0` → virtual `+0x8=Part::Name` `0x140062450` under Tracy naming, and `0x14004eebe` → child Part virtual `+0xd0=Part::Animate` `0x14004e9e0`. `AnimateEvents`' two computed sites `0x14004fdf6/0x14004fe4e` → `Gob::DoEvent` for forward/reverse crossings. `AnimateHierarchy`'s sites `0x14004fee1/0x14004feea/0x14004ff0c` are respectively MdlNode instance Control field `+0x18`, Part `AsPartLight` virtual `+0x48`, and owner Gob `DoEvent` virtual `+0x298`. Original MdlNode constructors bound the Control field to eight distinct base/subtype targets (base, TriMesh family, AnimMesh, Camera, Emitter, Light, Reference, Trigger); `model-instance-branch.md` and `animation-indirect-callsites.json` record each. The actual target at a given hierarchy node depends on its authored subtype, and its child descendants remain open. `MdlNodeEmitter::InternalControl`'s sole computed site `0x14005242b` is Part virtual `+0x68=AsPartEmitter` (`Part::AsPartEmitter` `0x14008c490` or `PartEmitter::AsPartEmitter` `0x140061690`). `Part::Part` `0x140087d50` fixes its base vtable at `0x140d87f08`, which supplies the base slots; subtype overrides still need a census.

The Control family separates common transforms/controllers from subtype work. `MdlNodeControl` `0x1400926c0` and `MdlNode::InternalControl` `0x140051c50` loop authored `NewController` records, interpolate float/vector/quaternion values through `GetFloatValue` `0x1400512c0`, `GetVectorValue` `0x140051750`, or `GetQuaternionValue` `0x140051530`, blend them into Part fields, and optionally report crossed keys when `AnimRun::m_pTraceRun` is set. Float/vector Bezier interpolation and quaternion slerp are CPU descendants; these common functions make no GL call (REA `ev_42b4ecbc`, `ev_a387359e`, `ev_dc8fc22b`, `ev_7ce66f2f`, `ev_e9ca4420`). TriMesh/Camera/Light/Reference Control wrappers call their matching Part type test then common InternalControl; Emitter Control also recalculates its radius. The AnimMesh Control wrapper `0x140092430` is a conditional upload path: with positive blend weight and an available vertex primitive/item, it computes an authored frame sample, blends changed vertex positions/UVs into `VertexDataObject::GetItemDynamicData` `0x1400bd7a0`, and only when values changed calls `CommitItemDynamicData` `0x1400bd540` before common InternalControl. That commit reaches `RenderInterface::UnlockPool` and the GL buffer update chain in `geometry-and-draw-boundary.md` (REA `ev_42972df6`). This is animation-driven buffer publication, not an unconditional per-frame GL upload.

Each public Control target is a five-byte jump thunk in the original PE: base `0x1400926c0` and Trigger `0x1400f08e0` → `MdlNode::InternalControl` `0x140051c50`; TriMesh-family `0x1400930e0` → `MdlNodeTriMesh::InternalControl` `0x140052520`; AnimMesh `0x140092430` → `0x140051e60`; Camera `0x1400925c0` → `0x1400523b0`; Emitter `0x140092990` → `0x140052400`; Light `0x140092b00` → `0x140052480`; Reference `0x140092e30` → `0x1400524d0`. REA's `outgoing_references` supplies these exact unconditional-jump edges. The subtype behavior described above belongs to the internal targets; the public thunk names are entrypoints.

Emitter simulation is also reached from a render-stage branch: `Scene::DoEmitterBucket` `0x1400c7ae0` (REA `ev_8206d1e4`) is invoked after the additive bucket from `RenderSinglePass`. It first applies Scene fog and calls Scene virtual `+0x280=Scene::IsAnimating` `0x1400cafe0`, then walks the emitter collection. It calls `PartEmitter::AnimateParticles` `0x140061210` with global `DeltaT` when the Scene is animating or the emitter's owner Gob virtual `+0x2a0=Gob::IsForceAnimated` `0x140092000` is true; these targets are read from constructor-backed original vtables. Emitters with live particles are sorted by camera distance and dispatched through the **per-instance function-pointer field** `PartEmitter+0x1b0`. This is a direct field call, not a virtual-table call. `PartEmitter::Initialize` `0x140061d80` (REA `ev_3905f9c8`) sets that field to `RenderStandard` `0x1400643b0` by default, `RenderMotionBlurred` `0x140064180` for the Motion_Blur mode, `RenderLinked` `0x140064170` for linked particles, or `RenderNothing` `0x140064190` when the source suppresses normal rendering. Instruction flow proves that the first three addresses are 5-byte jump thunks to the shared `PartEmitter::RenderEmitter` `0x140062900`; the distinct behavior is selected inside the shared function. `RenderEmitter` (REA `ev_03c94ab0`) builds a vertex stream, binds material textures/shader, sets blend/depth state and calls `RenderInterface::RenderVertexStreamData` `0x1400beed0`, which reaches OpenGL draw APIs. `RenderNothing` can still execute diagnostic bounding-sphere and helper work under its own conditions (REA `ev_01aaf24b`). `PartEmitter::AnimateParticles` (REA `ev_4b549bf3`) gates large delta, reads emitter flags, updates particle positions and calls PartEmitter virtual methods at `+0x18` and `+0x100`. `PartEmitter::Animate` `0x140061200` (REA `ev_782131ff`) has a separate child-Part animation dispatch. The concrete simulator dispatch is resolved below; subtype update descendants still need full branch closure. This document does not infer that all particles simulate in `Scene::Animate`.

The shared `RenderEmitter` returns before drawing when live particle count is below one or a required shader is unavailable. Otherwise it may draw an emitter sphere for the debug option, binds standard material textures, changes cull/depth/blend state by emitter mode, grows or obtains a shared vertex stream, writes geometry for the live particles, commits `six vertices per emitted quad`, and selects `vsparticle/fsparticle` with a mode-dependent variant before the final stream draw. Its decompiled body contains separate branches for linked mode (`+0x1a8==3`), motion blur (`==6`), directional alignment (`==5`) and world alignment (`==4`). These are observed conditions and do not establish which modes a live area exercises. Its sole targetless computed call at `0x140062aaa` reads the emitter owner's Gob vtable `+0x2d0=Gob::GetAdjustedScale` `0x14008e390`, guarded by nonnull PartEmitter `+0x50`; it scales particle geometry. Original Gob vtable `0x140d88a00` and `Gob::Gob` `0x1400869d0` establish the target (REA `ev_34f8fbdd`). Material/shader helper descendants remain open.

The original factory MdlNodeEmitter::InternalCreateInstance (0x1400621f0) is the source of concrete emitter vtables. Authored "Fountain" selects FountainEmitter vtable 0x140d84518; "Explosion" selects ExplosionEmitter 0x140d84630 and registers a Detonate callback on a supplied Gob. The remaining string-selection branch chooses LightningEmitter 0x140d84860 or SingleEmitter 0x140d84748. It stores the supplied Gob at PartEmitter+0x50 and calls virtual +0xf8=Initialize: Fountain, Explosion and Single use PartEmitter::Initialize 0x140061d80; Lightning uses LightningEmitter::Initialize 0x140061d30. The factory compares the seven bytes at 0x140d8499c (Single followed by NUL): a match selects Single and a mismatch selects Lightning, as proved in original-particle-lightning-source-publication.md. Authored subtype frequency remains unknown. Exact table-byte evidence is ev_7e530ad5042c51a2c709fb0cfbcf58ffe14ecac26a91cd1c8be9f6b03bf22acd. Evidence: REA ev_998902b7; original PE vtable slots 0x140d84610, 0x140d84728, 0x140d84840 and 0x140d84958.

In PartEmitter::AnimateParticles (0x140061210), the two calls at 0x14006132d and 0x14006145e use virtual +0x18=Part::GetWorld 0x14008f870, shared by all four concrete subtype vtables. The three movement callbacks converge on scene services and a CPU collision branch. moveParticleStandard (0x140068010) calls current Scene virtual +0x58=Scene::HitCheck at 0x1400684ba when its authored collision gate is reached. moveParticleP2PGrav (0x140067340) reads the callback-selected target Gob's +0xc0=Gob::GetPosition at 0x1400678db and calls Scene::HitCheck at 0x140067cf0. moveParticleP2PBezier (0x140066940) reads target Gob +0xc0=GetPosition at 0x140066bf2 and +0xc8=Gob::GetOrientation at 0x140066c92, then calls Scene::HitCheck at 0x140067054. All three also have a conditional Scene::GetWindVector direct call and vector/motion helpers. Scene::HitCheck is the same CPU BSP/Gob traversal mapped in lens-flare-hitcheck.md; these movement calls are not direct GL work. Scene vtable 0x140d8dd30 +0x58 and Gob vtable 0x140d88a00 +0xc0/+0xc8 fix the computed targets. Evidence: REA ev_efff8e57, ev_501e4405, ev_aef1d38f, Gob slot bytes ev_15dd5e10/ev_5b0e494b.

The movement callbacks' wind calls are at 0x1400683b4, 0x1400678b8 and 0x140066bd2 for Standard, P2PGrav and P2PBezier respectively. `Scene::GetWindVector` 0x1400c9b90 forwards through Scene+0x160 to `WindManager::GetGlobalWind` 0x1400f1560 at 0x1400c9bb8. The latter samples two 16-by-16 wind grids at WindManager+0x838/+0x840, blends with factor +0x850, applies strength factors +0x848/+0x84c, and combines `pointSourceWindVector` 0x1400f2070 at 0x1400f1638. That helper iterates the stored point-source count at WindManager+0x18, rejects points outside each source radius, normalizes qualifying direction vectors and accumulates weighted strength. The displayed code contains vector/quaternion and CRT math descendants but no GL call. These are read-only wind samples on the particle caller thread; the grid producer is traced below. Evidence: REA ev_b31f444c, ev_22e87930, ev_a1bd0505, ev_0512ae4a.

The grid producer is reachable in the same original scene render route: `Scene::Render` calls `WindManager::updateTimer` 0x1400f2250 at 0x1400ccda9. The update accumulates delta at WindManager+0x854, swaps the two grid pointers when it passes interval +0x858, calls `fillNoiseField` 0x1400f1e00 on the recycled 16-by-16 grid at 0x1400f23a8, and stores the interpolation fraction at +0x850. It also advances and removes expired point sources in the +0x10 array. `fillNoiseField` clears 256 floats, adds random multiscale patches over five halving levels, and draws from the same FLS-backed CRT RNG at 0x1400f1ec0. Thus the grid update and later particle samples share WindManager state, with execution order inherited from Scene::Render and the subsequent emitter pass. No separate worker or GPU work is established by these bodies. Evidence: REA ev_616bd02d, ev_23927c2c, ev_b230a9a9, ev_8cab9ae5, ev_e23506e5.

`Particle::initialize` 0x140066450 resets particle fields, copies authored emitter pose, chooses random position/velocity, optionally inherits emitter velocity, and conditionally randomizes direction. Its direct calls are `randomPosition` 0x140068d80, `inheritVelocity` 0x140066140 and `randomDirection` 0x140068800. The random helpers use 0x140c7ed00, whose original body updates a CRT per-thread state word (`state*0x343fd+0x269ec3`, returns high 15 bits); its state accessor 0x140ca98a0 uses Windows FLS via `__acrt_FlsGetValue`/`__acrt_FlsSetValue` and preserves the caller's last error. This establishes caller-thread RNG state, not independent worker ownership. `randomDirection` reads `CurrentCamera`, constructs quaternion rotations and can repeat an authored angle constraint loop.
