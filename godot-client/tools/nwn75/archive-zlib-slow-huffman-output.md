# NWN-75: compressed archive zlib slow Huffman output

This is a bounded continuation of the conditional [source-2 zlib resource path](archive-zlib-fast-decode-ownership.md) and [source-1 compressed block path](archive-zlib-stored-block.md). It concerns CPU decoded bytes before resource service and later model/texture consumers. It does not establish that an active asset uses zlib, this DEFLATE block type, or this slower arm.

After an XRES algorithm-1 provider and zlib wrapper are selected, `z_uncompress` calls `z_inflate` `0x14059e390` at `0x1405a4033`. The inflater constructs or selects its literal/length and distance Huffman tables and reaches state `0x3f48`. At `0x14059f36c` it requires at least 6 available input bytes **and** at least `0x102` free output bytes to call `z_inflate_fast` at `0x14059f39f`; either shortfall branches to the slower in-function symbol loop at `0x14059f3e5`. The fast arm and dynamic-table construction are mapped in the linked note. REA inflater `ev_578e682548bfaa6225ce37bd8b46b6345a304c947ae083ccef21eaa73c7b62d1` and original assembly at those addresses.

The slow loop reads the current literal/length table, replenishing its bit buffer only when input remains. A literal symbol enters state `0x3f4d` and, with output space, writes one decoded byte at `0x14059f869`, then returns to state `0x3f48` at `0x14059f87a`. An end-of-block symbol leaves this symbol loop for the block-end state; an invalid literal/length code enters error state `0x3f51`. A length symbol enters `0x3f49` for extra length bits, then `0x3f4a` for the distance table. The distance extra-bit state is `0x3f4b`. Invalid distance code likewise enters `0x3f51`. These are branches within `z_inflate`, not additional decompression calls. REA body `ev_578e682548bfaa6225ce37bd8b46b6345a304c947ae083ccef21eaa73c7b62d1`.

State `0x3f4c` copies a length/distance match one byte at a time from already decoded output or the retained sliding window. The output copy loop's read/write pair is `0x14059f830/0x14059f835`. It clamps the copy by available output space, preserves remaining match length for a later call, and returns to `0x3f48` when the match is exhausted (`0x14059f84e`). A too-far-back distance under its validity flag enters error state `0x3f51` at `0x14059f7c9`. Input exhaustion and output exhaustion return to `z_uncompress` with resumable inflater state; they are not successful stream-end by themselves. `z_uncompress` accepts only the eventual stream-end result, marks the actual decoded length in its DataBlock and the packed-file helper copies only a fitting block into the service-owned `CRes+0x20` buffer. Those ownership and exact-size gates are already mapped in the [source-2 continuation](archive-zlib-fast-decode-ownership.md). No GL/API call occurs in this slow Huffman output arm. Runtime source kind, archive entry, DEFLATE block, table symbols, buffer sizes, stream checksum and later render admission remain conditional.
