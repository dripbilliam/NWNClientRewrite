# File-backed KTX and S3TC header probes

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Exact source/call edges are in [the ledger](texture-file-compressed-header-probes-ledger.json). This is the header-only branch preceding the [file-backed 16-bit fallback](texture-file-4pc-image-header.md); installed resource-backed compressed texture reads and uploads are separately mapped in [compressed resource publication](texture-compressed-resource-publication.md).

`CAurTextureBasic::LoadImageHeader` `0x1400ec900` calls `AurGetImageHeaderWrapper` `0x1400e5b90` for its single-image case (`+0xce==0`). The wrapper enables compressed probes only when its input flag is nonzero. `LoadImageHeader` supplies that flag only when Basic `+0xe3==0` and the two image-count fields `+0xcc × +0xca` equal one. The wrapper tries filename `ImageReadKTXHeader` `0x1400735d0` at `0x1400e5bdc`; a nonzero return ends header selection. Otherwise it tries filename `ImageReadS3TCHeader` `0x140073bd0` at `0x1400e5bfb`. Only if both return zero does it try the 16-bit file header and then `AurGetRasterHeader`. Multi-image `LoadImageHeader` uses its own indexed 16-bit/raster loop and does not enter these compressed probes. Evidence Basic `ev_188251d8dde193c12b22b6f925a8d47e1a5bbc35c221e146c0085999790e07de`, wrapper `ev_be8e946273e61b5eda1abd194c5f63e0c2a962269594716877c587ce87ed095a`.

`ImageReadKTXHeader(char*)` rejects a null or empty name. It tries the name as supplied through CRT `fsopen` at `0x140073652`; on failure it tries `<name>.ktx` at `0x14007367f`. After a successful open it reads a 64-byte header at `0x1400736b8`. On an exact one-record read, it copies width and height, maps compressed format constants `0x9270/71/74/75/76/77` to numeric mode 3 and `0x9272/73/78/79` to mode 4, then calls `ImageGetKTXSize` `0x140071d50` at `0x140073709` to produce the aggregate compressed size. The size helper is a CPU leaf: it iterates mip dimensions, rounding each dimension to four-pixel blocks and multiplying by 8 bytes for mode 3 or 16 for mode 4. The header function closes the stream at `0x140073715` and returns one for an opened file even if its 64-byte read was short; initial output fields are zeroed, so the return value alone does not prove a valid KTX header. Neither the file function nor size helper validates the file signature in its shown body. Evidence header `ev_413fde2bf5d164b8b5cfa821de2d44c245cc8a7facc38e6519380084f3565faf`, size `ev_5caead88bc827b86cc6b7b8407e5aa3cbfda6317fef1a6f2272c84440f5f1e62`.

`ImageReadS3TCHeader(char*)` likewise rejects a null/empty name and tries the supplied name, then `<name>.dds` through `fsopen` at `0x140073c54/0x140073c81`. On an opened stream it initializes output fields, reads five 4-byte values at `0x140073cb6/cca/cde/cf2/d06` (dimensions, format, compressed size and scale-like float), closes at `0x140073d0e`, and returns one. The analyzed body checks neither read count nor a DDS signature. The FILE-pointer overloads of both header parsers are separate CPU metadata readers (`0x1400734d0` and `0x140073af0`); neither is called by this filename wrapper. Evidence S3TC `ev_c78a0474431543d9d96afafb2a76e92128f3bcf8c9f8f2ad8ad921a5dc59ab4d`, FILE KTX `ev_e08b208dab59cca4f8378598e5b10136540bf79e722106b4f4059c4388e5a6da`, FILE S3TC `ev_4c7d68f1517d209acda9eb2318885a2e93b8615e3e73ddd50a298f111e130b18`.

Both filename readers inherit the texture caller's thread, use synchronous CRT file operations, and have no GL calls. Shared CRT continuations reach conditional imported `KERNEL32.DLL::CreateFileW`, buffered or imported `ReadFile`, and conditional `CloseHandle`; exact lower sites and gates are in [archive open/close](archive-open-close-header-loading.md) and [file resource read](model-resource-storage.md). Their output is scalar image metadata; any later full image decode, GL upload or Scene draw is a separate gated path. The full filename KTX/S3TC pixel readers `0x1400732b0/0x1400739f0` have no direct code callers in the analyzed image; their data references do not establish a live render callback. Active file choice, callback state, header validity, compressed flag and runtime frequency remain unresolved.
