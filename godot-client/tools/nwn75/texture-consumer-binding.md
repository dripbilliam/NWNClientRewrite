# NWN-75: original texture consumer and bind-state path

Pinned original `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This follows draw-visible texture consumers, including material, grass, flare and GUI texture binds. Creation/decode and resource-provider I/O are separate conditional branches in [texture publication](texture-publication-per-frame.md) and the [shared GUI resource provider](gui-resource-demand-decoders.md); the latter owns archive/encapsulated reads and decompression target families. Physical sites and candidate target status are in `branch-ledger.json`.

## Wrapper and Basic getter dispatch

Six common `CAurTexture` getters—`GetWidth` `0x1400ebba0`, `GetHeight` `0x1400eb880`, `GetBPP` `0x1400eb6d0`, `GetImage` `0x1400eb8b0`, `IsCubeMap` `0x1400ec0d0`, and `GetNumX` `0x1400ebaa0`—first call wrapper vtable `+0x10=CAurTexture::GetReferencedTexture` `0x1400ebb00`, then call the returned object's `+0x8=AsCAurTextureBasic`. The base type test `0x1400e5a00` returns null; the Basic override `0x1400e5a10` returns self. The known wrapper and Basic vtable bytes at `0x140d90c78/0x140d90c80` and `0x140d90d98/0x140d90da0` establish these slots (REA `ev_c56fb57241b6d00368bdc2af3db99e400c394a9a5b6893711aaea23d8364cd4d`, `ev_9c7cc87fe323b27a4497bd049ca70d66664e2ec7b5da5c2b58626f3ac7058c07`, `ev_c6ea44ea033f3e75d14cbf36ffab323622c201dd32b6b03560de77c21a1059da`, `ev_cdae0604b18e41a5bd67bedb08aa446f0de73fc87fc5b36e84fd5918a78f1a66`). All 12 computed sites and their base/Basic candidates are ledgered.

When Basic admission succeeds, those getter bodies read Basic fields `+0x74` width, `+0x78` height, `+0x7c` BPP, `+0x58` image pointer, `+0xe3` cube flag or `+0xca` X tile count. A null type test returns zero/null/false. They make no direct GL call, but are not terminal leaves because of the two virtual dispatches. Original getter REA, in the same order: `ev_a3572cb5daaa440cc0eae923a9a0abd96869817877f94ba72e13102fef873ff8`, `ev_6e0a4d9ee4722e8f9aca4aa004dd592506b17196138e56294e74504378169fd4`, `ev_cf477b49526a0462cdba99f48d92573ec2d24d27f65da4b0832551fe982c6fd2`, `ev_0597b28970e176bc0fb1edb41d9d404fe9298de0d4f5efa69feb41b4be8893c6`, `ev_03d8458543f654ee1a652c011d0e36c107ff9ffb55e3c455232e1bea6ea48b85`, `ev_a2aafb73191902a17c57c8693d45d741499f5768ec5b7d4c18907d047bbc4de2`. `GetReferencedTexture` itself returns its `+0x18` reference or self and has no callee (`ev_9ec5040ebf3f040eede9251134d4e6c8de16fc3c831e96a7afb5d003e25bc031`); base/Basic type-test leaves are `ev_b81f61ae7254216c3fa7bfa27e47f2e9ffcdb7ac30129e5c28077a094afab486` and `ev_3146ebe2d108ab46f89547cdd3072862f2acf78eedc46a234743de2ba61e8d64`.

`CAurTexture::IncrementTIDIndex` `0x1400ebd90` uses the same two virtual slots, then copies one TID from Basic `+0x50` indexed array into current TID `+0x6c`. Its computed sites `0x1400ebd9c/0x1400ebda5` are ledgered, and the body has no direct GL call (REA `ev_eddc90ee9924d0f893d9d54ca574c96cfc282d412f65cf54b94008defafb1600`).

The same getter pattern also covers `CAurTexture::GetNumY` `0x1400ebad0` and `GetMipMap` `0x1400eba00`: wrapper `+0x10` calls at `0x1400ebad7/0x1400eba07`, then base-null or Basic-self `+0x8` calls at `0x1400ebae0/0x1400eba10`. An admitted Basic returns signed short `+0xcc` Y tile count or byte `+0xe4` mipmap flag; null returns zero/false. Neither body calls GL. REA `ev_03b1d6df37e253e7431fe8bc53bb376ec66176eaffc799baf45c2e3b6c20a414`, `ev_3de5a27bbd3daf43d30f83651901c01d1310b8f164a982ea5bbc574fe2b68812`.

The environment-mapped Part draw adds `CAurTexture::GetCompressionFormat` `0x1400eb7c0`: wrapper `+0x10=GetReferencedTexture` at `0x1400eb7c7`, then the referenced texture's `+0x8=AsCAurTextureBasic` at `0x1400eb7d0` (base-null or Basic-self). An admitted Basic returns its format field `+0x80`; null returns format enum 7. This body makes no direct GL call (`ev_269e0ce30093f9d75cd7255435516b8b5f5d5846a7133d91b2149f3d80f74212`). Its later `CAurTexture::IsNull` `0x1400ec1b0` calls wrapper `+0x10=GetReferencedTexture` at `0x1400ec1b9`, then `AurTextureGetNULL` at `0x1400ec1bf` and compares pointers. The latter may lazily acquire `NullTex`, so this is a conditional resource boundary even though `IsNull` itself issues no GL command (`ev_a8eb518ef2111e7ef1427cda055ef475f0d2b9c3a488c39819de87a12b857aa9`).

## Bind in unit to GL

`CAurTexture::BindInUnit` `0x1400ea490` resolves a referenced Basic texture. If it is null, the cached `NullTex`, or flagged `+0xe7`, it follows a zero-bind/state path. Otherwise a nonnegative requested index and Basic `+0x50` array invoke the virtual TID-index update; it obtains current TID, tests cube-map status, and calls `AurTextureBindTIDInUnit` at `0x1400ea508`. Only when an auxiliary controller exists at Basic `+0x38` and `enabletexturecontrollers` is true does it dispatch that controller's `+0x8=Control` at `0x1400ea543`, whose known candidate family is recorded in [texture controller runtime](texture-controller-runtime.md). Its six direct and seven computed physical sites are ledgered (REA `ev_e0255c509221b93994478aaab1e314d204ac1315f09e928262409ec4c80db5b5`).

`AurTextureGetNULL` `0x1400e8a20` acquires `NullTex` through `AurTextureGet` only when the cached null texture is absent; manager-list growth may `_realloc_base`. Both direct sites are ledgered. This lazy acquisition is not an unconditional per-frame decode (REA `ev_a9ea9ef95426bb9ca551f2a78d7e5ddf3e8db321afd28bace3e3b49f0ae1ffc6`). `AurTextureBindTIDInUnit` `0x1400e6870` honors `bindzero`, sets cube state with `Enable`/`Disable(0xe)`, and calls `RenderInterface::SetActiveTextureAndBind` only when its TID/`alwaysbind` gate allows. Its four direct sites are ledgered (REA `ev_dc31d7f815228f76e063f8622fcca6f7877340b8bf57d0ead60717cce75d75c0`).

The RenderInterface bind wrapper `0x1400befc0` tail-jumps to `GLRender::SetActiveTextureAndBind` `0x1400b66e0`. The GL body clears the enabled-stage bit for zero TID. For a nonzero TID it compares cached stage/target/ID. A changed unit calls extension `glActiveTexture` through cell `0x141442150` at `0x1400b6751`; an admitted changed 2D target calls imported `glBindTexture` at `0x1400b6794`, or a cube target at `0x1400b67ad`. Unchanged cached state avoids those API calls. The old unsited wrapper-to-API summary rows were replaced by the thunk/body/API chain. REA wrapper `ev_da564a2df1f68a5db0a8792121e9470fc1a0a40bef2e0f69001e76c4bd6667d2`, GL body `ev_b2cc57320fd688a85c532ba7e3db16139ba5a50e615344e5fa41f15cc00e8856`.

The known two texture classes share these getter slots, but unidentified derived texture types and the Basic `+0x38` auxiliary object's complete dynamic type set remain open. Texture construction/upload can be reached on a cache miss; this bind consumer path does not show a full image upload in every ordinary draw.

## Basic CPU-image release after publication

The Basic `+0xf0=FreeImage` dispatch reaches `CAurTextureBasic::FreeImage` `0x1400eb640` after the image has been published. With a nonnull image pointer at `+0x58`, its ownership flag `+0xe9` chooses either an installed callback or direct allocator free. For callback-owned mode `+0x84==4`, the indirect call at `0x1400eb671` uses cell `AurReleaseLayeredRaster` `0x14140b270`; other callback-owned raster modes call cell `AurReleaseRaster` `0x14140b258` at `0x1400eb699`. Both clear the ownership flag and image pointer. If the flag is clear, the direct `FUN_140c10370` free at `0x1400eb6b4` clears the pointer. The body has no `glDeleteTextures` call (full REA `ev_8a98c60a73cc4e9b4bd311bc938ebf5d908e89c6b96b99b7f6b3a3fd51b1eed8`).

The `CAuroraInterface` constructor `0x1400f4cf0` installs `ReleaseRaster` `0x1400f74d0` into the raster cell at `0x1400f4d33`, and `ReleaseLayeredRaster` `0x1400f71a0` into the layered cell at `0x1400f4d4f` (constructor REA `ev_00b1de98f1d324c012c96164374fe692e21c717759e9a0efb02ba985bad50008`; data-cell read/write REA `ev_cdc7f041e2527144a8dfd36b027726c11a358ea3a3172e5ceca4c22e9ed0d4dd`, `ev_ba2bc0ac497005d1a2a40b6c0dfcc7464c01e64433a00317faac83c37b376b5c`). `ReleaseRaster` validates source format: a 16-bit header calls `CAurora16BitTexture::Unload16BitTexture` at `0x1400f75c1`; a verified uncompressed raster header calls `CAuroraTexture::UnloadTexture` at `0x1400f75f9`; compressed modes invoke their object's virtual `+0x20` and destructor, while invalid headers log an error. The two explicit Unload bodies clear a loaded flag and tail to `CRes::Release` at `0x1400f2c21` and `0x1400f86c1`. `ReleaseLayeredRaster` searches/removes a cached layered texture by lowercased name, then calls `CAuroraLayeredTexture::UnloadTexture` at `0x1400f7482`; its flag-guarded `CRes::Release` tail is `0x1400f4641`. Release bodies are `ev_4a1970f3d3329ac2860168635c180dc330e507137b6a3c586559f65839f82452`, `ev_ab2f68152b609f7106c3f47b93eea7104f0d42f0e59e84e072ac4f2c3a8e61a6`, and unload bodies `ev_1eeacaaa2fabea3e01b343fe36fb017bcee6f9e01cdfaff367a2aa8eee05cd94`, `ev_e7bb9bf588cf37701332ba977c0a79efbe13131370c8f59005c3c1f3853e32d8`, `ev_b22b237a696e9690d13bfcb8e8a514a4963b169ce516cdefb11054248439d2b8`. Shared resource release is documented in [texture resource demand](texture-resource-demand.md); compressed object virtual targets and destructors are still open. This release chain handles CPU image/resource ownership and should not be counted as a GPU texture deletion without further evidence.

## Texture-object teardown and GPU ID deletion

`Material::HasBumpyShinyMap` `0x1400834c0` checks its optional texture `+0x18=CAurTexture::IsCubeMap` at `0x1400834d5`. Both known wrapper and Basic vtables resolve that slot to `0x1400ec0d0` (`ev_b61b1a251bd6174d2e32d2b2eb9759a27c20659a8dbdb8d7e9c6139be2d16be5`, `ev_02ace711599dd63ad32f447f3768134a9d055b0d5901203b763ea9294d9820e8`). A true result returns immediately. Otherwise it calls `AurTextureRelease` at `0x1400834e8`, removes the material's list reference, clears its index and pointer, and returns false (body `ev_e2f39d90bd149aa79dbd85642025dfd4cb852d0c8a719880ce1bb65c44d5f9a3`). The source name does not itself prove the texture's authored role; the exact test is `IsCubeMap`.

`AurTextureRelease` `0x1400e9130` acts only on a nonnull texture with zero at `+0x10`. Its virtual `+0x8` checks may return base-null or Basic-self, and its virtual `+0x0` deleting destructor can select the wrapper `0x1400e5500` or Basic `0x1400e5540` target from the two constructor-backed vtables (body `ev_81aa31c1cafb1d49fb6045694e26323301d59edc2a084b26ff9e41a10b51b3c6`; vtable slots `ev_de9bcde0c5501cbfac095a901f88f2432c3835ff8984fc8bf254b8d674e85204`, `ev_b3841f993f9eca47bc1308457368a9ba260c1b133f89566601d3ec7bbeba843a`). The Basic deleting destructor clears auxiliary objects, CPU image ownership and texture lists. If its TID array `+0x50` exists, it calls `RenderInterface::DeleteTextures` at `0x1400e55b5` with count `GetNumX*GetNumY`, then frees the array; it also releases any remaining owned CPU image through the installed raster callbacks. Basic body `ev_dcdf3fbb124d9ace2346b7aedfc7dfca6faa289858773a0735cccc7549fa20a8`. The wrapper deleting destructor calls the base texture destructor and optional deallocation (`ev_987f349bc4ab0d589c5ffc0a5c4fb61108045228c6301526e7cd9f25a8937b37`). The wrapper/base destructor's last-reference cascade and Basic auxiliary virtual destructor are not fully classified.

`RenderInterface::DeleteTextures` `0x1400be9b0` jumps to `GLRender::DeleteTextures` `0x1400afe20`. That body clears matching IDs in the 16 cached bound-texture slots, then tail-jumps to imported `glDeleteTextures` at `0x1400b0018`, even when the supplied count is zero (wrapper `ev_87e980312542d4150b9c7d7565a295617c0f54d0749d6c5fbf9c673651addd33`, GL body `ev_26f28cbb42e08d248cec1334b20812386fd1f5f40a615d4c901c6fd1d2db92d1`). This is a conditional GPU deletion descendant of texture-object teardown. It is distinct from `FreeImage`'s CPU image release above; the two can occur at different lifecycle points.
