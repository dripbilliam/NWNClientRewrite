# NWN-75: authored model animation scale to Part position

Pinned original `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This connects the already registered text-MDL `setanimationscale` command in [model command holders](model-text-other-command-holders.md) to a live [Gob animation](original-scene-animation-nonemitter.md) consumer. It is static behavior, not a measured animation population or cost.

`Model::Model` `0x140087bc0` initializes `Model+0xcc` to float `1.0` at `0x140087cab` (REA `ev_487d22f518fd1fdc568161117ccde18e7565eb1ad86d8c70ad352245f1492ea2`). The registered `setanimationscale` handler `0x1400a1970` starts its parse value at `1.0`, calls `sscanf("%f")`, and writes the result to `currentmodel+0xcc` at `0x1400a19a0` (REA `ev_dfdb51cec1d4a054e14093e111633de0b6ecf1b2937f2ad1c438e5a687b6db0a`). Its effect requires a parsed authored command on the current Model.

`Gob::PlayAnimation` `0x140052580` selects an animation from Gob's optional Model `+0x80` or fallback Model `+0x68`, calls `FindAnimScale` `0x140050ed0` at `0x140052895`, and stores the returned float in `AnimRun+0x20`. `FindAnimScale` starts at `1.0`; at each Model it searches the `+0x98/+0xa0` animation list by exact Animation pointer. If found there, it returns the factor accumulated so far. Otherwise it multiplies by that Model's `+0xcc` and follows its `+0xa8` supermodel pointer. A null Model returns the accumulated factor. For lists larger than 16 it also swaps the sought pointer into the last slot during lookup; this is CPU list mutation, not a resource load. Thus a Model's own animation gets factor `1.0` on this route; an animation inherited from a supermodel receives the product of traversed child-model scale values. REA `Gob::PlayAnimation` `ev_225949b5bdbee8bf34c101b1ae97e2fffca1c9a239e3ed372e17764bfa5384b7`, helper `ev_5cd16a5a634e29811a24bfef6ec50c1c036d597f647e3e50f959575bd65788d6`, exact call `ev_dc91e43a8e601ca76bbc9947a04af8144897c821681e1d09d7ec5f7710b1974d`.

On an admitted run in `Gob::Animate` `0x14004dbd0`, instruction `0x14004e804` copies `AnimRun+0x20` into process global `position_scale_factor` `0x14128e218`, before the direct `AnimateHierarchy` call at `0x14004e858` (REA `ev_1d0ad03770965d01dc064786265ef9bf22b58f61a325f0704ece9253b8d609a5`, direct call `ev_27a280c18496bd87c75e1f9646984b463c888fe79887d3bfc5112b0f4a5f89ce`). `AnimateHierarchy` invokes the MdlNode's installed Control callback; the mapped common `MdlNode::InternalControl` `0x140051c50` calls `NewController::GetVectorValue` `0x140051750` at `0x140051d2c`. That getter reads `position_scale_factor` at `0x14005182f` **only** when the vector controller's integer ID is `0x10`, otherwise uses `1.0`. It multiplies all three returned vector components after single-key, linear or Bezier sampling. `InternalControl` blends the returned vector into the Part at offset given by that same controller ID, so this ID writes `Part+0x10..+0x18` under its control/weight gate. REA vector getter `ev_7ce66f2fd45370e2068594a7a5e01d6ea30f86dc85644fdc2901bb8b75a72bbc`, common control `ev_a387359e5ed2f6c6155e330a6558f9101d3a60651342a29418dab4db236ee372`, exact vector call `ev_4bef991e1fadfe8f657645cd1e89db72af16028e5e095a5a86fa61856c48f4dc`, global read `ev_310bb1c87a5d4caf8d1c28129c4e67ad98c87e5e8301b01d7207e0b0b1df057e`.

`Gob::Reset` `0x140053110` separately recalculates each existing run's `+0x20` with `FindAnimScale` at `0x140053167`, then sets global `position_scale_factor` to `1.0` before its zero-time `AnimateHierarchy` call (REA `ev_dc4c76e6bc2713314ebe3901cbb9aba93e65902be8ce980e1a9a3729d2a34aa3`, exact call `ev_d71f5d7c5ac359f4cf650ca8ae94773894765c2b868027a2642ce2059cb2944f`). This reset application is distinct from an admitted active run. The authored token, selected Model/Animation, supermodel chain, controller ID, live run and blend weight remain conditional. The mapped scale route affects a vector position controller, **not the run's time-advance multiplier**; the latter has separate run speed/weight fields in `Gob::Animate`.
