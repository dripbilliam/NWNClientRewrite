# NWN-75 native resource cache reuse and reclamation

Pinned `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This closes a resource-lifetime branch shared by model, texture and GUI resource demand. It is a conditional CPU ownership path, not a GL draw or an unconditional per-frame sweep.

`CAuroraLayeredTexture::LoadTexture` `0x1400f4440` is one concrete caller: it demands its PLT `CRes` at `0x1400f444d`, consumes its fields, then releases it at `0x1400f44cd`. The general `CRes::Demand` `0x14018f300` tail-jumps to `CExoResMan::Demand` `0x14018ef90` at `0x14018f36a` after its null/global-manager checks. The manager services source classes 1/2/3/5 only if the resource is not already marked resident (`flags+0x1c` bit 4 and nonnull data at `+0x20`). On a resident cache hit with demand count zero and pending-free flag `0x100`, it removes that resource's linked-list node, increments its cache-hit counter and clears the pending flag; then it returns the existing `+0x20` data and increments demand count. The inlined list search is a fallback when `CRes+0x40` does not hold its node. The source services and later image/model publication are linked from [texture resource demand](texture-resource-demand.md) and [model resource storage](model-resource-storage.md). On final `CRes::Release` `0x1401912c0`, a resource already flagged for release can call `CExoResMan::Free` `0x14018f630`; otherwise the normal branch appends it to manager list `+0x28`, sets pending bit `0x100`, and stores the node at `CRes+0x40`. `CExoResMan::Release` `0x140191220` has the same final-count/list policy. `Free` removes the node, invokes the resource virtual `+0x18` freed hook, and conditionally calls `FreeResourceData` `0x14018f8d0`. That helper frees the CPU data buffer at `CRes+0x20`, returns byte count `+0x30` to available-memory accounting, and clears the pointer/size. As a concrete constructor-backed resource subtype, `CResPLT` installs vtable `0x140d92b30`, whose `+0x18` is `CResPLT::OnResourceFreed` `0x1400fab20`. The hook frees an auxiliary pointer only under its own flags, then clears PLT header/data fields. Other resource subtypes retain their own dynamic hook targets. `CExoResMan::FreeChunk` `0x14018f740` drains eligible list entries while its reclaimed-byte tally remains below `0x100000`; the last entry can take it past that threshold. It skips flagged entries, calls the resource freed hook for demand-zero entries, releases their buffer and optionally the resource object, removes visited nodes, and updates available-memory accounting.
