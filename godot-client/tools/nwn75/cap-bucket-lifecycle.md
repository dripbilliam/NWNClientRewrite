## The 32-bit table entry is a PE export

The original PE export directory begins at RVA `0x010d16a0` (VA `0x1410d16a0`), reports ordinal base `1` and `18,245` functions, and points `AddressOfFunctions` to RVA `0x010d16c8` (VA `0x1410d16c8`). Entry `5104` at `0x1410d6688` contains RVA `0x000d75c0`, naming export ordinal `5105`, `?AddPartToCapBuckets@@YAXPEAVPartTriMesh@@@Z`. This is an export address table entry, not a function-pointer dispatch by Scene. `inspect-pe-exports.cjs` reproduces the identity from the pinned bytes; the export-directory and entry bytes are `00 00 00 00 ff ff ff ff ... c8 16 0d 01` and `c0 75 0d 00` respectively. The wrapper `0x1400d75c0` moves its Part argument, loads global cap-list object `0x14140afe0`, and tail-jumps at `0x1400d75ca` to `CExoArrayList<PartTriMesh*>::Add` `0x14006bc30`. Neither Ghidra's incoming-reference census nor a pinned executable rel32 scan establishes an **internal** call to this wrapper. An external module could call an export; that runtime possibility remains open.

## Scene producers append directly

For a Scene with BSP, `Scene::ManageSceneBSP` `0x1400db320` reaches `HandleFadingInBucket` `0x1400d9670` at `0x1400dbb7e` and `HandleFadingOutBucket` `0x1400d9ab0` at `0x1400dbb83`. Each first needs a nonempty fading-node bucket. Under the node fade comparison `node+0x70 <= 1.0` and `!= 1.0`, each handler has two append loops: it copies Part pointers from node array `+0x90`/count `+0x98`; then it scans node array `+0xa0`/count `+0xa8`, admitting entries only when their referenced owner fade at `+0x70` is at least `1.0`. These are inline writes to the cap-list pointer at `0x14140afe0` with count at `0x14140afe8` and capacity at `0x14140afec`; capacity exhaustion takes a conditional reallocation path. The cap helper export is bypassed by these internal producers. Pinned store instructions `48 89 34 c2` occur at fading-in `0x1400d97a2` and `0x1400d99ea`, and fading-out `0x1400d9be2` and `0x1400d9e2a`; each is followed by a count increment/store at `0x1400d97ae/0x1400d99f6/0x1400d9bee/0x1400d9e36`. These establish four physical append sites, two per handler, independent of any call to `AddPartToCapBuckets`. Whether the source node lists are populated and the fade gates pass is dynamic.
