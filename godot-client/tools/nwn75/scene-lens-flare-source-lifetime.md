# NWN-75: lens-flare source, visibility and layer lifetime

Scope: installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This extends the [41-site immediate flare census](scene-optional-pass-callsite-census.md) and the existing [HitCheck occlusion tree](lens-flare-occlusion.md). It records source arrays, per-light gates, stream publication and texture cleanup without repeating shared renderer internals. Static code does not establish any live flare count or frame cost.

## Authored data and lifetime

The text `MdlNodeLight::InternalParseField` `0x14009db90` fills flare radius at node `+0xa0`, texture-name list `+0xe8/+0xf0`, size list `+0xb8/+0xc0`, position list `+0xc8/+0xd0`, color-shift list `+0xd8/+0xe0`, and other light flags. The binary Light-node builder `FUN_14007a790` fills the corresponding arrays from offsets in authored binary data. Text `MdlNodeLight::InternalPostProcess` `0x1400a9940` sizes node `+0xa8/+0xb0` to the number of texture names at `+0xf0`, obtains each `CAurTexture` reference by name at `0x1400a99a8`, and stores it in a 16-byte `SafePointer` entry at `0x1400a99ba`. The binary builder obtains/assigns references in its own path. This is CPU/resource setup; generic texture demand/upload remains in the shared texture/resource branch. Evidence: source parser `ev_bb7e34953b05b4066ab286ba7822c26b53eff2b7e26b9e6b888364febaf61938`; binary builder `ev_413af25b8cd8cd4e21fd0e863bdcb6a6fcd9fcfe8b1b806dfca0bc1f49cefd42`; postprocess `ev_f96d691ff082b395c591457ecd0fe60826b133aa2d898fd5b2259e08b7ee7d2e`.

`MdlNodeLight::InternalDestructor` `0x140091cf0` and `MdlNodeLight::BinaryInternalDestructor` `0x14008cb60` both walk the `+0xa8` safe-pointer array backward while count `+0xb0` is nonzero, remove each texture observer registration, clear its pointer, and call `AurTextureRelease` `0x1400e9130`; they then reduce the count. The binary variant also frees the array. The ordinary `MdlNodeLight` destructor `0x140089430` frees the authored name, color, position and size arrays and destroys the safe-pointer list before the base node. These are model-lifetime operations, not per-frame cleanup. Evidence: `ev_a1b8830338f7367fcba0e4272bdc5cfd9a40479532ecb1c45c1f90dd52cd7270`, `ev_6cb62077f5605e054f41603ea2a600311207485186bb9141d85de4e229cbeb55`, `ev_d1c0a21da325d3c9b9a0862311ba603c73ab186b78f6f999399673d9f4230322`.

## Per-frame selection and visibility

`Scene::RenderSinglePass` calls `Scene::RenderLensFlares` `0x1400cea90` after additive and emitter work. The pass calls `LightManager::GetLensFlareLights` `0x14007f290` at `0x1400cebe3`. That selector resets cached list count `LightManager+0x88`, scans its current light pointer list `+0x40/+0x48`, and appends a PartLight only when its source node color-shift count `+0xe0` is positive. It grows cached pointer-array capacity at `+0x80/+0x8c` only on a full array. This scan occurs even when no light qualifies. The pass then lazily gets a shared six-vertex, nonindexed stream token `(6,0,0x805)` at `0x1400cec26` and calls state/matrix setup before testing whether the selected list is empty; on an empty list it skips the light loop but still restores state and matrix. A null or unchanged cached GL state may suppress lower API calls, so these static wrapper calls are not a measured GL cost. Evidence: Scene `ev_8a80227264647e9a20b32adc7274b48c4b23b4d009e072f79fdb4188f7567a69`; selector `ev_142e4bc238d6d42994fd3e8709ab3b2e260e4c276e6bed42e8cc73fe9bcfe327`.

For each selected PartLight, the pass measures distance from current Camera to PartLight world position `+0xb0..+0xb8`, requires distance at most authored flare radius `MdlNodeLight+0xa0`, and tests the light position with `BSPFitSphere` `0x140229690` at `0x1400ced36`. It proceeds to hit testing if the fitted node, its payload, or its tile-data pointer is absent, or if the indicated tile-data byte at `+0xc4` differs from `1`. It allocates a 0x80-byte `CHitInfo` at `0x1400ced76`, initializes it, calls Scene virtual `+0x58=Scene::HitCheck` `0x1400c9c90` at `0x1400cee38` from Camera to light, then destroys/frees the hit record at `0x1400cee40/0x1400cee4d`. The BSP/Gob/Part/polygon descendants of `HitCheck` are already mapped in [flare occlusion](lens-flare-occlusion.md). This allocation and hit check occur once per light admitted by the range/BSP gate, whether or not the hit blocks the flare. Evidence: Scene body above; `BSPFitSphere` CPU leaf `ev_e2ba6c92fbcf634cb43b73ab1adfc203942898a75a099e65bfcc1d2776a7e7b6`.

`PartLight+0xa4` is a persistent flare visibility scalar initialized to zero by `PartLight::PartLight` `0x140087e00`. The pass uses `max(DeltaT,0.02)` and adds `3 × dt` toward `1` when `HitCheck` returns no hit, or subtracts `3 × dt` toward `0` on a hit. A hit that reaches zero skips all texture layers. When distance/BSP checks reject a light, this body does not update that scalar; it resumes from its previous value on a later admitted call. Evidence: Part constructor `ev_4578ef8f42b45a4f0804972a41fe0212a4c2e3b5742d8d45231d21ffc6fb2054`; Scene body above.

## Per-layer draw

For a light that passes the above gates and retains positive visibility, the pass derives a Camera-facing flare axis and screen plane, then loops over the **texture-reference count** `MdlNodeLight+0xb0`. At each layer it loads one safe-pointer texture from node `+0xa8`, calls its vtable `+0x100=CAurTexture::BindInUnit` `0x1400ea490` at `0x1400cf074`, reads that layer's position `+0xc8`, size `+0xb8` and color shift `+0xd8`, combines them with current PartLight color `+0x68`, flare visibility `+0xa4`, distance falloff and authored radius, clamps RGB, writes six packed 24-byte vertices, commits them at `0x1400cf30f`, and calls `RenderInterface::RenderVertexStreamData` at `0x1400cf326` with primitive `3`, count `6`. The shared stream wrapper reaches imported `glDrawArrays` for this nonindexed stream, and texture bind reaches `glActiveTexture`/`glBindTexture` under the cached binding gates. Thus there is one texture bind request and one six-vertex draw submission per admitted authored layer. The selector uses color-shift count `+0xe0` while the draw loop uses texture count `+0xb0`; the function does not itself check that the accompanying size/position/color arrays have matching lengths. Valid authored/model setup is therefore an input invariant, and malformed sources are outside this static closure. Evidence: Scene body above; texture slot resolution and shared GL path in [auxiliary passes](scene-auxiliary-passes.md) and [geometry/draw boundary](geometry-and-draw-boundary.md).

Runtime light populations, hit frequency, authored layer count, texture-cache misses, and per-frame time remain open. The concrete recurring zero-list setup and per-admitted-light hit-record allocation are source-backed optimization candidates for later measurement, not measured bottlenecks.
