# NWN-75: Scene fog state source and per-pass consumer

Scope: installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This connects Scene fog initialization and one bounded range-update caller to the already mapped [DoFog/state boundary](scene-auxiliary-passes.md). It does not infer live fog values, caller frequency or GPU time.

`Scene::Scene` `0x1400c0ca0` initializes fog enable at `+0x140` to zero, start/end floats at `+0x144/+0x148` to `5/40`, and color vector `+0x14c..+0x154` to `(1,1,1)`. It also registers console fields `fog`, `fogcolor`, `fogstart` and `fogend` against those in-Scene addresses. These are defaults and writable field registrations, not proof that a console command executes during a frame. Evidence: Scene constructor `ev_9bd85911eebb0eb0c68866794c5c484152b6059e0e8e29e18ffda6e3851cf60b`.

Scene vtable `0x140d8dd30` has `+0x88=Scene::SetFogRange` `0x1400d3360` (entry `0x140d8ddb8`) and `+0xa0=Scene::SetFogColor` `0x1400d3340` (entry `0x140d8ddd0`). The range setter copies its two incoming floats to Scene `+0x144/+0x148`; the color setter copies the incoming three floats to `+0x14c..+0x154`. Both are CPU stores with no GL call. Their full external/indirect caller sets are not established by the setter bodies. Evidence: range `ev_195313f96dd7c049d9654a89f73cfe78b16e49e8b7cb51a34fafb0e115d47a9a`, color `ev_defe6261716c3b003b8a8a04fbea47998cbfab6b1f05bb19288107b70b4ae776`, original vtable bytes `0x140d8ddb0..0x140d8ddd7`.

One concrete range updater is `FUN_1407d44a0` `0x1407d44a0`: it parses a positive float with `sscanf("%f")` at `0x1407d44b0`, requires the client environment pointer at `+0xe8`, then obtains its range through virtual `+0x78`. When the current client area and Scene at area `+0x248` exist, it re-reads that environment range, preserves the first float, adjusts the second by `(requested - prior second)`, writes the environment via its `+0x80` setter, then calls Scene `+0x80=GetFogRange` at `0x1407d45bb` and `+0x88=SetFogRange` at `0x1407d45e2`. It marks client `+0x134` dirty. The command's registration/name and the environment object's concrete subtype are outside this branch; the observed Scene callsite and arithmetic are exact. Evidence: `ev_0ffff77eca58f6bf5dffe16268c121bbbc040fe1e42fdb0ccb50715932cc5891`, Scene getter `ev_cac6409a6ff216d9c430cde9d308dabdd7e2b956ae74211414b7aee664e74b79`.

`Scene::DoFog` `0x1400c7f10` tests the enable flag `+0x140` on each invocation. When enabled, it enables fog render state, chooses Scene color `+0x14c` or black when `LightManager::m_pOnlyGob` is nonnull, and passes the two range floats to `RenderInterface::SetFogModef` modes `0/1`. When disabled, it disables fog state. These wrappers compare/cache values and later shader uniform publication is mapped in [render state](render-state-boundaries.md); this body itself has no direct GL draw. `RenderSinglePass` invokes DoFog in its early and later state stages, with additional restoration sites already mapped in the auxiliary pass note. Evidence: DoFog `ev_75304e5dfc6610bfa385a9cdb3a31a13f2b04d8248f0268accc067739183ddf9`.

The named [`fogcolor` console route](scene-fog-console-vector.md) is a separate conditional writer: its vector holder parses directly into Scene `+0x14c..+0x154` without calling `SetFogColor`. A nondefault `SetFogColor` caller and the exact origin of area/environment fog values remain open. This note closes the constructor/defaults and one range-update route to the existing per-pass consumer.
