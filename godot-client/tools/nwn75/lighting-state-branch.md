# NWN-75: original scene lighting state branch

Binary: `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This maps the per-pass light-selection and render-state branch reached from `Scene::RenderSinglePass` `0x1400d0f10`. It describes static control flow; the original evidence does not establish which OS thread executes the pass or how often a gate is taken.

The pass calls `LightManager::EnableLights` `0x14007e890` through LightManager vtable `0x140d85f70` slot `+0x10` when full dynamic lighting is enabled and at later pass boundaries. With full dynamic lighting disabled it calls `EnableLightsDynamicOnly` `0x14007ea70` through slot `+0x18` before the opaque bucket. Both call virtual slot `+0x60`, whose original PE pointer is `0x14007ddb0=LightManager::ControlLightsFade`; the callsites are `0x14007e9a7` and `0x14007ec19`. The first passes the full light list at `LightManager+0x40` and active list at `+0x60` with mode 0. The second builds a temporary subset of list entries whose light kind at `+0x8c` is 1, then passes that subset and the active list at `+0x70` with mode 1. REA evidence: `ev_6c5e8fcf`, `ev_2c0b7821`, `ev_5e1b9864`; vtable pointer is at original VA `0x140d85fd0`.

`ControlLightsFade` caps the active-slot count at `min(m_nMaxLights,128)`, reserves two slots when the headlight is enabled, and limits selection to `m_pOnlyGob` when set. It compares the selected and active PartLight lists, increases or decreases each light's mode-specific fade value at PartLight `+0x94` or `+0x98` using `max(DeltaT,0.0001)` and `GetLightFadeSpeed`, removes expired entries, adds new selected entries, and sets area ambient/diffuse values. If enabled, `SetHeadLightProperties` `0x140080950` populates slots 0 and 1 from the current camera and headlight colors. For each admitted active PartLight it calls `SetLightGL` `0x140080c10` with its slot and fade; it disables remaining slots through `RenderInterface::DisableLight` `0x1400bea00`. Evidence: `ev_5e1b9864`, `ev_73cdea20`.

`SetLightGL` chooses area ambient/diffuse output when slot is `-1`; for a numbered slot it writes color, position, attenuation and radius through `RenderInterface::SetLightProperties` `0x1400bf190`, then enables or disables the slot according to the global shader parameter and `GetIsLightInViewVolume` camera-frustum result. These helpers perform CPU/data work before the shared shader-uniform publication path. Evidence: `ev_00ada174`, `ev_a410aa84`, `ev_93a5760b`.

`GetIsLightInViewVolume` `0x14007f180` calls `GetLightAdjustedRadius` `0x14007f480` at `0x14007f19c`. A light with adjusted radius at least 1000, or absent current Camera/Scene, passes without plane tests. Otherwise the function starts at the previously rejecting plane index `DAT_1413017a8`, tests each of Camera's `+0x4f8` planes in wrapped order, and records the first plane that rejects the light. Plane index 1 receives a Scene-versus-Camera height offset when Scene `+0x140` is nonzero. Each test calls `SphereAbovePlane` `0x14022e360` at `0x14007f238`, which computes signed center-to-plane distance minus radius with scalar arithmetic and no child calls. The body has no GL call (`ev_a410aa841946c8f3400c7b044486d80124f934865e47c8d5cac965dab797e478`, `ev_31205cbcdd335ed78360cc6dc702fc30b4d43bbbfe03f301d1f0a89629884279`).

`GetLightAdjustedRadius` reads PartLight radius `+0x74`. Below 1000 it multiplies by the light's scale `+0xa8`, then calls integer global shader parameter 0 at `0x14007f4b4`. If that mode is active, it also scales by the largest color component above one and calls float parameter `0x12` at `0x14007f4ee`; otherwise it returns the scaled radius. Both getters read cached shader parameters and issue no direct GL command (`ev_cf8b12e758a39498ab71eccc3a6ea5b8b11c0338ae2ed28678d21c28a275a5c8`).

When the headlight gate admits it, `LightManager::SetHeadLightProperties` `0x140080950` publishes two light slots. Slot 0 uses Camera position, authored headlight ambient, zero diffuse and a negative radius term; slot 1 uses Camera position, zero ambient, authored headlight diffuse and a positive radius term. Each slot writes position, ambient, diffuse, attenuation and adjusted radius through `RenderInterface::SetLightProperties` before `RenderInterface::EnableLight` at `0x140080ab1` or `0x140080bef`. The adjusted radius reads cached float shader parameters `0x12` and `0x14`; nonzero `0x14` scales its RGB. This function makes 24 direct calls in all, each site recorded in the ledger, but no immediate GL call. The interface setters update cached light state for later uniform publication (`ev_73cdea20b6ee0abd2976320842b17b7af61a011717706f8b143452c5249e5a2f`).

The shared `normalize` `0x140230920`, reached twice while `ControlLightsFade` computes area light direction, copies nearly unit vectors, substitutes `(1,0,0)` for zero length, and otherwise calls the CRT square-root helper `0x140c7d6d8` at `0x1402309bb` to divide by vector length. The helper uses a scalar square-root instruction for ordinary positive input; its NaN/domain-error branches call CRT handlers. This path performs no GL work, but the exceptional CRT descendants remain a runtime-library boundary (`ev_8f6a2c146e601a6de371e301b1f3a9357b925b4cfa27aa1375c414626f55f1e3`, `ev_388be500fb4be7cacb9e6f84cdc3ba0e0dd2f40ae59ca3ba0a0a4aff1f466d71`).

The `GetLightFadeSpeed` `0x14007f510` helper itself has three exact child calls: `GetLightAdjustedColor` `0x14007f380` at `0x14007f537`, integer global shader parameter 0 at `0x14007f599` only for light radius below 1000, and float global shader parameter `0x12` at `0x14007f5d0` only when that integer mode is enabled. It combines adjusted maximum RGB, PartLight radius and per-light fade scale, clamps the intermediate to 1–10, then returns `10/intermediate`; no GL call occurs in this body (`ev_93a5760b6fe68aae44d54946db986902f14b7646144eddc2a140a9895f029ab6`). `GetLightAdjustedColor` calls the same integer shader getter at `0x14007f3a4` only for radius below 1000; under enabled mode it normalizes RGB if its maximum exceeds one, otherwise copies the original color (`ev_1adb097b2796d7fb9eaafa9391484a58131df074f790870526bc9f6f115b5218`). These are CPU helpers with read-only shader-constant children, not terminal functions; the four sites are now ledgered.

`RenderInterface::SetLightProperties`, `EnableLight` `0x1400beab0`, `DisableLight`, `SetAreaAmbientLight` `0x1400befd0`, and `SetAreaDiffuseLight` `0x1400befe0` compare/write the GLRender light cache and increment global shader-uniform dirty generation `DAT_1413d26fc` on changes. They do not issue immediate OpenGL calls. The later `GLRender::SetUniforms` `0x1400b8380` consumes the changed light group at program selection; its exact original `glUniform*` callsites and conditions are in `shader-uniform-gl-callsites.json` and `shader-program-branch.md`. This reaches the external GL boundary through that shared descendant. Evidence: `ev_f1548ec9`, `ev_451f02ae`, `ev_f8bb79f3`, `ev_5b67a8c9`, `ev_9128ff35`.

`LightManager::GetShadowLights` `0x14007f840` is a CPU selection branch used only when `enableshadows` is set in `RenderSinglePass`. Mode 2 scans the source list for entries with nonzero active flag at `+0x78` and zero flag at `+0x84`, requires either authored radius at least 1000 or light kind 0 at `+0x8c`, then keeps the candidate with the smallest model priority integer at `+0xf8`; it may grow the output array through `_realloc_base` at `0x14007f943`. Other modes scan the prioritized light list at `+0x50`, admitting lights by kind and effective radius until the configured `m_nMaxShadowLights` limit; `CExoArrayList<PartLight*>::Add` occurs at `0x14007f9d1`. The function copies the previous mode-specific list into a local working array via `SetSize` `0x14007fa29` and byte copy `0x14007fa45`, then reconciles membership. Dropped lights fade down at `DeltaT*2/0.3`, retained lights fade up at `DeltaT/0.3`, both stored at PartLight `+0xac`; array growth, shifting, and final mode-list publication use the remaining exact site-backed allocator/copy calls. This body has no draw or GL call (`ev_ae63e4bf061e12c4053bf45db0fa0a0b0e0b1e60a4e0e632b6a206ce75e22a59`). The `Add` helper `0x14007db60` grows a full pointer array and calls `_realloc_base` at `0x14007dba8` (`ev_c8b53666d04a8b1db4799031c2e87a8e6a30910fae8d39f4da02d39f8f7c1df5`). `SetSize` `0x140080f00` frees storage for zero size at `0x140080f16` or grows it at `0x140080f50` (`ev_1c9c03e165e84d7a08f044ec516772691595f92e75250f79294e67f58ca7e38f`). The shared CRT allocator/copy/free descendants remain bounded in their separate runtime branch.

`LightManager::GetEmitterLighting` `0x14007ee50` is the focus/emitter color branch: it accumulates distance/radius/fade-scaled contributions from the active light list, optionally excludes lights in a supplied list, adds headlight and area light colors, clamps output channels to 1, and returns a `Vector`. Its only call children are vector add and magnitude, with no draw or GL call (REA `ev_6c921ee5`).

`RenderSinglePass` also copies a `List<PartLight*>` through `0x1400c23a0` while preparing shadow lights. The assignment tests self-assignment, resizes destination storage to the source count, copies `count × 8` bytes, or frees/zeros destination storage for an empty source. This is CPU list handling, not a draw; its allocator and copy/free helper descendants are still open (REA `ev_943545cab23b5303f4027822d8e970bc48a91f2bacf740bdd2c38fe09fe48922`). `Homogenize` `0x14022cb70`, used in the light-state path, copies a Vector and a float into process-global scratch at `0x14140d1c0` and returns that address. It does no arithmetic or GL call in its body; the shared scratch is an observed data dependency (REA `ev_41cd98fc04b608fdc0a28cdb192ad01aafbd126deb2394c0c0334176bdca4908`).

`Scene::RenderSinglePass` also calls `Gob::CollectLights` `0x14008cd30` at `0x1400d1e28` for the focus Gob's model hierarchy. The routine resets its output PartLight list, allocates a breadth-first Part worklist from Gob+0x90, invokes each Part's virtual `+0x48=AsPartLight` at `0x14008cdba`, appends accepted lights, then enqueues each Part child in stored order. The worklist and result list grow through `_realloc_base`; the local worklist is freed before return. This is CPU selection, with no GL call in the observed body. The dynamic Part subtype at each worklist item determines whether the base null or PartLight self target is used. Evidence: REA `ev_1e0bf51b`, `ev_ee6e0e27`, original Part slot `ev_251847d2` and PartLight method `0x14008c4a0`.

The no-BSP `Scene::RenderOnlyGobs` route calls `LightManager::GetNearestLights` `0x14007f660` at `0x1400cfbca`. It optionally sets headlight slots, applies two area lights, then scans the registered PartLight list at LightManager+0x10 up to `min(m_nMaxLights,128)`, admits lights by authored kind, range and optional mode filter, and calls `SetLightGL` for each accepted slot. It disables unused slots through `RenderInterface::DisableLight`. This joins the same cached light-state → shader-uniform path above, with no immediate GL call in `GetNearestLights` itself. Evidence: REA `ev_6466027d`, `ev_9311f36f`.

When debug light ranges are enabled, `LightManager::RenderLightRanges` `0x1400805a0` takes the current Camera projection, iterates source and active lights, and calls `RenderInterface::DrawCrosshair` `0x1400bea40` or `DrawCircleBound` `0x1400bea20` after adjusted color/radius checks (REA `ev_469e2e00`). `DrawCrosshair` builds a four-line static vector list and calls `GLRender::DrawLines` `0x1400b1d70` (REA `ev_1bf6bb01`, `ev_424c484a`). `DrawLines` commits a `VertexStreamDataObject` and calls `GLRender::RenderVertexStreamData` `0x1400b5c20`, which reaches the draw API chain in `geometry-and-draw-boundary.md`. `DrawCircleBound` builds a line loop and calls `GLRender::RenderVertexData` `0x1400b59b0` (REA `ev_ba3e569a`), the same mapped draw boundary. These are gated debug geometry, not an unconditional light pass.

The two `ControlLightsFade` virtual callsites are resolved. Collection/prioritization and per-uniform input attribution remain open in the main branch ledger.
