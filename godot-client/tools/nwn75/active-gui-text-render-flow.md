# NWN-75 original GUI text presentation flow

Scope: installed `nwmain.exe`, SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are original image VAs. The [edge ledger](active-gui-text-render-ledger.json) joins two constructed text paths to their GL/API leaves. A constructed path is an eligible original-code route, not proof that a particular label or Nui window was visible in a captured frame.

## Shared screen owner and order

`UpdateScreen` `0x1400451c0` enters its GUI branch only if argument 2 is nonzero. It calls `AurMakeCurrent`, then `CGuiMan::UpdateAndRender` at `0x1400452e4`. Its separate posted-text scene and swap require argument 4 zero and the client guard `FUN_1406abc60` to return zero. `CGuiMan::UpdateAndRender` itself requires manager `+0x2c != 0`; after its registered-object update pass, the client guard must return zero before its render pass. It renders registered GUI scene-view cameras, calls `Nui::Window::RenderAll` through thunk `0x1406c39e0` at `0x1401f76e1`, then calls the Nuklear draw `0x140a71760` at `0x1401f76e9`. Thus the panel-scene text lane precedes the Nui command-conversion lane on this direct path. Original REA `ev_64a8c164456d63647a40fedfdd9e979c03c5a514b4c7429feb58d8f5b9b24133`, `ev_32e5e54090ea151bc3781f1d0872ed7b7373b8d8fae90e7a1e8a5dafd99c5856`, Nuklear draw incoming census `ev_fbbb8405b48c9d1e8b33cec99b3dcbbc93600ae8bb52ac4c94d3f4b277d24183`.

The registered-object pass calls `CGuiObject::UnRegisterUpdate` `0x1401fba80` at `0x1401f72f1` only when a virtual `+0x58` update returns sentinel `0x80000001`; it is an update-list mutation before the draw pass. In the Nui window update, `Nui::Window::UpdateWindow` `0x1406c79a0` calls `HandleCloseIntrinsics` `0x1406c28c0` at `0x1406c7f67` if its transition byte `window+0x119` is set after the named-context checks. That releases/dispatches close state, including a concrete JsonWindow `_window_`/`close` event candidate; it is not a text GL draw. Original REA `ev_32e5e54090ea151bc3781f1d0872ed7b7373b8d8fae90e7a1e8a5dafd99c5856`, `ev_e1af32e46b523bdfbd6624cc7234925492cae9178364659e51a73eff29921bfc`, `ev_44c91c0141bb7d92242329d82a8465caa36a5ff379c6597824410744fce88854`.

## Panel label → font stream

`CGuiPanel::Activate` `0x1401fbe70` can construct a GUI scene/camera, attach its root model through Gob virtual `+0x90` → `Gob::AttachToScene` `0x1400c5780`, and register the view with `CGuiMan`. `CGuiLabel` constructor `0x1401e80b0` creates `NewCAurString` `0x1400492f0`; `CGuiLabel::AddToPanel` `0x1401e8f60`/`0x1401e8e00` attaches its `StringGob` to the panel model and propagates that Scene when attachment succeeds. Manager view camera virtual `+0x10` resolves by the constructed Camera table to `Camera::RenderScene` `0x14005a5d0`; Scene `+0x18` resolves to `Scene::Render` `0x1400cc730`. A scene without BSP takes `Scene::RenderOnlyGobs` `0x1400cf9b0` and each Scene child Gob virtual `+0x20`. The constructed StringGob table `0x140d81440` maps that slot to `StringGob::Render` `0x1400498a0`. An installed BSP takes the shared `Scene::RenderSinglePass` branch instead. Active view, successful hooks, scene contents, viewport and text visibility are runtime gates. Original path and table evidence: `ev_59a27eca9979c6ac9a91a8016fd807444610412e3af0c3f721d631d0baa4a8cb`, `ev_c678d4a6b86551c949966d8764115b85ffde9764f97dfa7e9f039345fdd93b86`, `ev_8bf4c4a7b7e2e548382ae2a128096910a143012caa964a5e52184f593d3aa945`, `ev_cb7cf4fd2ea02bc0a972057750745b05fd56f2c424ab6688817f97e067b83bbd`, `ev_17ec38a8462fe63e54833099ba8a0936b20e0b67c55d26a0bda6bf049d07a6a8`, `ev_d48d788ea591d6f4c257237674ad87a57f1a635a3748ccc946cb8771653b9b15`.

`StringGob::Render` binds its font texture through texture virtual `+0x100`, sets transforms/color, then walks only the selected visible line range (`+0x528` start, `+0x52c` count, bounded by total `+0x508`). It calls `CAurFont::TextOut` `0x14004c870` at `0x140049c5c` for a line and conditionally at `0x140049d08`/`0x140049e78` for caret text. A font flag pair at font-info `+0x68/+0x69` can trigger `CAurTexture::BuildAndStore` before line submission. TextOut itself requires font-info `+0x40 == 0` and a nonnull texture; it may call the texture virtual `+0x30` and `BuildAndStore` under readiness conditions. It gets or grows a reusable vertex stream token for six vertices per character, reads `CAurFontInfo::GetSymbolCoords` for each input byte, emits glyph quads, and commits/draws at color-markup transitions or at the end. Its two direct stream callsites are `0x14004ca6f` and `0x14004ccb5` → `RenderInterface::RenderVertexStreamData` `0x1400beed0`, which calls imported `glDrawArrays` when stream index data is absent and imported `glDrawElements` otherwise. A text string may therefore cause zero or multiple draw calls depending on its gates and markup. Original REA `ev_d550614a2af7ec7775eeb665961fc362a84cf0f886207550ab8df61e5ba54ef2`, `ev_d78d7d499a4bc9bde2ce720acb873f9be1514e0b9900535f0fd34f795a1f6ff9`, `ev_eaf33b364606d13b12fdfb9676cea44ec793bb9242b05438298e9edc56bca4fd`, `ev_44f72a719a8f7e7bf2a2854d4bf9b2bd856e003300b12ac1bd2407bc9d49782e`, `ev_eebcfb2e63d9940d0fdf01c2de8150cfcda589fde0e7d844a8be9b3a26969efb`.

The font object is separately owned. Named `CAurFont` construction `0x14004b4d0` obtains a referenced `CAurTexture` and its font info; `_s_LoadedFontList` receives fonts with symbols. `AurTextureGetReference` `0x1400e8b60` searches the named texture cache through `AurTextureGet`/`AurTextureFind` and constructs `CAurTextureBasic` only on a miss. The index constructor and `CAurFont::Reset` reuse/copied font information. Conditional `BuildAndStore` reaches Basic image creation, optional TTF resource demand and `stbtt_PackFontRanges` for a missing image, then `glImageBasic` and `GLRender::CreateTexture` reach imported `glTexImage2D`/`glTexSubImage2D` or a compressed upload. This is a readiness/build path, not the normal per-glyph operation. `CAurFont::~CAurFont` `0x14004b670` releases its texture and loaded-list node; `AurDeleteAllFonts` `0x14004c0c0` walks that list; Basic reset/destructor can delete the GL texture through `RenderInterface::DeleteTextures` → `GLRender::DeleteTextures` → imported `glDeleteTextures`. Original cache/build/teardown evidence: `ev_bfe4dd1a01bcba296b31034f6ec01f76aca1db76bcc81e7cd361b7f1174b8b88`, `ev_58e32829c45065d42dbb23e27380ac551464fb5b01ef76a91a9f508a9abccc9b`, `ev_3da65d17a98f227ececaf4b457322e76a4829c312b383a4a4d88ed612c3cda32`, `ev_b57aca3c1c0feb074828270991b35a27ca01a1359ae4129aaeda57041307f2dc`, `ev_3b2f7919d1c5ffb6a5cd1c62d60fd78b1c113074c7bbb1a574c2c022ac91b917`, `ev_75368d94af22e27b50b2177d95fe61232ce2fad1041ccdff4e4806e4f84764d8`.

The `CAurTexture::BuildAndStore` body calls `CAurTextureBasic::Reset` at `0x1400ea5c0` only after the referenced texture's `AsCAurTextureBasic` virtual returns nonnull. Reset frees an existing texture ID array through `RenderInterface::DeleteTextures` when `Basic+0x50` is nonnull; `BuildAndStoreTexture` then follows. This direct connector makes prior-texture deletion part of a conditional rebuild, rather than a per-text draw. Original REA `ev_0766c8553c4e6595ae7aa3c2dcd3f5912c442394ee22c499d54893262d08b82b`, `ev_3b2f7919d1c5ffb6a5cd1c62d60fd78b1c113074c7bbb1a574c2c022ac91b917`.

`UpdateScreen` also draws posted strings after `CGuiMan`: `AurRenderStrings` `0x14006a040` → `AurPrintString` `0x140069b80` → `CAurFont::TextOut` at `0x14006a001` or a `StringGob` route. ## Nui text command → baked glyph → indexed draw

The registered Nui path has explicit lifetime and content gates: `Nui::Window::RenderAll` `0x1406c4b20` iterates its weak window registry, passes a surviving/renderable window to `RenderWindow` `0x1406c5350`, and a `JsonWindow` can dispatch content virtual `+0x20`. Constructor-backed layout tables resolve groups, layout children and Widgets to several concrete callback families. One bounded text example is the `Nui::Layout::MoviePlayer` table `0x140e6e070`, content `+0x20` → `0x14095b1a0`: its loaded controls and failed-load message have direct kind-16 producer calls at `0x14095b474`, `0x14095b850`, and `0x14095b92c` to `0x140a81600`. A `textedit` StatefulWidget and JSON draw-list callback are further static producer families. The runtime registry contents, open/visible flag, widget state and selected command type remain unknown; the example does not assert a movie widget is active. Original REA `ev_fdd4a2429d1f0bc34d80bd3dadc79ae2cbe7531002b9758ca8a00086277d1cbe`, `ev_daabb01e3b637193b6eafc330825d4cbb65b3affd3c3ac9e9de6028146e8097b`, `ev_33c77e978b141241f1dd816751c87f4cb43f214c74dd06825b165408ec7d26af`, kind-16 incoming census `ev_003ef7a3852046c1f3737677618378ee3910c2cb7a239d3610f4b8554479c6fd`.

The kind-16 producer rejects null context/text, zero length, fully transparent foreground/background, invalid clip dimensions and text outside clip. It measures width through font-view `+0x10`, may truncate to the clip, then allocates a numeric `0x10` command through `0x140a619c0`, storing the font view, clipped rectangle, color and text bytes. `0x140a71760` calls `nk_sdl_refresh_config` `0x140a70d90` at `0x140a7185f`, maps the UI VBO/EBO and calls converter `0x140a7c340`. A kind-16 command dispatches to `0x140a7de20` at `0x140a7d001`; that requires nonnull text/font and clip intersection, decodes text through `0x140a919a0`, calls the font-view `+0x18` glyph callback, and writes quad geometry through `0x140a688a0`. For the published baked-font view, callback `+0x18` is `0x140a6b9a0`, which calls `0x140a840c0` for range-selected or fallback glyph metrics/UVs. `0x140a71760` then unmaps buffers and, for nonempty draw commands, binds texture, calls imported `glScissor`, and imported `glDrawElements`. The Nuklear device/font owner is distinct from `CAurFont`. `SDL_main` calls UI setup `0x140a70a50` at `0x140046da5`, which creates program/VBO/EBO/VAO and calls font refresh. Refresh only rebuilds if dirty byte `0x1412996e0` is set: it builds font entries `0x140a824b0`, bakes pixels and glyph records `0x140a82f20`, uploads/replaces atlas texture `0x140a6fe10`, and publishes baked font view `0x141429c20` with width callback `0x140a6ba50` and glyph callback `0x140a6b9a0`. Scale/reshape/resource/NUI reload paths can set the dirty byte. Shutdown `0x140a71ef0`, called from `SDL_main` at `0x140046de2`, frees CPU atlas/font state, detaches/deletes shaders and UI program, deletes atlas texture and VBO/EBO. No explicit delete of UI VAO `0x141429a68` is established on that path. ## Boundaries and open conditions

The panel lane and Nui lane follow direct calls/virtual dispatch on the caller of `UpdateScreen` and `CGuiMan::UpdateAndRender`; no worker enqueue or wait appears in these mapped draw bodies. Static code does not identify the OS thread of every `UpdateScreen` caller, how many labels/windows/strings are live, whether a font texture rebuild occurs in a particular frame, or which stream index branch is used. The Nui path depends on runtime registry, content and command-list state. Alternate font-view substitution remains open. The exported `CAurGUIStringInternal::Draw` `0x14006f200` is **not** inserted into either route: its factory and Draw have only data/vtable incoming references in the exact census, so a live indirect caller is unproved ([standalone GUI entries](gui-standalone-draw-and-animate-entries.md)).
