## Encapsulated producer and demand selection

That builder tries supported encapsulated file types, reads the header, checks its magic, version and resource count, allocates a key table, then creates one `CExoEncapsulatedFile` object. It installs vtable `0x140da12f8` at `0x140188e18`, publishes the object as the first entry of key table array `+0x50` at `0x140188e9c`, and invokes virtual `+0x48` at `0x140188ee8`. The pinned slot resolves to `CExoEncapsulatedFile::LoadHeader` `0x14018b4e0`, which opens the selected file, reads a 0xa0-byte header, checks type/version and optional OID, then populates resource entries. ## Plain entry and file boundary

`CExoEncapsulatedFile::ReadResource` `0x14018ca10` requires open state `+0x2c`, a nonnull destination and resource index below the header's entry count. It seeks to that entry's offset through `CExoFile::Seek` at `0x14018ca65`. Compression flag `1` calls `CExoPackedFile::ReadNWCompressedBuffer` at `0x14018ca87`, the separate compressed-buffer/algorithm branch. For a **plain** entry, caller capacity below stored size invokes `CExoFile::Read` at `0x14018cab5` for a truncated request; otherwise `0x14018caf2` requests full stored size. Both paths require the read count to equal the requested count, or they log a short-read warning and fail the service. REA `ev_2762701c06bf22adf3fbdb2c18b1b53bf29bea16e0290001af26c25d80192ed6`.

The shared `CExoFile::Read` entry `0x140166ca0` tail-jumps at `0x140166ca4` to `CExoFileInternal::Read` `0x140167c60`. Its generic memory-backed mode `2` copies bytes through `0x140c417f0` at `0x140167ca7` and stops at a CPU leaf. For a file stream, it calls `fread` at `0x140167cdb`; `fread` → `fread_s` → `_fread_nolock_s` use exact sites `0x140c7e2b3`, `0x140c7e350`. A warm CRT buffer can be copied without an OS read. On the direct large-read branch, `_fread_nolock_s` calls `_read_nolock` at `0x140c7e1e6`, which reaches imported `KERNEL32.DLL::ReadFile` through cell `0x140d7c678` at `0x140ca7a53` for a file handle. Console/error/EOF branches remain conditional. ## Bounded frontier

This closes the built-in source-2 provider identity and one plain-entry path to CPU/Win32 boundaries. Runtime `CRes` source selection, key-table id, resource index, entry compression flag, CRT buffer state and successful byte count remain unobserved. The compressed branch's provider/codec choice is mapped in the GUI decoder supplement but deep entropy work remains separate. Dynamic replacement of the key-table provider object is not excluded by static evidence.
