When node vertex count `+0x284` starts at zero, the function calls `ProcessVerts`; for positive face count it generates vertices, neighbor lists, indices, vertex pools and tangent basis. After that branch it resets float node `+0x2bc` to zero, calls `RenderInterface::LockPool` `0x1400bee30` at `0x1400a9b6d` for position handle `+0x280`, and for every node face reads three 16-bit vertex indices at face offsets `+0x1a/+0x1c/+0x1e`. Assembly `0x1400a9ba0..0x1400a9c43` forms both vectors from the first indexed position to the second and third positions, passes them at `R8/RDX` to `cross` `0x14022fba0` (`ev_d5cce9192b5aec9ed4cd9a025909ab8756bc4b0f716d502691809c56b4c23b41`), invokes `magnitude` `0x1402303d0`, and adds half that magnitude to `+0x2bc`. This is the sum of triangle areas over the faces in the locked position pool; the cross product's orientation does not change its magnitude. It calls `UnlockPool` `0x1400bf3d0` at `0x1400a9c90`, which enters the shared conditional pool-to-GL path. The decompiler displays only one explicit input to `cross`; assembly establishes the second. The shown body does not prove a positive face count at the lock site or a successful pool handle in malformed models.

It next invokes node callback `+0xa8` to release temporary arrays. Ordinary TriMesh constructor `0x140087900` installs `MdlNodeTriMeshRemoveTemporaryArrays` `0x1400931c0`, which forwards to `InternalRemoveTemporaryArrays` `0x1400a9f40` (REA constructor `ev_411440c52f1670df564d1122ec98e51a2471f5fffb95418d43b516267fa16ee9`, remover `ev_f8639874bf80b5c2fa13fbc32710855c1dd2fa757bbd91177e3783edcfe0303e`). The remover frees nested generated-vertex lists at postprocess `+0x90/+0x98`, clears several global temporary-list count slots, destroys the `0xb0`-byte postprocess object, frees it and clears node `+0x278`. These are CPU lifetime leaves; subtype constructors can install another `+0xa8` target, mapped separately for Skin/AnimMesh. When vertex count was already nonzero, this `InternalPostProcess` instead calls tangent-basis calculation and returns, with no area scan or temporary-array release in that branch.

There is no worker enqueue in this postprocess tail. Active model type/face count, pool handle state, subtype callback and later draw remain dynamic; static code does not establish OS thread identity or runtime cost.
