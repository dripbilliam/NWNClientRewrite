# Primary CAurTexture vtable census

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. The [ledger](texture-rtti-primary-vtables-ledger.json) bounds the concrete texture-class candidates for [2D and cube image publication](texture-publication-per-frame.md). A complete aligned scan of the pinned PE `.rdata` for MSVC x64 Complete Object Locators with signature 1, self-RVA validation and a class-hierarchy base list containing `.?AVCAurTexture@@` yields **two primary vtables**: `CAurTexture` `0x140d90c70` (COL `0x140ee86c0`) and `CAurTextureBasic` `0x140d90d90` (COL `0x140ee88b8`). The scan method is the one in `audit-part-draw-vtables.cjs`, with the inheritance predicate changed from `.?AVPart@@` to `.?AVCAurTexture@@`; the temporary adaptation was removed after the scan. This is exhaustive for that RTTI structure and `.rdata` in this pinned image, not for RTTI-stripped or externally supplied classes.

The base constructor `0x1400e4cc0` installs `0x140d90c70` at `0x1400e4ce2/e9` (REA `ev_305d28611dce0eb253596075b1d7ac26a968348c0bef1a30f870c5c40921020f`). The Basic constructor `0x1400e4d60` first calls it at `0x1400e4d89`, then overwrites the primary vtable with `0x140d90d90` at `0x1400e4d8f/96` (REA `ev_7c6b4e03abdc85bad33e4653d02caa5265596f7ede5fbfae061f8f6b7ed5b276`). Original table reads are REA `ev_c0aac1eacfca1ae9eed75bed32c5c2599e3f58abdb296b3fc9c466c2fcc0b13f` and `ev_1f347aae5714bc22bd9266ae9e3f3574a5ac2f7aaab54a4beddd4f04d6d01514`.

Every virtual getter slot used by `GLRender::CreateTexture` and `CreateCubeTexture` is byte-identical in these two tables: `+0x60/+0x70/+0x78/+0x80/+0x88/+0x90/+0x98/+0xa0/+0xa8/+0xb0/+0xb8/+0xc0/+0xd0`. The only differences through slot `+0x110` are `+0x0` destruction (`0x1400e5500` base, `0x1400e5540` Basic), `+0x8` Basic type test (`0x1400e5a00` base null, `0x1400e5a10` Basic self), and `+0xf0` image release (`0x1400eb610` base, `0x1400eb640` Basic). Thus the existing [2D computed-call map](texture-create-indirect-callsites.json) and [cube map](texture-cube-indirect-callsites.json) have no additional getter override target in the binary's RTTI-backed primary texture class family. These vtable bytes establish possible dispatch targets, not whether a particular texture object, image branch or GL call executes. Dynamic class loading, RTTI-stripped tables and malformed table records remain outside this bounded census.
