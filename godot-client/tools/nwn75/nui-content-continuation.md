# NWN-75 original Nui content continuation

Scope: installed `nwmain.exe`, SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This is documentation of original binary bytes and existing REA evidence only. Addresses are image virtual addresses. No client comparison or recommendation is made.

## Registry to content boundary

`Nui::Window::RenderAll` `0x1406c4b20` walks an identifier-keyed window registry under its UI-enable gate. It initializes a surviving active window once, invokes its update/render paths and handles open intrinsics. The 43 named original window/wrapper vtables in `nui-window-vtable-census.json` resolve their `+0x40` initialize, `+0x58` update and `+0x60` render slots to two, six and eleven distinct target addresses respectively. These are candidates for registered objects, not a runtime active-window census. REA `ev_74d8d73453f582b8c256a0045e8858e65c2aa3a509fd2f4eefec94eae3f35817`, `ev_75101c46db8fe527f673a2bc4ee7f55f305ad291320da94ce352c6dd2c02fb47`; each vtable has its own evidence ID in the census.

The base `Nui::Window::Render` `0x1406c44e0` calls a non-null content object's virtual slot `+0x20` at `0x1406c4a88` after context/layout setup, then restores layout state. This is the broad unresolved content-dispatch edge in `gui-presentation-ledger.json` (REA `ev_daabb01e3b637193b6eafc330825d4cbb65b3affd3c3ac9e9de6028146e8097b`). For `JsonWindow`, `0x14074c0b0` stores an existing `LayoutGroup` or wraps a supplied child in a `SingleGroup` at window `+0x108` with a refcount owner at `+0x110` (REA `ev_2f28694d29789d72db7d1c593570250dcb5a3d78b7908452ea8256ebe0f4801a`, `ev_f54583d451dab0323abec3d97c94dd3f5f6c361c82ab8ba41b74b4b6b2fc5eb1`). Other registered windows' content ownership and concrete type remain open.
