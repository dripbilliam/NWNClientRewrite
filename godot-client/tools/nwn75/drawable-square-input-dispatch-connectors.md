## Frame/input entry

The existing [input activation connector](area-post-build-pvp-panel-refresh.md) site-backs `SDL_main` → client loop `FUN_1406db800` → input helper `FUN_1406f14e0` → event dispatcher `FUN_1406ed720` at `0x1406f16c5`, conditional on the active input/event path. The dispatcher switches on a table selected by its event argument. In its case 0, it calls `FUN_1406f0d80` when `param_3==0` and `FUN_1406f02c0` when `param_3!=0` (the latter receives whether the value equals `0xffffffff`). The exact call instructions, despite their different machine order, are `0x1406edaa1: e8da320000` → `0x1406f0d80` and `0x1406eda82: e839280000` → `0x1406f02c0`. This is a conditional input-dispatch connector, not an assertion that the event occurs on every frame. ## Other cleanup callers and queue lifetime

Client input deactivation helper `FUN_1406e1d70` calls `FUN_1406f0d80` at `0x1406e1dbc` only on its `param_2==0` branch, after releasing GUI mouse capture and resetting nearby input state. Area loadscreen owner `FUN_1406e37f0` calls the same cleanup at `0x1406e3852` before choosing/creating the loadscreen panel. These are **additional possible removal** routes for a square retained at input object `+0x464/+0x468`; the handler itself checks the active flag before `AurRemoveDrawableSquare`. They do not imply a square exists at every deactivation or area load. Decoded callsites: `ev_37f61cd440d25e48186b3067b14ecbbb6ef045ee2ca266d8204280e1cfba30d2`, `ev_c265985ccff2a57f58ba484428a8251e923838c90539995191352e8c68c42c08`; caller bodies `ev_a6133e1b0772443e8d488b246df6f0e2d3a70c4c2671791205553a0051ee8686`, `ev_7cb4961b85235572831ee86085ede6a2036d332616dc633a405f6c2e62e30416`.

The mouse-down body further gates `AurAddDrawableSquare` on GUI input, scene, hit-test and modifier state and can remove an old active square before replacing it. The mouse-up body clears its active flag and removes only a retained handle. The established Scene render pass visits the process-global square queue and may submit zero vertices when empty. Thus the connector proves an input-to-render queue path, while its active scene, input mode, hit result, queue count and visible effect remain runtime dependent.
