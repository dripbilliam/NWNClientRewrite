## Authored source and projection lifetime

The text TriMesh parser stores authored `beaming` as integer `MdlNodeTriMesh+0x114`; `shadow` is the distinct `+0x110` flag. `BSPCreateStaticProjections` `0x1400d7f00`, gated by `buildstaticshadows`, gets shadow-capable PartLights and traverses BSP mesh parts. For a candidate mesh whose model node has `+0x110` or `+0x114` set, it requires a qualifying light with radius `>=1000`, checks the mesh/light range through TriMesh virtual `+0x108`, then chooses the beam subtype only when **`MdlNodeTriMesh+0x114 != 0`**. It allocates a `0xb8`-byte `PartProjection`, runs its constructor, overwrites its vtable with `PartBeam::vftable` `0x140d8ff90` at the beam branch, and calls `PartProjection::Init` `0x1400a2b30`. A zero resulting face count `PartBeam+0xac` destroys the temporary object; otherwise `SceneBSPAddPart` inserts it into the fitted node's beam array at payload `+0x50/+0x58`. The alternative `+0x110` branch creates `PartShadow`. Evidence: text parser `ev_8409ed5d3e208577f1c622c827df419f71f703212b27394a18f66bd37ed40107`, projection producer `ev_eff8a632af50e8b7398f18971af5b8e8a003d81f943fa0567e268048664ef013`, constructor `ev_ddc9ff058cd6e4b563a1ef2e36c11df5a5d26517497ee59b77b7a387a21533e3`, [BSP membership](scene-bsp-membership.md).

`PartProjection::Init` copies/derives light direction and mesh bounds, then calls the TriMesh virtual `+0xb8=PartTriMesh::Project` `0x1400a3770`. That shared projector requires source geometry and `GetProjectsShadows`, classifies faces and can return without any emitted face. With a nonnull projection and emitted faces, it lazily obtains a type-1 indexed VDO at projection `+0xa0`, removes the prior item only if its ID `+0xa8` is valid, adds a new item, stores its ID and face count at `+0xa8/+0xac`, writes static projected vertices and element indices, and commits both. This is projection preparation at static build/rebuild, not work shown inside `RenderBeams` each frame. Its shared VDO/pool/GL publication leaves are in [shadows and dynamic geometry](shadows-and-dynamic.md). Evidence: init `ev_5fb6cb2f01dbf3078168732767d96c250c25d67c0ce0dece1f1896bcdb1cae63`, projector `ev_96f7c8a1c7a9b9b2f795a7d4fc47f3e5f131ddefb9a258bb78f04d23f775826d`.

`SceneBSPVisibleCallback` `0x1400dc140` culls each node payload beam at `+0x50/+0x58` with `PartOutside` and appends survivors to `_staticbeambucket`; `Scene::AddPartsToDrawBuckets` `0x1400c38f0` then places each nonnull survivor in DrawBucketManager bucket `0xf`. On `CAurScene::ComputeStaticLighting` rebuild, `RemoveBeams` `0x1400dcde0` drains the BSP beam array and invokes each PartBeam virtual deleting destructor. `PartBeam::vftable` slot zero at `0x140d8ff90` is `0x1400d7350`, which calls `PartProjection::~PartProjection` `0x140089e00`; that destructor removes the valid VDO item before the Part base destructor. This establishes the producer-owned projection and its bounded rebuild teardown. ## Frame admission and GL boundary

`Scene::RenderBeams` `0x1400cceb0` returns unless `enablebeams` is set. It scans Scene's light list `+0x60/+0x68` until the first light with radius `>=1000`, nonzero type `+0x78`, and zero exclusion `+0x84`; it then breaks after processing that light. It normalizes the light vector from `+0xb0`, stages additive/blend/depth state, and lazily obtains `vs_beamvol/fs_beamvol` in global shader cache `0x14140af30`. If the shader is absent it skips bucket traversal. Otherwise it walks bucket `0xf`; each item must pass Part virtual `+0x88=AsPartBeam`, and the returned PartBeam must have nonnull **VDO `+0xa0`**. The older auxiliary summary called this a node pointer; the exact assembly tests `[RAX+0xa0]` after subtype admission. For each admitted beam, it binds the cached custom program, publishes the normalized negative light direction and shader float `-20`, and invokes PartBeam virtual `+0xc8=Draw` `0x1400a22a0`. The static projection VDO is not reconstructed in this loop. Evidence: Scene `ev_78473ae3837a89964d1c467aaa31ad5d31ec9a5dd51c3bf5c45f34eeaa5d6648`, PartBeam draw `ev_df4829008dfbc5e8f689e12769c809244d7951aa2d7f7dc299b4f83d2496011a`.

`PartBeam::Draw` submits its `+0xa0` VDO and item `+0xa8` through `RenderInterface::RenderVertexData` `0x1400beec0` with primitive `4`. Original primitive table `0x140d8ad20` maps index 4 to enum `5` (`GL_TRIANGLE_STRIP`). The type-1 indexed VDO route in `GLRender::RenderVertexData` `0x1400b59b0` uses item element count/offset and the extension draw pointer `glDrawElementsBaseVertex`; a missing usable VDO or shader/Scene gate prevents this leaf. These GL wrapper details are already in [geometry and draw boundary](geometry-and-draw-boundary.md).
