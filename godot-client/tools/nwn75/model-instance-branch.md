# NWN-75: original scene-view model instance branch

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. The GUI creation caller is recorded in `gui-presentation.md`; this file follows `NewCAurObject` `0x1400931f0` into scene resource and Part construction. It is an object-creation branch, not evidence that these calls repeat every frame. Static call order inherits its caller's thread; no separate worker or OS-thread identity is established.

`NewCAurObject` reads a model resource, with an alternate composite-resource branch that parses up to three model names and calls `FindModel` `0x140098cd0`. Its ordinary resource branch calls `LoadModel` `0x1400a0130`. On a model result it constructs a `Gob` `0x1400869d0`, retains the base and optional secondary Models, creates one Part tree per model through `CreateInstanceTreeR` `0x14008dab0`, post-processes each root through Part virtual `+0xd8`, creates reference objects, requests the Gob `_EmitterTarget` event, and recursively initializes materials through `PartInitMaterial` `0x140093850`. It then computes the Gob's minimum bounding box when the model flags request it and always computes its minimum sphere. Original Gob vtable `0x140d88a00` resolves `+0x298=Gob::DoEvent` `0x140050d50`, `+0x2c0=Gob::GetMinimumBoundingBox` `0x14008ea70`, and `+0x2c8=Gob::GetMinimumSphere` `0x14008ee60`; base Part vtable `0x140d87f08` has `+0xd8=Part::PostProcess` `0x140093aa0`, while skin Part vtable `0x140d88438` overrides it with `PartSkin::PostProcess` `0x1400df860`. Evidence: REA `ev_f456a590`, `ev_45309f16`, `ev_86cdb10` and original PE vtable bytes.

`LoadModel` temporarily clears `currentmodel`, calls `IODispatcher::ReadSync(_iobuf*)` `0x140079e40`, converts the parsed `MaxTree` to a Model, then returns an existing same-name Model if one is already in the global table; the duplicate parse is destroyed. The `_iobuf*` read route calls `AurResGet`, detects text versus binary resource data, interprets nonblank noncomment lines through `FuncInterp` in the text case, or uses the binary parser `FUN_140079d50` in the binary case. `FindModel` first binary-searches the Model table, and on a miss calls `IODispatcher::ReadSync(char const*)` `0x140079f70` with a temporary whitelist. That overload forwards to `FUN_140079a80`, which obtains a named `.mdl` resource: a binary header calls the same parser, while text data is passed to `dofile` with a composed model name; then it restores `currentmodel`. `AurResGet(_iobuf*)` `0x14005da80` wraps an already-open stream, using CRT seek/tell to size it. Named `AurResGet` `0x14005dbc0` first calls an installed `AurGetResource` callback when present; if that returns null and the caller permits fallback, it composes a local path and calls `FUN_140c4fb20` → `common_fsopen<char>` for a CRT file stream. The callback and CRT filesystem tail do not imply GL work. Evidence: REA `ev_a5bead04`, `ev_fa504c1b`, `ev_d424beed`, `ev_110b2ffe`, `ev_bea68fec`, `ev_db49c028`, `ev_4b5c726e`, `ev_24fad0bb`.

The installed callback is now identified: `CAuroraInterface::CAuroraInterface` `0x1400f4cf0` stores `0x1400f63d0=CAuroraInterface::GetResource` into global `AurGetResource` `0x1412e0c10`; original instruction bytes at `0x1400f4cf6/0x1400f4d00` and named `AurResGet` load at `0x14005dc13` prove the edge (REA `ev_293a404c`, `ev_4b5c726e`). For a model extension, the callback's model branch calls `CAuroraModel::LoadModel` `0x1400f4a70`, which demands a `CResMDL` through `CRes::Demand` `0x14018f300` → `CExoResMan::Demand` `0x14018ef90` and returns its data pointer/size (REA `ev_e194b570`, `ev_ce5f03ec`, `ev_afe77ed9`). `CExoResMan::Demand` dispatches by resource storage class: 1 to `ServiceFromResFile` `0x140193b80`, 2 to `ServiceFromEncapsulated` `0x140192cf0`, 3 to `ServiceFromDirectory` `0x140191e80`, and 5 to `ServiceFromManifest` `0x140193520`; otherwise it may reuse resident data. The storage-class read and OS file boundaries are traced in `model-resource-storage.md`; compressed provider and manifest database descendants remain open (REA `ev_5d7c92d5`). The callback also branches to texture/shader/TXI/MTR resources for other extensions; those are separate material/shader descendants.

On its composite-resource branch, `NewCAurObject` releases the temporary `CRes`, then conditionally invokes its virtual slot 0 with a delete flag. `CRes::CRes` `0x14018d920` installs vtable `0x140da2640`, whose original first pointer is `0x14018e180`; that function logs a still-demanded resource, unlinks its resource-manager node when flagged, and releases the object. The computed callsite is `0x1400935b8` (REA `ev_0d398f88`, `ev_04ac7f63`). This is a resource-lifetime branch, not GL work.

`CreateInstanceTreeR` calls the node's function-pointer field `+0x28` to create a typed Part and `+0x18` to apply its initial control state. It stores the Gob owner, sizes the child array, recursively creates children in original array order, sets each parent pointer and copies the node's render flags to Part `+0x30` (REA `ev_25a7501b`). These are instance fields initialized by MdlNode constructors, not vtable slots. The base constructor `MdlNode::MdlNode` `0x140087290` assigns `MdlNodeCreateInstance` `0x1400926d0` and `MdlNodeControl` `0x1400926c0`; subclass constructors assign these creation targets: AABB `0x140092250`, AnimMesh `0x140092440`, Camera `0x1400925d0`, DanglyMesh `0x140092760`, Emitter `0x1400929a0`, Light `0x140092b10`, Reference `0x140092e40`, Skin `0x140093000`, TriMesh `0x1400930f0`, Trigger `0x1400f08f0`. Constructor REA: `ev_8a036846`, `ev_4565c767`, `ev_a9e0ea73`, `ev_6bac58a7`, `ev_3e6c2eca`, `ev_411440c5`, `ev_09704729`, `ev_ae47c019`, `ev_60687c60`, `ev_f493d499`, `ev_3f2d712b`. The two computed callsites in `CreateInstanceTreeR` therefore have a bounded family of targets; the exact authored node type selects a member. The creation functions construct typed Parts or return null for a Trigger, with the emitter function further selecting Fountain/Explosion/Lightning and other emitter types from the authored update string. The eight distinct `+0x18` Control targets are five-byte jump thunks to subtype InternalControl functions; their interpolation and conditional AnimMesh buffer-publication descendants are mapped in `animation-and-emitter.md`.

`PartInitMaterial` starts with Part `+0x58=AsPartTriMesh`; if nonnull it loads material textures, then tests Part `+0xa0=AsPartSkin`, `+0x60=AsPartAnimMesh`, `+0x98=AsPartDanglyMesh`, and `+0x90=AsPartAABB` in that order. It allocates a `VertexPrimitiveSkinned`, `Anim`, `Dangly`, `AABB`-vtable Flat, or plain Flat primitive and stores it at TriMesh `+0x90`, then recurses over Part children (REA `ev_beef504a`). Base Part vtable `0x140d87f08` returns null at those type-test slots. Constructor-backed TriMesh `0x140d88308`, Skin `0x140d88438`, and AnimMesh `0x140d88568` vtable bytes confirm their appropriate overrides. The texture-load and primitive initialization descendants lead to the separate resource/pool/API paths in `geometry-and-draw-boundary.md`; their exact creation-time leaves remain open here.

`Material::LoadTextures` `0x140084410` uses Part virtual `+0x58=AsPartTriMesh` and `+0x68=AsPartEmitter`; a mesh supplies its MdlNode material/texture names and an emitter supplies its own authored texture name, then `Material::InitializeTextures` `0x140083c90` runs (REA `ev_3e2e50ca`). The latter optionally obtains a `SharedMaterial` and copies parameters, resolves each of three standard texture names to a null texture or `AurTextureGetReference` `0x1400e8b60`, resolves extra bump/environment slots similarly, and registers `SafePointer` links. It does not upload GL texture data in this body (REA `ev_e099f8f1`). Later material binding through `CAurTexture::BindInUnit` reaches texture bind and lazy resource publication as mapped in `geometry-and-draw-boundary.md`.

`Part::PostProcess` recursively invokes each child Part's `+0xd8` slot. The Skin override `PartSkin::PostProcess` `0x1400df860` returns early without skin geometry data; otherwise it may reset the owner Gob, gathers bones, rebuilds the model mesh's vertex indices/neighbors and generated vertex data, and allocates/fills skin pools through `RenderInterface::RequestPool`, `LockPool`, and `UnlockPool`. The latter reaches the mapped GL buffer allocation/upload branch (`glGenBuffers`, `glBufferData`, `glBufferSubData`) in `geometry-and-draw-boundary.md`. Its four computed sites `0x1400dfbec/0x1400dfc5c/0x1400dfccc/0x1400dfd3c` iterate a list built by `MakeInlinePartList` and call each Part's virtual `+0x8=Part::Name` `0x140062450` while matching bone names. The final two sites read the skin MdlNode's instance fields: `0x1400dfdff` calls `+0xa0=MdlNodeSkinGenVertices` `0x140093050` → `MdlNodeSkin::InternalGenVertices` `0x1400df200`; `0x1400e0360` calls `+0xa8=MdlNodeSkinRemoveTemporaryArrays` `0x140093080` → `MdlNodeSkin::InternalRemoveTemporaryArrays` `0x1400a9f30`. `MdlNodeSkin::MdlNodeSkin` `0x140087790` installs both pointers at `0x140087832/0x140087840`. The internal functions generate/deduplicate weighted skin vertices and release temporary post-process arrays; neither body makes a GL call. All six computed targets are now identified (REA `ev_3547b374`, `ev_1bed5127`, `ev_44dbec2a`, `ev_812215a1`, `ev_2f2eaff1`, `ev_d6322143`).
