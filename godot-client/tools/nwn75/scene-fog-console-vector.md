# NWN-75: Scene fog-color console vector route

Scope: installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This closes one named, conditional producer of Scene fog color. It does not establish that any live frame executes a fog command or identify the still-open caller of `Scene::SetFogColor`.

`Scene::Scene` `0x1400c0ca0` initializes Scene `+0x14c..+0x154` to `(1,1,1)`. For a nonempty Scene name, it constructs the name `<scene>.fogcolor` and, after a successful 0x58-byte allocation, calls the `Vector*` overload `ConsoleFunc::ConsoleFunc` `0x14005d3c0` at `0x1400c116e` with `Scene+0x14c` at `0x1400c1161`. The overload copies the command name, allocates a 0x10-byte `funcholder<Vector*>`, stores that exact Scene vector pointer at holder `+8`, installs vtable `0x140d83e98`, stores the holder at `ConsoleFunc+0x50`, then calls `ConsoleFuncs_Add` `0x14005e2e0` at `0x14005d418`. The latter inserts the object into the process-global `ConsoleFuncs` name-ordered list. The allocation and nonempty-name gates matter; the constructor route does not itself set a nondefault color. Evidence: Scene constructor `ev_9bd85911eebb0eb0c68866794c5c484152b6059e0e8e29e18ffda6e3851cf60b`; overload `ev_9c0f9898ef6834938ef293f7b23637e32c6d8d07f721044737a4b88fbd61264c`; registry `ev_13df428cadda1e3289c912f978aac73996217540fac6228b26aa2b1556eddc13`.

`FuncInterp` `0x14005ebf0` trims and parses a command name and argument string. Subject to its optional whitelist, it calls `FindConCallBack` `0x14005eb10` at `0x14005f589`; the lookup compares the exact registered name (checking a cached index first, then scanning) and returns `ConsoleFunc+0x50` when found. `FuncInterp` trims trailing argument whitespace and invokes holder virtual `+8` at `0x14005f68c`. Original table bytes `0x140d83e98..0x140d83eaf` resolve this slot to `funcholder<Vector*>::Engage` `0x14005ea80` and `+0x10` to `PreEngage` `0x14005fd90`. `Engage` calls `sscanf(argument, "%f %f %f", vector, vector+4, vector+8)` at `0x14005eaae`, writing directly into the registered Scene color floats; it then formats the current three floats into the global return buffer with `sprintf` at `0x14005eaec`. It does not test `sscanf`'s conversion count, so a partial numeric command can change only its successfully parsed leading components. `PreEngage` formats the existing floats and does not write them. Evidence: interpreter `ev_4c8c9ea5dfefb1eb4e86efb8909542d085de1ed7f1f7dbb589eaef8f3bfecc3a`, lookup `ev_e68621f446c5da69ccc0c66aedbbdb0bf03b790cbb8a3485886539e96c748151`, table bytes `ev_9dcbc42fc171438159ba18cbca201e59ce98b71c7eef59a627dc4e9931187761`, Engage `ev_f459dc19999caf23c8d9c3134bbf2bc8b401958a980144ae4a18e7b64547c0a9`, PreEngage `ev_896a65b4f01aa9cac4fec1d2306b61ce9ef0892d10aaa27996e0880be84276a5`.

`Scene::DoFog` `0x1400c7f10` reads enable flag `+0x140`. When enabled and `LightManager::m_pOnlyGob` is null, it passes Scene `+0x14c` to `RenderInterface::SetFogModev(2, ...)` at `0x1400c7f5a`, followed by range floats `+0x144/+0x148` to `SetFogModef` at `0x1400c7f69/0x1400c7f80`. With an only-Gob target, it submits a local zero color instead; when fog is disabled, it calls `RenderInterface::Disable(2)` and does not consume the color. These state wrappers join the already mapped GL/render-state route. Evidence: `ev_afa6d6d91d704cbe6e5053d04c4408e0323fc599f289ef86b4557d7521ce93b9`, [fog state source](scene-fog-state-source.md).

**Separate paths:** the registered console holder writes `Scene+0x14c` directly. It does not call `Scene::SetFogColor` `0x1400d3340`; that setter is an independent virtual writer of the same fields. No caller of the setter was proven by this console route. Command execution, active Scene name, whitelist result, parsed values, fog enable, only-Gob mode and actual GL publication remain runtime conditions. Scene/console unregister on destruction is covered by [Scene lifecycle](scene-lifecycle-area-entry.md); this note adds no new ownership claim there.
