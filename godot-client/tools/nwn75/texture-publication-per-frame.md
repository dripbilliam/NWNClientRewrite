# NWN-75: original frame-entry texture publication

## Texture GL leaves

The two named constructor-backed texture classes in the analyzed program are `CAurTexture` (wrapper/reference vtable `0x140d90c70`) and `CAurTextureBasic` (vtable `0x140d90d90`). Their pinned vtable pointer values match at every texture getter slot used by `GLRender::CreateTexture`/`CreateCubeTexture` from `+0x60` through `+0xd0`; across the first `0x110` bytes, only destructor `+0x0`, Basic type test `+0x8`, and image free `+0xf0` differ. This closes the getter target difference between these two known classes, while retaining the possibility of unidentified texture object types. REA vtable bytes base `ev_acec412ca9d834c715dfb020fe3ee6674f7dd0d27b18a5356e050cbdc1545aaf`, Basic `ev_4454508da695161022160c7906d35778b05bbff81821a0b1bf7687b8e00632a4`.

The ordinary `glImageBasic` branch calls `RenderInterface::CreateTexture` `0x1400be960` → `GLRender::CreateTexture` `0x1400af440`, or `CreateCubeTexture` `0x1400be930` → `GLRender::CreateCubeTexture` `0x1400aeff0`. The 2D path derives tile/subimage data, sets texture parameters, selects compressed or uncompressed formats and either updates an existing image through `glTexSubImage2D` or defines one through `glTexImage2D`; compressed cases call `glCompressedTexImage2D` through extension cell `0x141442168`, and optional mip generation calls `glGenerateMipmap` through `0x1414432b0`. The [DDS/KTX resource continuation](texture-compressed-resource-publication.md) now traces compressed selection, header fields and release feeding this branch. The cube path can rotate a face image, updates or defines each face through the same two imported GL calls, and has optional active-unit/mipmap extension calls. The original Basic texture getter and extension callsites are exhaustively listed for that candidate in [2D indirect callsites](texture-create-indirect-callsites.json) and [cube indirect callsites](texture-cube-indirect-callsites.json); the two RTTI-backed primary texture vtables and their getter-slot equality are bounded in [the class census](texture-rtti-primary-vtables.md); RTTI-stripped or external overrides remain open. REA 2D `ev_d9f20d82577fc92e61ef6ad0953e8fc3979e31caed21e08b158755528c9a1572`, cube `ev_7bdb766b9546fae47a5860acf2d70ca4c77defb967fb7ad429a2256499ae09c8`, wrappers `ev_6f517ac932bbff998901cd5c4a411310fb353b5117dfeeb40718a361bb26e34d` / `ev_bdbc6d4acfc5cf516ed38f0a046931be62177166b892db3596db1d5524050ba8`.

The palette FBO branch's `RenderInterface::DirectCreateTexture` `0x1400be9d0` forwards to `GLRender::DirectCreateTexture` `0x1400b0150`, which conditionally sets unpack alignment and mip-level parameters, selects format/type, and calls imported `glTexImage2D`; it restores alignment when altered. The 2D/cube `GLRender::SetTextureParameters` `0x1400b8100` path writes `glTexParameteri` and queries `glGetFloatv` for anisotropy state under its parameter gates. REA direct-create `ev_3ebec5fb5b7ea67d757507906ef7b2b59a9479c1b10a838750fcc406dcadf529`, wrapper `ev_01fe5e85fa31c00da7f0879d16971be710cb1075c2efe31b9bfed824af7c4680`, parameters `ev_06bcbaf87bdd2b2afc20f49672a4671991ad73946f7daa2451b04d20eb62fa01`. These are conditional GL upload and parameter leaves, not an ordinary geometry bucket draw.

Pinned `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This is the texture work reachable from `Scene::Render` → `AurTextureMakeCurrent` and from a material-time texture controller. It is a static branch map; no claim is made that every frame builds or uploads an image. The texture acquisition and controller producers are in [texture acquisition](texture-acquisition.md) and [texture controller runtime](texture-controller-runtime.md).

With unchanged anisotropy and nonempty pending refresh count, `AurTextureMakeCurrent` calls `AurTextureBuildAndStoreAll` `0x1400e6910`. The latter iterates `_RefreshTextures`, calls `CAurTextureBasic::BuildAndStoreTexture` at `0x1400e6d2a` only for entries whose `+0xeb` flag is clear, then resets pending count. It sorts `_m_StaticTextureList` at `0x1400e6d5d` and rebuilds texture ordering/TID arrays from eligible entries. Thus the sort/list rebuilding is gated by pending texture work; the body is not an unconditional per-frame full-texture walk. REA `ev_b2dd32c23ecb4cd1e301b41e4f7d16c1eb5a117230364ec7d34e91aa814e23d4`. The comparison itself is the original alpha-mean comparator `0x1400ef1a0`, documented as a CPU leaf in [bucket classification](bucket-classification.md).

`BuildAndStoreTexture` `0x1400ea5e0` enters only when its `+0xe8` built flag is clear. It calls `ConstructImage` at `0x1400eaab7` when image-construction flag `+0xe6` is clear. With image bytes present, Basic virtual `+0xe8` at `0x1400eaace` calls `CAurTexture::glImage` `0x1400ee130` → `CAurTextureBasic::glImageBasic` `0x1400ee1b0`. If alpha mean remains unspecified, it computes `ImageGetAlphaMean` at `0x1400eab13` for the eligible uncompressed image mode, otherwise uses format-specific fixed values. Basic `+0x38` is the optional texture controller installed by `.txi` parsing; image mode `+0x70==0` calls its virtual `+0x10=Init` at `0x1400eab2f`, now resolved through six constructor-backed targets in [controller build initialization](texture-controller-build-init.md). Basic virtual `+0xf0` at `0x1400eab38` resolves to `CAurTextureBasic::FreeImage` `0x1400eb640`, which releases CPU image data according to ownership. REA `ev_3da65d17a98f227ececaf4b457322e76a4829c312b383a4a4d88ed612c3cda32`.

`glImageBasic` has two major publication routes. For ordinary 2D/cube image handling (`g_bGeneratePLTOnGPU==0` or image kind `+0x84!=4`), it conditionally generates texture IDs, sets the active unit and calls `RenderInterface::CreateTexture` at `0x1400eecdd` or `CreateCubeTexture` at `0x1400eecd6` per tile/face. Their GLRender descendants reach `glTexImage2D` or `glTexSubImage2D`, plus format/parameter and optional mipmap calls, as address-backed in [GUI presentation](gui-presentation.md). For GPU palette generation on kind 4 with a palette source, it lazily constructs a `masterPalette` Basic texture and invokes its virtual `+0xe8=glImage` at `0x1400ee821`. It then creates/binds palette and output textures, lazily builds a shared quad VDO/FBO and `vs_pltgen`/`fs_pltgen` shader, attaches the output, and calls `RenderInterface::RenderVertexData` at `0x1400eeb87` to draw the conversion quad. It restores framebuffer/viewport/state and optionally generates mipmaps. The recursive master-palette image call is a one-time cache branch, not proof of unbounded recursion. Full `glImageBasic` REA `ev_73403af00633745774d0de4928fa5a3d9f11a946ea304aa7116e71c1641307cd`; original Basic vtable target evidence is in [texture acquisition](texture-acquisition.md).

On changed anisotropy, `AurTextureRefreshAll` `0x1400e8eb0` instead prepares the refresh list, invokes `AurInitFont`, conditionally deletes existing GL texture IDs at `0x1400e903e`, and then calls `AurTextureBuildAndStoreAll` at `0x1400e90b3`. This can cause broad asset publication, but it is an anisotropy-change branch. REA `ev_6173744b1f63288237b594c7cdb92994d9083ed252515f5978303e559a9030ff`.

`ConstructImage` `0x1400eac60` calls `LoadImageA` at `0x1400eb163` or `0x1400eb2af`. The latter checks a single image name or indexed multi-image names with `AurGetImageWrapper`, falling back to `LoadFromTTF` for a missing single image. The wrapper tries compressed image, 16-bit image and raster callbacks in order, with format fields set from the successful representation. Its initial 16-bit/raster callbacks are file-backed `ImageRead16bit`/`ImageRead`; `CAuroraInterface` later installs resource-backed `Get16BitRaster`/`GetRaster` plus `GetCompressedRaster`. Those targets and resource demand paths are mapped in [GUI presentation](gui-presentation.md). `ConstructImage` also has a layered/palette route when Basic `+0x48` is present and the initial image is unavailable or ineligible. Call at `0x1400eb1d5` uses cell `AurGetLayeredRaster` `0x14128edf0`: the shipped pointer is `ImageReadPLT` `0x140073770`, while `CAuroraInterface` installs `GetLayeredRaster` `0x1400f5d80` at `0x1400f4d41`. The latter caches/loads a `CAuroraLayeredTexture`; `LoadTexture` `0x1400f4440` calls `CRes::Demand`, obtains PLT attributes/data and releases the resource. If GPU PLT generation is disabled, `ConstructImage` calls `ImageDecode` at `0x1400eb261` to expand 16-bit palette indices into 4-byte pixels; `ImageDecode` increments `g_nImagesDecoded`, allocates a destination and expands pixels on the CPU. An installed `AurReleaseLayeredRaster` cell `0x14140b270` points to `CAuroraInterface::ReleaseLayeredRaster` `0x1400f71a0` and releases the source when owned. Later optional `ImageFillAlpha` changes four-byte raster pixels in place for low-end environment map mode. `ImageGammaCorrect` affects an existing raster only when gamma is neither zero nor one.
