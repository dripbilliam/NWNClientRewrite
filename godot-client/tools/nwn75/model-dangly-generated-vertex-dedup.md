The [ledger](model-dangly-generated-vertex-dedup-ledger.json) expands the [DanglyMesh model payload](model-dangly-payload.md) at its installed `+0xa0` generator, `MdlNodeDanglyMesh::InternalGenVertices` `0x1400a89b0` (REA `ev_bfbe9afc0421e74683c87f72d3e5df23950f2e1f767a9a93a7fcc46657f4d0c5`). This is CPU model postprocessing before the shared vertex-stream pools and the later [dynamic animation](dangly-animation-dynamic-publication.md).

For every postprocess face and its three corners, the function selects indexed position, normal, optional UV/color/tangent and mirror inputs, plus one original float constraint from node `+0x2c8` using the corner's source vertex index. It allocates a `0x70`-byte `NodeVertexDangly` candidate and calls its constructor `0x1400aad90` at `0x1400a8b92`. The constructor calls base `NodeVertex::NodeVertex` and stores the constraint at `+0x6c`, marking subtype 2 at `+0x68` (REA `ev_49d273e9b486f172598edcaecfb212b19e013dd3e965c13737006e78fc83dcca`).

Each candidate scans all earlier generated vertices in postprocess `+0x90/+0x98`. `NodeVertex::AsNodeVertexDangly` `0x1400ab9e0` at `0x1400a8bbe` checks subtype 2 (REA `ev_794929c1c079d8acd042e5395306def58fa6b2021211d8a38c72e460a23c19de`). `NodeVertexDangly::operator==` `0x1400ab660` at `0x1400a8bc9` invokes base `NodeVertex::operator==` `0x1400ab270` at `0x1400ab70f`, then requires exact float equality of the constraint `+0x6c` (REA derived comparator `ev_499e75aab740e28461cd9e5ac115da9afe30aeb924b9e9c9e38740e40d90cb9f`, base comparator `ev_44c76004558ff07dea1e4705530f6b4a03d5bfb661897019aca9a49e78c4cee5`). A match frees the candidate and writes the prior 16-bit generated index to the face. A miss appends the candidate and writes a new index, while appending its constraint to a temporary unique-vertex float list. After all corners, the list replaces the node's `+0x2c8/+0x2d0` constraints. The later animation reads those remapped constraints by generated vertex index.

This is a linear prior-vertex scan per face corner with an exact constraint-sensitive equality condition. Face count, candidate attributes, duplicate rate, malformed indices, allocation failures, 16-bit overflow and later GL admission remain data-dependent. The static generator establishes no worker handoff or runtime cost.
