Installed `nwmain.exe`, SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`; image virtual addresses. ## TTF and installed resource demand

`CAuroraTTFTexture::Load` `0x1400fb720` demands its `CResTTF` helper's resource through `CRes::Demand` `0x14018f300`. A null result clears output atlas data and exits. With data, it allocates the atlas bitmap and packed-character arrays, calls `stbrp_init_target` `0x1401032c0` and `stbtt_PackFontRanges` `0x140106ac0` using the demanded resource buffer, then computes per-glyph positions/UVs and enhances the bitmap. The helper destructor `0x1400fb2e0` calls `CRes::Release` `0x1401912c0`, then destroys its `CResHelper<CResTTF,2074>`. This is conditional CPU atlas construction upstream of the already mapped GL texture publication. REA `ev_e91cc23e0b8c331e8cccba7beab6c6c53e6f73124c061e4f499bbb5d989dc682`, `ev_a851f1afcaa258f5895e8b9d15a32acff506d38827d3200be9bc8c66731c2054`.

The previously unexpanded enhancement step is a concrete CPU leaf. With demanded TTF bytes, `Load` loops over its nonzero packed bitmap pixel count and calls `CAuroraTTFTexture::EnhanceCharacter` `0x1400fb490` at `0x1400fbfed` for each pixel. That function reads the current byte plus bounded neighboring atlas bytes, applies contrast/outline/alpha arithmetic, and returns color and alpha bytes; `Load` writes four output bytes per pixel to its RGBA atlas. `EnhanceCharacter` has no callees or GL API calls. The loop is conditional on successful `CRes::Demand` and a nonzero bitmap count, and its cost belongs to atlas creation rather than every text draw. REA `ev_46d96eae50d0073f49fb50ed48622e2d95d9fc077ab9b0d6b43082555d36fe74`, `ev_46879af4b2f2fe81677a3ba35d3797859fd22c13c58e2c4524562d155da78653`.

## Initial file-backed raster callback

Before the Aurora interface replaces the initial callback pointer, `AurGetRaster` can point to `ImageRead` `0x140072eb0`. Given a nonempty filename, it attempts the supplied name, then `<name>.tga` through the CRT open path. A successful open calls `ImageReadTGAHeader` `0x140073f50`, which reads 18 bytes and extracts width, height and bytes per pixel; `ImageReadTGAImage` `0x140073fc0` allocates `width*height*components` bytes and calls `fread`. After `fclose`, `ImageFlipRB` `0x140071990` swaps red/blue channels when components exceed two. If opening the TGA path fails, it tries `<name>.jpg` via `ImageReadJPG` `0x140228f50`; on success, `ImageFlipY` `0x1400719e0` allocates a temporary full-image buffer, reverses rows, copies back and frees the temporary buffer. REA `ev_32924882e3d890833dc71949c122dfc1643d975d0dccf55ffef24c6c22ba2027`, `ev_eb7befb26699b6677fb8f57c9bbd5267257275d3d3ef314f614db59450842c86`, `ev_57df4276865efaedf2f4256254afacded3da3b4264b451013f89087776a61058`, `ev_9ec04dcb87d5b9ce0df90aacaca36306cf6db5a6320b01c4be193dca5f11b718`, `ev_67c0dad2f339ffe27c2a5b29c24748d2c38c8b971c3a488e8abace93641ebbe7`.

`ImageReadJPG` opens the JPEG file with the same CRT helper, installs `my_error_exit`, then on the normal decode path calls bundled `jpeg_CreateDecompress`, `jpeg_stdio_src`, `jpeg_read_header`, `jpeg_start_decompress`, allocates `width*height*components` output bytes, reads scanlines with `jpeg_read_scanlines`, finishes/destroys the decompressor and closes the file. A decoder error destroys/closes and returns null. This closes the immediate JPEG decoder and CRT/Win32 file API boundary; libjpeg's internal marker/Huffman/color conversion descendants are not yet followed.
