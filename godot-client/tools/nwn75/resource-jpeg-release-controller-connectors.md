# Resource and JPEG controller source connectors

Pinned original `nwmain.exe` SHA256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. These edges close three disconnected source nodes in the [resource/JPEG connector ledger](resource-jpeg-release-controller-connectors-ledger.json). They establish static ownership and conditional reachability; they do not establish live asset choice or call frequency.

## 4PC release callback `0x1400f9a00`

The already mapped `CRes4PC` constructor `0x1400f98a0` installs vtable `0x140d92a40`. Original table bytes at `+0x18` contain pointer `0x1400f9a00` (`ev_60e2e7034c18f954b524fe29fe36151e7a6c51fdb699efc592dfdf8809c39764`). `CExoResMan::Free` `0x14018f630` dispatches `CALL [vtable+0x18]` at `0x14018f708` after a loaded resource passes its free gates (`ev_e855bbc5195799660c26ee82ec5743835fe1b3c6bfcd023d791ecf0de96f82f5`, `ev_071cbef5733972ee84a8f8d881163ddeb73743fc88a20d4f29417f5e1f730b22`). For a constructed 4PC object, this selects `OnResourceFreed`, which clears its three data/header pointers. The generic free site also serves other resource subtypes, and `CRes::Release` can defer free by adding a resource to the release list. No immediate release is implied by a wrapper unload.
