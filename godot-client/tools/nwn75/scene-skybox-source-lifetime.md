# NWN-75: skybox Gob source, Scene admission and lifetime

Scope: installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This closes the indexed-Gob producer and teardown feeding [Scene skybox drawing](scene-no-bsp-sky-gob.md). It records original binary control flow, not a measured frame cost. Resource-provider internals, packet dispatch outside the skybox case, and the already mapped Gob draw/GL leaves are outside this branch.

## Source and admission

`CNWCArea::LoadSkyBox` is the stripped function at `0x1407e1930`, identified by its `LoadSkyBox` log location and skybox strings. It runs only when the area skybox ID byte at `+0xe0` is nonzero. It constructs/loads `SkyBoxes.2da`, finds the `DAWN` column, and for the selected ID row checks four consecutive columns. Each successful string entry is passed as a model name to `NewCAurObject` `0x1400931f0`, with names `skybox0` through `skybox3`. The returned Gob pointers occupy area `+0x398`, `+0x3a0`, `+0x3a8`, `+0x3b0`; a failed or absent entry leaves its slot null. `NewCAurObject` resolves the Model, allocates a Gob, creates its Part trees and initializes their materials. If the first area slot is null after the loop, the loader clears area `+0xe0` and logs an error. This establishes the authored model names and concrete Gob producer without assuming all four entries exist. Evidence: loader `ev_3b0517d76ee75548e759ecb7b75a6b332fea5fe23b2174f1104c08788035dff4`; object constructor `ev_f456a590b87bf33093742cf8df2e8e3f9803908ba96690c150afdc9f60a001f5`.

With a nonnull first sky Gob, the loader additionally creates `NewCAurObject("skyfade1", "skyfade", nullptr)` at area `+0x3b8`. If area Scene pointer `+0x248` is nonnull, it passes the four sky Gob pointers through Scene virtual `+0x150=Scene::SetSkyBox` `0x1400d3d70`, the fade Gob through `+0x160=Scene::SetSkyFade` `0x1400d3dc0`, then passes area `+0x3c4` float and `+0x3c1` index through `+0x158=Scene::SetSkyAlpha` `0x1400d3d40`. Original Scene vtable `0x140d8dd30` has those three targets at `0x140d8de80`, `0x140d8de90`, `0x140d8de88`, respectively. `SetSkyBox` stores the four pointers at Scene `+0x18..+0x30`, marks each nonnull object byte `+0x18`, enables sky drawing at Scene `+0x4c=0` and clears blend fraction `+0x40`; `SetSkyFade` stores the separate pointer at Scene `+0x38` and marks its byte `+0x19`. `SetSkyAlpha` keeps current index `+0x44`, next index `+0x48`, and blend fraction `+0x40`: for a changed target it clamps negative alpha to zero, promotes the next index to current at alpha at least one, otherwise retains it as next. The exact producer of the area alpha/index fields outside this loader is not established here. Evidence: loader above, Scene setters `ev_882d77d02a4a5c04287bc17a5cdd2d906ae5e15f301cf144d234d3ecb5455a26`, `ev_7547898f05cf148a9b9c81445544bc1f61b8b612960f6f0a9253a45d933d468f`, `ev_191c764d80fdc11920673a6989cebc2dafe686b6235a734049dd5288c8d6595d`, vtable bytes read `0x140d8de80..0x140d8deaf`.

`Scene::Scene` `0x1400c0ca0` initializes all four indexed slots and fade pointer to null, current/next indexes to `-1`, blend fraction to zero and sky-off byte to one. Later `Scene::RenderSkyBoxes` `0x1400d28f0` first tests the sky-off byte, then uses the current/next indexes to select pointers from the fixed four-slot Scene array; it renders the fade Gob separately when nonnull. Its position/alpha state and Gob/Part/GL descendants are documented in the existing sky draw note. Evidence: Scene constructor `ev_9bd85911eebb0eb0c68866794c5c484152b6059e0e8e29e18ffda6e3851cf60b`, renderer `ev_42236e463657ac2dd1aef1287e8e8de03b857bdb5414f7a07564b69ebc321374`.

## Replacement and teardown

The skybox packet branch in `0x14076d910` (case `7`) reads a new skybox ID, obtains current client area and checks its identity at area `+0x118`. When skyboxes are enabled, it calls unload `0x1407e7d00` at `0x14076e861`, writes the new ID to area `+0xe0`, and calls loader `0x1407e1930` at `0x14076e878`. This is a bounded producer edge; packet routing and the server-side sender are not traced here. A separate skybox-enable callback `0x1406f5300` also calls loader or unload based on its flag. The large initial area load `0x1407dba70` calls loader at `0x1407de4a4` when the application skybox setting is enabled. Evidence: packet retained pseudocode `ev_1c2b055d5f6d0625b26aae8d99d65ccc6dd62f141dda8d5c5d2be4fe437811a9`, enable callback `ev_720ff2b1b3dd5e058fa75f80ef8921d1e198a19ef0bdba4d0c3c0e103159ef49`, initial load retained pseudocode `ev_f95eaa0a0bafbeb7b15f37558791794c8c2a1933dffefee3b9c58131537cf941`.

Unload `0x1407e7d00` invokes Scene virtual `+0x178=Scene::ClearSkyBox` `0x1400c5b50` only when area loaded flag `+0x3c8` and skybox ID `+0xe0` are nonzero. The Scene method sets blend fraction to zero and sky-off byte to one; it does not free or clear the stored Scene pointers. Unload then calls each nonnull Gob's virtual destructor (argument `1`) for the fade pointer and four indexed area pointers, nulls their area slots, and clears loaded flag `+0x3c8`. Thus Scene is quiesced before area-owned Gobs are destroyed on that guarded path. If that guard is false, the available code still destroys area pointers but does not call `ClearSkyBox`; no broader safety claim is made. `Scene::~Scene` does not itself destroy the sky slots in its complete analyzed body. Evidence: unload `ev_8180c42d7fd4ebc240749fec2cba9c8fbf61d78b3389c268e71f83238a723801`, clear method `ev_0e2cfe5dd14c227b9ab7ac6816cb21e8e778dfa4e370b3c7f089c72a15031a60`, Scene destructor `ev_9e802bd7b0e6aca27fe4d398c3eccb7dfe399651ab19baeeac749b7e2a851c2a`.

The selected model assets, index/blend updates during live play, and actual Part subtype mix are dynamic. This closure proves the fixed four-slot producer, Scene alias and teardown gates; it does not assign a per-frame cost or claim a particular sky Gob was drawn in a captured frame.
