# NWN-75: original dynamic geometry and shadow branches

Original binary `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are original PE virtual addresses. This is a partial branch map; callee descendants not described below remain open in `branch-ledger.json`.

## Dynamic geometry

`Scene::RenderDynamicGeometry` `0x1400ce110` (REA `ev_284c28b5`) is called from `RenderSinglePass` through Scene virtual slot `+0x220`. It sets stencil state when `enableshadows != 0`; when full dynamic lighting is disabled, its computed call at `0x1400ce266` goes to `LightManager::EnableLights` `0x14007e890` through the LightManager `+0x10` vtable slot. It then always draws bucket `2` with blend/alpha disabled and bucket `3` with them enabled through `Scene::RenderDrawBucket` `0x1400cd210`. It restores stencil and scene fog state afterward. Bucket draw reaches the Part dispatch and graphics API boundary documented in `geometry-and-draw-boundary.md`.

## Shadow pass selection

`Scene::RenderShadows(int,bool)` `0x1400d0ab0` (REA `ev_13a6ac6c`) is called twice from `RenderSinglePass` only when `enableshadows != 0`: `(this,0,1)` for dynamic lights and `(this)` for static/default argument. It sets stencil/depth/color masks; the boolean clears stencil to `0x7f` when true. For mode 0, it iterates Scene dynamic shadow lights at offsets `+0x70/+0x78` in reverse order. Per light, it calls Scene virtual `+0x1c0` when `shadowdynamicgeom`, Scene virtual `+0x1d8` when `shadowstaticgeom`, then `Scene::RenderDynamicShadows`. For lights with distance at most 1000 it calls `Scene::RenderShadowPlanes` and clears stencil before the next light. The other mode may call Scene virtual `+0x1c8` for static shadows, `RenderShadowPlanes` for a present static light and optionally repeats volume geometry under `g_nRenderShadowVolumes`. It restores masks and enabled states.

Original `Scene::vftable` `0x140d8dd30` slots resolve `+0x1c0` to `Scene::DoGobShadows` `0x1400c7f90`, `+0x1c8` to `Scene::RenderStaticShadows` `0x1400d2ca0`, and `+0x1d8` to `Scene::DoDynamicMeshProjections` `0x1400c7910`. Each is a computed call in Ghidra until the vtable pointer bytes are applied.

The six indirect sites in `Scene::DoGobShadows` resolve as follows. `0x1400c7fc0` calls Scene virtual `+0x2a8=Scene::GetShadowGob` `0x1400c9b80`. `0x1400c8064`, `0x1400c808c` and `0x1400c8141` call behavior virtual `+0x30=AsBehaviorAttach`: base `CAurBehavior::AsBehaviorAttach` `0x140054a60` returns null, while `CAurBehaviorAttach::AsBehaviorAttach` `0x140054a70` returns the attachment; the caller follows its target Gob at `+0x20`. `0x1400c80ac` and `0x1400c8160` call Gob virtual `+0x2d8=Gob::GetAdjustedPosition` `0x14008e2c0`. These targets are read from Scene `0x140d8dd30`, Gob `0x140d88a00` and behavior constructor-backed original PE vtables; subtype behavior target sets remain open.

`Scene::DoDynamicMeshProjections`' indirect `0x1400c7a01` reads PartTriMesh vtable slot `+0x108=PartTriMesh::WithinRange` `0x1400a4940`; `0x1400c7a7f` reads slot `+0xb8=PartTriMesh::Project` `0x1400a3770`. `PartTriMesh::PartTriMesh` `0x140087fd0` installs vtable `0x140d88308`; pinned PE entries at both offsets match these targets. `WithinRange` (REA `ev_0e9bb0fc`) tests expanded mesh bounds and a box/plane condition. `Project` (REA `ev_162bac41`) checks the mesh's shadow flag and source geometry, classifies vertices/faces against the light, builds shadow index/vertex data, and can call `Scene::RenderDynamicShadows` `0x1400ce3a0`, which reaches the draw API. Its indirect `0x1400a3f52` is a `VertexPrimitive` virtual `+0x38`; the concrete Flat, Skinned, Anim and Dangly constructor vtables `0x140d8ab68`, `0x140d8abb8`, `0x140d8ac08`, `0x140d8ac58` all point to `VertexPrimitiveFlat::SetupProjectionArrays` `0x1400acc90` (REA constructors `ev_3fb716c4`, `ev_da92b6bd`, `ev_71d18014`, `ev_5d5ace76`). Base `VertexPrimitive` vtable `0x140d8ab18` has a pure-call sentinel at that slot; the admitted projection path needs a concrete primitive.

`PartTriMesh::WithinRange` `0x1400a4940` first tests the light center against the mesh's expanded axis-aligned bounds. Only an overlapping candidate computes center-to-mesh distance with `magnitude` `0x1402303d0` at `0x1400a49f8`, builds a normalized direction (retaining zero safely), and calls `BoxAbovePlane` `0x14022b350` at `0x1400a4adb`. It accepts when that scalar box/plane result is within the light radius. This is CPU culling before projection construction, with no direct GL call; `BoxAbovePlane` is an already proven no-call math leaf, while `magnitude` may jump to the CRT scalar square-root helper (`ev_0e9bb0fc3dc4362af16836875e69280ea2384409da3d68556a1bbb1c586f6bff`).

Between its `WithinRange` test and the mesh's `Project` virtual call, `Scene::DoDynamicMeshProjections` transforms the selected light direction with quaternion unary minus `0x14022b0c0` at `0x1400c7a4f` and quaternion-by-Vector multiplication `0x14022ae90` at `0x1400c7a61`. Both are scalar CPU arithmetic leaves; the unary-minus body copies three components and negates one with no child calls (`ev_756ee8edad4bf3a4087162cc881514435fdb0f7b74929a4426f8cf4fad24450b`, `ev_c5e2a91bad56eb656ef9a681c7a3e8e7c738c12ad24506a03c4982c93cb4b011`).

`Scene::RenderStaticShadows`' `0x1400d2f5c` is Part virtual `+0x80=AsPartShadow`. Base `Part::AsPartShadow` `0x1400616d0` returns null, while `PartShadow::AsPartShadow` `0x1400d7c80` returns itself; its incoming vtable reference `0x140d8ff08` establishes `PartShadow::vftable` at `0x140d8fe88`. The next call `0x1400d2fcd` uses this shadow Part's `+0xc8=PartShadow::Draw` `0x1400a2490`; its body calls `RenderInterface::RenderVertexData` `0x1400beec0`. Pinned PE vtable entries at `+0x80` and `+0xc8` agree (REA `ev_d9146924`, `ev_4e78a688`).

`Scene::RenderDynamicShadows`' `0x1400ce6c5` is Part virtual `+0x58=AsPartTriMesh`: base `Part` returns null (`0x1400616f0`), while `PartTriMesh` returns itself (`0x14008c4e0`). It then tests the primitive's pending element count and calls the same `RenderInterface::RenderVertexData` draw route. Pinned Part/PartTriMesh vtable entries `0x140d87f08`/`0x140d88308` establish these slot targets (REA `ev_ce442f03`).

`RenderDynamicShadows` first calls `VertexDataObject::CommitElementStreamData` at `0x1400ce47f` on every entry, before testing the cached shadow shader. That helper calls `RenderInterface::UnlockPool` at `0x1400bd525` with `2 × current element count` bytes, then sets `m_nElementStreamCurrentElements=0`. The pool implementation may publish a dirty buffer range under its own state gates. The shadow shader `vs_shadowvol`/`fs_shadowvol` is looked up only when its cached pointer is null; if the lookup fails, the routine returns after the stream commit. With an available shader, it disables culling, configures stencil operations, iterates the selected shadow buckets through `GetFirstItem`/`GetNextItem`, and submits only admitted TriMesh items with positive pending element count. It clears each submitted primitive's pending count after `RenderVertexData` at `0x1400ce7aa`, so a subsequent flush does not redraw that same index span. Full pass REA `ev_ebe848986636b24851eb3c828cd531ee8501c623fdf724e02e5b5de27da8736e`; commit REA `ev_f21a4a8e90c9c4bee82b65c182429dd5a7eb5f050cfcca49f12248c0c4f3d995`.

### Per-mesh shadow projection publication

`PartTriMesh::Project` `0x1400a3770` first requires source geometry at its model node `+0x110` or `+0x114` and `GetProjectsShadows` true (`0x1400a37da`). It caps the source face count at `0xfffe`, classifies source vertices against the incoming light vector, and emits at most `0x2aaa` shadow faces into a shared CPU index scratch array. A zero emitted-face count returns without stream or buffer work. REA `ev_96f7c8a1c7a9b9b2f795a7d4fc47f3e5f131ddefb9a258bb78f04d23f775826d`.

With no `PartProjection` argument, it uses the primitive's existing vertex-data object, calls the primitive `+0x38=SetupProjectionArrays` only when that object is absent (`0x1400a3f52`), and returns if setup still did not produce one. It requests `six indices per emitted face` from the shared element stream. If available space is insufficient, `0x1400a3f7d` calls `Scene::RenderDynamicShadows` before reserving the next span; that is a conditional draw/flush, not an unconditional second shadow pass. `GetElementStreamData` at `0x1400a3fa0` may request or resize the CPU pool and lock it. The project routine fills alternating-winding edge indices; the caller's later dynamic-shadow pass commits and renders them.

With a nonnull `PartProjection`, the routine instead builds or reuses a type-1 `VertexDataObject`: compatible token lookup at `0x1400a3d34` occurs only on a missing object, a prior item is removed at `0x1400a3d57` only when its ID is valid, and `AddItem` at `0x1400a3d73` reserves the new static and element space. It locks the source vertex pool at `0x1400a3dc5`, transforms projected vertices, commits static bytes at `0x1400a3f30`, fills the indices, then commits element bytes at `0x1400a40a4`. Both commits forward byte ranges through `RenderInterface::UnlockPool` to the conditional GL buffer create/orphan/update path mapped in [geometry and draw boundary](geometry-and-draw-boundary.md). The token manager reuses compatible capacity/attributes or calls `VertexDataObject::Build` for a new object; `AddItem` may repack or resize pools, while `RemoveItem` only updates CPU bookkeeping. Evidence: token manager `ev_e8d793f44e3150c64ea5436b5e73b29ca961be0c7c3cb83f1a065f2e6ba02fc3`, `Build` `ev_03fc70642a83b90a5e5473f5c35134c4bb9ec347d2b1b8ec55eb0b1ac088dbb9`, `AddItem` `ev_0dac3fbb60a464bbf767c15a6d386c22a098a297ef014a7ddce75b0ad92980bb`, `RemoveItem` `ev_142beb35079ae709cbd155f803ff6695f9b690f81740ed613527b2855c929ff4`, static commit `ev_3d721ba78c775158ea29541ab6ddd2da1965d2a1685989b062db06a4f4d3d6f6`, element commit `ev_5df14ed2d8805ce848f3fcafcd60b8a419a6f3a69e24e2831e601ccc9465169c`, stream reservation `ev_53a19d8d4066fa70e0125975e4f8e19e9953d51451997c00dd431e388388f81e`. Runtime branch frequencies remain unmeasured.

`Gob::PartVolumeProject` `0x1400a3550` (REA `ev_9f8df6d6`) recursively visits visible Part children with the light vector transformed into each Part's local coordinates. On the root, computed calls `0x1400a3596`, `0x1400a35aa`, `0x1400a35e9` read Gob slots `+0x2d0=GetAdjustedScale`, `+0x2d8=GetAdjustedPosition`, `+0x2e0=GetAdjustedOrientation`. Before projecting a child, `0x1400a3692` checks Part `+0x60=AsPartAnimMesh` and `0x1400a36a0` checks `+0xa0=AsPartSkin`; the base implementations `0x140061640`/`0x1400616e0` return null, while PartAnimMesh `0x14008c3d0` and PartSkin `0x14008c4d0` return self. Only a Part that is neither type, has nonzero local light vector, and reaches `0x1400a36e0` calls Part `+0xb8=Project`. Base `Part::Project` `0x1400a3760` is empty; PartTriMesh and its AnimMesh/Skin derived vtables point to `PartTriMesh::Project` `0x1400a3770`, although the two derived types were excluded by the earlier checks. Pinned original Part, TriMesh, AnimMesh and Skin vtables `0x140d87f08`, `0x140d88308`, `0x140d88568`, `0x140d88438` establish all six computed targets. The admitted TriMesh projection then follows the vertex/index and draw branch above.
