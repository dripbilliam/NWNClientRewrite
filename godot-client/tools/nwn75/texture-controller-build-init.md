# NWN-75: original texture-controller build-time initialization

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This branch extends [texture publication](texture-publication-per-frame.md) from `CAurTextureBasic::BuildAndStoreTexture` `0x1400ea5e0`. The [ledger](texture-controller-build-init-ledger.json) records the computed targets and their CPU descendants. Static calls inherit the build caller's thread; these bodies contain no worker dispatch. The live authored controller mix and execution frequency are unknown.

`BuildAndStoreTexture` enters only with its `+0xe8` built flag clear. It conditionally constructs the image (`+0xe6` clear), publishes present image bytes through Basic virtual `+0xe8=CAurTexture::glImage` `0x1400ee130`, and establishes alpha mean when unspecified. It then checks image mode `Basic+0x70==0` and nonnull `Basic+0x38`. At `0x1400eab2f`, it calls that auxiliary object's vtable `+0x10`; the following `0x1400eab38` calls Basic `+0xf0=CAurTextureBasic::FreeImage` `0x1400eb640`. The auxiliary field is the `TextureController*` installed by `.txi` `proceduretype` in `CAurTextureBasic::ParseField` `0x1400ecf20`. Thus this is a build-time `Init` call, separate from the draw-time `+0x8=Control` dispatch in [controller runtime](texture-controller-runtime.md). The order is image publication → optional controller initialization → image release. This does not prove that a first build, controller, or GL publication happens every frame. The subtype `+0x30` image builders and CRT random/allocator descendants are followed in [controller runtime](texture-controller-runtime.md). These are CPU image/state preparation paths; GL publication at this point was the preceding Basic `glImage` branch.

Open runtime selectors are authored `.txi` type and settings, Basic image mode and dimensions, first-use state, source image presence, and the actual build caller/thread. The [parser registration proof](texture-controller-parser-registration.md) establishes five `.txi`-selectable tables; Water is a sixth compiled table with no proved parser selector or direct constructor caller. Externally installed or malformed controller pointers are not proven to use one of these tables.
