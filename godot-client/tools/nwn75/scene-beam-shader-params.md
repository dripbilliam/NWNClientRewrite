`Scene::RenderSinglePass` calls `Scene::RenderBeams` `0x1400cceb0` in its later additive/emitter sequence. The body exits unless `enablebeams` is set. It scans Scene's light list `+0x60/+0x68` and chooses the first nonnull candidate with radius `PartLight+0x74 >=1000`, nonzero type `+0x78`, and zero exclusion `+0x84`; it stops after that candidate. It prepares a normalized light direction and blend/depth/color state, then uses a cached `vs_beamvol`/`fs_beamvol` shader at `0x14140af30`, requesting one when null. A missing program skips the bucket traversal. REA `ev_faea81d1e7d8ced4faa8e334a7026b4cce06d394bc4eb45de925390bfe365e1b`.

With a program available, the pass walks bucket `0xf`. Each nonnull item calls Part virtual `+0x88=AsPartBeam`; the returned `PartBeam` must be nonnull and have VDO `+0xa0` nonnull. The admitted branch stages the cached custom shader, then calls `RenderInterface::SetShaderParamv4(0, value)` at `0x1400cd10e`, where `value` is the negated normalized light direction with fourth component `-1`. It calls `SetShaderParamf(1,-20)` at `0x1400cd11b`, then invokes virtual `+0xc8=PartBeam::Draw` `0x1400a22a0`, which joins the existing VDO/SetProgram/SetUniforms and conditional GL draw route. The vector/float setters unconditionally advance shared generation `0x1413d273c` and store the supplied values, as proven in the [dynamic-shadow continuation](scene-dynamic-shadow-shader-params.md). The selected program's `SetUniforms` generation check can revisit `projectionSource` and `projectionWorldZClip`; valid locations and per-program cached-value differences still gate `glUniform4fv`/`glUniform1f`. For repeated beam items under the same light, the float `-20` is the same at each site, so the value comparison can suppress its API upload even though the setter advances the generation.
