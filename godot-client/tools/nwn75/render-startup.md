# NWN-75: original render-system startup branch

Status: partial original-binary map. Installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are original PE virtual addresses. Ghidra pseudocode is not source code. The concrete initializer dispatch is identified below; its context-creation alternatives and callers remain open.

The PE Optional Header `AddressOfEntryPoint` resolves to `0x140c11bdc`. That stub has `.pdata` bounds `0x140c11bdc..0x140c11bee` (end exclusive) and directly calls `__security_init_cookie` `0x140c133bc` at `0x140c11be0`. The [CRT entry bridge](crt-entry-to-sdl-main.md) follows its subsequent tail jump to the CRT selector `0x140c11a00`, the selected `0x140cc87a0` thunk and SDL Windows-main wrapper `0x140cc87c0`, then `SDL_main` `0x140046340` at `0x140cc88e7`. CRT initialization and command-line allocation gates can exit before SDL_main. A second direct SDL-main caller at `0x140cc89e8` in `0x140cc8940` has no proven executable incoming route from this PE entry. The render-specific startup below begins once `SDL_main` is entered.

`CAurInternalGL::Initialize` `0x140075310` receives width, height, color/depth options and other setup fields. It clamps the requested depth bit count to at most 24 for `SDL_GL_SetAttribute(6, ...)`, calls two further `SDL_GL_SetAttribute` sites whose decompiled arguments are incomplete, sets its stored mode and global color/depth fields, then calls `AurInitExtensions` `0x1400a4fa0`. The original instruction at `AurInitExtensions` is a tail jump to `RenderInterface::InitExtensions` `0x1400bedf0`, which tail-jumps to `GLRender::InitExtensions` `0x1400b3f50`; that leaf is a single `RET`. Thus this named extension-init chain performs no loader work in the analyzed binary. REA initializer `ev_1d32b00e99eff1742cf3be8ff93f8d7d0441f3bd092d650e714670e93b914b65`, tail jumps `ev_b4947cbd88f3b39bcd7615eb9a606c69c0234820cb53bfd7471fa63f06d5be2f`, `ev_4459a994f41a5551af097d4024bf5e580e9673bafed7e8637c10c28028b33f9a`, leaf `ev_4efd1d6734f97ee89c7074450ef3b108789232bd970529fab7c46116f708fcd3`.

The pinned PE has a pointer to `0x140075310` at `.rdata` `0x140d85680`. The preceding entries at `0x140d85670` and `0x140d85678` point to `0x140074d40` and `0x1400752a0`; five RIP-relative code references target `0x140d85670` at `0x140074c2f`, `0x140074c8a`, `0x140074d61`, `0x140075413` and `0x140075493`. This supports `0x140d85670` as the concrete renderer vtable and `Initialize` as its `+0x10` slot. These bytes are reproducible with `scan-pointer-references.cjs` and `scan-rip-references.cjs` against the hash above.

The concrete virtual call is in `ReInitAurora` `0x140043340`: after its window setup, it loads `g_pAurora` from `0x1412df8e8`, reads vtable slot `+0x10`, and calls the loaded target with screen width, height and setup parameter at `0x1400435b4`. `NewCAurora` `0x1400a5130` installs the `CAurInternalGL` vtable; client startup `0x1406e3c80` calls it at `0x1406e3ec0` and stores the resulting object in `g_pAurora` at `0x1406e3ec5`. Therefore this constructor-backed slot resolves the indirect call to `CAurInternalGL::Initialize` for that object. REA high-pcode/call evidence: ReInitAurora `ev_e02bab4212dd2bc352ddebab8c7bba5c32ed8f0400cae9386710ea1c6ec63be2`, `NewCAurora` `ev_68c2d460493cef658934187c2ea35fa8eaa4a938768782bccdc6bac19167a629`, client startup `ev_34cff70119652b759670aa44d6fca8883543bd8c6dd10f7ed8a79b604f0b94b5`, exact CALL R10 `ev_0751149f81509eca9bbcfa8c3f8d3b82db47f34653987087e694eec582cc7726`. The constructor and callsite establish the target; the frequency of this path remains to be measured.

The initial client-startup route reaches that construction from `SDL_main`: direct E8 call at `0x140046cb6` targets the small thunk `0x1406acd40`; that thunk loads the client object from its wrapper at `+0x8` and tail-jumps at `0x1406acd44` to `0x1406e3c80`. These are original PE rel32 sites from `scan-rip-references.cjs`; the function body at `0x1406e3c80` is the REA-backed client startup above. This connects the frame-root process entry to construction of `g_pAurora`, though the surrounding SDL/main startup gates remain only partly classified.

The two external incoming callsites for `ReInitAurora` are `Update` `0x140044d49` under its reinitialization branch and display-mode route `FUN_1406e2b40` at `0x1406e2c73`. The mode-change route queries the SDL display mode and, when `g_nReInitializing==1`, first invokes `CAurInternalGL::RestoreDesktopDisplayMode` through vtable `+0x20`. Inside `ReInitAurora`, vtable `+0x38` tests initialized state, vtable `+0x30` invokes `CAurInternalGL::ShutDown(this,0)` when needed, SDL setters change the existing global window's grab, size, fullscreen, display mode and title, then the `+0x10` initializer runs. `ShutDown(this,0)` skips `AurTextureClearAll`, conditionally destroys only its own `this+0xc0` window field, and clears its initialized flag. REA incoming `ev_229db3f0c3fc8b783941fae51590789695c35e8ff7e4f084a8eee33086307e6c`, mode route `ev_a8b48124eda93809792cff1df2d9dc36aa73c9955a2712ec60730eb13cfe148d`, `Update` `ev_3957e705c146df933c995e572aaf92eb3c23c4e0496ad434efca96649e1b9376`, shutdown `ev_42379a914f7f756bc61c756f528ee7ec800149b95ef0de0b1a08254153e92f29`.

The same pinned PE vtable bytes resolve `+0x20=0x1400756f0` (`RestoreDesktopDisplayMode`), `+0x30=0x140075750` (`ShutDown`), and `+0x38=0x1400752d0` (`GetIsInitialized`) next to the initializer slot. This corroborates the computed dispatch targets without assuming every possible `CAurInternal` subtype is the same concrete renderer.

`SDL_main` constructs the global window and GL context and directly calls the `SDL_GL_CreateContext` wrapper `0x140ab15d0` at `0x140046b7d` (REA `ev_833c7aa9adb229ef33dd413c495d7c0f61fbec645c741d6268e78b62f252dd65`, wrapper incoming `ev_928862009b47e1160cde66d001e2a516faa7c95427dfd714d9c73bffab77306a`). No `SDL_GL_CreateContext` call appears in the analyzed `CAurInternalGL::Initialize` or ReInitAurora body. The observed reinitialization path therefore operates on the existing global window/context, while an indirect alternate context route remains unexcluded by this bounded static search.

The initializer then checks `DAT_14128e554`, whose pinned `.data` DWORD initializes to `1` at `0x14128e554` (bytes `01 00 00 00`). If zero, it calls `RenderInterface::ResetRenderStates`; otherwise it clears that field with `C7 05` at `0x140075395` and calls `RenderInterface::InitRenderSystem` `0x1400bee00` → `GLRender::InitRenderSystem` `0x1400b3f60`. It marks the concrete renderer initialized at `this+0xb4`, calls `RenderInterface::SetViewPort(0,0,width,height)`, and returns success. These are alternative setup routes; the initial value admits full system initialization on the first observed eligible call, while later calls take reset unless an indirect or non-rel32 writer changes the field.

`GLRender::InitRenderSystem` initializes 13 stock shader source-name pairs, loading two program variants for each pair through `GLRender::LoadShader` `0x1400b45b0`; the second variant passes its alternate boolean flag. It first zeros `0x60` bytes of shader dirty state, then sets four matrix stacks to identity, zeros `0xa4` bytes of exposed runtime shader data, and calls `ResetRenderStates` `0x1400b6050`. Shader source acquisition, compile/link and uniform-location setup are in [shader program setup](shader-program-branch.md). The conditional later reload follows the same 13-pair stock build after deleting existing IDs, plus any loaded custom programs. REA `ev_3a5fac314c39d2fd8c8bae7c4568d61ec107c9e9ac88274a8a8fe972015904c3`.

The `FUN_140b7b8e0` body calls the extension-pointer loader at `0x140b7bf28`. The wrapper and caller sites are REA `ev_9615475f476b98c70b66b591e5593ee5930cbb24bfedf486b3a2a74e84461969` and `ev_7403180870f4bac4da8aae2c9e3100639636871d08c1432ca99e664c164d8531`; the loader incoming-reference evidence is `ev_bffd043579f3ab5d2e199009e2d7e4cf1c9093978009d0b9398bee209cc2bc99`. The large caller's internal branches and the wrapper's alternate tail-jump condition remain open. This branch is not closed merely because all pointer names are known.

The shutdown route is also directly reachable from `SDL_main`: its call displacement at `0x140046ded` targets the one-jump wrapper `0x1400bf380`, which jumps to `GLRender::Shutdown` `0x1400bb560`. This is pinned-PE rel32 evidence from `scan-rip-references.cjs`, plus the original REA name for the GL function.
