# NWN-75: compressed GUI archive read and codec dispatch

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are PE virtual addresses. This continues the source-1 [resource-file provider](gui-keytable-archive-provider.md) and source-2 [encapsulated provider](gui-encapsulated-archive-provider.md) through their **compressed entry** branch. The resource/entry selected for a particular GUI demand remains runtime data. The [GUI resource decoder map](gui-resource-demand-decoders.md) names these codecs; this supplement pins their file-read and virtual-dispatch sites and keeps the deeper library internals bounded.

## CPU codec entries and output publication

Zstd provider `0x1401aa230` requires an inner header of at least **8** bytes and inner version **1**. It calls `ZSTD_findDecompressedSize` at `0x1401aa2c6`, rejects an error or a decoded size different from outer expected size, allocates a block, and requires dictionary id **0**. It then uses a thread-local decode context and calls `ZSTD_decompressDCtx` `0x1409e9670` at `0x1401aa448`. An error clears the output. This is the bounded Zstd CPU entry; `ZSTD_decompressDCtx` calls `ZSTD_decompressMultiFrame` `0x1409e9950` at `0x1409e968f`, whose deeper entropy/sequence tree is outside this supplement. Only a nonnull decoded block whose length fits the caller's capacity reaches the final `CExoPackedFile` CPU copy at `0x14018c8b9`. Otherwise the helper returns zero.
