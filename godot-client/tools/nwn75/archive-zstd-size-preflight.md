`ZSTD_findDecompressedSize` loops through input frames. Fewer than five remaining bytes are accepted only at exact exhaustion; nonzero trailing bytes return an unknown-size sentinel. Skippable magic `(word & 0xfffffff0)==0x184d2a50` requires eight header bytes and its declared payload to fit, then advances input without adding output size. An ordinary frame calls header parser `FUN_1409ec6d0` at `0x1409ec128`, takes the declared content size if available, checks accumulated-size overflow, and calls `ZSTD_findFrameCompressedSize 0x1409ec1a0` at `0x1409ec156` to advance to the next frame. Evidence preflight `ev_aa89a34a6dc3bdbfc66dc612c159c5c990f0f98ee31b9b89a06740fd3ea83f92`.

`ZSTD_findFrameCompressedSize` calls the same header parser again at `0x1409ec1e2`. On a valid ordinary header it starts after the header and walks each three-byte block header: type 1 has one payload byte, types 0/2 use `header >> 3`, and type 3 rejects. Each payload plus three-byte header must fit. The last-block bit ends the walk, and a checksum-enabled frame requires four trailing checksum bytes before the compressed span is returned. This pass does not entropy-decode or copy literals into the output. The later full frame decoder also calls `FUN_1409ec6d0` at `0x1409e9756` before decoding blocks. Thus the pinned code parses an admitted ordinary frame header in size preflight, compressed-span discovery, and full decode; each call has its own conditions and error handling.
