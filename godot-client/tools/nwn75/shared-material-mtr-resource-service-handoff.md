# NWN-75: SharedMaterial MTR resource service handoff

Pinned installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This connects the existing SharedMaterial miss/parse branch to its concrete type-`0x818` `CResMTR` resource object, serviced byte buffer and release. The [two-sided material continuation](shared-material-two-sided-cull-consumer.md) follows one authored draw-state consumer. None of these static edges establishes that a particular `.mtr` is requested in an active frame.

`SharedMaterial::GetSharedMaterial 0x140083340` returns a cached object when `FindSharedMaterialIndex` succeeds. On a nonempty uncached name it calls `AurResGet(name,".mtr",...,true)` at `0x1400833cd`. If the resource returns, it constructs a SharedMaterial, iterates `AurResGetNextLine`, calls `SharedMaterial::ParseField 0x1400849a0` at `0x14008341b`, releases the resource at `0x14008342d`, initializes the material and inserts it into the shared table. The installed `AurGetResource` callback is `CAuroraInterface::GetResource 0x1400f63d0` as shown in the [TXI callback handoff](texture-txi-resource-service-handoff.md). The `true` fallback flag makes a null callback result return null without trying the local-file fallback in this call. `GetResource` strips an initial dot and uppercases the extension, eventually matching the four bytes `4d 54 52 00` (`MTR`) at `0x140d92684`. It allocates `CAuroraMTR` and calls its constructor at `0x1400f6d27`, then `LoadMTR` at `0x1400f6d3b`. The constructor asks `CExoResMan::GetResObject` for type `0x818` at `0x1400f93fb`; on a miss it constructs `CResMTR 0x1400fae40` at `0x1400f941d` and registers that object at `0x1400f943d`. The `CResMTR` constructor installs vtable `0x140d92b90`, whose `+0x18` freed and `+0x20` serviced slots target `0x1400faf00` and `0x1400faf10`. All four generic resource storage services can call that serviced slot only after their source-specific successful data read/copy for a constructed MTR object. `LoadMTR 0x1400f96d0` calls `CRes::Demand` at `0x1400f96dd`, returns zero on failure, and on success gets the serviced byte pointer, writes the type `0x818` and `CAuroraMTR` owner immediately before that pointer, and marks loaded state `+0x28`. `CResMTR::OnResourceServiced` requires a nonnull `CRes+0x20`; on its first service it copies length `+0x30` to MTR `+0x64`, data pointer to `+0x68`, and sets its serviced flag `+0x60`. `GetResource` then reads MTR size and pointer at `0x1400f6d4b/0x1400f6d57`, returning them to `AurResGet`. The resource callback has no GL call. Material parsing and later texture references or draw-state use remain separately gated. `AurResFree` invokes the installed `ReleaseResource` callback for its callback-backed buffer.
