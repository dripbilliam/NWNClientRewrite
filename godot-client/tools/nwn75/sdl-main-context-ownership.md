## Built-in shutdown: unbind and unload

After app and Aurora cleanup, `SDL_main` calls `SDL_Quit` at `0x140046e86` only if `SDL_WasInit` returned nonzero at `0x140046e7d`. The built-in quit path reaches video teardown `0x140ad50c0` only when the VIDEO subsystem's final-reference gate succeeds. That routine destroys remaining video windows through built-in `SDL_DestroyWindow` `0x140acfaa0`. The SDL dynamic API and video driver may select different implementations; these are built-in Windows descendants. REA `ev_833c7aa9adb229ef33dd413c495d7c0f61fbec645c741d6268e78b62f252dd65`, video teardown `ev_0235366165d1f4c23caa2ba0b1b2b79b46e28f0ffe27c3823ca1578e0e806230`.

When `SDL_DestroyWindow` receives a valid OpenGL window that equals video-device current window `+0x3f0`, it passes that window and **null context** to `0x140ad08e0` at `0x140acfb2a` (`XOR EDX,EDX` at `0x140acfb25`). That helper invokes device slot `+0x170` at `0x140ad0971`; on success it clears video-device current window/context `+0x3f0/+0x3f8` at `0x140ad098b/0x140ad0992` and updates thread keys. The Windows video constructor installs `0x140af3510` in slot `+0x170` at `0x140ab9ff5`. That function calls the dynamically loaded GL table slot `+0x38` at `0x140af3567`, resolved by the loader as `wglMakeCurrent`; it has no call to slot `+0x30` (`wglDeleteContext`). Thus this window-destruction branch attempts to unbind the current context, with actual success governed by its guards and the WGL return. Only on the final count does it dispatch device slot `+0x160` at `0x140ad0faa`. The Windows slot target `0x140af3a90`, installed at `0x140ab9fd9`, calls module release `0x140ad5740` at `0x140af3aa0`, then frees and clears the device GL table `+0x530` at `0x140af3ab7/0x140af3abc`. `0x140ad5740` jumps to imported `KERNEL32.FreeLibrary` for a nonnull module at `0x140ad5745`. ## Delete paths and limit

Built-in `SDL_GL_DeleteContext` `0x140ad00a0` would call video-device slot `+0x198` at `0x140ad00e5` after a nonnull device/context check and current-context unbind. The Windows slot target at `0x140af2f80` requires a nonnull GL table `+0x530` and tail-jumps through its `+0x30` entry at `0x140af2f8f`; loader `0x140af3390` resolves that entry as `wglDeleteContext`. The exported `SDL_GL_DeleteContext` `0x140ab15e0` has no code caller in the analyzed original. The built-in function has two direct callers, `GL_DestroyRenderer` at `0x140b06dbb` and `GLES2_DestroyRenderer` at `0x140b0c2c7`, each gated by its own renderer-held context. No connection from `SDL_main`'s `g_pContext` to either renderer object is established. REA `ev_5e1b5a2271ca31d3f881221ee3fbb107802500b519527dbf9cda2ec1d361fbec`, Windows tail bytes `ev_eb378fb37da6335bd572896fe8f820d1dfc10654bd231d9ec24099f66937551f`, loader `ev_97e6bb0c478694c1a0bb76e41c5dc49ccea5b39102139030b34cf12a86b15e7f`, built-in incoming references `ev_8e5d53d84e25b6701de4dcfa60fee59ef0a2f2d745e9b8bd4913165388508f69`.

Windows context creation `0x140af2c10` can itself call the same loaded `wglDeleteContext` slot at `0x140af2df8`, `0x140af2f22`, or `0x140af2f5b`: respectively failed first make-current, disposal of a temporary legacy context after an attributed context is created, or failed final make-current. These occur before a successful context is returned to `SDL_main`, and do not prove deletion of its stored context during teardown. REA `ev_db098456533fe7cafa6d18318fa19d5846951aba9f66b57b572b0726e969dad0`, exact sites `ev_715405a98af1c56833f4b2f5920518787a47ecae350d13b57c2e1b98d7f16a84`.

**Conclusion:** the pinned built-in Windows shutdown route proves conditional unbinding through `wglMakeCurrent` and module unload through `FreeLibrary`; it does not show an explicit `SDL_GL_DeleteContext` or `wglDeleteContext` call for the context returned to `SDL_main`. External `SDL_DYNAMIC_API`, alternate `SDL_VIDEODRIVER`, `SDL_OPENGL_LIBRARY`, and runtime ownership outside the inspected branch remain unobserved. No claim is made about driver or process-exit reclamation of the native context.
