# NWN-75: name-based MDL parser to typed model tree

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This supplement starts at the `FindModel` cache miss described in `model-instance-branch.md`. It covers original parser construction, not a per-frame draw call. The machine sites and full REA evidence IDs are in `model-name-parser-tree-ledger.json`.

## Name and resource gate

`FindModel` `0x140098cd0` returns null for a null or `NULL` name, returns a cached Model on `BinarySearchModel` hit, and otherwise saves `currentmodel`, installs the top-level command whitelist `0x1400a16e0`, and calls `IODispatcher::ReadSync(char const*)` at `0x140098ecf`. The whitelist admits `filedependancy`, `setsupermodel`, `setanimationscale`, `classification`, `newmodel`, `newanim`, `beginmodelgeom`, `donemodel`, and `ignorefog`. It does not govern every line read by `ImportMaxTree`: those lines are dispatched directly through the MaxTree and MdlNode parse fields. On return, `FindModel` restores its prior `currentmodel`; its typed acceptance calls `MaxTree::AsModel`, which requires kind `2` at `+0x88`. REA `ev_9ae09257`, `ev_0781026e`, `ev_b250e690`.

`ReadSync` forwards to `FUN_140079a80` at `0x140079f82`. The latter requests `<name>.mdl` through `AurResGet` with local fallback enabled, asks for four data bytes, and returns null when either demand fails. It selects **binary** when the first byte is zero and **text** otherwise. For binary it calls `FUN_140079d50` then `AsModel`. For text it frees the probed resource, composes `<name>.mdl`, invokes `dofile`, and returns the resulting `currentmodel`. Named resource callback, storage-class selectors, archive/manifest/file leaves are already mapped in `model-resource-storage.md`; those are the resource boundary here. REA `ev_e6d14006`, `ev_2efb3964`.

## Binary MDL route

`FUN_140079d50` takes two 32-bit lengths from `AurResGetDataBytes`, copies the principal model block into heap memory, conditionally copies the second raw-geometry block when its length is nonzero, then calls `FUN_140079f90`. It frees the AurRes and temporary blocks afterwards. Only a null result from the first four-byte demand is checked in this wrapper; the observed body does not establish independent bounds for each later length. REA `ev_7c2123d9`.

`FUN_140079f90` allocates a `0x110` MaxTree/Model, copies name, bounds, flags and other authored metadata from the binary block, resolves the optional supermodel name via `FindModel` and `Model::AddRef`, and resets its free lists. It copies an animation-offset table when the count at binary `+0x7c` is nonzero, allocates `0xe8` per Animation, copies its metadata and keys, and invokes recursive node constructor `FUN_14007abe0` for each animation root at `0x14007a301`. It invokes the same constructor for the model geometry root at `0x14007a36f`, stores it at Model `+0x50`, recursively normalizes mesh normals in `FUN_140079500`, installs Model parse/destructor fields, and inserts the Model in the global table. The supermodel lookup can re-enter this name parser; the cache hit/miss gate remains significant. REA `ev_f4158e56`, `ev_3846e53e`.

`FUN_14007abe0` selects a concrete node class by binary node type at `+0x6c`: `0x1` base, `0x9` camera, `0x5` emitter, `0x3` light, `0x11` reference, `0x21` TriMesh, `0x61` skin, `0xa1` AnimMesh, `0x121` DanglyMesh, `0x221` AABB, `0x421` trigger; an unknown type returns null. It installs subtype-specific function fields including the `+0x28` CreateInstance field later consumed by `CreateInstanceTreeR` in `model-instance-branch.md`. The common node builder `FUN_14007b6c0` copies the child-offset table, allocates the child list, recurses at `0x14007b7b6`, sets each child parent at `+0x60`, and copies controller tables/data. Other subtype payload helpers remain distinct descendants. REA `ev_84972c82`, `ev_aa629682`.

For the binary TriMesh family, `FUN_14007be10` first builds the common node, then copies face and index arrays. It calls `RenderInterface::RequestPool`, `LockPool`, CPU `memcpy`, and `UnlockPool` for the base vertex stream at `0x14007c082/094/0af/0be`; other attribute streams depend on authored format bits and `0xffffffff` sentinels. `FUN_140079500` locks optional normal pools, normalizes each vector on CPU, unlocks them, and recurses through children. The pool's later GL allocation/upload behavior is mapped in `geometry-and-draw-boundary.md`; the parser itself is not a direct GL draw. REA `ev_cd7a346b`, `ev_3846e53e`.

## Text MDL route

`dofile` splits the composed name and extension, demands the named resource again with local fallback disabled, and reads resource lines through either resident-resource iteration or CRT `common_fgets`. It skips whitespace-only/comment lines and calls `FuncInterp` at `0x140060157` for each command. `FuncInterp` applies the active whitelist, looks up a registered callback by name, and invokes its holder through computed `+0x8` callsite `0x14005f68c`. The [text command registration](model-text-command-registration.md) resolves the `newmodel`/`beginmodelgeom` holder chain; [six other command holders](model-text-other-command-holders.md) resolve `classification`, `donemodel`, `ignorefog`, `newanim`, `setanimationscale` and `setsupermodel` through their own startup producers and typed effects. REA `ev_b7ceeb48`, `ev_e100938d`, `ev_5a0b0d6e`, `ev_83909690`.

`newmodel` allocates a `0x110` object and invokes `Model::Model`, which initializes kind `2`, inserts it into the model table, and installs `ModelParseField` at object `+0x8`. `beginmodelgeom` optionally seeds model count from a supermodel, invokes `ImportMaxTree`, and tail-jumps to `MaxTree::SynchronizeTree` for the supermodel. `ImportMaxTree` consumes lines until `done` or `end`, calls current MaxTree `+0x8` at `0x140099078` for each line, and reorders children recursively when `AsModel` succeeds. For a Model, the field target is `ModelParseField` → `Model::InternalParseField` `0x14009ff50`; `radius`, `bmin`, and `bmax` are parsed locally, while a `node...` line calls `ParseNode` at `0x1400a00ff`. REA `ev_78e5ee01`, `ev_487d22f5`, `ev_c7ce3917`, `ev_c3b479d5`, `ev_0dca19a9`.

`ParseNode` reads node type and name, creates the typed MdlNode constructors for camera, emitter, light, TriMesh, AnimMesh, DanglyMesh, reference, AABB, skin, or a base node for other names, and sets its owning MaxTree at `+0x58`. It reads lines until `endnode`, calling the node's `+0x8` parse field at `0x1400a109f`. The base `MdlNode::InternalParseField` handles position/orientation/scale controller variants and `parent`: `parent NULL` stores the node at tree `+0x50`, while a named parent is located below the root and receives this node in its child array. After the terminator, `ParseNode` increments tree node count, stores node index, and calls the subtype `+0x10` postprocess at `0x1400a10b3`. This makes a typed tree rather than a flat list. REA `ev_d48a96fe`, `ev_2b4f1308`, `ev_70757fbb`, `ev_b250e690`.

On a text TriMesh whose vertex count field `+0x284` is zero, `MdlNodeTriMesh::InternalPostProcess` processes authored vertices; with faces present it builds neighbors/indices and calls `GenerateVertexData` at `0x1400a9b49`. That function requests and locks position/normal pools, conditionally requests color/tangent/UV streams from vertex format bits, writes expanded vertex data on CPU, then unlocks the pools. If the count is already nonzero, the postprocess takes a tangent-basis path. This reaches the same render-pool boundary as binary geometry, subject to different authoring gates. REA `ev_4161d5fa`, `ev_fbbde492`.

## Open frontier

The eight named command holders above have constructor-backed target and registry lookup chains. The whitelist's `filedependancy` spelling still lacks a proved holder/target. Subtype-specific binary payload builders and text field/postprocess variants beyond the representative TriMesh are not all expanded here. Binary offset/count validation through the resource layer is not proved by the shown wrapper. The created Model flows to `CreateInstanceTreeR`, material setup and later GL draw as mapped in `model-instance-branch.md` and `geometry-and-draw-boundary.md`.
