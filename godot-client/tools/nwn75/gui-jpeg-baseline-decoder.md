# Original file-backed JPEG baseline decoder

Pinned `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This deepens the conditional `ImageRead` → `ImageReadJPG` path in [GUI resource demand and image decoders](gui-resource-demand-decoders.md). The pinned symbol is `ImageReadJPG` `0x140228f50`; no `CResJPEG` procedure name is present in this image. This is the **initial file-backed** `AurGetRaster` callback path. The Aurora interface later replaces that callback with resource-backed raster retrieval, so this supplement does not assert that JPEG file decoding occurs after replacement or on a particular frame. Exact sites and gates are in [the ledger](gui-jpeg-baseline-decoder-ledger.json).

## Baseline sample production

At state `0xCA`, `jpeg_start_decompress` directly initializes the master controller at `0x140218613`. For the single-scan, nonarithmetic, no-color-quantization, nonmerged output branch, master setup `0x14021eaf0` installs color conversion (`0x14021ecfa`), upsampler (`0x14021ed02`), post controller (`0x14021ed0e`), inverse DCT (`0x14021ed16`), baseline Huffman decoder (`0x14021ed48`), one-pass coefficient controller (`0x14021ed69`), and main controller (`0x14021ed79`). The progressive-Huffman branch chooses `jinit_phuff_decoder` at `0x14021ed41`; merged upsampling, quantization, buffered-image and raw-output paths select other callbacks. The default inverse-DCT method is initialized to `0` in `0x140217cb0`; for ordinary 8×8 output, `0x14021a700` maps method `0` to `jpeg_idct_islow` `0x140223be0`, method `1` to `jpeg_idct_ifast` `0x140223480`, and method `2` to `jpeg_idct_float` `0x140222bb0`. Different scaled sizes map to 1×1, 2×2 or 4×4 variants. `jpeg_read_scanlines` `0x140218530` requires scanline state `0xCD` and output rows remaining, then invokes the installed main-controller `+0x8` callback at `0x1402185db`. ## Publication and frontier

After start, `ImageReadJPG` writes output width, height and component count through its three caller pointers, allocates `width×height×components` bytes at `0x14022904f`, and points each `jpeg_read_scanlines` call at the next row in that allocation (`0x140229080`). On the normal completion path it calls `jpeg_finish_decompress`, `jpeg_destroy_decompress` and `fclose` at `0x140229092/0x14022909c/0x1402290a6`, then returns the allocation. `jpeg_finish_decompress` checks that all output rows were consumed, drains the input controller to EOI and aborts/free-pools after completion. `ImageRead` flips the returned JPEG rows vertically at `0x140072fd0`, then returns the pointer. If the initial `AurGetRaster` callback is still selected, `CAurTextureBasic::LoadImageA` can receive that raster through `AurGetImageWrapper` and store its returned pointer at `this+0x58`; the later texture-publication path is mapped separately. Evidence finish `ev_371c844f28aaa4abec0486466e31502d1769fcf7c6fd86f11e5467812f3dc9d8`, `ImageReadJPG` and `ImageRead` above, texture acquisition `ev_6408088da110e8043032c1b4bdd9a678ddd3dc92b975633c58ac1711313fd61e`.

This branch closes a conditional baseline decode to CPU pixel output and the existing CRT/Win32 read boundary. Runtime JPEG marker sequence, sampling/color-space selectors, output mode, source suspension and active raster callback remain data dependent. Progressive, arithmetic, merged upsampling, other fancy upsampling ratios, scaled IDCT, quantization, multi-scan and malformed-input error descendants are separate branches; none is silently equated with the selected baseline path. `ImageReadJPG` does not itself call GL.
