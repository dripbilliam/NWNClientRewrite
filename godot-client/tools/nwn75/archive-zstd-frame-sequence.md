## One complete frame and compressed-block branch

`ZSTD_decompressDCtx` calls `ZSTD_decompressMultiFrame` `0x1409e9950` at `0x1409e968f`. For an ordinary, non-skippable frame, with no dictionary supplied, the latter resets sequence tables/repeat offsets and calls the frame decoder `FUN_1409e96a0` at `0x1409e9bd6`. The frame decoder parses and validates its header through `FUN_1409ec6d0` at `0x1409e9756`, checks any declared dictionary ID against context state, then reads a three-byte block header. Type `(header >> 1) & 3 == 2` selects a compressed block; it checks that its encoded payload fits the remaining input and calls `ZSTD_decompressBlock_internal` `0x1409e9120` at **`0x1409e982d`**, passing the current output pointer and remaining output capacity. Block types 0/1 go to raw copy `0x1409e986e`/RLE fill `0x1409e984f`; type 3 fails. The compressed-block decoder requires payload size `< 0x20000`. ## Publication, lifetime, and alternate branches

`ReadNWCompressedBuffer` requires a nonnull decoded block and used length no larger than caller capacity (`0x14018c8a2`–`0x14018c8b1`). It copies the decoded bytes at `0x14018c8b9` through CPU `0x140c417f0` into the service-owned `CRes+0x20` buffer, returns the used length, and decrements decoded and compressed temporary block references at `0x14018c8ce` and `0x14018c8ff`. Final strong-reference release reaches `_Ref_count_obj<DataBlock>::_Destroy` `0x14010f6a0` → `DataView::~DataView` `0x140109050` → owned shared-storage destruction `0x14010f690` when its final reference and ownership flag permit. Source-1 service `0x140193b80` checks returned length against expected table length at `0x140193ed6` and, on equality, releases the archive provider at `0x140193f28` then invokes the `CRes` serviced hook at `0x140193f31`. Source-2 service `0x140192cf0` does the corresponding check at `0x140193037`, release at `0x140193086`, and hook at `0x14019308f`. Only a successful hook sets serviced status. Later eligible `CExoResMan::FreeResourceData` `0x14018f8d0` frees `CRes+0x20` at `0x14018f8ff`.
