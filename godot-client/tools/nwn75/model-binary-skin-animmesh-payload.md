## AnimMesh kind `0xa1`

`FUN_14007abe0` allocates a `0x318`-byte AnimMesh node for source kind `0xa1` and calls `FUN_14007a530` `0x14007a530` at `0x14007adfe`. The helper copies source `+0x270` into node `+0x2c8` (the text parser's `sampleperiod` field), plus source `+0x2a0/+0x2a4` into node `+0x310/+0x314`. It calls shared mesh metadata copier `FUN_140078ab0` at `0x14007a57d`, then the shared `FUN_14007be10` at `0x14007a59c`, so an AnimMesh can have all the base face/index/geometry streams before its subtype arrays. Evidence decoder `ev_84972c82b2b72d9d3febb9c48d59aea19eff280be68bdbc6c1b6f8ef0d1c9147`, helper `ev_4e46c4b6e865f033137a3c14b6b79d8a753482d301603cfba5df441d33ccb472`.

Three nonzero count gates copy Vector-sized (12-byte) arrays from the principal binary block: source offset/count `+0x274/+0x278` to node `+0x2d0/+0x2d8`, `+0x280/+0x284` to `+0x2e0/+0x2e8`, and `+0x28c/+0x290` to `+0x2f0/+0x2f8`. The first two match the text node's `animverts` and `animtverts` lists; the third supplies additional sampled vectors. When source `+0x2a0` is nonzero, it allocates node `+0x300` for `vertex_count × count × 3` 4-byte values copied from principal-block offset `+0x298`. A nonzero `+0x2a4` similarly allocates node `+0x308` for `vertex_count × count × 2` values from offset `+0x29c`. These are CPU allocations/copies; the shown helper adds no extra GL pool call beyond `FUN_14007be10`. It installs AnimMesh parse/postprocess/control/CreateInstance/vertex-generation/cleanup fields, including `+0x28=MdlNodeAnimMeshCreateInstance` `0x140092440`. The later instance becomes `PartAnimMesh`, whose animation and draw publication are mapped in the text subtype and [primitive/VDO](primitive-vdo-preparation.md) branches. Exact authored counts, model admission and per-frame animation remain dynamic.

## Skin kind `0x61`

The decoder allocates a `0x3a0`-byte Skin node, constructs it, and calls `FUN_14007b9f0` `0x14007b9f0` at `0x14007b4f7`. The helper copies source raw stream words `+0x27c/+0x280` into node `+0x2d8/+0x2dc`, source `+0x288` into node `+0x2e8`, and fixed source `+0x2b0..+0x32c` transform/scalar data into node `+0x320..+0x39c`. It calls the same metadata copier at `0x14007bac4` and shared fifteen-stream builder at `0x14007bae6`, then installs Skin parse/postprocess/TriMesh control/CreateInstance/vertex-generation/cleanup fields. Its `+0x28=MdlNodeSkinCreateInstance` `0x140093000` later creates `PartSkin`, whose bone resolution and draw descendants are mapped in [text Skin/AnimMesh](model-text-skin-animmesh.md) and [non-emitter animation](original-scene-animation-nonemitter.md). Evidence helper `ev_e24abfb32b914fffa681326bf4cb6c6f30b8f8cae3d15960da595a99e822c560`.

The helper checks node vertex count `+0x284`. If zero, it writes `0xffffffff` to both extra stream slots and does no extra pool copy. Otherwise the saved raw offset in `+0x2d8` is used to request a kind-0 `16 × vertex_count` byte pool at `0x14007bb6f`, lock it at `0x14007bb82`, copy raw-geometry bytes, and unlock at `0x14007bbaa`; slot `+0x2dc` similarly requests `8 × vertex_count` bytes at `0x14007bbca`, locks at `0x14007bbdd`, copies, and unlocks at `0x14007bc05`. These two extra streams can join the same conditional GL-buffer publication path as the shared mesh streams. The numeric stream widths and source slots are observed; semantic bone-index/weight interpretation depends on the later PartSkin consumer. Evidence `ev_e24abfb32b914fffa681326bf4cb6c6f30b8f8cae3d15960da595a99e822c560`.

The remaining nonzero count gates copy four CPU arrays from the principal binary block: source `+0x284/+0x288` supplies `count × 2` bytes to node `+0x2e0/+0x2e8`; source `+0x28c/+0x290` supplies `count × 16` Quaternion bytes to `+0x2f0/+0x2f8`; source `+0x298/+0x29c` supplies `count × 12` Vector bytes to `+0x300/+0x308`; and source `+0x2a4/+0x2a8` supplies `count × 4` integer bytes to `+0x310/+0x318`. Those latter three correspond to text `qbone_ref_inv`, `tbone_ref_inv`, and `boneconstantindices`. The helper's Quaternion list growth constructs default elements, copies any prior entries, and frees the old backing array before copying serialized values. All allocations/copies are CPU operations; the only GL-capable descendants are the shared and two extra pool unlocks, gated by pool state. No worker handoff is visible in either binary helper. Malformed binary offsets/counts, active model choice, actual pool state and eventual Scene/GL draw remain unresolved.
