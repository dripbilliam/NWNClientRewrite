# NWN-75: original Gob callback registration and render-visible effects

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses below are PE virtual addresses. This is a **bounded static callsite census**, not an authored effect count or runtime frequency claim.

The [Gob callback ledger](original-gob-callback-ledger.json) records exact machine sites for all 39 direct-kind edges in this scope. Seventeen formerly site-less edges were resolved from REA function assembly, then each of their 42 CALL instructions was independently decoded and matched to its containing procedure and target. Seven of those edges call their target from multiple sites, recorded as parallel `callsites` and `callsite_evidence_ids` arrays. The remaining byte-proven tiny thunks are distinguished from decoded procedure calls. This closes the direct-site bookkeeping gap; authored callback occurrence and runtime frequency remain data-dependent.

## Registration mechanism and bounded producer census

`Gob::RegisterCallBack` `0x140052a30` is dispatched through Gob vtable slot `+0x50`. Its body allocates a 0x30-byte `CallBack` record, writes the supplied function pointer at `+0x20`, stores the event string in the inline 32-byte prefix and context at `+0x28`, then appends the record to Gob `+0x460/+0x468`. The record is a data structure with a direct function field; **no callback-object vtable** is installed. `Gob::DoEvent` `0x140050d50` scans records in reverse order and calls field `+0x20` at `0x140050e38` for a case-insensitive event match, an empty name or `*`. ## `GobReset` to highlight state and draw

`CNWCAnimBase::LoadModel` registers `GobReset` on its body model Gob with anim-base context. The registered pointer `0x140960b30` forwards to anim-base virtual `+0x170`; its constructor-backed base slot is `0x140966160`, a jump to `RefreshHilite` `0x140966170`. The refresh requires a nonnull model Gob at anim-base `+0xc8`, then scans five flags at `+0x9c` onward and selects the first active slot. For that slot it calls Gob `+0x180=SetIllumination` `0x140094b50` and `+0x178=SetColorShifting` `0x1400948d0` with stored vectors and the anim-base alpha at `+0xd8`. These setters publish Gob material fields and may raise propagation events. If the corresponding highlight flag at anim-base `+0xb0` onward is set and an area Scene exists, the refresh checks Gob `+0x218=GetScene` before calling Scene `+0x118=AddHighlightGob` `0x1400c3350` with the Gob and selected vector. With no active slot, it writes zero illumination and white color shift and, when the Scene is present, calls Scene `+0x120=RemoveHighlightGob` `0x1400cc600`. The Scene highlight array at `+0x80` and vector array at `+0x90` feed the already mapped `Scene::DoHighlightGob` `0x1400c8260` outline vertex and GL draw route. Thus the event reaches CPU material/highlight publication and a conditional draw consumer, with no GL call in `RefreshHilite` itself. Derived anim-base `+0x170` targets, live selected slot and Scene/highlight texture presence remain dynamic. Evidence base slot `ev_9ac456c1c77ea480da2c84a2bff27bc02105cc61cb932a6ef9b518363054a735`, refresh `ev_152b856526a80c1a3a03d13c2b1e5325a81d73a36aebe899bc724361a78b9b8c`, Scene vtable slots `ev_20cc930120741a63eb565fb049eedc63dab39714e3c3ff9ce96e3581becf1fbe`, add/remove bodies `ev_c5b175b109f300f5c9dfad07d6b9a6415f11776a92f5e65a313b72a6bf41e71c`, `ev_3dd8f27d1bcb607aae4cc2868ffb6f811a95ca1484db5ea989ba1e312dd1789c`, Gob setters `ev_8ce615802292d08f85dd2cfae93c7182dcf3ead583e98db2024e519740698b02`, `ev_97a3aa5e161e3861b18559ef87c10385042039ffa678062b4026a4b5a609f9ae`; highlight draw consumer is linked in [scene auxiliary passes](scene-auxiliary-passes.md).

The constructor-backed `+0x170` slot has an additional equipment path. Base, TW, Head and VisualEffect animation-base vtables `0x140e6e978/0x140e74980/0x140e74c88/0x140e78590` point to `0x140966160`. Wield `0x140e74fe8` points to adjustor `0x14099cbf0`, while HeadWield `0x140e75280` and Parts `0x140e755e8` point to adjustor `0x14099dd80`; both derived entries reach `0x14099cc00` then `0x14099cb00`. ## `draw_weapon` to item Gob attachment

The registered `SwitchWeaponEvent` body `0x14080e9d0` looks up both equipped item object IDs, rejects the observed excluded item flag, reads `WEAPONSCALE` from a rules 2DA row when available, obtains each item model Gob through the item's animation-base virtual `+0x140` with selector `0xff`, and calls virtual `+0xc8` on the creature animation model at creature `+0x78`. Its chosen attachment name is `rhand`, `lhand`, or `lforearm`, with a null/empty name to clear one side; item/base-type and model presence determine the branch. The accessor at `0x1407630a0` only returns creature `+0x78`.
