# NWN-75: archive metadata and file lifetime for source classes 1/2

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are PE virtual addresses. This supplements the [key-table source-1](gui-keytable-archive-provider.md) and [encapsulated source-2](gui-encapsulated-archive-provider.md) read maps. It traces metadata loading at provider construction, demand-time reopening, and file close to CRT and Win32 boundaries. It does not assign either source to a particular GUI resource.

## Construction and metadata reads

`AddFixedKeyTableFile` `0x14018e300` calls `AddKeyTable` at `0x14018e31d` with builder kind **1**; `BuildNewTable` `0x14018a690` dispatches to `AddKeyTableContents` `0x140189280` at `0x14018a7e4`. The builder tries `.key` (`CExoFile` extension id `0x270f`) at `0x1401895d0`, `0x1401896ac`, or `0x14018976a` as the path/alias branches permit. A successful `FileOpened` leads to a 0x40-byte KEY header read at `0x1401897e0`. The code checks `KEY ` magic (`0x2059454b`), V1/E1 version (`0x20203156`/`0x20203145`), and a nonzero table count. It allocates the key hash and archive-provider array at key table `+0x50`, seeks to the file-table offset and reads its byte block at `0x140189b52`/`0x140189b64`, then seeks to the key-entry offset and reads each ref/type/id record at `0x14018a021`, `0x14018a051`, `0x14018a06a`, `0x14018a080` and, for E1, `0x14018a0a2`. The 0x40 header and file-table short-read comparisons emit warnings but do not themselves force an exit at those sites. The provider object receives vtable `0x140da1298` at `0x140189c03` and is published in `+0x50` at `0x140189c25`. Its virtual `+0x48` metadata loader is attempted at `0x140189e48`; a failed first attempt takes an alias/fallback path and attempts it again at `0x140189f41`. The builder later deletes its open KEY `CExoFile` while draining the temporary table-info list through virtual slot zero at `0x14018a169`. REA `ev_9be495966491f516145314e4ce7ec21f7f00a430a5224e2898f0fa0c8348705b`.

`CExoResFile::LoadHeader` `0x14018bd80` returns immediately when `+0x30` says loaded. Otherwise it opens a **temporary** `.bif` `CExoFile` (extension id `0x270e`, mode `rb`) at `0x14018be37`, checks `FileOpened` at `0x14018be65`, caches file size at provider `+0x1c`, and reads a 0x34-byte BIFF header at `0x14018be9d` into `+0x40`. It requires `BIFF` magic (`0x46464942`) and V1/E1 version (`0x20203156`/`0x20203145`); an E1 OID is compared when the caller supplies one. For a nonzero variable-resource count, it allocates `0x18 * count` bytes at `+0x48`, seeks to header offset `+0x10` at `0x14018c032`, then either reads V1 `0x10 * count` into temporary storage at `0x14018c072` and expands entries with CPU copies (`0x14018c0b2`), or reads E1 `0x18 * count` directly at `0x14018c12c`. Header/table short reads are logged but the allocated valid-magic path can still set `+0x30 = 1` and return 1. The temporary file is deleted at `0x14018c19f`; metadata remains resident for demand-time size/read. REA `ev_cc749a1dbf3120d6e572a1b73054b9411da3066e61dc8559116cebe2a1c195f6`.

## Frontier

This is a static, conditional source-class path. It does not reveal a live resource's selector, resolved alias/path, archive type, cache state, successful byte count, or whether a particular frame opens or reads a file. The prior provider supplements map the plain-entry read to CRT buffering and the conditional `ReadFile` boundary; compressed-entry routes are separate. The short-read warning paths above are recorded as observed control flow, not evidence that malformed archives are accepted safely.
