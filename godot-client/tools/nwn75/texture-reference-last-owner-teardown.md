# NWN-75 texture reference last-owner teardown

Pinned original `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This is a conditional lifetime continuation of [texture acquisition](texture-acquisition.md) and [texture consumer binding](texture-consumer-binding.md), not a claim that draw-time binds release textures. Exact sites are in the companion ledger.

`AurTextureGetReference` `0x1400e8b60` first resolves a named texture with `AurTextureGet` at `0x1400e8b79`, then calls the same function with a null name and the resulting pointer at `0x1400e8b96`. That second route constructs a `0x28`-byte `CAurTexture` wrapper at `0x1400e8822` and assigns its `SafePointer` at `+0x18` to the resolved texture at `0x1400e8831`. The assignment registers a back-reference in the target's list; the wrapper itself does not load an image or publish GL. The named lookup can return an existing Basic texture or allocate a new one under the already mapped `AurTextureFind` gates. Evidence: `ev_75368d94af22e27b50b2177d95fe61232ce2fad1041ccdff4e4806e4f84764d8`, `ev_58e32829c45065d42dbb23e27380ac551464fb5b01ef76a91a9f508a9abccc9b`.

`AurTextureRelease` `0x1400e9130` returns for null input or a nonzero `CAurTexture+0x10` safe-pointer count. With zero count, it tests virtual `+0x8=AsCAurTextureBasic`; a Basic result is tested again and then receives virtual slot zero deleting destruction if still nonnull. A wrapper's base `+0x8` is null, so its slot-zero target `0x1400e5500` calls `CAurTexture::~CAurTexture` `0x1400e50e0` at `0x1400e550f` and frees the wrapper when the deleting flag is set. The base destructor removes its `+0x18` registration from the referenced texture's back-reference array, repairs the moved entry index, and clears its pointer. Only if that target's resulting back-reference count is zero does it call the target's `+0x8` at `0x1400e516f`; a Basic target reaches its slot-zero deleting destructor at `0x1400e5192`, whereas a base target can reach slot zero at `0x1400e519d`. The target's exact runtime class and any other owner registrations remain conditional. Evidence: `ev_81aa31c1cafb1d49fb6045694e26323301d59edc2a084b26ff9e41a10b51b3c6`, `ev_987f349bc4ab0d589c5ffc0a5c4fb61108045228c6301526e7cd9f25a8937b37`, `ev_0aac477adc6d35c2f3e9932058943a17ab03ff7e4ca528f9383393469211a78c`.

The Basic deleting destructor `0x1400e5540` frees its auxiliary fields and controller through virtual slot zero when present. With a nonnull texture-ID array `+0x50`, it passes the ID count `GetNumX*GetNumY` to `RenderInterface::DeleteTextures` at `0x1400e55b5`; the wrapper and GL body eventually call imported `glDeleteTextures` under the previously mapped path. It releases a remaining CPU raster through direct free or the installed ordinary/layered release callback, then removes the Basic object from the ordered list at `0x1400e5647`, the static-or-dynamic list at `0x1400e5667`, and the pending `RefreshTextures` list at `0x1400e5677`. Finally it calls the base texture destructor at `0x1400e5680` and conditionally frees the Basic allocation. `SafePointerList<CAurTexture>::~SafePointerList` `0x1400e5010` clears any remaining observers and frees its list storage; it has no direct GL call. This closes the wrapper-to-Basic last-owner cache removal and conditional GPU deletion chain. Controller subtype destruction, resource callback ownership, and actual live owner count remain dynamic boundaries. Evidence: `ev_31dcfb139dc14fbf306ad7cf7a24579778f8be9aa7acd2edb576d5b90026413d`, `ev_cb440e5e5d69c83a364eb1be91240da54574a4ec2fd88301ca4648377714d20e`.
