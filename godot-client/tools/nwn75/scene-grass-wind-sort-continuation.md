# NWN-75: active grass wind and sort continuation

Pinned original `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. The [BSP active-bin route](scene-bsp-visible-callback.md) collects candidate grass bins, and [Scene pass order](render-single-pass.md) reaches `Scene::DoBinBucket` `0x1400c7580` before its cap bucket. This note follows newly closed CPU wind and sort descendants. It does not assert a live grass population or measured frame cost.

`DoBinBucket` first requires Scene virtual `+0x288=GrassIsEnabled`; its direct call `0x1400c7722` then invokes `CAurTriangleBin::UpdateGrassForWind` for every entry of active `_binbucket` with positive count `0x14140b0c0`. Each bin loops its triangle lists at `+0x38/+0x40`, calling `CAurTriangleList::UpdateGrassForWind` at `0x14006deeb`. The latter calls current Scene virtual `+0x280` at `0x14006df2a`; the constructed Scene table `0x140d8dd30` holds `Scene::IsAnimating` `0x1400cafe0` at slot `0x140d8dfb0`. It returns unless animation is enabled **and** the list VDO pointer `+0x48` is nonnull. This means the bin/list calls can still run on a grass-enabled, nonanimating Scene, but the per-entry writes and commit stop at the list gate. On that admitted list path, `UpdateGrassForWind` caps `DeltaT` at `0.1`, reads grass strength from the active material-indexed grass table, gets VDO dynamic item data at `0x14006dff8`, and samples `WindManager::GetGlobalWindNoPoint` once at `0x14006e054`. It walks the list's `+0x58` dynamic-entry count with a 72-byte stride. When `fastwindongrass==0`, it repeats the global-wind sample at `0x14006e12b` for each entry; otherwise it reuses the first sample. It calls `WindManager::GetGlobalPointWind` at `0x14006e164` for **each** entry, updates position-like and displacement-like floats in the dynamic item, and calls `VertexDataObject::CommitItemDynamicData` once at `0x14006e28b` after the loop. The commit is outside the positive-count loop, so an admitted list with zero entries still reaches that helper; its actual pool/GL publication remains conditional on the shared VDO/pool state. `GetGlobalWindNoPoint` samples/interpolates the WindManager's two 16×16 fields. `GetGlobalPointWind` enters `pointSourceWindVector` at `0x1400f1551`, which scans the current point-source array `+0x10/+0x18`, rejects source boxes/spheres that do not contain the sample, and for accepted sources uses CPU square root, normalization and vector accumulation. No GL call appears in these wind helpers. The caller loads comparator code label `0x1400c5980` at `0x1400c779c`. Its exact 13 bytes `f30f1041080f2f42080f97c0c3` compare bin `+0x8` with `COMISS` and return true when the first is greater, so the enabled sort orders farther bins before nearer bins for ordinary finite values. The sort uses insertion for fewer than 33 entries, recursive median partition for larger sets, and heap fallback on exhausted depth budget; its comparison count depends on bin count and order. The sorted active-bin array is then scanned under each in-use grass material and passed to the already mapped `CAurTriangleBin::RenderGrassPolys` draw route.
