# NWN-75: VP8 decode worker to movie frame presentation

Pinned `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are original PE virtual addresses. Ghidra pseudocode is decompiler evidence, not source. This supplement follows the movie's conditional decode worker into the synchronous frame getter and the two existing presentation routes. It does not establish a live movie in a gameplay frame or an OS thread ID for the GL context.

## Codec and worker ownership

`CExoMoviePlayerInternal::Initialize` `0x140233100` calls `InitializeCodec` `0x140233630` only after its stream probe succeeds. The latter opens a `nestegg` container, identifies video/audio tracks, obtains interface pointer `0x140ee2090` from `FUN_140024af0`, and initializes one VP8 decoder context at codec block `+0x58` and an optional second context at `+0x90`. The interface string is `WebM Project VP8 Decoder v1.4.0`. Original PE pointer slots `+0x38` at `0x140ee20c8` and `+0x40` at `0x140ee20d0` contain decoder `0x140023cf0` and frame getter `0x140024370`. The wrappers `0x1400234e0` and `0x140023540` call those slots only when their context/interface fields are nonnull. On first decoder setup, `0x140023cf0` calls worker initializer `0x140027420` at `0x140023ee9`. It enables parallel rows only when the minimum of `8`, decoder `+0x4324` and `+0x3488` exceeds one; it then creates `count−1` worker threads with `_beginthreadex` at `0x1400276a0`, each entering `0x140027360` with a worker index and the same decoder state. A worker waits on its indexed `+0x4398` semaphore and calls row decoder `0x140026390` with index `i+1` after a start signal. Otherwise decode remains on the caller path. Evidence decoder `ev_49581dfc56eb2c49a184b6dca57a044519887689762f2e7922143bf84e0f782c`, worker initializer `ev_ef0aef578738504482d367cbe0df227434274e816485e21f448673ab2d7792f8`, worker entry `ev_1d13243fd0dd6b8eeaf1b549f416b29411d5b80bd61729d91873d8dc311cf608`.

For an enabled parallel frame, decoder `0x140023cf0` calls `0x140025430` → `0x14002d3e0`; under decoder flags `+0x4320!=0` and `+0x3484!=0`, that calls `0x140028080`. The latter releases each worker start semaphore at `0x140028514`, decodes row zero itself through `0x140026390` at `0x14002852d`, then waits indefinitely on completion semaphore `+0x43a0` at `0x140028556`. The worker's final-row path releases that completion semaphore at `0x140027343`. The alternate `0x14002d3e0` branch calls serial `0x14002c390`. This is a **synchronous codec handoff**: worker writes are to shared decoder frame state, and the decode call cannot return from this branch before the completion wait succeeds. No OpenGL call was observed in the worker or row decoder. ## Frame transfer and texture publication

`CExoMoviePlayerInternal::RenderFrame` `0x140233980` requires codec block `internal+0x20`. It calls `UpdateMovie` `0x140234210` and, while no frame is returned and end flag `+0x28` remains clear, optionally delays to the next frame timestamp and retries. `UpdateMovie` first gates on end, pause/timing state and a nonnull codec block, then reads a `nestegg` packet. For video packets it conditionally decodes an additional data plane through context `block+0x90` when track field `+0x34` is set, and decodes the ordinary packet through context `block+0x58`. After each successful decoder call, `FUN_140023540` invokes the VP8 frame getter `0x140024370`; that getter returns a frame only when decoder frame-ready state is set. This frame pointer is the handoff from synchronized codec state to the movie updater, not a separate worker-to-GL queue. Packet exhaustion sets end `+0x28`, except for the loop/seek branch that resets clock fields and continues. Evidence `RenderFrame` `ev_38fcfc901015460d4ce6c6a208e53e484c76c1709e098a17b9d73defb8ce26d7`, updater `ev_f8c4b2066951eb65fc05a0a66a5e5adedc4f54fc6fa08fd96f9d3ac62f9f0f2c`, getter `ev_d4ac39e185b32fb37fb2cb0c600f2b1519f625f99e4b2699cada95d26b1345d5`.

For each returned frame, `UpdateMovie` calls CPU pixel conversion `0x140bb8b10` with the frame planes and writes the movie block's output buffer `+0xd8`; the two branches pass distinct output-format constants for the ordinary and additional planes. It binds texture ID `internal+0x78`, chooses a format by `RenderInterface::GetColorDepth`, and calls `RenderInterface::DirectCreateSubTexture` `0x1400be9c0` at `0x1402344a3` or `0x14023461f`. That thunk jumps to `GLRender::DirectCreateSubTexture` `0x1400b0020`, which calls imported `glTexSubImage2D` at `0x1400b0117`. `Initialize` creates the texture and allocates its storage once the codec block is available; the update path changes its pixels. This work executes on the `UpdateMovie` caller after synchronized decode; the decoder workers do not publish to GL. Evidence updater `ev_f8c4b2066951eb65fc05a0a66a5e5adedc4f54fc6fa08fd96f9d3ac62f9f0f2c`, conversion `ev_61c011d166c36e4ec64a16ed0a9313f3a4e9fe860651499201f4edb518e95273`, upload thunk `ev_67a9d11aba5abec9c7d0058c3cf9636ae7a7f7d90ef9fec5b10ebc509bbf5cf4`, GL upload `ev_a90dc9acfb64f5c54b5090f8f3e86571ca479767d70f93ff1a00921c55225207`.

The direct-show byte `internal+0x0` gates `ShowFrame` `0x140233b20` after upload. When true, `ShowFrame` clears the frame, installs an orthographic transform, rebuilds a four-vertex static movie quad only when dimensions change, and calls `RenderInterface::RenderVertexData` `0x1400beec0` at `0x140233ea1`; its GL target `0x1400b59b0` reaches imported `glDrawArrays` at `0x1400b5bcb`. `RenderFrame` then calls `EndScene` and `SwapBuffers` at `0x140233a75/0x140233a81` and returns whether end `+0x28` remains clear. The [direct movie entry](movie-presentation-entry.md) maps the outer client gate and subsequent completion cleanup. Evidence `ShowFrame` `ev_1cb899297af2b5bcbf7116d707d917736c1b713d3be8b7d9da99fbf754489f6e`, draw thunk `ev_fd1063f9bc1ced526a102710e50b6f337f53a992d3754352083991b176eb3843`, GL draw `ev_8e9e440e5c5b0a364b9a6d1d9a76e16c1b4aa69d7c12cefc9a356392c92a273f`.

The [Nui movie widget route](nui-movieplayer-presentation.md) calls `UpdateMovie` with constructor-backed direct-show byte false. It still decodes, converts and uploads the texture, then presents it as a Nuklear image during the GUI draw pass; it does not use the `RenderFrame` swap path. The byte is set by constructor/Initialize; other writers or active widget frequency are not inferred here.

## Teardown boundary

The VP8 interface's `+0x18` slot points to `0x140023a00` → `0x1400257e0`. One movie-owner connection is proven: `InitializeCodec` calls context initializer `0x140023300`; if its decoder initialization callback fails and the context/interface remain nonnull, the initializer calls interface slot `+0x18` at `0x140023404` (`ev_a6ac67be52604321d3b4e203ab801e6fadc5afccdfa58c6379c0c7478a834365`). When invoked on an active codec, this destructor clears worker flag `+0x4320`, releases their start semaphores, waits on each thread handle, closes handles and frees worker arrays (`ev_04c6ae42102dc2be40c4c136aa8d2cfc036bb1379760d4a0b1eafc6f2e4f9ffd`). This proves the interface's worker teardown behavior, not that the movie's normal shutdown calls it.

`CExoMoviePlayerInternal::~CExoMoviePlayerInternal` calls `ShutDown` `0x140233f50`. Under its initialized-object gate (`internal+0x8`), `ShutDown` stops audio, frees the output buffer, releases the raw `0x348`-byte codec block through `0x140c10360` at `0x14023412c`, clears `internal+0x20`, and deletes the GL texture through `RenderInterface::DeleteTextures` at `0x14023413e` (`ev_907955a4719e9030a48d7731d82eb286e7548c6975f642f544fee359361d1562`). Its complete direct body contains no codec interface destructor dispatch. The normal successful-movie shutdown to VP8 worker teardown is therefore a bounded unresolved frontier; no such edge is added to the ledger. This does not establish a runtime leak or the exact process-exit behavior.
