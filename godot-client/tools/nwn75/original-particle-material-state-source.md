## Conditional graphics-state leaves

After the live-count/lifespan gates and texture binding, `RenderEmitter` reads source `twosidedtex +0x168` at `0x140062efc`: zero calls `RenderInterface::Enable(3)` at `0x140062f0c`, nonzero calls `Disable(3)` at `0x140062f05`. Aurora state `3` is culling. The cached wrappers issue `glEnable(GL_CULL_FACE)` or `glDisable(GL_CULL_FACE)` only on a state change; an unchanged state is a CPU bit check. It then reads instance blend mode `+0x68` at `0x140062f11`. Mode `1` disables blend, enables Aurora lighting and depth writes (`0x140062f19/0x140062f23/0x140062f2a`); modes `0/2` disable Aurora lighting, enable blending, disable depth writes, and call `SetBlendFunc(0,1)` or `(0,2)` (`0x140062f36/0x140062f3d/0x140062f44/0x140062f56`). Lighting state `1` marks shader state dirty here rather than directly calling GL. The blend/depth wrappers reach `glEnable`/`glDisable`, `glBlendFunc` and `glDepthMask` only when cached state changes. These state calls precede stream creation and the later shader-null/draw gate, so they can execute without a successful draw.
