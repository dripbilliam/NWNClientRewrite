## Animated and dangly meshes

`PartAnimMesh::Draw` `0x1400a2150` returns for an inactive Part or missing/empty source mesh. An ownerless Part pushes and transforms the current matrix, calls inherited `+0xf8=PartTriMesh::MatStatic` `0x1400a3270`, then pops the matrix on exit; an owned Part calls `+0xc0=PartTriMesh::Mat` `0x1400a2f50`. The primitive at Part `+0x90` calls `+0x30=VertexPrimitiveFlat::SetupArrays` `0x1400abca0`. The branch enables/disables shader feature `0x11` according to its color pool and current only-Gob light, then chooses `RenderBumpyShiny` when its material and water setting permit, otherwise environment mapping or `RenderFlat`. Each branch obtains primitive `+0x8=AsVertexPrimitiveFlat` `0x14008c520`, a self-return. The primitive constructor vtable `0x140d8ac08` fixes the `+0x8/+0x30` targets. All ten direct and six computed callsites are in the scene ledger. REA `ev_af0dc0ec216d1bfe53502cdf2a71b5606c68205eb2491247c745a2d60383aa76`; primitive slot bytes `ev_a42949c1b4dd72762ce7050ad9a93fe48601a6145296e778c32210afc7e6de32`, `ev_4dcae03b5bb8b950c685a0b79fcf2442a795324cea5c9195cb2982a7853788f2`.

`PartDanglyMesh::Draw` `0x1400a22d0` has the same inactive/empty-source gate and inherited static/dynamic material split. It additionally calls inherited `+0x118=PartTriMesh::TransformTextureMatrix` `0x1400a4930` before primitive setup and `+0x120=PartTriMesh::RestoreTextureMatrix` `0x1400a4880` on each of the bumpy, environment and flat exits. The original Dangly vtable base `0x140d88698` resolves those slots; its primitive `0x140d8ac58` resolves `+0x8=AsVertexPrimitiveFlat` and `+0x30=SetupArrays`. A nonzero texture rotation at Part `+0xb8` pushes an identity/rotated texture matrix and advances generation `DAT_1413d274c`; restore pops it and advances the same generation. This is CPU matrix staging for a later shader uniform, with conditional vector growth and no immediate GL call in the transform/restore bodies. The three tail-jump restores at `0x1400a23f9`, `0x1400a2440`, `0x1400a2467` are recorded as separate site-backed edges. REA Dangly draw `ev_6edb203293b6c9e3206107fc3cc8a3585e45547c8f52be9ee39408fd43e343ff`, texture transform `ev_96508067c7fb52aa3cce852ce71d978f1c7bb99f82690a45d37179f17ee9402b`, restore `ev_a0f6aa543240133b1b4fb707036414a4024b0a6b894437488145dc4a33b50e3e`.

Both mesh variants join the existing `RenderFlat`/environment/bumpy primitive path through [geometry and draw boundary](geometry-and-draw-boundary.md). Their material branches are in [material draw state](material-draw-branch.md). The exact authored mesh/material mix remains a runtime question.

## AABB, beam, shadow and trigger

`PartAABB::Draw` `0x1400a1c70` is gated by a nonnull current Scene and Scene flag `+0x1e0`; it returns during ordinary frames with that flag off. Its first-use static initializer `0x1400a2640` creates a 128-byte colored pool. A valid AABB mesh locks source positions and that color pool, obtains/grows a vertex stream, groups faces by packed color, and for each group submits two stream draws with opposite front face and complementary RGB before restoring render states. This reaches `GLRender::RenderVertexStreamData` → imported `glDrawArrays`/`glDrawElements`, subject to the flag and mesh data. The body has 27 direct callsites in the ledger, with no unresolved computed site. REA draw `ev_1fe5ea042492324d181eedf5fbe87c6158751dafda0970e301ec931fcad25635`, first-use initializer `ev_9747f8571d0765a2b4dcd6a9912c6179a69da465f605c0b4ca30b734fdbfee0a`.

`PartBeam::Draw` `0x1400a22a0` and `PartShadow::Draw` `0x1400a2490` each make one direct `RenderInterface::RenderVertexData` call with their stored VDO `+0xa0`, **VDO item ID** `+0xa8` and primitive type 4. `PartProjection::~PartProjection` passes that same `+0xa8` value to `VertexDataObject::RemoveItem` when it is not `0xffffffff`; the element count belongs to the selected VDO item. The draw joins the mapped indexed/nonindexed boundary if the VDO item is usable. `PartTrigger::Draw` `0x1400f0210` requires nonzero `parttriggeralpha + PartTrigger+0x74`.
