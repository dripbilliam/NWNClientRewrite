This lists twelve direct or tail-jump sites in the pinned executable. It is not a completeness claim for computed calls or an execution-frequency count. Further REA analysis is needed for unnamed callers, and runtime corroboration is needed where active branches or thread identity are ambiguous. The area-handler sites are also being followed in the scene ledger; other caller rows remain explicit frontiers.

The [alternate-screen ledger](alternate-screen-ledger.json) records all twelve sites, the client-to-fade-helper connector and the helper-to-loadscreen-panel connector. The ledger's conditions retain unknown branch gates; none of these sites establishes a per-frame present count.

The cleanup callback can reenter this screen route from scene destruction. `SDL_main` loads the function address with a RIP-relative `LEA` at `0x140046c2a` and stores it through `MOV [RIP+displacement],RAX` at `0x140046c37` into global `0x14128ebf8`. `DeleteNonGobParts` `0x1400d9100` has six indirect `FF 15` callsites through that same global (displacement fields `0x1400d9134`, `0x1400d9174`, `0x1400d91e6`, `0x1400d9248`, `0x1400d92a8`, `0x1400d9308`). The installed `.data` initial value of that global is `0x1400bf480`; `SDL_main` overwrites it with `NWMainSceneCleanupCallback` before normal area work. The original bytes connect the normal install → scene teardown callback → conditional `UpdateScreen`; they do not show how often cleanup invokes the callback in an Arelith session. The initial/default target at 0x1400bf480 is a tiny `RET 0` stub (`c2 00 00` followed by `cc` padding), so it performs no cleanup callback work until replaced. `scan-rip-references.cjs` with target `0x14128ebf8` reproduces the seven store/call references; `scan-pointer-references.cjs` with target `0x1400bf480` shows the initial value.
