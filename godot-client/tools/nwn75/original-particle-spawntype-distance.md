## Source field and instance handoff

In the text model path, `MdlNodeEmitter::InternalParseField` `0x14009a030` compares the field name with `spawntype` at `0x14009ac1b` and, on equality, calls `Parse(char const*, int&)` `0x1400a0280` at `0x14009ac36` with destination node `+0xb4`. `Parse` first scans `%d`; if that fails, it recognizes `TRUE` as `1` and `FALSE` as `0`. The emitter-node constructor `0x1400875a0` writes a default zero to `+0xb4` at `0x14008760b`. This is an integer selector; the observed Fountain code distinguishes zero from every nonzero value, without a further enum dispatch. The compiled model path has the same source field. `FUN_14007abe0` `0x14007abe0` selects serialized node type `5` (the compared original four bytes at `0x140d86860` are `05 00 00 00`), reconstructs the emitter node, then loads serialized `+0x84` at `0x14007b16f` and stores node `+0xb4` at `0x14007b175`. Its method table includes `MdlNodeEmitterControl` and `MdlNodeEmitterCreateInstance`. Evidence `ev_84972c82b2b72d9d3febb9c48d59aea19eff280be68bdbc6c1b6f8ef0d1c9147`, type bytes `ev_1d7a84775298ad17d5fe85743f90356bfa9b9a1776b9ea5db859537f9112bd51`.

`MdlNodeEmitter::InternalCreateInstance` `0x1400621f0` compares the authored update string at source `+0xb8` with `Fountain`, constructs `PartEmitter` and installs the Fountain vtable, then calls virtual initializer `+0xf8` at `0x14006237c`. `Part::Part` stores its source `MdlNode*` at Part `+0x8` at `0x140087d91`, so the later Fountain update reads the exact instantiated source node. Birthrate is a separate controller: `birthrate`/key/bezier entries target Part `+0x74`; `MdlNodeEmitter::InternalControl` calls base controller sampling and publishes the value there during animation. The text and compiled controller routes are mapped in [Lightning source publication](original-particle-lightning-source-publication.md) and apply to the shared emitter source. ## One frame through the nonzero selector

`Scene::DoEmitterBucket` calls `PartEmitter::AnimateParticles` at `0x1400c7c94` when Scene animation or the owner Gob force-animation gate admits it. `AnimateParticles` derives current and previous emitter pose and caps its delta at `0.5`, then calls subtype virtual `+0x100` at `0x1400615bf`; the installed Fountain vtable resolves this branch to `FountainEmitter::Update` `0x140064b30`. The update reads birthrate `+0x74` at `0x140064b91`, recycles expired particles through `chkParticleLife` at `0x140064bd9`, advances old particle rotation, and calls the instance movement callback `+0x170` at `0x140064cfa`. Only after movement does the spawn gate convert birthrate to an integer at `0x140064cfc` and return when it is nonpositive at `0x140064d03`. Thus a positive fractional birthrate below `1` does not enter either spawn scheduler on that frame. Evidence Scene `ev_b4881207528882fb849869474dcd3a31c18cf9f00dad89280e126d85fcdd7ed3`, animation `ev_94298fdbef50a777edca20b8e740cf4bb6069376493f19ec2c974abe89f3eb53`, Fountain `ev_8d49308bf3baade8551d571633fd403d485118bc9ddd9dc8cfd63cefb1b6e0cd`.

The branch at `0x140064d12` tests source `+0xb4`: zero jumps to the time accumulator at `0x1400650d1`; **any nonzero value** takes traveled-distance scheduling. That branch forms displacement `current emitter position (+0x1e0..+0x1e8) − previous position (+0x19c..+0x1a4) + carried residual (+0x164..+0x16c)` at `0x140064d20..0x140064d68`. It calls the scalar square-root helper at `0x140064d94` for the displacement length, derives a normalized step when length is positive, and truncates `length × birthrate` to an integer at `0x140064de8` when the positive-rate flag permits it. The square-root helper reaches hardware `SQRTSS` at `0x140c7d76c` for ordinary nonnegative input, with exceptional floating-point handling in the same helper. This is a CPU math leaf, not a GPU operation. Evidence Fountain above, square-root helper `ev_82580b3b061fc08e0dda0f6c5e9a381cec22879dc7f5839a166bce80d8f3a893`.

For each scheduled particle, the update takes a recycled pointer from `+0x130/+0x138`, or tests source `chunkName` `+0x158` at `0x140064e66`: empty constructs `Particle` at `0x140064ebb`, nonempty constructs `ChunkyParticle` at `0x140064e90`. The virtual initialize call at `0x140064ed4` resolves through the constructed particle's vtable to `Particle::initialize` `0x140066450` or `ChunkyParticle::initialize` `0x1400663d0`. The latter calls the former at `0x1400663e9` and may publish its attached model Gob through virtual Scene/animation/event operations; the model construction branch is mapped in [particle lifecycle](original-particle-effect-lifecycle.md). Base initialize uses random position, inherited velocity and random direction helpers according to authored fields, and its random calls reach the per-thread CRT generator `0x140c7ed00`. After initialization, the distance branch appends the pointer to live list `+0x188/+0x190` at `0x140064f36/0x140064f3a`, then calls `chkRandom` at `0x140064f56` for optional authored random atlas selection. `chkRandom` calls the same CRT generator at `0x14006610c` when source flag `+0x174` bit `5` admits random start. It positions the spawned particle along the traversed segment at `0x140064fe2/0x140064feb` or `0x140065040/0x140065049`, then stores unconsumed displacement back to `+0x164..+0x16c` at `0x1400650ba/0x1400650c6`. Evidence Fountain above, particle initialize `ev_6e072379e7c8ab3444fd75c3c2427a822035b68918abb247d9747090214e118c`, Chunky initialize `ev_65645e3fdedf1bc0e299e49d0f38911da109e38bf8004db95233c840fd213747`, atlas selection `ev_0d319e3bfd443ed59db1b8f7bc74500510aa112b058457cd319f65fa205f0dba`, generator `ev_95cdd088fd6dcb5f6e18adf92c290ea96578aa8174ff5274f2a6d552200fa6c4`.

This live-list publication is consumed by `Scene::DoEmitterBucket` later in the same emitter bucket. It sorts eligible emitters, invokes their installed render callback at `0x1400c7dae`, and the shared RenderEmitter branch can upload a vertex stream and reach imported `glDrawArrays` through `GLRender::RenderVertexStreamData` if texture, shader, fade and live-count gates pass. A nonempty `chunkName` instead installs `RenderNothing`, which updates attached Gobs rather than drawing particle quads; their later Scene admission is separate. Those exact render descendants and gates are in [emitter render callbacks](original-particle-render-callbacks-fountain.md).

## Dynamic boundary

Static evidence does not establish which installed assets choose nonzero `spawntype`, their actual controller birthrate, displacement per frame, recycled particle population, active movement callback, allocation success, or whether a live particle reaches the GPU draw gate. The movement call at `0x140064cfa` is computed from PartEmitter `+0x170`; `Initialize` installs standard movement or one of two point-to-point callbacks based on source flags. The particle initialize call at `0x140064ed4` is virtual but constructor-bounded to Particle/Chunky for the fresh-allocation route; recycled pointers are runtime contents. The ledger preserves these computed edges explicitly instead of turning them into unconditional calls.
