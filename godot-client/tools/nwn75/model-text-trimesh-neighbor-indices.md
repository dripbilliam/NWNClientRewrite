# Text TriMesh neighbor and index construction

The [ledger](model-text-trimesh-neighbor-indices-ledger.json) continues [ProcessVerts](model-text-trimesh-processverts.md) under `MdlNodeTriMesh::InternalPostProcess` `0x1400a9ae0`. It calls `BuildNeighborLists` `0x1400a5a10` at `0x1400a9b39`, then `BuildVertexIndices` `0x1400a5e20` at `0x1400a9b41`, only inside its positive-face-count branch after vertex count `+0x284` was zero. The subsequent vertex-stream builder is [mapped separately](model-name-parser-tree.md). Caller evidence `ev_4161d5fa56b2eb3cd8578eb37a7bcd27fa4d9ca5f63bb94e1ab33c37fabc3d19`.

`BuildNeighborLists` (REA `ev_dc6fc9c1211018dce4dc61475a27ac8b903bad30efea407d0789788492a2b4e6`) iterates every 0x20-byte face from the postprocess list, computes a plane normal through `NormalOf` `0x14022d960` from authored positions and writes plane data to the node face list `+0xb0`. For each of the face's three edges it scans other faces, skipping itself, and compares their three vertex-index slots for a matching edge. It writes a 16-bit neighbor face index into the node face's three neighbor slots, or `0xffff` when none is found. The visible algorithm is a nested face scan per edge; its count therefore grows with face population, but no runtime timing is implied. It reaches CPU math and face-list writes, with no resource or GL call.

`BuildVertexIndices` (REA `ev_531084ce51347df271618035ffa1af04c899ac851d360df7c073a1edb107715f`) allocates a temporary `face_count × 3` 32-bit index array from node face corner indices, appends that array to node pointer list `+0x228/+0x230`, and appends the corresponding count to `+0x248/+0x250`. For each index list, including any previously authored `vertexindices`, it calls `RenderInterface::RequestPool` `0x1400beee0` at `0x1400a5fe2` for a kind-1 index pool sized at `2 × index_count` bytes, stores its handle in node list `+0x258/+0x260`, then `LockPool` at `0x1400a6064`. It copies the low 16 bits of each source 32-bit index into the locked pool and calls `UnlockPool` at `0x1400a60ba`. It frees temporary source arrays and clears the pointer list afterward; it also sets `+0x268=0xffffffff` and `+0x26c=0`. Pool unlock reaches conditional GL buffer allocation/upload through the shared [geometry boundary](geometry-and-draw-boundary.md); pool state and actual upload are dynamic. The 16-bit conversion is observed in this builder, not a claim that every authored index fits.

Neither function enqueues a worker. Static code does not identify its invoking OS thread or active model/face count. The neighbor stage is CPU-only; the index stage crosses the shared conditional pool-to-GL boundary before [vertex-stream publication](model-text-trimesh-vertex-streams.md), [tangent-basis and possible vertex-split work](model-text-trimesh-tangent-pools.md), and later Scene draw admission.
