`CExoResMan::Update` starts an instrumentation scope and reads a microsecond timer. Only after more than 1,000,000 microseconds since its static last-check value does it iterate the currently registered key-table array. It considers a table only when `+0x68` is nonzero and its rebuild-in-progress field `+4` is zero. Each eligible table gets `CheckForModificationsInStorage` `0x14018a7f0` at `0x140195977`. That helper checks table kind `2` and `+0x78` before invoking the imported `_stat64i32` on the stored directory path. Its first successful stamp seeds `+0x80`; a later changed stamp updates `+0x80` and returns `1`. A failed stat or unchanged stamp returns `0`. These are table-content and filesystem gates, so the installed code does not prove a rebuild every second. The `+0x68` gate is set by `CExoKeyTable::SetAllowDynamicReload` `0x14018d0a0`, called from `CExoResMan::AddKeyTable` at `0x14018e678` after a successful build. On a changed stamp, `Update` calls `DropContentsFromCache` `0x14018ad30` at `0x140195983` and `RebuildTable` `0x14018ccf0` at `0x14019598b`. DropContents walks old entries and clears `CRes+0x48` for attached objects.
