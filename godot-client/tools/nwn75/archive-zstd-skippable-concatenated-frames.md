# NWN-75: Zstd skippable and concatenated frames

Pinned installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This closes the outer frame loop left open by the [ordinary Zstd frame](archive-zstd-frame-sequence.md). It is a conditional XRES algorithm-2 archive path; selected asset bytes and runtime frequency are unknown.

`ZstdCompressionProvider::DecompressBuffer 0x1401aa230` calls `ZSTD_decompressDCtx 0x1409e9670` at `0x1401aa448`, which calls `ZSTD_decompressMultiFrame 0x1409e9950` at `0x1409e968f`. Its loop requires at least five remaining input bytes before reading a 32-bit magic. If `(magic & 0xfffffff0)==0x184d2a50` at `0x1409e99c3`–`0x1409e99cb`, it treats the frame as skippable. It requires at least an eight-byte header and the declared 32-bit payload length plus eight bytes to fit the remaining input, otherwise returns error `-0x48`. On success it advances the input pointer and remaining byte count at `0x1409e99e8/0x1409e99eb`, changes no output pointer, and loops. A skippable frame is therefore an input skip, not decoded resource bytes. Evidence MultiFrame `ev_04f5c3277bfd87d07322f6bf752a18e0df13c9fd613ad6e212316603320923d5`.

For an ordinary frame, the loop initializes/reset context or loads a supplied dictionary and calls frame decoder `FUN_1409e96a0` at `0x1409e9bd6`. A decoder error-size return propagates. On success it adds produced bytes to the output pointer and subtracts that count from output capacity at `0x1409e9c0d/0x1409e9c10`, keeps the decoder-updated input pointer/count, and loops while at least five input bytes remain. It calls `ZSTD_getErrorCode 0x1409e7b60` at `0x1409e9be1`; returned code 10 after a previous successful ordinary frame is treated as error `-0x48` at `0x1409e9beb`–`0x1409e9bef`. If trailing input is nonzero but shorter than five bytes, the final gate also returns `-0x48`. On exact input exhaustion it returns total produced bytes (`0x1409e9c44`–`0x1409e9c47`). The provider still requires a non-error decoder result and marks the output DataBlock used bytes; `ReadNWCompressedBuffer` must copy them to `CRes+0x20`, then source-1/source-2 service requires an exact expected length before the subtype hook. These publication gates are mapped in the linked frame note. Thus a skippable-only input can yield zero produced bytes, but it does not by itself establish a successful nonzero resource demand. Evidence provider `ev_1a7f0a6f44741d4409261c4d5708028844a0a6328caf28fd02c55194bcb9ba1c`, MultiFrame `ev_04f5c3277bfd87d07322f6bf752a18e0df13c9fd613ad6e212316603320923d5`.

Frame count, dictionary pointer, skippable payload, ordinary frame block modes, malformed input, expected resource length, subtype and later draw remain conditional. No graphics API is called in this outer loop.
