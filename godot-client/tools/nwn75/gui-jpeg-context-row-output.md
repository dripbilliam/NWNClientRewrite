# Original JPEG context-row scanline output

Pinned `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This closes the context-row frontier left by [the progressive JPEG supplement](gui-jpeg-progressive-decoder.md). The same output selector can also be reached by a compatible baseline JPEG. It applies only to the initial file-backed `ImageReadJPG` raster callback; asset data and the active callback determine runtime reachability. Exact sites and gates are in [the ledger](gui-jpeg-context-row-output-ledger.json).

## Selection and row buffer

For normal, nonraw, nonquantized, nonmerged output, the master calls `jinit_upsampler` `0x140220e20` at `0x14021ed02`. It sets fancy-mode eligibility only when `do_fancy_upsampling` (`+0x60`) is on and minimum scaled DCT size (`+0x180`) exceeds one. For a component with both horizontal and vertical sampling at half the output rates, and more than two source sample rows, the selector loads `0x140220ae0` at `0x140220f80` and sets upsampler `need_context_rows` (`+0x10`) at `0x140220f8a`. If any gate fails, it takes simple 2×2 upsampling `0x140220c60` without that flag; other ratios use their own routines. Evidence upsampler `ev_ed6a0c2bd00987172625c630b19d6f2682a237d4b31e551492b3232b9f1f3894`, fancy CPU routine `ev_d3f38c865e96463eca404702cced28cf32586d4a1a5242ac5bde28fe3cb6c4c4`.

`jinit_d_main_controller` `0x14021bf70` detects that context flag and allocates two row-pointer groups plus per-component sample buffers with extra neighboring rows. On normal output-pass start, master `0x14021ee10` invokes the main-controller start callback `0x14021c590` at `0x14021ef1a`. With `need_context_rows=1` and pass mode zero, it installs `0x14021c150` at `0x14021c5ec`, initializes row counters/state and copies boundary pointers into the double buffer. Without context rows, it installs `0x14021c4e0` instead. The master also starts the upsampler and post controller before the main controller. Evidence main allocation `ev_1df01cd68fd0b3f8976de4f2c0688659ac6a47ff22c36bfccce0c6785b9f8d46`, output-pass master `ev_51dcb9b4576854995fbe8221f9f6834f7387d45fc9a9b43e7007e06530240109`, main start `ev_17b490eb22557a0602ce372e4433339b39945a4f0cb8054376f986ac429dedff`.

## Decode to pixels and publication

`jpeg_read_scanlines` invokes main-controller `+0x8` at `0x1402185db`; the context-row candidate is `0x14021c150`. It fills the current sample group by calling coefficient controller `+0x18` at `0x14021c18b`. For progressive input this reaches either ordinary full-buffer `0x140218eb0` or conditional block-smoothing `0x140219390`; both call the selected inverse DCT and produce component sample rows. The context-row main controller then runs a three-state row schedule. It passes the current, previous and next sample rows to post-controller `+0x8` at `0x14021c201` or `0x14021c32c`, duplicates boundary pointers for the first and last groups, toggles its row-pointer group and preserves counters across partial output. A zero result from coefficient output returns without publishing more scanlines. Evidence context controller `ev_e5d003a33a753be39ec8b00f5e1e5a51e25ed04db1e6776e782189b48005d0ca`, ordinary coefficient output `ev_671083f7ef2dcfdd8879145f67fa7686a327365c7112df2d73bfe965e27d052e`, smoothing `ev_8319b96876ac78df912175f0c156b49ddf1536b659924c29c505c586fadc5f16`.

In the no-quantization branch, post-controller start `0x140220870` copies the upsampler's output callback into post-controller `+0x8`; both context-row calls therefore reach `0x140221070`. Its per-component call at `0x140221100` reaches `0x140220ae0` for the component that triggered context rows. That CPU leaf interpolates adjacent rows and columns into 2×2 output samples; it has no further decoder-descendant calls. Full-resolution and other components use their separately selected routines. The upsampler calls color-converter `+0x8` at `0x14022117b`. For the conditional three-component YCbCr-to-RGB route, `0x14021a2d0` writes RGB bytes directly into the row pointers supplied by `ImageReadJPG`. Evidence post start `ev_a3b52372724f7586ee57d7fc80eb1655cb5aa93f2c9d17de9e6533bdde5f7822`, upsampler output `ev_464357c4eacb5b894bc4bd3e3c2bbda8644fb4048e32516a2ebdcf5b37f02b1f`, RGB CPU leaf `ev_a0d14c2b390d8f0cc5e9ce7566ed93670edb843629a1e9af5db7d9980b243847`.

`ImageReadJPG` allocated its pixel block at `0x14022904f` and passes successive row pointers through `jpeg_read_scanlines` at `0x140229080`. After all rows it finishes, destroys the decoder and closes the CRT stream; `ImageRead` flips the JPEG raster vertically at `0x140072fd0` before returning it. Texture acquisition from that raster is documented in [the baseline supplement](gui-jpeg-baseline-decoder.md). No GL call occurs inside the JPEG decoder. Evidence image reader `ev_0247d39d9d07cd96331ad8062ed202eeda22bd217ca0feee96500e38c246a550`, caller `ev_32924882e3d890833dc71949c122dfc1643d975d0dccf55ffef24c6c22ba2027`.

## Remaining gates

This is a conditional CPU pixel-output route for context-row upsampling and normal scanlines. Actual JPEG sampling ratios, fancy setting, minimum DCT size, progressive smoothing choice, source suspension, color space and active raster callback remain runtime data. Arithmetic/lossless JPEG, raw and quantized output, merged upsampling, alternate DCT scales and malformed-input error descendants remain separate.
