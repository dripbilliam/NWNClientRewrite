# NWN-75: original per-Part material draw branch

## Custom shader staging

`Material::CheckAndBindCustomShader` `0x140082b80` reads the shared material at `Material+0xd0`. The boolean passed by `Mat`/`MatStatic` chooses an available custom program at shared offsets `+0x1c8` or `+0x1c0`. It stages that program through `RenderInterface::SetCustomShaderProgram` at `0x140082bbb` or `0x140082c2f`, then loops the material's `0x64`-byte parameter records and stages float/vector values through `SetCustomParameterValuef` at `0x140082c0e` or `0x140082c7e`, or integer values through `SetCustomParameterValuei` at `0x140082bf4` or `0x140082c64`. Program and parameter presence gate all six calls. REA `ev_97b98d6ca98ae9e6c0198ed655b56b752f68565892376e0db3af50d6228f0d6a`.

The three RenderInterface methods tail-jump to `GLRender::SetCustomShaderProgram` `0x1400b6f30`, `SetCustomParameterValuef` `0x1400b6df0`, and `SetCustomParameterValuei` `0x1400b6f00`. Shader selection stores a nonnull program pointer. Float/int staging checks that the parameter has a valid location and compares against cached values; only a changed value sets the program dirty marker at `+0x48` to `-1`. None of these three bodies directly calls OpenGL. Later program use/uniform publication is in [shader program branch](shader-program-branch.md) and [shader uniform dirty gates](shader-uniform-dirty-gates.md). REA GL setters `ev_5e1f2ddeb8bd21b95dd8ef6240d2421179e1f20263afa5b383156e28c3c2361d`, `ev_b9843cf42c27bf1cb594e5b8cb5fd19ca2d85455b30b7a7a7cc1f2ededa069d9`, `ev_76963b6f8f720d5fc83d52620f3089ed229d90857408373e4abeb2179a236797`; forwarding wrappers `ev_a6f18e53e720a1afa1ce7103fdc4ed30cd2c57c859831a57da276f81517ae29f`, `ev_5296d94e54db68638e4a2466ac99028b27ff871ba6a391addc59497cbf5c4947`, `ev_e1be78295a284bca041c0d912e64fa45bbefb78af42bd72f5c8525766dc0b54e`.

Pinned original `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Virtual dispatch and draw API boundaries are in [geometry and draw boundary](geometry-and-draw-boundary.md). This supplement records the immediate material-state branch and exact callsites in `branch-ledger.json`.

`PartTriMesh::Draw` `0x1400a24c0` chooses virtual `+0xf8=MatStatic` `0x1400a3270` when Part `+0x50` has no dynamic owner, otherwise `+0xc0=Mat` `0x1400a2f50`. `Mat` itself delegates to `MatStatic` at `0x1400a2f65` if its owner disappeared. On the dynamic path, it combines Part `+0xa8` alpha with owner fade/color fields, conditionally calls `Material::SetBlendingMode` at `0x1400a30cd`, binds standard textures at `0x1400a315b`, checks a custom shader at `0x1400a3189`, then writes color or three material vectors through render-state wrappers. On the static path, `MatStatic` always calls `SetBlendingMode` at `0x1400a3292`, `BindAllStandardTextures` at `0x1400a329b`, and `CheckAndBindCustomShader` at `0x1400a32c4` before its color/material output. Its area tile-color multiplication at `0x1400a3346` is gated by Part tile reference and flags. Full REA `Mat` `ev_8eb1896642e5fc302f6f9e49cbc5701f76698dfa8a9865b563a32bfb9397920b`, `MatStatic` `ev_3a01f2cb336622e042c81c4fa3ddc3862060febaed8837b8a0919756a5dc3a61`, `Draw` `ev_c71ed738e7b17f5a797049dd882453cd562f5d3a00b1397cff45724ce6f182f0`.

`Material::SetBlendingMode` `0x140085790` passes authored blend modes to `RenderInterface::SetBlendFunc` at `0x1400857a5`. Blend pair `(0,2)` chooses a disabled depth mask at `0x1400857c3`; all other pairs choose an enabled depth mask at `0x1400857cf`. The render-state wrappers have their own change gates before GL publication. REA `ev_8cf87c9014563e18ecd1f964f1bf5c5674c2a4b6c58504c33760a3564edcfe0e`.

The original material bodies do not issue immediate GL calls; their texture and shader descendants are mapped in [geometry and draw boundary](geometry-and-draw-boundary.md), [texture controller runtime](texture-controller-runtime.md) and [shader program branch](shader-program-branch.md). This static control flow does not establish which material or texture branch occurs in a given frame.

## Standard texture binding

`Material::BindAllStandardTextures` `0x140082630` iterates eleven texture units. It first checks whether the bump texture at `Material+0x50` is a cube map. A noncube entry is released and removed; a cube entry causes up to three material textures to have their controller enabled flag set according to `g_nEnableBumpyWater == 0`. For each of the eleven units, a custom slot at shared material `+0xd8` takes priority. If no custom slot exists, units 0–2 may bind the corresponding ordinary material texture through virtual `+0x100=CAurTexture::BindInUnit` `0x1400ea490`; all other empty units stage texture ID zero through `RenderInterface::SetActiveTextureAndBind` `0x1400befc0`. A second loop binds the eleven nonnull shared custom textures. These loops are per material bind, with texture/GL cache gates in the descendants. REA `ev_510a344263a525ba1eab56313101add61fcb39a8f2395fd62128a69a7051ab0a`.

The optional bump texture at `Material+0x40` sets render feature `0x12`. An invalid texture is replaced by `AurTextureGetNULL`; its cube-map test chooses texture unit `13` or `14`, then `BindInUnit` and `AurTextureGetTID` run. Cube-map status also enables feature `0x13`. An absent bump texture disables feature `0x12`. If the authored scheme count at `Material+0x114` is positive, `RenderInterface::SetSchemeData` `0x1400bf250` compares the supplied floats to its CPU cache and advances dirty counter `DAT_1413d2720` on changes; it has no immediate GL call (REA `ev_f378e1dcd35fd743a37e7de0132abf7dffd9c05209fcf24c3ae1c8c57f9ad0d4`). The later shader consumer is covered by [shader uniform dirty gates](shader-uniform-dirty-gates.md).

The seven computed callsites in `BindAllStandardTextures` resolve through the constructor-backed base and Basic texture vtables: `0x14008265a`, `0x1400827cd`, `0x1400827f6` to `IsCubeMap` `0x1400ec0d0`; `0x14008279f` to `IsInvalid` `0x1400ec160`; and `0x14008272f`, `0x140082776`, `0x1400827e0` to `BindInUnit` `0x1400ea490`. `CAurTexture::SetControllerEnabled` `0x1400edae0` follows two reference/Basic-subtype virtual pairs and, when a controller exists and `enabletexturecontrollers` is true, only writes its enabled byte at `+0x51`. No GL call occurs in that method (REA `ev_c3dd39526367f24d315d00d8e046228b61b808da0da739178454b55504f5ae03`). `AurTextureRelease` `0x1400e9130` conditionally follows reference/destructor virtuals when the texture's refcount is zero; exact dynamic subtype cleanup remains an open resource boundary (REA `ev_ae10e2230298fa2415bf7a12b732f9a0691a72b56f9a56a758c47a3986044c88`).
