# NWN-75: original lens-flare visibility hit test

Original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This follows `Scene::RenderLensFlares` `0x1400cea90` → Scene virtual `+0x58=Scene::HitCheck` `0x1400c9c90`. It is CPU visibility work before the flare texture/draw branch described in `scene-auxiliary-passes.md`. The static call tree inherits the render caller's thread; no internal worker dispatch is visible here.

The same Scene virtual `+0x58` is called from the three original particle movement functions `PartEmitter::moveParticleStandard` `0x140068010`, `moveParticleP2PGrav` `0x140067340`, and `moveParticleP2PBezier` `0x140066940` under their collision gates; those callsites and target-Gob reads are recorded in `animation-and-emitter.md`. This shares the CPU hit-test descendant, with a different caller and hit-info input.

`Scene::HitCheck` takes start/end vectors, optional output point and `CHitInfo`. It clears a default hit record when the caller supplies none, sets the current hit-info pointer, and calls `BSPHitCheck` `0x140229710` with callback `HitPartOnBSPNode` `0x1400d9f20`. On a BSP hit it records hit kind 1 and the endpoint. If the hit-info permits more testing, it scans the active Gob list (`gobbucket` when a BSP exists, otherwise Scene `+0x130`), filters by model flags/alpha and skip-list identity, then invokes Gob virtual `+0x128=Gob::HitCheck` `0x14008fa90` at `0x1400c9eb2`. A Gob hit records kind 2 and the returned point. Original Gob vtable `0x140d88a00` slot `+0x128` contains `0x14008fa90`. Evidence: REA `ev_641449c45311898be7ede1cb0e114949eda0b938b53c4b9305757f7c7f80770f`, original PE pointer bytes.

`BSPHitCheck` tests an optional node callback before traversing child planes. With no callback, a solid leaf can itself count as a hit. It classifies both segment endpoints against the node plane, computes an intersection on a crossing, recurses near side first and then far side when needed, passing the current shortened endpoint. At computed site `0x140229783` the callback argument is the directly supplied `HitPartOnBSPNode`; the same function recurses at two direct sites. Evidence: REA `ev_5c984b8e75117096eb74072a85b8a8308150b372df77f3f9b7bbb60b4ae3eb25`.

`HitPartOnBSPNode` first tests node dynamic Parts with `BoxIntersect`, then optional static triangle Parts when `hitcheck_static_trimesh_parts` is true, then a static BSP Part when `hitcheck_static_bsp_parts` is true. The no-BSP-ground flag can synthesize a ground-plane hit when the z segment crosses zero. Each admitted Part invokes virtual `+0x38=Part::HitCheck` `0x14008fd80` at `0x1400da002`, `0x1400da0c3`, or `0x1400da16d`; original base, TriMesh, Skin, AnimMesh, AABB, Trigger and Emitter vtables all carry that target. Evidence: REA `ev_9e344bf0747f34d392800b8924e485e7fb7de02c51507f068657da80009f4e16`, original PE vtable bytes.

`Gob::HitCheck` tests model/door visibility, reads adjusted position/orientation/scale from Gob slots `+0x2d8/+0x2e0/+0x2d0`, rejects a segment missing the Gob bounding sphere, transforms the admitted segment into local coordinates, then calls the root Part virtual `+0x38=Part::HitCheck` at `0x14008fcb3`. A Part hit is transformed back to world coordinates and returned. Evidence: REA `ev_2bf2769b3cf77ad0f680a982be12a1d14fc1a2cb0be0cb0277a53039c15bb173`.

`Part::HitCheck` transforms the segment through its local pose and scale, calls its own virtual `+0x40=HitCheckGeom` at `0x14008ff5c`, then visits children in stored order through virtual `+0x38=Part::HitCheck` at `0x14008ffd5`, preserving the last admitted hit. It restores a hit point/normal through the Part pose. Concrete `+0x40` entries are base Part `0x140090440` (empty), TriMesh and Skin `0x1400905b0`, AnimMesh `0x140090540`, AABB `0x140090450`, Trigger `0x1400f06d0`; original vtables `0x140d87f08`, `0x140d88308`, `0x140d88438`, `0x140d88568`, `0x140d888d0`, `0x140d91840` establish the targets. The `+0x8` name callback at `0x14008ff77` is separate hit-info metadata. Evidence: REA `ev_d6b0f8747b4798721ebcbf625a5e5d1905e2d4a3d4fbdf0681e6dd6d809c7f42`, original PE vtable bytes.

The geometry implementations terminate in CPU intersection work: AABB `0x140090450` → `HitCheckAABBnode` `0x140090170`; AnimMesh `0x140090540` → `AnimMeshHitCheck` `0x14008bd40`; TriMesh `0x1400905b0` does box and face tests with `polyhit` `0x140231810` and accesses a vertex pool through `RenderInterface::LockPool`/`UnlockPool`; Trigger `0x1400f06d0` does box and `polyhit` `0x140231070`.
