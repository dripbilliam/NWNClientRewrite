## Control callback to radius calculation

`MdlNodeEmitter::MdlNodeEmitter` installs `MdlNodeEmitterControl` at source node `+0x18`. When an active animation's Part/node identifiers match in `AnimateHierarchy`, the callback enters `MdlNodeEmitter::InternalControl` `0x140052400`. It obtains Part virtual `+0x68=AsPartEmitter` at `0x14005242b`, calls `MdlNode::InternalControl` `0x140051c50` at `0x14005244c` to sample and blend active authored controllers into the Part, then tail-jumps to `PartEmitter::CalculateRadius` `0x140061710` at `0x14005246d`. The radius update follows control publication; it is a CPU calculation with no GL call. Existing [animation mapping](animation-and-emitter.md) covers the parent `AnimateHierarchy` gate. Evidence emitter control `ev_386e07dcd92138affad11d8674d65f32869013ffffbcbf173746076d45c6542c`, emitter constructor `ev_ae47c019ed30702e173ef5762e372237bb0cc1a155980e01a6b3ce3ea22c1787`.

`CalculateRadius` first checks owner Gob `PartEmitter+0x50`, its model pointer `Gob+0x68`, and model flag byte `+0x92` bit `0`. If all are present, it stores IEEE float `1000.0` at `PartEmitter+0x20c` at `0x14006173e` and returns. Otherwise it obtains the emitter's world position via Part virtual `+0x18=Part::GetWorld` at `0x140061789`. With a target Gob at `+0x1c0`, it calls Gob virtual `+0xc0=GetPosition` at `0x14006179f`, computes the magnitude of target minus emitter world position at `0x1400617d5`, and stores that distance as radius `+0x20c` at `0x1400617da`. The target is the reference Gob selected by the previously mapped `_EmitterTarget` callback, not a Gob created by `CalculateRadius`. Evidence calculation `ev_ae5dd1aec23503dd4a60d768f4d5b4b038bcb00ebb9471808e554a36487d0735`, Part world target `ev_a696136e482470afb0b78309732798beacd3feb2832cfc0eb4aa02f244559b4d`, Gob target slot `ev_15dd5e10911047e0f9099bb67a11928c97ae578a55fa4549a0802d3cab696213`.

Without a target Gob, `CalculateRadius` records `abs(mass(+0xb0) × -9.81)` at `+0x210`, optionally adds the magnitude of vector `+0x20..+0x28` from the nonnull `+0x1f8` object, then combines authored speed/lifetime/size fields `+0xdc/+0xc0/+0xac/+0xc4/+0xc8/+0x228/+0xcc/+0xd0/+0x22c` into an analytic outer radius. The scalar square-root helper is called at `0x1400618f6`, and `+0x20c` is stored at `0x140061906`. If the live list `+0x188/+0x190` is nonempty, it calls each Particle virtual `+0x8=AsChunkyParticle` at `0x14006193e`. A Chunky result with attached Gob `+0x78` expands the radius to the maximum of the current radius and distance from emitter world position to that Gob's position plus Gob radius `+0x178` (`magnitude` at `0x140061989`, store at `0x1400619a6`). The base Particle slot returns null and takes an immediate return at `0x140061944`; thus a base Particle encountered in this loop prevents inspection of later live entries in this call. No particle or Gob is created here. Evidence calculation above, base `AsChunkyParticle` `ev_08baa24937951e870381b8318c21a22c96c581c66314c15254bc278c8b5d8be4`, Chunky override `ev_ad5466085cbb959fcd071370e6ff18b5d62b63df2504bcb2d696e019a2f29e81`.

## Consumers and exact boundary

The calculated `+0x20c` is read by `PartEmitter::RenderBoundingSphere` `0x140062870` at `0x1400628a6`; its separately gated debug path calls `RenderInterface::DrawSphereBound` at `0x1400628c9` and `DrawCrosshair` at `0x1400628f4`, reaching the diagnostic GL leaves already mapped in [particle lifecycle](original-particle-effect-lifecycle.md). This is not the normal emitter quad draw.

The same radius can enter a model Gob's cached minimum sphere: `Part::GetMinimumSphere` `0x14008ef40` checks owner model flag `+0x92` bit `0`, calls the Part's virtual `+0x68=AsPartEmitter` at `0x14008efbf`, and if that succeeds reads the emitter `+0x20c` at `0x14008efc7`. It then combines child Part spheres through virtual `+0xf0` and CPU vector math. `Gob::GetMinimumSphere` `0x14008ee60` invokes root Part `+0xf0` at `0x14008ee97`, applies model/owner transform and adjusted scale, and caches center/radius at Gob `+0x17c/+0x178`. `Gob::GetMinimumBoundingSphere` `0x14008ee10` calls Gob `+0x2c8=GetMinimumSphere` at `0x14008ee2b` before returning the cache. `NewCAurObject` also calls Gob `+0x2c8` after model construction at `0x14009378f`. In `Gob::Animate`, the observed active-root branch increments a counter at `Gob+0x188`, computes modulo `5`, and calls virtual `+0x2c8` at `0x14004e8ee` when the result is zero. These are CPU bounds publications. `PartOutside` `0x1400dbdc0` also reads `PartEmitter+0x20c` and calls `SphereAbovePlane` `0x14022e360`, but the analyzed binary has no actionable code call reference to that function (only unwind-data references). It is recorded as a bounded potential consumer, not a proven Scene admission edge. The proven route stops at CPU radius/cache writes and the separately gated debug GL draw. Actual animation/controller values, owner model flag, target presence, live Particle subtype order, attached Gob state, debug flag and whether any bounds consumer runs remain runtime/data boundaries. No Scene culling decision is inferred solely from the radius field.
