The body is a size- and overlap-aware CPU byte copy. REA's reference manager labels that terminal jump as a call, but the original instruction is a short JMP (`ev_8f09dbf65898d5da7d5ac2f935a3f80483682389b2636ac771d88dd696865830`). The fallback body copies bytes in a loop and has no callees (`ev_75f58eddd7ce0e6cdd226edd24d6409ae2aa2ef26e4f2e95c2981bc228fe5339`).

This path copies CPU memory. It performs no direct GL draw, buffer upload, file I/O or worker dispatch in these bodies. The corresponding VDO/pool branches can later publish changed bytes through `UnlockPool`; their conditional GL path is separate in [primitive/VDO preparation](primitive-vdo-preparation.md) and [geometry/draw boundary](geometry-and-draw-boundary.md). The ledger records the short-jump edge without mislabeling it an E8/E9 direct call.
