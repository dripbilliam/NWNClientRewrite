# NWN-75: Scene focus vector to shadow-plane height

Scope: installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This identifies the Scene field consumed as a shadow-plane Z limit in [shadow-plane rendering](scene-shadow-plane-source-and-draw.md). It does not establish that a live scene uses a nonzero focus or that an actual shadow-plane draw occurs.

`Scene::Scene` `0x1400c0ca0` initializes the three-component Scene focus vector at `+0x190..+0x198` to zero. For a nonempty Scene name, it constructs `<scene>.focus` and, after successful `ConsoleFunc` allocation, calls the `Vector*` overload `ConsoleFunc::ConsoleFunc` `0x14005d3c0` at `0x1400c135a`, passing Scene `+0x190` at `0x1400c134d`. That overload stores the vector pointer in its `funcholder<Vector*>` and registers the command. The exact-name lookup, constructor-backed holder `+8=Engage` dispatch and `%f %f %f` direct float parser are documented in [fog-color console vector](scene-fog-console-vector.md); they apply to this focus registration without a distinct implementation. A focus console command can therefore write the three Scene components directly, subject to the same command/whitelist/parser gates. Evidence: constructor `ev_9bd85911eebb0eb0c68866794c5c484152b6059e0e8e29e18ffda6e3851cf60b`, holder `ev_9c0f9898ef6834938ef293f7b23637e32c6d8d07f721044737a4b88fbd61264c`, dispatch and parser in the linked note.

The independent virtual `Scene::SetSceneFocus` `0x1400d3580` copies all three incoming vector floats into Scene `+0x190..+0x198`. Its installed Scene vtable `0x140d8dd30+0xa8` points to this target at `0x140d8ddd8`. The analyzed incoming reference set contains that vtable entry and one data reference, with no direct code caller; an indirect or external setter caller is still open. Evidence: setter `ev_4a72ce7cbe83f2cdbfaeccdb310a9a2fe7deac07462d92920a063a444dae6c54`, incoming references `ev_41fdbc78dacf08a1967df9bc7b8bc48a2becf959c1adb4fcde0cadedab072ce2`, original slot bytes `ev_f32775fe600df87a02ca8728e19bc11f699239cecf20ef601abeed9a0d2d37a0`.

`Scene::RenderShadowPlanes` `0x1400d0350` reads Scene `+0x198` on both local and directional branches. On the local light branch it chooses the lower of `PartLight world-Z + vertical displacement - 1` and focus Z as the plane Z, then derives radius from the light's selected radius and vertical separation. On the directional branch it chooses the lower of `Camera Z - 1` and focus Z. Later directional vertices use that focus-derived plane Z; local vertices use the same clamped value. The Scene `+0x140` read in the directional branch is the **fog enable flag**; when enabled it substitutes Scene fog end `+0x148` for a fixed `10000` distance in one geometry extent. These fields have separate meanings and neither is itself an independent ground-height source. Evidence: shadow-plane body `ev_f521b02b49aa40df1ea8ff3e9e4ea4030d8bb3cdf05ad4f54ec71c4b3d96f70b`, [fog defaults and consumption](scene-fog-state-source.md).

This closes the known default, console and setter producers for the focus-Z input, while leaving indirect setter callers, runtime focus values and actual pass frequency open. No additional GL branch is introduced: an admitted plane follows the existing shadow-plane stream/shader/draw route.
