# Original file-backed progressive JPEG decode

Pinned `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This follows the conditional `ImageReadJPG` path after [the baseline decoder supplement](gui-jpeg-baseline-decoder.md). It applies only while the initial file-backed raster callback is active and a JPEG stream reaches progressive SOF2. [The edge ledger](gui-jpeg-progressive-decoder-ledger.json) records sites and gates. This is a static branch map, not a claim that a particular asset or frame executes it.

## Marker, scan and controller selection

The marker reader `0x14021dd70` handles SOF2 (`0xC2`) through its shared frame parser call at `0x14021df8b`, passing progressive=true and arithmetic=false. The parser `0x14021d2a0` stores the progressive flag at decompressor `+0x128`; the SOS parser `0x14021d5f0` reads component selectors and the spectral start `Ss` (`+0x1ec`), spectral end `Se` (`+0x1f0`), successive approximation high `Ah` (`+0x1f4`), and low `Al` (`+0x1f8`). It increments the input scan count. The input controller `0x14021b990` marks multiple scans when progressive, including when the first SOS covers every component. At decompressor state `0xCA`, `jpeg_start_decompress` initializes the master. For nonarithmetic progressive input, master `0x14021eaf0` calls `jinit_phuff_decoder` `0x140220110` at `0x14021ed41`. Because multiple scans are marked, its `jinit_d_coef_controller` call at `0x14021ed69` passes the full-buffer selector. That controller `0x140219ac0` allocates per-component virtual block arrays and assigns `0x140218c30` as scan coefficient consumption and `0x140218eb0` as ordinary output from the saved blocks. These arrays span scans; they are not the one-pass scratch blocks used for baseline output. The master still installs inverse DCT, main, post, upsampling and color conversion controllers under their existing raw, quantization and merged-output gates. `jinit_phuff_decoder` installs its scan-start callback `0x1402202b0`. On each SOS, input controller `0x14021be20` computes MCU/component geometry, installs missing quantization tables, then invokes that progressive scan-start callback at `0x14021bf37` and the coefficient input-pass callback at `0x14021bf43`. Scan-start validates `Ss/Se/Ah/Al` and per-component prior-bit state, and chooses exactly one entropy callback: DC first `0x14021fdc0` when `Ss=0, Ah=0`; DC refinement `0x140220000` when `Ss=0, Ah>0`; AC first `0x14021f6a0` when `Ss>0, Ah=0`; AC refinement `0x14021f910` when `Ss>0, Ah>0`. AC scans require one component. It builds derived DC or AC Huffman tables for initial scans as required, resets bit/restart state, and stores the selected callback at entropy-controller `+0x8`. Invalid progression, table, selector or approximation values go through error callbacks. ## Coefficient work and output

`jpeg_start_decompress` sees the multiple-scan flag and repeatedly invokes input-controller `+0x0` at `0x140218668` until EOI or suspension, before starting the ordinary output pass. At each scan start, `0x14021be20` copies the coefficient input-pass callback to that input-controller slot, so the call at `0x140218668` reaches full-buffer coefficient consumption `0x140218c30` during scan data. That routine traverses the virtual block arrays MCU by MCU and invokes the installed entropy callback at `0x140218dbb`. At scan completion, input-controller `+0x18` restores marker consumption `0x14021b860` through the stub at `0x14021b970`; the next SOS starts another coefficient pass. A suspension preserves MCU row/column and coefficient state. The four callback bodies reach CPU coefficient leaves: DC first decodes differential DC values into coefficient 0; DC refinement ORs one bit at `Al`; AC first decodes run/size pairs into zigzag AC positions with EOB runs; AC refinement updates existing nonzero coefficients and inserts newly nonzero ones, rolling back inserts on suspension. Initial DC and AC modes call `jpeg_fill_bit_buffer` and slow-path `jpeg_huff_decode`; refinement modes also call bit refill. Restart intervals call `0x140220200` to reset per-scan state and advance the marker reader. Source-buffer exhaustion joins the baseline supplement's `fread` and conditional CRT/Win32 read boundary. For the normal scanline output branch with no required context rows, main-controller `0x14021c4e0` calls coefficient output callback `+0x18` at `0x14021c515`. The ordinary full-buffer target `0x140218eb0` reads saved blocks and calls the selected inverse DCT at `0x140219000`; default 8×8/method-0 reaches CPU leaf `jpeg_idct_islow` `0x140223be0`. A separate conditional block-smoothing path can replace output callback with `0x140219390` at `0x140219e5a` when smoothing is enabled and progression/quantizer conditions match; it estimates still-missing AC values, copies a block row, and also invokes the selected IDCT at `0x14021993a`. The ordinary callback is restored at `0x140219e89` when its gate fails. Both then join the existing postprocessor at `0x14021c554`, and the baseline supplement's conditional upsampling, color conversion and caller-owned pixel publication. ## Remaining gates

This closes a conditional nonarithmetic progressive Huffman route through full-buffer coefficients to CPU sample output, with the same conditional CRT read boundary and caller publication as the baseline path. Exact scan sequence, component/sampling layout, whether smoothing or a context-row main controller is selected, output color space, source suspension and active raster callback are runtime data. Arithmetic SOF10, lossless/differential modes, raw output, quantized output, merged conversion, scaled/alternate IDCT and malformed-input error descendants remain separate and are not inferred from this route. `ImageReadJPG` itself does not call GL.
