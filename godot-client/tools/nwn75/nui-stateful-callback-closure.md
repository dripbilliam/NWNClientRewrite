## Callback ownership and dispatch

The JSON `textedit` constructor `0x1409605d0` calls `0x140954e50` at `0x140960697`. That constructor creates a `StatefulWidget` and at `0x140954eb6` calls `0x140956430`, which allocates a 0xd8-byte stored function object with vtable `0x140e6e4c8`. The same constructor calls `0x140956030` at `0x140954f1c`; it allocates a 0x48-byte wrapper with vtable `0x140e6e270`, clones the inner object through its virtual clone slot, and stores the clone at wrapper `+0x40`. The wrapper is installed in the widget's stored render callback slot. The constructor releases its temporary function objects after cloning; the widget-owned wrapper and its cloned inner object persist through the refcounted layout object. This is constructor-backed ownership, not an inference from two adjacent vtable addresses. `Widget::Render` `0x1409528e0` invokes the stored callback's virtual `+0x10`. The wrapper slot `0x140e6e270+0x10` points to `0x14095ca70`. ## Render and edit leaves

`0x14095a020` lazily allocates 0x40 bytes of edit state only when widget `+0x700` is null. It hashes current text and initializes the input buffer. Its call at `0x14095a25e` enters `0x140a81c70` → `0x140a81a10` → `0x140a817d0` → large Nuklear edit helper `0x140a62c70` at `0x140a81941`. The original direct-caller census for that helper records conditional numeric commands: kind **1 clip** at `0x140a63ea3/0x140a64477/0x140a64562`, kind **4 rectangle outline** at `0x140a6368f`, kind **5 filled rectangle** at `0x140a636b0/0x140a6434e/0x140a64407`, kind **16 text** at `0x140a6438d`, and kind **17 image** at `0x140a6365c`. These are possible branches of edit drawing, not proof that all emit in one frame. The helper's full input/style/clip decision tree remains open; its Ghidra dossier was retained as `ev_247644383e75a1578074fbfe0ad36e8fc7643aa5c8d59beec2c9e8e53b9d5232` because the complete response exceeds the transport limit. The producer callsite census and each producer dossier independently anchor the numeric leaves.

Separately, when the edit buffer is empty and the configured placeholder text is nonempty, `0x14095a020` calls `0x140a81600` at `0x14095a3ce`. That producer checks nonzero text length, color alpha, clip intersection and command allocation before writing kind **16 text** through `0x140a619c0`; it is a conditional placeholder draw. The numeric records flow through the already mapped converter `0x140a7c340` and reach imported `glDrawElements` only if nonempty converted geometry is submitted. ## CPU state and remaining dynamic edges

After edit input, `0x14095a020` hashes the current buffer and compares it with stored hashes. On the changed-text branch it converts UTF-8 back to a game string and calls `0x1409582e0` at `0x14095a4d9`. That function assigns the text to a `DynamicValue`, conditionally invokes a listener stored at its `+0xc0`, then calls another value publication helper; the listener's runtime object and downstream effects are data-dependent. Key/edit events also invoke optional stored callbacks through virtual `+0x10` at `0x14095a5e6`, `0x14095a695` and `0x14095a6db`, after flag and pointer tests. Their concrete installed targets, side effects and active-window frequency are not established by this static branch. No OS-thread identity or per-frame frequency is inferred from the call graph.
