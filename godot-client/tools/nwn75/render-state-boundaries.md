# NWN-75: original render-state API boundaries

Original `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are original PE virtual addresses. This is a partial scene-state descendant map. Static callsites do not establish runtime invocation counts or OS-thread scheduling.

These wrappers are reached from `Scene::Render`, `RenderSinglePass`, `RenderDrawBucket`, shadow passes and auxiliary passes under their respective stage gates. Their GL calls execute synchronously on the inherited render caller when the condition is met. Other state wrappers, extension pointer callsites and dirty-uniform group conditions remain open in the branch ledger.

Each `RenderInterface` entry above is a one-instruction jump thunk to its `GLRender` implementation: Enable `0x1400b30a0`, Disable `0x1400b0310`, BlendFunc `0x1400b6910`, DepthFunc `0x1400b6f60`, ColorMask `0x1400b6cf0`, StencilOpSeparate `0x1400b7ec0`, PolygonMode `0x1400b7a20`. In the original assembly, the seven `glEnable` call/tail-jump sites are `0x1400b30e5`, `0x1400b311c`, `0x1400b3138`, `0x1400b3148`, `0x1400b3158`, `0x1400b3168`, `0x1400b3183`; parallel `glDisable` sites are `0x1400b0357`, `0x1400b038e`, `0x1400b03aa`, `0x1400b03ba`, `0x1400b03ca`, `0x1400b03da`, `0x1400b03f5`. All refer to imported IAT cells. The changed-state sites are `glBlendFunc` tail `0x1400b6947`, `glDepthFunc` tail `0x1400b6f6d`, `glColorMask` call `0x1400b6d36`, `glStencilOpSeparate` extension call `0x1400b7f5c`, and `glPolygonMode` tail `0x1400b7a32` (REA `ev_97b1deb7`, `ev_c6056aa5`, `ev_e2f617a7`, `ev_0918c468`, `ev_73ac5262`, `ev_6f34842e`, `ev_8256a7dd`).

The additional high-fan-in color/material and state wrappers are also one-instruction jumps: `SetColor4f` `0x1400bf050` → `GLRender::SetColor4f` `0x1400b6c80` (`ev_97c2ba431262e1970f9934a9ef913e53d676142c8252a57993a6cfef723e58af`), `SetColorv` `0x1400bf070` → `GLRender::SetColorv` `0x1400b6d50` (`ev_790f973a3b201f954ec91a2f410ddf47747995093bf5513a1c9c6e8fb0e0dd12`), and `SetMaterialv` `0x1400bf1b0` → `GLRender::SetMaterialv` `0x1400b75b0` (`ev_203e6be6006983545b0efa1e2fceb2093a2adc9cc984bd76124fb74732656961`). The three implementation bodies compare the cached values, increment global-color or material dirty generation only on a change, and have no direct GL or further calls (full bodies `ev_8550e91ef36308d67fa3de54d8c7c0aa67ff047bdfd90a3b02047326ec75640d`, `ev_40e01930317985fb6a10c5676b8343b3d70a9412335bce95a1b55846dace3bb6`, `ev_f8997cc9b7c0f01c42f122b4387a25ee3be3512f6acb881faf5ca230a0506152`). The separate `SetMatrixMode` wrapper `0x1400bf1c0` jumps to `GLRender::SetMatrixMode` `0x1400b7800`, which only stores its selector (`ev_d3bcec460bccae9b17c0d887a159a6f425420bb79fb84c6c2c615c0712919d30`). `SetFrontFace` `0x1400bf130` jumps to `GLRender::SetFrontFace` `0x1400b7180`, whose `0x1400b718d` tail jump reaches imported `glFrontFace` after enum translation (`ev_386db7fa1504e424642270103bebc4570f92f13009b39c7aa89833f36b74873c`). These are immediate-body boundaries; dirty-group consumption remains in the shader uniform branch.

`RenderInterface::GetColorSpaceFromSRGB` `0x1400beb90`, reached by material/light consumers, first calls `GLRender::GetGlobalShaderParami` at `0x1400beba2`. That helper performs only an indexed read of the global integer shader constant cache (`ev_e1d5427d6f96604e89e4b6afbd7ed8b66c7643097712c0b813c843367dce1f56`). When parameter index 0 is nonzero, the wrapper calls `color_pow` at `0x1400bebb6`; it conditionally applies exponent 2.2 to each of three channels greater than zero and unequal to one, via CRT math helper calls at `0x1400bf40f/0x1400bf431/0x1400bf454`. The final vector copy occurs in the wrapper. There is no GL API in these bodies; the CRT math helper remains a lower runtime boundary. Original wrapper `ev_fa33348a8a61f2bcc33db236629b8238b01adaf5efdafdd107b944889aecffa9`, `color_pow` `ev_7446a08d681b44c1fab2845920e9cbca9717803ce6a5733cf1c4cac970e49b91`.

`Scene::Render` calls `RenderInterface::CheckAndUpdateUniformDirtyDataForFrame` `0x1400be8d0` once in its BSP branch after wind-timer update. The wrapper enters `GLRender::CheckAndUpdateUniformDirtyDataForFrame` `0x1400bbe80` (REA `ev_79a90e2b`, `ev_477c60f3`). It reads the app's world timer and exposed runtime/world/area fields, current Scene data, and camera pose/view angle; each changed group updates a cached copy and increments its shader-uniform dirty generation. It has no direct OpenGL call in this function. Its six computed sites read the current Camera's primary vtable `0x140d82e08`: `0x1400bc2c0` and `0x1400bc382` slot `+0x40=Camera::GetPosition` `0x140058e10`; `0x1400bc2ce` and `0x1400bc3a4` slot `+0x48=Camera::GetOrientation` `0x140058db0`; `0x1400bc2d7` and `0x1400bc4d2` slot `+0x90=Camera::GetViewAngle` `0x140058fe0`. The first three samples participate in the cache comparison; the later three populate changed cached values. Camera constructor `0x1400571f0` installs that vtable (REA `ev_3664c794`), and each getter's REA body only reads the corresponding Camera field. `GLRender::SetUniforms` consumes the dirty groups at program selection; its GL upload callsites are catalogued in `shader-uniform-gl-callsites.json`.

The Camera setup route's `Camera::SetClipDist` `0x14005b440` calls `RenderInterface::SetClipDist` `0x1400bf040` → `GLRender::SetClipDist` `0x1400b6c30` (REA `ev_04983c9c43654301bf15f088282db83d30daa34b0959a83f03963f212d0f0c10`, `ev_c329f6e035a01a4f1602b1a4c3e84238a676f81732eb24458690230e54c73043`). This compares near/far floats against its cache and increments dirty generation `DAT_1413d2730` only on a change. It has no immediate GL call; `SetUniforms` is the later API route. The GUI-side CSceneView camera construction and setter dispatch is mapped separately in `gui-presentation.md`.

## Reset after presentation and shader setup

`GLRender::ResetRenderStates` `0x1400b6050` is reached from `GLRender::InitRenderSystem` at `0x1400b41c8`, `GLRender::ReloadShaders` at `0x1400b5418`, the `RenderInterface::ResetRenderStates` tail-jump thunk `0x1400beef0`, and `GLRender::SwapBuffers` at `0x1400bb79f`. The swap body calls it **after every** `SDL_GL_SwapWindow` on that path; the reset call itself is unconditional in the analyzed swap body. In `CAurInternalGL::Initialize`, the `DAT_14128e554==0` branch uses the RenderInterface thunk, while the alternate `InitRenderSystem` branch also reaches reset. Incoming REA `ev_b7304a42725a6b35f177ecf56fdcf01de6bdf7e184ef72aba5744e64549c6b77`, reset body `ev_753f31d018b6d13a4dd92c3a0cb353c8ae2602de030939ffd7dca50461e324aa`, swap `ev_c11c50fe4c140466818d71bad2a1971fa61ffcdf3463d879a4fb5cb25d3058ec`, initializer `ev_d2382b2a89a02f03b99288823a7f76538a358acc2c0ed00b2bbaad9b6c052d6e`.

The reset restores default framebuffer and render-state caches. It conditionally calls `glBindFramebuffer` when its default-ID cache is not `0xffffffff`, calls its first `glBlendFunc` only when the cached prior mode differs from 2/3, creates a default VAO only if its ID is zero, and then always binds that VAO. On a completed reset it clears current VDO/state caches; issues six `glDisable` and four `glEnable` calls plus a final `glEnable(0x884f)` tail; sets front-face, depth/color masks, the second blend mode, polygon and stencil state; resets light slots using `LightManager::GetMaxLights`; advances or resets shader/material/fog dirty state; and selects/reset-caches the active texture unit. The per-light helper call at `0x1400b634d` repeats only when light count is positive. These effects occur on the inherited swap/init/reload caller thread. Their runtime cost and driver synchronization are unmeasured here.

Exact direct call/tail sites in the analyzed body: conditional `glBlendFunc` `0x1400b60c9` and unconditional second `glBlendFunc` `0x1400b6279`; `glDisable` `0x1400b6109/6114/611f/612a/6135/6140`; `glEnable` `0x1400b615e/618f/61b0/61d1`, tail `0x1400b6492`; `glFrontFace` `0x1400b6209`; `glDepthMask` `0x1400b6218`; `glColorMask` `0x1400b623a`; `glPolygonMode` `0x1400b6289`; `glStencilMask` `0x1400b629a`; `glStencilFunc` `0x1400b62b7`; `glStencilOp` `0x1400b62e2`; `LightManager::GetMaxLights` `0x1400b62fc`, conditional per-light `0x1400b634d`. The four computed extension sites resolve through loader-named cells: `0x1400b608c` → `glBindFramebuffer` at `0x141443248`, `0x1400b60e5` → `glGenVertexArrays` at `0x141443f58`, `0x1400b60f1` → `glBindVertexArray` at `0x141443f48`, and `0x1400b645d` → `glActiveTexture` at `0x141442150`.
