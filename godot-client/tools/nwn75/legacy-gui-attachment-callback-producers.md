# Original legacy GUI attachment and panel callback producers

Installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are original image VAs. This is static original-binary mapping, not a count of active objects. The companion [ledger](legacy-gui-attachment-callback-ledger.json) records exact edges. The [draw ownership branch](legacy-gui-draw-ownership.md) covers the common GUI scene and GL descendants.

## `StringGob` embedded-model branch

`StringGob::AddLine` `0x140047760` allocates a 0x30-byte `CStringItem`, explicitly writes zero to item `+0x28`, and appends it to the StringGob list. `SetLine` `0x14004a6e0` likewise zeros `+0x28` for every newly created item. `StringGob::AttachModel` `0x140047ca0` is a direct writer: it stores its supplied polymorphic `CAurObject*` at the selected item's `+0x28`, with no source-class check. `StringGob::Render` `0x1400498a0` tests that field on each visible item; when nonzero it invokes the object's virtual `+0x28` animate and `+0x20` render before `CAurFont::TextOut` `0x14004c870`. For a `Gob` object those slots resolve to `Gob::Animate` `0x14004dbd0` and `Gob::Render` `0x1400a4280`, whose renderable TriMesh branch reaches `RenderInterface::RenderVertexData` `0x1400beec0` and conditional `glDrawElementsBaseVertex`/`glDrawArrays`. The text branch reaches `RenderInterface::RenderVertexStreamData` `0x1400beed0` and conditional `glDrawArrays`/`glDrawElements`. These object and GL leaves are conditional on actual item pointer, object subtype, visibility, Part and texture state. Evidence: REA `ev_38f35103385f40f5b481c02a2d7fc337a2a8c893962e50a2172e98eceaec25f4`, `ev_0ecbaba4bcc4b5fa9dc1e363eeb71dd1bb55ecf275563c2a0735238c235c6882`, `ev_5667b9dbf4ebc7b8f1bf50ade3c62ad73c3a39d816fc0253e95edd1d86244ab8`, `ev_d550614a2af7ec7775eeb665961fc362a84cf0f886207550ab8df61e5ba54ef2`; GL leaf evidence in the linked draw branch.

The exact incoming-reference query for `AttachModel` finds only two DATA references, including its StringGob interface-table slot `0x140d81780`; it finds no direct code callsite. `GetAttachedModel` similarly has table/data references only. That bounds **direct** callers, but an indirect caller is now proven: `CGuiListBox::CGuiListBox` `0x1401e8160` installs a `NewCAurString` interface at listbox `+0x90`; both `CGuiListBox::SetItem` overloads `0x1401ebce0` and `0x1401ebed0` read the selected item's existing attached pointer through interface slot `+0x38` (`GetAttachedModel`), change its text and state, then call interface slot `+0x30` (`AttachModel`) at `0x1401ebe78`/`0x1401ebfed` with that **same** saved pointer and index. This is an exact attached-object **reattachment** producer. It preserves an existing model, including null, and does not identify the initial source of a nonnull pointer. If such a pointer is present, subsequent `StringGob::Render` can take the model/Part GL route above. Evidence: REA `ev_3380a88f3545f315f88043ba9158025dadf9605b00d10d0ff6852b862889a0de`, `ev_9c592ab42cb2b9f0e15ec1497d890778b89b0ea64406862159929ca889dd49a4`, `ev_682057ae814f40c4307cedb4daa517f499a0aff5bb201fbbc55d1b80c1f4fb22`, `ev_3330c119cb89de6760ad5b36f2e2ee156306fb9919f160032cc38370f4b54510`, `ev_81e170f87e09642feb6d12891f8c5bf32d2bdf07d07dbc986dffa045d5491e49`.

One concrete local path is narrower: `AurPrintString` `0x140069b80` constructs a fresh `StringGob`, sets its font, position, text and color, calls `StringGob::Render` directly, then destroys it. `SetText` `0x14004aae0` clears prior text and dispatches interface slot `+0xd8` to `AddText` `0x140047870`; if no item exists, `AddText` dispatches interface slot `+0x120` to `AddLine` `0x140047760`. That new item begins with null `+0x28`, and no local call attaches a model. The posted-string overlay through this local object therefore has a proven text draw route and no proven embedded-model producer. Other scene-attached StringGobs, including GUI labels, can be mutated after construction and remain conditional. Evidence: REA `ev_222d2523fd429495255b2735569aef13910ece8c54b541e3b3c3a2b102819644`, `ev_7bf6ef2798e3a6c521c221f3dabfe3345c54c5d1579816ebc9c54daa51b6ef50`, `ev_57d6e7ef2f7eae5311cca67d69681a32e9d3554b22d3473d790b174c224a4cc6`, `ev_7069524ef5d1b4151cd17352a82c3a8482f2dac4d6ad599bba331e956967fe94`, `ev_47930dd38517d133f745cf0403de13173a705644702492cb0c40e4723075e833`.

`StringGob::Render` also calls its virtual `+0x298` `Gob::DoEvent` with `propagaterender` only when its render argument asks for propagation. The [Gob callback census](original-gob-callback-census.md) has one concrete `CAurBehaviorAttach` registration for that event and explicitly leaves the live handler set unknown. The direct `AurPrintString` call passes false, closing this event branch for that local posted-string path; GUI scene dispatch can pass different values. Evidence: REA `ev_d550614a2af7ec7775eeb665961fc362a84cf0f886207550ab8df61e5ba54ef2`, `ev_222d2523fd429495255b2735569aef13910ece8c54b541e3b3c3a2b102819644`.

The initial **nonnull** model source remains bounded rather than proven. The three `CGuiListBox::AddItem` overloads `0x1401e8a30/0x1401e8b50/0x1401e8cf0` only dispatch `StringGob::AddLine` at interface `+0x120`, set line height and register update. The two `InsertItem` overloads `0x1401eaa30/0x1401eae90` insert a string and shift color/height metadata; the observed body does not call interface `+0x30`. `SetItem`'s two `+0x30` calls use the immediately saved `GetAttachedModel` return rather than a new model. `SetHighlightModel` `0x1401ebbd0` does call `NewCAurObject`, but stores that object at **listbox `+0x438`**, separate from each StringGob line's `+0x28`. Thus the examined listbox API creates null embedded-model slots and preserves any prior slot; it does not establish how a nonnull line pointer first arrives. Other callers can reach the exposed polymorphic StringGob interface or its item array, and remain open. Evidence: REA `ev_cc20965632b6dbdcb66289ed2924090061c8fefbaa630271f17d982b71c4d480`, `ev_2d8978382e3257379a75b15138e569c7ed2421123e40b4eb3d672e6c931308a7`, `ev_6269dde25ecf52505e579cf52c0ceb44bf24b198293252ca7625bf4f1494533d`, `ev_4af98a59c597f6fb7b3d4a213890a47e24ecf8d7c0c6a0c944341a4423e24b9c`, `ev_51b64f034d2fcf6a61d36fa0c26ae816ea7476a285689c037a8671ee88d62bea`, `ev_73d8ad40126690aa1db78e4830328f5c7661c76a68a56d6aa19d7f2103bd9741`.

## Panel callback `+0x88`: deactivation, then the draw owner

`CGuiPanel::CGuiPanel` `0x1401fbb80` initializes the callback receiver at panel `+0x80` and the function at `+0x88` to `CGuiCallbackv1<void,int>::HandleUninitializedCallback`. `CGuiPanel::Deactivate` `0x1401fc470` invokes it synchronously at `0x1401fc62d` **only after** active flag `panel+0xb0 & 1`, virtual `OnDeactivate`, scene/model disable, active-list removal, `UnRegisterUpdate`, and `DoPanelEvent`; it passes the deactivation reason. That callback is a lifecycle/event leaf, not an immediate GL draw. Destruction can call `Deactivate` when an active-list node remains. No worker queue is present in these bodies; the callback inherits the thread that called `Deactivate`. Evidence: REA `ev_ab2bd50191881b9a2ff2814c8c8714f6fedf2552f055f86ac3aa44a9bbea5432`, `ev_bb311dc99fd68b7244b7c3b7a22d4eed385764a219805c3852ab40bb9da6232a`, `ev_370d900cf6b18851cf629b46ae8168b0556e56b063342f6b4e7624f454f7e423`.

## Other named GUI render entries

`CStringItem::Render` `0x140049880` is a one-call wrapper to `CAurFont::TextOut` `0x14004c870`, passing its item string and count. Its only exact incoming references in REA are DATA at vtable `0x140d81428` (slot `+0x8` of the `CStringItem` table `0x140d81420`) and another data cell; there is no direct code caller. The mapped `StringGob::Render` loop itself calls `CAurFont::TextOut` directly, bypassing `CStringItem::Render`. Thus this named entry has a known conditional text GL descendant through `RenderVertexStreamData`, but an active virtual caller is **not** established from the direct-reference census. Evidence: REA `ev_4547a55c613e6e6ee1c75eb845dccdf9072047b3b5a11e17d4d2ebc9316373fd`, `ev_d476734ed27b46760ceac5162e7f943091d957a39a3519223479c231a2a7c51a`, `ev_d550614a2af7ec7775eeb665961fc362a84cf0f886207550ab8df61e5ba54ef2`.

`CGuiPanel::RenderSceneViewFirst` `0x1401fc940` and `RenderSceneViewLast` `0x1401fc9b0` are ordering operations, not draw calls. Both remove the panel-owned `CSceneView*` at panel `+0xb8` from manager view array `+0x18` and append it; `First` then shifts the other entries and writes that pointer at index zero, while `Last` leaves it at the tail. Concrete `First` callsites are `0x1406e9722`/`0x1406e987e` for text-bubble activation/position, `0x1407665c1` under `param_3!=0` and panel `+0x148==0`, `0x1407e8634` for the lightning flash panel, and `0x140972830` when a floaty-text panel has no active node `+0xa0`. `Last` has one direct caller `0x140892a1d`, gated by `param_2` bit `0x12`; it also calls `GobRenderLast` on owner `+0x4d8`. Their visible effect requires that a registered GUI view later reaches the camera/scene render loop, then a visible attached model or StringGob reaches the conditional GL leaves. There is no worker dispatch in these small reordering bodies; they run synchronously on their callers' thread. ## Fade completion callback `+0xf8`

`CPanelScreenFade::CPanelScreenFade` `0x1401ffdc0` initializes receiver `+0xf0` and callback `+0xf8` to `CGuiCallback::HandleUninitializedCallback`. `CPanelScreenFade::Update` `0x140202450` calls that callback synchronously only when the fade clock is active and reaches completion, after its alpha update. The constructor has four direct caller procedures: `0x140708540` (credits clickable), `0x140719b90` (intro clickable), `0x1407e7da0` (lightning flash), and `0x140836f60` (area loadscreen). The two clickable derived constructors install separate child-control callbacks at `+0x1b0` and do not replace the base fade callback `+0xf8`. The immediately examined producers of those four classes did not show a `+0xf8` assignment. This is a bounded constructor/caller observation, not proof that no later owner mutates it. The concrete completed-fade function target on these observed default paths is the no-op; the conditional alpha/model draw still follows the scene path above. Evidence: REA `ev_a8e2e53935dfb5e927782791ce94a7dd1283b1b19d10ac0e6c0022fd92d8aa07`, `ev_3fae1f68d938397a8538ecf60ac079d53aa97b943f77caba0f93c405ee142567`, `ev_0b7e5b0adbae7a32bf19b16625216729bc060fc99fe82dbe584c91bdba31972c`, `ev_01277c13b8d4edbab709a5382264b73902eac8bbf976ce6ad09b24f29b267ba0`, `ev_96464140fb9fe2f53801e0369960fb8d81ed42994f65de79e998030e3bc67875`, `ev_7857f863aa2e610142292f805b7df428b8813baa572e579c0aeb61478c0dbbdf`.

The direct `SetFade` reference census yields `FUN_1406e1670` (a wrapper adding three string-color updates), `FUN_140717f60` (credits stage update), `FUN_14071a4b0` (intro stage update), and `FUN_1407e7da0` (lightning flash). The completion callback is invoked on the GUI update caller thread; `setalpha` changes model state, with actual GL submission later through GUI scene traversal. ## Remaining static and runtime edges

1. The initial nonnull `AttachModel` writer and actual `CAurObject` subtype. The two `CGuiListBox::SetItem` indirect callsites only preserve an existing pointer; other indirect/dynamic callers or post-construction mutation remain open.
2. Any later assignment to fade completion `+0xf8` outside the examined constructors/immediate owners, and the exact active panels in a particular frame.
3. Data-dependent layout resrefs, attached Part subtypes, active GUI views, font texture state, and the live `propagaterender` handler set. Their target families and conditional GL leaves are mapped in the linked branches, but static analysis cannot select a runtime instance.
