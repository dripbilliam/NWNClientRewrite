# NWN-75: original particle and attached-effect render branch

Original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are original PE virtual addresses. REA/Ghidra pseudocode is decompiler evidence, not source. This branch starts at the emitter stage of `Scene::RenderSinglePass`; shared GL state and other scene buckets are cross-referenced, not claimed as particle-only work.

The [Lightning source and target publication supplement](original-particle-lightning-source-publication.md) and its [address ledger](original-particle-lightning-source-ledger.json) trace text and compiled model fields, command callback registration, controller defaults/publication, and recursive Reference Gob creation into the update branch below. Actual static-initializer execution order and text command whitelist choice remain runtime-dependent.

The [emitter material and state source supplement](original-particle-material-state-source.md) and its [address ledger](original-particle-material-state-source-ledger.json) trace authored `texture`, `blend` and `twosidedtex` into Material initialization and conditional OpenGL texture/state calls.

## Call tree and stage order

```text
Scene::RenderSinglePass 0x1400d0f10 [stage 21, after additive bucket]
  Scene::DoEmitterBucket 0x1400c7ae0 [fog; IsAnimating/force gate; collect/sort]
    PartEmitter::AnimateParticles 0x140061210 [delta clamped to 0.5]
      virtual PartEmitter+0x100 → Fountain/Explosion/Single/Lightning::Update
        particle lifetime, movement/collision, emission/RNG, attached-Gob lifecycle
    PartEmitter+0x1b0 per-instance render callback, camera-distance order

      RenderMotionBlurred 0x140064180 ├→ PartEmitter::RenderEmitter 0x140062900
      RenderLinked 0x140064170 ───┘     material → six CPU vertices/particle
                                        → stream upload → shader/state → glDrawArrays
```

The dispatch and source-dependent callback selections are established by `DoEmitterBucket` (`ev_a6bfdd377081f8ddc99385863fdd0608e54dafff7e58ee35926199eb87a2b3e9`), `PartEmitter::Initialize` (`ev_3905f9c842ca12afc35eb75262ef0cd7f3c3c00c111e7fe9567cdee463bb828d`) and `RenderEmitter` (`ev_03c94ab09a5b369db37c9ac35170fa07ce8eeb85ca5d48ade2c233992d604f88`). The three named render entries are jump thunks to one shared routine; their mode branches are inside that routine. `RenderNothing` is a real alternate callback, not an empty function (`ev_01aaf24b7152fc88809d7b7a5c2af64528b42a22d382eea40b92e22eb22f2364`). The caller executes animation and rendering sequentially in the scene render route; no separate particle worker is established here. Authored emitter counts and per-frame frequency require runtime evidence.

`Scene::DoEmitterBucket` wraps its emitter collection with `PartEmitter::StartEmitterLayer` `0x140064720` and `StopEmitterLayer` `0x140064760`. Start sets the emitter color to white and changes enabled render states; Stop restores depth mask, blending and other state (`ev_6641a7ea4880c99cc48de4c6187d41989d6511037cd3fab7217e05fb1d00461b`, `ev_8731a9b13db29b39bb1f3c0da81da4f26dab17f542c46612651e2f1339441bb6`). The state helper descendants join the shared GL state path.

## Simulation, emission and service leaves

`AnimateParticles` (`ev_94298fdbef50a777edca20b8e740cf4bb6069376493f19ec2c974abe89f3eb53`) rejects inactive owner/parent fade states, derives owner/world pose through Part virtual `+0x18=GetWorld`, keeps previous and current transforms for movement emission, clamps delta to 0.5, then invokes emitter virtual `+0x100`. ## Normal quad render to graphics API

`RenderEmitter` `0x140062900` returns before draw when its owner/parent fade gate fails, effective live count is below one (linked mode uses `live−1`), or emitter lifespan is zero. An enabled debug flag can draw an emitter bound sphere. It binds the source Material, picks camera/emitter/world/directional/motion-blur/linked geometry branches, uses owner adjusted scale, optional `LightManager::GetEmitterLighting`, lifetime color/size/alpha/UV and authored atlas dimensions, then sets cull, depth and blending by mode (`ev_03c94ab09a5b369db37c9ac35170fa07ce8eeb85ca5d48ade2c233992d604f88`). Material binding is described below. No claim is made that every mode executes in a particular live scene.

For modes other than Linked and Motion_Blur, the generic path at `0x140063aa6` applies the particle's rotation `+0x1c` through scalar angle helpers and quaternion multiplication `0x140063b3e`; particle flag `+0x70` selects its saved direction `+0x4c..+0x54` or the mode's base axis. All seven modes converge at `0x140063c38` and write the same six-vertex, 24-byte-per-vertex format: packed color at `+0`, position XYZ at `+4/+8/+12`, and UV at `+16/+20`. The helper names for `0x140c7ac70/0x140c7a2b0` are not recovered in this Ghidra session, so only their angle-input role is established by their callsites and surrounding quaternion arithmetic.

When the source lighting flag is set, `LightManager::GetEmitterLighting` `0x14007ee50` walks its selected light list, measures each distance from the emitter, accumulates attenuated RGB for lights inside radius, adds optional headlight/global contributions and clamps components to one (`ev_6c921ee5585940d4c297043530bb266a12bd47f431f70b88466904cc8ed514d7`). The routine obtains one shared, nonindexed `VertexStreamDataObject` at global `0x141301318`, with capacity `0x14128e38c`. After the stream commit, the routine looks up cached `vsparticle`/`fsparticle` custom shader variants keyed by blending mode, sets a shader float, binds a custom program and material parameters, then calls `RenderInterface::RenderVertexStreamData(stream,3,6×count,0)` `0x1400beed0` (`ev_03c94ab09a5b369db37c9ac35170fa07ce8eeb85ca5d48ade2c233992d604f88`). **The stream upload precedes shader lookup's null-return gate**, so a missing shader can leave CPU/GL buffer work without a draw. `RenderInterface::RenderVertexStreamData` is a five-byte jump to `GLRender::RenderVertexStreamData` `0x1400b5c20` (`ev_9682f759461cac1698e530425c68a1f6f64f7873fe4f153285f9011c35724cfb`, `ev_faed7a96ea930f48e2170d7800f7dc1d4110c2b5267b35fe6813a21dee29899a`). It clears temporary render hint/custom program state after drawing. `GLRender::SetVertexStreamDataObject` `0x1400bacc0` avoids reselecting the same object, otherwise binds/creates a VAO and configures vertex attributes (`ev_bae9b5bff5ac07495c2764495f240af3ad83df46761f74011e01445c7d2676cb`). `GLRender::SetProgram` `0x1400b7a40` avoids rebinding the same program, then sets uniforms (`ev_c2fa9ed1743a63b47c3b92d6a2cd636bdebff3734eddc2913bdeac583cee5a97`). ## RenderNothing and attached-model branch
