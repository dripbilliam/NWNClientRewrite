## Startup producers

The CRT startup route `FUN_140c11a00` invokes `_initterm` at `0x140c11a77` over pointer entries `[0x140d7d790, 0x140d7fea8)`. The two entries at `0x140d7da90` and `0x140d7daa0` contain original little-endian pointers to `FUN_1400152d0` and `FUN_140015150` respectively. `_initterm` calls each nonnull entry in its range. These are startup registrations, not model-load-time constructor calls. REA `ev_1ebf0e68`, `ev_be6263d5`, `ev_b266f15a`, `ev_f0ca02df`.

`FUN_1400152d0` passes static `ConFnewmodel` `0x141301c90`, literal `newmodel` at `0x140d890f0`, and function `newmodel` `0x1400a1920` to `ConsoleFunc::ConsoleFunc` at `0x1400152e9`. `FUN_140015150` similarly passes `ConFbeginmodelgeom` `0x141301e10`, literal `beginmodelgeom` at `0x140d89110`, and `beginmodelgeom` `0x1400a1160` at `0x140015169`. The pointer producers are directly visible in the preceding `LEA RCX/RDX/R8` instructions. REA `ev_52600853`, `ev_86d90316`, and instruction IDs in the ledger.

`ConsoleFunc::ConsoleFunc` `0x14005d040` copies the command name into the static `ConsoleFunc`, allocates a 16-byte `funcholder<void (*)(char*)>`, stores the command-specific function pointer at holder `+0x8`, and stores vtable `0x140d83d48` at holder `+0x0`. It stores the holder pointer at `ConsoleFunc +0x50`, then calls `ConsoleFuncs_Add` at `0x14005d098`. `ConsoleFuncs_Add` inserts into the global `ConsoleFuncs` pointer array at `0x1412e1030` while maintaining raw byte lexicographic order and increments `ConsoleFuncs_num` at `0x1412e1028`. The static `ConsoleFunc` objects own the registration; their destructor removes the registry entry and releases its holder. REA `ev_51b62a3c`, `ev_13df428c`, `ev_010edbe1`.

## Lookup and two-stage computed dispatch

`FindConCallBack` `0x14005eb10` first tests the remembered index `0x14128e35c` if it is within `ConsoleFuncs_num`, compares the requested token byte-for-byte with the stored name, and returns that entry's holder at `+0x50` on a match. Otherwise it resets the index and scans the registry linearly, returning the matching holder or null. The lookup comparison is byte-exact; the model whitelist is a separate case-insensitive prefix check. Thus whitelist acceptance alone does not select a callback. REA `ev_dcfb84ee`, `ev_4bda6811`.

`FindModel` installs whitelist `0x1400a16e0` on a cache miss before the text resource is interpreted. In `FuncInterp` `0x14005ebf0`, an empty token or null whitelist passes the gate, and a nonempty token with a whitelist must return nonzero. It then calls `FindConCallBack` at `0x14005f589`; a missing entry reports a not-found result. A found holder receives the trimmed argument string through computed vtable `+0x8` at `0x14005f68c`. Original vtable bytes at `0x140d83d48` are `0x14005d650`, `0x14005e670`, `0x14005fc70`, so this slot is `funcholder<...>::Engage` `0x14005e670`. `Engage` calls the holder's stored command pointer at computed `0x14005e67a` and clears `returnvalue` byte zero. For the registered `ConFnewmodel` the target is `newmodel` `0x1400a1920`; for `ConFbeginmodelgeom` it is `beginmodelgeom` `0x1400a1160`. This resolves those two candidates at the same two computed sites without claiming all console commands share these targets. REA `ev_e100938d`, `ev_003c054d`, `ev_7a8dda85`.

The resulting typed construction and `ImportMaxTree` paths are mapped in `model-name-parser-tree.md`. Other registered console commands retain their own function pointers and are outside this bounded branch. The callback selection can vary if registrations are removed during lifetime or a token does not match exactly; this static map establishes the original producer/lookup/dispatch chain, not a particular runtime invocation count.
