## Classification and active Model

The text-MDL `classification` handler `0x1400a11b0` compares the authored word case-insensitively. `door` writes byte **`0x8`** to `currentmodel+0x92`; `tile`, `character` and `effect(s)` write distinct values. The parser callback registration and dispatch are in [other text command holders](model-text-other-command-holders.md). `NewCAurObject` stores the primary Model at Gob `+0x68` and builds its Part tree, with possible alternate LOD Models at `+0x70/+0x78`. `Gob::SetLODModel` may later swap the active Model `+0x68` and matching Part root `+0x90`, so the render-time classification test is against the **active** model. The byte's origin for every compiled/binary model format is outside this text-token branch. `Gob::Gob` initializes owner fade alpha `+0x10c` to 1.0. ## Scene update and material consumer

`Scene::RenderSinglePass` calls virtual `+0x258=FadeDoors` `0x1400c9320` early in the pass. `FadeDoors` scans `_gobbucket`, and only Gobs with a nonnull active Model at `Gob+0x68` and bit 3 set in Model `+0x92` enter its geometry/update branch. It computes the center of Gob bounds `+0x160..+0x174`, transforms camera relative position/direction by Gob pose, then calls CPU `BoxIntersect` `0x14022b400` at `0x1400c95f8`. That leaf tests a segment against six AABB faces and returns a face index 1..6, zero, or -1; it has no GL child. A -1 result or any other result whose transformed normal has view dot `<=0.1` subtracts `DeltaT/0.3` from Gob `+0x10c`; the remaining branch adds the same amount. The result is clamped to `[mindooralpha,1]`. This work is per eligible Gob in the visible Gob bucket and does not itself draw. Evidence: fade body `ev_65b14b6b7ce72308524124fafa548a317adc1b06f84f3fa415bbcb4afa769f92`, box leaf `ev_803c57170127c1f6d1a52c58f5feda2db730d24da0a0740403d3f1b90fdb5461`.

An ordinary admitted `PartTriMesh::Draw` `0x1400a24c0` invokes its dynamic `+0xc0=PartTriMesh::Mat` `0x1400a2f50` when the Part has an owner Gob at `+0x50`. `Mat` starts with Part alpha `+0xa8`, applies other owner color/alpha factors when selected, tests that same active Model `Gob+0x68 -> +0x92 & 8`, and multiplies its local alpha by Gob fade `+0x10c`. Its subsequent material path may call `RenderInterface::SetColor4f` with that alpha or include it in `SetMaterialv` diffuse publication, depending on render state/material flags. It then binds standard textures and selects a custom shader as appropriate. The admitted TriMesh Draw route continues through `RenderFlat` or environment/water variants to `RenderInterface::RenderVertexData` and conditional `glDrawArrays`/indexed GL submission, as mapped in the shared boundary; the alpha change itself does not create an extra draw call. The static link establishes state propagation, not that a particular door is drawn in a measured frame. Evidence: Draw `ev_c71ed73886caf625dd53c91057d40e26fa6a18417d916a54db3aba9ee05d19ee`, Mat `ev_8eb1896642e5fc302f6f9e49cbc5701f76698dfa8a9865b563a32bfb9397920b`.

The flag value is authored model state, while `mindooralpha`, camera pose, visible bucket membership and actual material branch are runtime-dependent. This is a per-frame CPU fade calculation for admitted door Gobs, but its contribution to frame time is unmeasured.
