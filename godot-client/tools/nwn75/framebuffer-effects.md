# NWN-75: original camera framebuffer-effects branch

Pinned original `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. `Camera::DoFrameBufferEffects(int)` begins at `0x140057b20` (REA `ev_eb53ac3aa7cbcc23c21013c1ebcba08b8306ede42ace739e4afd40a8047679dd`). `Scene::RenderSinglePass` calls phase 0 only for `mainscene && enableFBeffects`, and phase 1 for `mainscene`; the function itself exits without work when `enableFBeffects==0`. All phase branches are synchronous callees on the inherited render caller thread in the static call tree.

The earlier `mainscene` entry calls `Camera::InitializeFrameBufferResources` `0x140059670` before those effect passes. Each call submits 17 float and four integer global shader parameters (SSAO, levels, contrast, vibrance, DOF, toon and bloom groups) through RenderInterface setters, then compares cached resolution, HDR, renderbuffer, bloom offset and MSAA settings. Only a changed setting calls `Camera::ClearFrameBufferResources` `0x140057930`. The float and integer setter bodies compare each value with a cache and only increment shader dirty generation on change; the integer setter can also flag shader reload for selected indices. Thus the 21 calls do not imply 21 GPU uploads. It then resets camera framebuffer state `+0x530`, sets the viewport with dimensions clamped to at least one, calls `Camera::RefreshRenderSubframeResources` `0x14005a0f0`, binds framebuffer `Camera+0x534`, and clears mask `7`. `RenderInterface::SetViewPort` reaches imported `glViewport` on every call, although it updates its dirty generation only on changed dimensions. `RenderInterface::Clear(7)` reaches imported `glClear` with the translated color/depth/stencil bits. These latter calls are in the body without an effect-enable gate; refresh/bind wrappers have their own resource/state checks. REA initializer `ev_e76e387ba5c5ae151f6d71c8bc18232692c3f55845145ae27121f380868a4866`, setters `ev_7896c849`/`ev_ec32b7ef`, viewport `ev_ab6c5a6a`, clear `ev_95a9de03`. Lazy FBO creation and conditional resource deletion are traced below.

After saving depth/blend/matrix state, the function lazily creates a full-screen quad `VertexDataObject` and commits its static vertices. Its two phase branches are:

The original `Camera::DoFrameBufferEffects` body has **six** physical calls to `RenderInterface::Finish`, and all six have the additional `glFinishBeforeFBO != 0` gate. Site `0x1400580d7` is phase-0 bit-0 SSAO before its copy; `0x140058626` is phase-1 bit-1 bloom before its copy; `0x1400586b9` is bloom after extraction draw; `0x140058764` is inside its bounded downscale loop; `0x140058846` is inside its bounded upscale loop; `0x140058974` is phase-1 bit-2 postprocess. The last two bloom sites can execute across multiple iterations, so six static callsites is not a runtime call count. `RenderInterface::Finish` `0x1400bead0` is an E9 thunk to `GLRender::Finish` `0x1400b3390`, which tail-jumps to imported `glFinish` at its entry. The six exact connectors replace the old unsited wrapper-to-GL summary in the scene ledger. Camera body `ev_1f13dbbf7bcca0527a9ecdce6cbcc35bf10d632e0740d00174f7fd4d09245fa7`, Finish wrapper `ev_c448f4928245c349f0c2e9d4bf60b2d02817c94edb56398b9dc1c105f33b0a75`, GL body `ev_10047bf4a30f362c27705fe18f521ece052d05725a6697717f34c1c3461d1729`.

The same body calls `Camera::SetRenderSubframeTarget` `0x14005b720` at four distinct phase sites: `0x140058552` selects SSAO subframe 0; `0x140058687` selects bloom extraction subframe 8; `0x1400586e9` selects downscale subframe `index+9`; `0x14005879b` selects upscale subframe `index+15`. `Camera::CopyRenderSubframe` `0x140057a20` (REA `ev_534676fd`) binds/copies a framebuffer and refreshes its resources when needed. `Camera::RefreshRenderSubframeResources` `0x14005a0f0` and `Camera::SetRenderSubframeTarget` `0x14005b720` are direct descendants. The shader/FBO setup branches include `RenderInterface::GenFramebuffer`, `BindFramebuffer`, `GenTextures`, `DirectCreateTexture`, `SetFramebufferRenderTarget`, `CheckIsFramebufferValid`, and `GetCustomShaderProgram`. `RenderInterface::BindFramebuffer` `0x1400be8a0` and `CopyFramebuffer` `0x1400be910` reach function pointers `DAT_141443248=glBindFramebuffer` and `DAT_141443258=glBlitFramebuffer`; `GenFramebuffer` `0x1400beae0` reaches `DAT_1414432a0=glGenFramebuffers`; `CheckIsFramebufferValid` `0x1400be8e0` reaches `DAT_141443260=glCheckFramebufferStatus`. The pointer loader `FUN_140b6e940` `0x140b6e940` names these APIs in `wglGetProcAddress` calls (REA `ev_808064ca`). These are external API boundaries. Lazy resource creation and deletion are traced below; nested custom-shader lookup remains a separate branch. No runtime effect settings are inferred from this static tree.

The FBO attachment branch has a more precise external boundary. `RenderInterface::SetFramebufferRenderTarget` `0x1400bf120` is a jump thunk to `GLRender::SetFramebufferRenderTarget` `0x1400b70c0` (REA `ev_78e9007f`). It first binds the FBO and translates attachment type. For `param_4==0` it loads global `0x141443278`, assigned `glFramebufferRenderbuffer` by `FUN_140b6e940`; otherwise it loads `0x1414429c0`, assigned `glFramebufferTexture` by loader `0x140b7b8e0`. The latter assignment is proved by the pinned PE instruction sequence `0x140b7c13e` (`LEA RCX,[glFramebufferTexture]` at string `0x140eac0f8`), the following `wglGetProcAddress` import call, and store to `0x1414429c0` at `0x140b7c14b`. Both branches end in the computed tail jump `0x1400b7171`, with read/draw/combined framebuffer target determined by `param_6`. This closes the two attachment API targets; camera subframe texture lifetime is traced below, while exact high-level caller conditions remain conditional.

Texture allocation/upload also reaches an original external API boundary. `RenderInterface::DirectCreateTexture` `0x1400be9d0` is a jump thunk to `GLRender::DirectCreateTexture` `0x1400b0150` (REA `ev_6b820762`). It restores alignment 4 on the altered-alignment branch. `RenderInterface::GenTextures` `0x1400beb10` jumps to `GLRender::GenTextures` `0x1400b34c0` and imported `glGenTextures`; `RenderInterface::DeleteTextures` `0x1400be9b0` jumps to `GLRender::DeleteTextures` `0x1400afe20`, which clears cached bound IDs before imported `glDeleteTextures`. Optional `RenderInterface::Finish` `0x1400bead0` reaches imported `glFinish` through `GLRender::Finish` `0x1400b3390`. These are static conditional paths; execution counts and the session's configured value remain unmeasured.

The camera subframe lifetime is now more explicit. `Camera::RefreshRenderSubframeResources` `0x14005a0f0` immediately returns for sentinel subframe `0x1a` or an already allocated framebuffer ID. Otherwise it generates and binds an FBO and creates attachment textures for the relevant subframe case; subframe 0 under camera `+0xe3c` instead creates depth/color renderbuffers, and cases 3, 4–5 and 7–23 select different texture formats/attachment slots. It checks FBO validity, logs failure, then rebinds the previously active camera target or ID zero. The creation branch reaches `glGenFramebuffers`, `glGenTextures`, `glTexImage2D`, `glFramebufferTexture`/`glFramebufferRenderbuffer`, `glCheckFramebufferStatus`, and for the renderbuffer case `glGenRenderbuffers`, `glBindRenderbuffer`, imported `glGetIntegerv` on first sample-cap query, and `glRenderbufferStorageMultisample`. Each admitted new texture also calls `SetTextureParameters`, which issues GL texture-parameter calls. This work is lazy per subframe ID, not a full allocation on every `Refresh` call.
