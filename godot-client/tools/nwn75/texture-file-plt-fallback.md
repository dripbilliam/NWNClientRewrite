# File-backed PLT fallback to texture publication

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Address-backed edges are in [the ledger](texture-file-plt-fallback-ledger.json). This is the shipped initial `AurGetLayeredRaster` callback route. The later installed `CAuroraInterface::GetLayeredRaster` resource/cache route is already in [texture resource demand](texture-resource-demand.md), and [texture publication](texture-publication-per-frame.md) covers its common CPU/GPU consumers.

`CAurTextureBasic::ConstructImage` `0x1400eac60` takes its layered/palette route when Basic `+0x48` is present and an initial image is unavailable or ineligible. Its indirect call at `0x1400eb1d5` uses cell `AurGetLayeredRaster` `0x14128edf0`. The shipped cell points to `ImageReadPLT` `0x140073770`; `CAuroraInterface` can later replace it with `GetLayeredRaster` `0x1400f5d80`, so the file fallback is conditional on callback state. Evidence wrapper `ev_79c644d15734853e063a31ca0b2f501a9d8845c8a45ec2c9199dfef10ee21b32`, shipped/installed pointer evidence `ev_0a97361c446ef2e3bdf50b0a7b35b626aa5506a24eb2343fad5129ba97275a95` and `ev_293a404c845695d708fa6a2b6768a66b2f0592aa21d05fcb34f38830dda9b141`.

`ImageReadPLT` formats `<name>.plt` into a local path at `0x14007379c`, opens it through CRT `fsopen` at `0x1400737ad`, and returns null if open fails. On an open stream it reads one 24-byte header at `0x1400737cb`, takes width and height from local header fields, allocates `uint32(width × height × 2)` bytes at `0x1400737e6`, reads that many index bytes at `0x14007380b`, closes the stream at `0x140073813`, and returns the CPU buffer. The routine does not test either `fread` return before publishing dimensions or buffer. If allocation fails, the observed branch returns null at `0x14007381d` without reaching the `fclose` site. These are static failure-path observations, not a claim that malformed/failed files execute in a normal session. Evidence `ev_839d24229a2bf9c2d551906baf2efea996f672b067e3a53057fac4f5127ed67e`.

The open continuation is `fsopen` `0x140c4fb20` → `common_fsopen<char>` `0x140c4f8f4` → `_openfile` `0x140cac950` → `_sopen_nolock` and the installed imported `KERNEL32.DLL::CreateFileW`, with mode/error gates. `fread` `0x140c7e2a0` → `fread_s` `0x140c7e2c0` → `_fread_nolock_s` `0x140c7e010`; a warm CRT buffer can satisfy reads, otherwise `_read_nolock` can reach imported `KERNEL32.DLL::ReadFile` at `0x140ca7a53`. `fclose` `0x140c4f7e8` conditionally reaches `_fclose_nolock`, `_close_nolock`, and imported `KERNEL32.DLL::CloseHandle` at `0x140ca6f22`. These are the external OS file boundaries; the source bytes and CRT buffering state are unknown. The shared CRT/Win32 descendants and exact sites are documented in [archive open/close](archive-open-close-header-loading.md) and [file resource read](model-resource-storage.md). On a successful callback result, `ConstructImage` stores the index buffer at Basic `+0x58` with kind `+0x84=4`. If `g_bGeneratePLTOnGPU==0`, it calls `ImageDecode` at `0x1400eb261` to make four-byte pixels, then releases the index buffer through the installed `AurReleaseLayeredRaster` callback when the ownership flag is set, or direct allocator free otherwise. With GPU PLT generation, `glImageBasic` can bind the index/palette sources and draw the conversion quad into an output texture through the already mapped `RenderInterface::RenderVertexData` and GL boundary. Later `CAurTextureBasic::FreeImage` `0x1400eb640` releases a remaining nonnull image buffer by callback for callback-owned kind 4 or direct free when the flag is clear. The callback state, palette content, GPU-generation setting, texture construction success and later Scene draw remain dynamic. This path is synchronous on its inherited caller thread; no worker handoff appears in `ImageReadPLT` or its direct wrapper.
