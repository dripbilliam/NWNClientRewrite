# Original Lightning segment scheduling and CPU/GL leaves

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This supplements the existing [Lightning update map](original-particle-lightning-update.md) with exact update callsites and terminal effects. The authored text/compiled model, controller publication and `_EmitterTarget` reference-Gob producer are already traced in [Lightning source publication](original-particle-lightning-source-publication.md). This file starts at their instance fields and target pointer; it does not assume a particular authored effect executes. The address-backed edges are in [the scheduling ledger](original-particle-lightning-scheduling-ledger.json).

## Admission and list ownership

The source controller's `birthrate` becomes `PartEmitter+0x74`, converted to an integer at `LightningEmitter::Update` `0x1400652f7`. The `lightningDelay`, `lightningRadius` and `lightningScale` controllers become `+0xec`, `+0xf0` and `+0xf4`. `_EmitterTarget` reference publication stores the referenced Gob at `+0x1c0`; this update does not own or create that Gob. `Scene::DoEmitterBucket` calls `PartEmitter::AnimateParticles` at `0x1400c7c94` only for a Scene-animating or force-animated emitter; that wrapper dispatches virtual `+0x100=LightningEmitter::Update` at `0x1400615bf`. Update first obtains optional owner-Gob adjusted scale through `+0x2d0` at `0x140065353` and adds its incoming delta to `+0x1c8` at `0x140065360/0x140065368`. If integer count is zero or target Gob is null (`0x140065377/0x140065380`), it moves all live pointers from `+0x188/+0x190` to reuse `+0x130/+0x138` (loop begins `0x140065bab`) and returns. These are pointer-list writes, with possible list reallocation, without particle destruction or GL. Evidence update `ev_5658b85d9569397b683aeb2e762ee8398582fe5cc5ddee7f660a69e58dc81566`, wrapper `ev_ff99575ef698342f5a24d5144b760ebffc363ceb850792f77cdda4b6fe686c88`, Scene `ev_b4881207528882fb849869474dcd3a31c18cf9f00dad89280e126d85fcdd7ed3`.

With target and a positive integer count, Update grows or shrinks the live list to the count. Growth first takes a pointer from the reuse list at `0x1400653c5`; if empty, it allocates `0x78` bytes for a base `Particle` at `0x14006541e`, sets the Particle vtable and emitter pointer, then calls `Particle::initialize` at `0x140065470`. Reused particles skip that initialize call. Source flag `+0x174` bit 5 conditionally chooses an atlas frame with the CRT random helper at `0x1400654b3` for **either** newly allocated or reused entries. Appending to the live pointer list occurs at `0x14006553a/0x14006553e`; excess entries go back to reuse at `0x140065570..0x140065622`. Neither shrink nor zero-target handling frees Particle objects. The allocation is `Particle`, not `ChunkyParticle`, and no attached model Gob is constructed here. Negative authored counts are outside the established valid-input boundary. Evidence update above.

New `Particle::initialize` `0x140066450` resets particle clocks and pose, samples authored spread, optionally calls `Particle::randomPosition` at `0x140066553`, optionally calls `inheritVelocity` at `0x140066585` and `randomDirection` at `0x1400665a8`, and writes the resulting CPU orientation/position. `randomPosition` `0x140068d80` samples the same random helper at `0x140068da3/0x140068dcb/0x140068de8/0x140068dfe`, then writes Particle position `+0x10..+0x18` from emitter basis/origin. Its terminal effect is CPU memory. Evidence initialize `ev_6e072379e7c8ab3444fd75c3c2427a822035b68918abb247d9747090214e118c`, random position `ev_03f70d717ae46077ec4689f7518c3eeff8743f6b873d3899df2ea54d5a61506b`.

## Geometry update and random source

Update advances each live particle clock `+0x74`; render mode `6` also updates previous-position `+0x64..+0x6c` for motion blur. It compares accumulated `+0x1c8` with delay `+0xec` at `0x140065707`. While at or below delay, it reads target Gob `GetPosition` through virtual `+0xc0` at `0x140065a4c`, computes a `RotationArc` at `0x140065ab2`, rotates every live point through vector `operator*` at `0x140065b1d`, and updates cached target direction/origin `+0x248..+0x25c`. Past delay, it sets the first endpoint to emitter origin or calls `Particle::randomPosition` at `0x140065782` when emitter spread `+0xe0/+0xe4` is nonzero; target Gob `GetPosition` at `0x1400657a8` supplies the last endpoint. If endpoints differ, it resets `+0x1c8` at `0x140065810`, uses `normalize` and `cross` at `0x140065834/0x14006588d`, and calls `PartEmitter::RecursiveFractal` at `0x1400658dc` to fill middle points. A separate interior-point loop can add random displacement scaled by `+0xf4` and `+0x2c`, subject to the computed per-segment distance gate at `0x140065958`. All of these write Particle CPU coordinates, not a vertex stream or GL. Evidence update above.

`RecursiveFractal` `0x140062460` samples the random helper at `0x1400624b3`, and conditionally at `0x140062590/0x14006267a` under radius `+0xf0>=0.01`; it writes the midpoint Particle position and recursively calls itself at `0x140062792/0x1400627dc` until its halved span reaches zero. The helper `0x140c7ed00` calls `0x140ca98a0` at `0x140c7ed04` to obtain CRT per-thread data, advances the seed at `+0x28` with multiplier `0x343fd` and addend `0x269ec3`, and returns high 15 bits. `0x140ca98a0` obtains the per-thread data through CRT fiber-local storage. Thus random samples and their ordering are tied to the executing thread's CRT state; this is a static state-flow fact, not a claim about performance or a particular seed. Evidence fractal `ev_1ff832019830188ce5ae5831700c712b21c7d452907115921e2b16481be83bd5`, RNG `ev_c659766f9959e856d770a404a1d8aa77348f7f19d0c0bb900a63350fb167b12f`, thread data `ev_b8345eec615015af74425e060d597eb170b05f98f9e2fe5a7bd86175a706485e`.

## Conditional render leaf and open gates

After animation, `Scene::DoEmitterBucket` admits positive live-count emitters to its sorted list and invokes the installed instance callback `PartEmitter+0x1b0` at `0x1400c7dae`. Base `PartEmitter::Initialize` selects Standard, Linked, Motion_Blur or `RenderNothing` from authored render mode and nonempty `chunkName`. The geometry callbacks reach shared `PartEmitter::RenderEmitter` `0x140062900`; Linked mode needs at least two live particles. Under fade, material, shader and vertex-stream gates, shared RenderEmitter commits vertex data at `0x140063ff5` and calls `RenderInterface::RenderVertexStreamData` at `0x140064109`. That thunk `0x1400beed0` jumps to `GLRender::RenderVertexStreamData` `0x1400b5c20`, whose admitted nonindexed stream calls imported `glDrawArrays` at `0x1400b5d66` (indexed mode has an alternate `glDrawElements` branch). This is the conditional GL leaf, not a call made by Lightning Update. The `RenderNothing` alternative and attached Gob route are mapped in [Chunky Scene draw](original-particle-chunky-scene-draw.md); Lightning Update itself constructs only base Particles, so static source selection alone does not establish a visible attached model for a Lightning effect. Evidence Scene `ev_b4881207528882fb849869474dcd3a31c18cf9f00dad89280e126d85fcdd7ed3`, renderer `ev_56fb44ae2e3c724cc03625ef50df907410e9d0ee97ba3ed7f1c7b0d1102a2152`, thunk `ev_eebcfb2e63d9940d0fdf01c2de8150cfcda589fde0e7d844a8be9b3a26969efb`, GL `ev_f07bc8ffc5b8e28cb307462a960e15bf144503071ed421fe7b86612de920e47a`.

Remaining runtime frontiers are the actual authored controller values and reference model, `_EmitterTarget` event timing and target lifetime, positive/live segment count, source render mode, material/texture/shader admission, and actual GL execution. The owner Gob's adjusted-scale `+0x2d0`, target Gob `GetPosition +0xc0`, and installed render callback `+0x1b0` are the computed sites; their base targets are constructor-backed, while model-subtype overrides and selected authored content remain dynamic.
