# Text TriMesh material name to Part handoff

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. The [ledger](model-text-trimesh-material-handoff-ledger.json) ties authored [text TriMesh fields](model-text-trimesh-fields.md) to the already mapped [model instance](model-instance-branch.md), [material/resource](original-particle-material-state-source.md) and [texture consumer](texture-consumer-binding.md) branches. It is a creation-time CPU/material connector, not evidence of a per-frame load.

`CreateInstanceTreeR` selects node `+0x28=MdlNodeTriMeshCreateInstance` `0x1400930f0` for an ordinary TriMesh. The factory allocates a `0xc0`-byte `PartTriMesh`, calls its constructor `0x140087fd0`, copies node tilefade `+0x224` to Part `+0xac` and turns node `render +0x118` into Part boolean `+0x9e` (REA `ev_f89431dcf108875c4cdf21f53a5bb4cee2eca590fad831563d52b007727ada2c`). The constructor stores the source MdlNode at Part `+0x8`, allocates a `0x130`-byte `Material` at Part `+0x58`, initializes Part alpha to 1 and other fields, and checks a Model flag when a typed owner exists (REA `ev_7d996c349b3ebca5e755ca9b77f7876daaab2291708abfa4b5b5b68422f76f38`). Later `PartInitMaterial` loads texture references and creates a typed vertex primitive before recursing to children, as mapped in the instance branch.

`Material::LoadTextures` `0x140084410` tests `AsPartTriMesh` at Part virtual `+0x58` and `AsPartEmitter` at `+0x68`; with neither, it returns. On a mesh, it obtains the source node through Part `+0x8`, passes node texture names `+0x124/+0x164/+0x1a4` as the three standard texture arguments, and passes `MdlNodeTriMesh::GetMaterialName` `0x14008e970` as the fourth material name to `Material::InitializeTextures` `0x140083c90` (REA `ev_3e2e50cadd678a3ba9698411cfd17a19e8f0bfd1c05e05679739629f3ad1ed9d`). `GetMaterialName` returns node `+0x1e4` when nonempty; otherwise it returns node `+0x124`, so an absent `materialname` uses `texture0` as the material name (REA `ev_e79fd78d8a4e3f092b821e8c42e4b3f378d79b312ba1fabeee064868621f6d3d`). The emitter route instead uses its own texture field and does not consume these TriMesh offsets.

`InitializeTextures` can obtain a shared material, parse associated TXI state and acquire texture references through `AurTextureGetReference`; it performs no GL upload in that body. The [instance branch](model-instance-branch.md) and [texture consumer binding](texture-consumer-binding.md) follow conditional texture demand, lazy publication and draw-time binding to imported GL APIs. The exact source asset, absence/default sentinels, shared-material contents, cache hit, later bind and render admission are runtime conditions. There is no worker enqueue in the shown factory or material-name handoff; static code does not prove the invoking OS thread or its execution frequency.
