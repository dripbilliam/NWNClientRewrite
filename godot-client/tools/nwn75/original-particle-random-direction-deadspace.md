# Original particle random-direction and deadspace branch

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This follows one shared particle initialization branch that was only named in the subtype maps: authored `spread` and `deadspace` through `Particle::randomDirection` to CPU orientation/direction writes and the existing conditional draw boundary. It is not an additional emitter subtype. Exact address edges are in [the companion ledger](original-particle-random-direction-ledger.json).

## Authored source and entry gate

`MdlNodeEmitter::InternalParseField` `0x14009a030` recognizes `spread`, `spreadkey` and `spreadbezierkey` at `0x14009cbb7/0x14009cbf5/0x14009cc33`. Their literal/key/bezier handlers register Part controller offset `0xd4` at `0x14009cbd8/0x14009cc16/0x14009cc4e`. The same parser recognizes static `deadspace` at `0x14009b05c` and parses its float into source `MdlNodeEmitter+0xa0` through the call at `0x14009b07e`. The emitter source constructor `0x1400875a0` zeros that static field; the `PartEmitter` constructor `0x140060420` zeros instance `+0xd4`. The model's compiled-data branch can also populate source fields and controller arrays, as established in [source publication](original-particle-lightning-source-publication.md). Active animation control reaches `MdlNodeEmitter::InternalControl` `0x140052400`, then base controller sampling to publish `PartEmitter+0xd4`. Exact authored values and key times remain content dependent. Evidence parser `ev_2a9abd307179d433805724d593a53d8466bcf46eb5ac5eaaca63d33fce0a34a6`, source constructor `ev_ae47c019ed30702e173ef5762e372237bb0cc1a155980e01a6b3ce3ea22c1787`, Part constructor `ev_79437732e3dca6dd7bbc7156956fd5d4e067f8cd146357d6131acf6d1a9096fd`, control `ev_386e07dcd92138affad11d8674d65f32869013ffffbcbf173746076d45c6542c`.

`Particle::initialize` `0x140066450` reads instance spread `+0xd4` at `0x14006658e`. Only a nonzero value calls `Particle::randomDirection` `0x140068800` at `0x1400665a8`. This same initializer is reached from a fresh or recycled base/Chunky Particle in Fountain or Explosion, from fresh Single construction, and from Lightning's fresh base Particle; those scheduling gates are in their subtype maps. The helper's two formal integer arguments are passed from the initializer's position-spread calculation, but its analyzed body does not use either; it reads emitter/camera state instead. Evidence initializer `ev_6e072379e7c8ab3444fd75c3c2427a822035b68918abb247d9747090214e118c`, direction helper `ev_980b001ad99e3d5d1897af93ea7f8bb67bd04ed6339b1c5a7ed01de8e8a2352c`.

## Camera-dependent orientation and correction

`randomDirection` reads `CurrentCamera` from `0x1412e0318` and subtracts camera position `+0xb0..+0xb8` from Particle position `+0x10..+0x18` at `0x140068866..0x140068882`; it normalizes that vector at `0x14006889c`. It samples CRT random at `0x1400688a1`, uses instance spread `+0xd4` to form a first angle, loads emitter basis `+0x140..+0x148`, normalizes it at `0x1400688f4`, then constructs a quaternion through the scalar angle and vector/quaternion helpers at `0x1400688fc..0x14006894e`. It writes the resulting Particle quaternion `+0x34..+0x40` at `0x140068956`. A second CRT sample at `0x14006895a` is reduced modulo `0x274`; emitter basis `+0x158..+0x160` supplies a second axis and the second quaternion multiply writes the same Particle fields at `0x140068a1d`. The two random calls go to the CRT thread-state generator `0x140c7ed00` mapped in [Lightning scheduling](original-particle-lightning-scheduling-leaves.md). These are CPU vector/quaternion writes, not particle vertex submission. Evidence direction helper above.

Source `deadspace+0xa0` is read at `0x140068a25`; exact zero skips the correction loop at `0x140068a34`. Otherwise the function compares a camera-relative direction measure derived from the candidate quaternion with scalar angle helper `0x140c79d30` at `0x140068b06/0x140068b0b`. If the predicate fails, it derives a correction axis with `cross` `0x140068bc3`, normalizes it at `0x140068be3`, constructs a corrected quaternion through `0x140068bec..0x140068c3f`, and rechecks with the same scalar helper at `0x140068d06`. Branch `0x140068d0f` repeats from `0x140068b20` while the predicate still fails, then `0x140068d30` stores the accepted quaternion to Particle `+0x34..+0x40`. This loop has no additional RNG call and no explicit iteration counter in the analyzed body; termination depends on the angle predicate and runtime floats. The scalar helper computes cosine-like angle arithmetic, but its original source symbol is not recovered. Evidence direction helper above; scalar helper `ev_a69794e09aaf5335dc070a9abd97e8735650fa02cf976238f29d7f6cc8cce0a4`.

After `randomDirection` returns, `Particle::initialize` derives a direction vector from quaternion `+0x34..+0x40` and stores it at `Particle+0x4c..+0x54` at `0x140066642/0x140066647`; it multiplies by authored velocity and stores `+0x58..+0x60` at `0x14006666a/0x140066679`. The selected movement callback may later consume that CPU state, and an admitted Scene render callback may read it into shared `RenderEmitter` vertex construction before conditional `RenderInterface::RenderVertexStreamData` `0x140064109` and GL draw. The movement and render chains are already mapped in [movement callbacks](original-particle-movement-callbacks.md) and [particle rendering](original-particle-effect-render.md). This branch itself has no GL call. Its open boundaries are actual spread/deadspace values, camera pose, finite/valid angle inputs, correction-loop iteration count, live particle admission, render mode/material gates and actual draw execution.
