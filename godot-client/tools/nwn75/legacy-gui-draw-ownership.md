# NWN-75 original legacy GUI draw ownership

Scope: installed `nwmain.exe`, SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are original image VAs. This follows the legacy `CGuiPanel`/`CGuiObject` model route, separate from Nuklear numeric commands. Static registration and dispatch do not establish which panel or widget is visible in a particular frame.

## Screen entry and panel construction

`UpdateScreen` `0x1400451c0` calls `CGuiMan::UpdateAndRender` `0x1401f70e0` when its GUI argument is enabled. In its presentation branch it can clear, call the GUI manager, begin a scene for posted strings, call `AurRenderStrings` `0x14006a040`, end the scene, and swap. Other `UpdateScreen` arguments gate client/server/network/audio work and whether that final presentation branch runs. REA `ev_c6dab2e3d95fa827df1d17ab1acf4b8224cdb3b130d46260a0bf8be8ba728609`.

`CGuiPanel::Activate` `0x1401fbe70` loads its layout models/tags if the panel's layout flag is set and its root model is absent. `LoadLayoutFileModelsAndTags` `0x1401feba0` calls `RecursiveLoadLayoutFileModelAndTag` `0x1401ff120`, which reads each GFF `Obj_Tag`, `Obj_ResRef`, `Obj_Parent_Hook`, `Obj_X/Y/Z` and `Obj_ChildList` recursively. `CGuiObject::LoadModelFromGff` `0x1401feea0` constructs a `NewCAurObject` for a nonempty resref and attaches each child to its parent through `GuiAurAttachToObject` `0x140203500`; the panel takes the root tag's model as its own `+0x10`. This is layout/model construction, not a per-frame immediate widget draw loop. REA `ev_52ba1f7c007232b0c1e8620369f2a4339d8189a989eab7aa770a414367b2c78c`, `ev_9b96ea529a94023fb720b80d19906d784cfb841bc2b52659d8715df1c03525a8`, `ev_cfadd799ba8b5317029cf2576850e22dd5763472829c3515e56b8a2df215bb29`, `ev_112d8b384c00bc3a2ca5131b90e2027916cd5a24574b0fa14df47da925f382b7`.

On activation, a missing panel `CSceneView` at `+0xb8` is created with a `sceneGUI...` `NewCAurScene` and `NewCAurCamera`. The panel invokes its root model's virtual `+0x90` with that scene. `NewCAurObject` constructs a `Gob`; its pinned vtable `0x140d88a00` resolves `+0x90` to `Gob::AttachToScene` `0x1400c5780` (`ev_a9ddbff2d0c4ec6244fdaa5e8d7d2424dfd7c2a4a7da2b2b512d36c395c3a6f5`). That calls `Gob::SetScene` `0x140095250`, which invokes `Scene::ChildAdd` via Scene slot `+0x200`; `ChildAdd` appends the Gob to Scene `+0x130`/count `+0x138`. The panel then enables and appends the view to `CGuiMan` view vector `+0x18`/count `+0x20`, and calls `CGuiMan::AddPanel`. A child widget's `CGuiObject::AddToPanel` `0x1401fafa0` uses its model virtual `+0x98` to attach to the panel model; the same Gob table resolves this to `Gob::AttachToObject` `0x14008c540`, which propagates the parent's Scene through `Gob::SetScene` on a successful hook attachment. REA `ev_59a27eca9979c6ac9a91a8016fd807444610412e3af0c3f721d631d0baa4a8cb`, `ev_643830a77c06dfc50804134d4969249c53b6633d7f12508994ddf59720aae7aa`, `ev_6b28523eef3201dc9117e17337c6a83ac7dea5eed4ce7f940c48e8c8b8ef8851`, `ev_84b7668aa840e3d85c79f54683e4b447eb5d170f5a6bc21be09ca050f7ddfcf3`, `ev_3fefc1242dc4f5d734c1cecda8553f39b7453fb5c6729751b5fd8a62608d5a9c`, `ev_309e3ad46f012c8e02c143d8afbf93c0fa8f7891969bce193879e456ed72b5a7`.

## Per-frame scene and widget dispatch

`CGuiMan::UpdateAndRender` first walks registered GUI objects through virtual `+0x58`; this is an update list with generation and unregister-sentinel gates, not a draw of every widget. It then conditionally animates each registered scene view and calls each view camera's virtual `+0x10` during its render phase. The panel activation above supplies one ordinary registered view. `NewCAurCamera`'s pinned `Camera` vtable `0x140d82e08` resolves `+0x10` to `Camera::RenderScene` `0x14005a5d0` (`ev_8bf4c4a7b7e2e548382ae2a128096910a143012caa964a5e52184f593d3aa945`). The two manager-owned Overlay/MouseOverlay cameras are called separately. REA manager `ev_e89c777fe9978d01554dbfdb34e21733672c56e4a3eb34090604337158400564`.

`Camera::RenderScene` requires a scene at camera `+0x90`, begins a render scene, rejects an offscreen viewport under its viewport gate, sets projection/viewport/depth state (including special `sceneGUI...` names), and calls scene virtual `+0x18`. `NewCAurScene` constructs a concrete `Scene` whose vtable `0x140d8dd30` resolves `+0x18` to `Scene::Render` `0x1400cc730` (`ev_cb7cf4fd2ea02bc0a972057750745b05fd56f2c424ab6688817f97e067b83bbd`). The constructor initializes Scene BSP pointer `+0x188` to null. If it remains null, `Scene::Render` selects virtual `+0x270` → `Scene::RenderOnlyGobs` `0x1400cf9b0` (slot bytes `ev_565efb2ab78e69973698807c775eeb3ba95ab49951e8b6f141b49d3c9fc75cbd`). That function sets GUI state and loops Scene `+0x130`/count `+0x138`, invoking each Gob's virtual `+0x20`; `sceneGUI_guiModelView` and `sceneGUI_Viewport_Compass` have a distinct nearest-lighting branch. If a BSP is later installed, `Scene::Render` instead adds parts to draw buckets and selects virtual `+0x210` → `Scene::RenderSinglePass` `0x1400d0f10` (slot bytes `ev_8b89ae175b94e648ee3c9aca0565088c01b8adfbca18257a6945c027454d16d0`), whose downstream buckets are in `render-single-pass.md`. The static panel-activation path does not install a BSP, but later mutation and per-frame scene population remain unproven. REA `ev_4393914dd018195bd1a10f8edf54a40ad4cff9b0c8d0e56fa03049d3137f7161`, `ev_17ec38a8462fe63e54833099ba8a0936b20e0b67c55d26a0bda6bf049d07a6a8`, `ev_3413e3eeb663fb062b14838d6e5e77d65faf53e71ce65f746a81b0e056ba4d44`, `ev_f3e7cf7fddcff3c8512ddc4780431d9a2ba68276d39707b244896ef25392c3f5`.

## Text and model/image leaves

**Model/image route.** `Gob` vtable `0x140d88a00` slot `+0x20` resolves to `Gob::Render` `0x1400a4280` (`ev_cce3c9b15cf17160abdcc1cd1e1ad0f57f8515967072c7f9491cc703fff3706c`). It requires a model Part, processed/visible Gob and positive fade, applies transforms/fog, and calls `Gob::PartDraw` `0x1400a3440`. `PartDraw` recurses visible Part children in stored order and calls each Part's virtual `+0xc8`. The `PartTriMesh` target `0x1400a24c0` can choose bumpy/environment/plain `RenderFlat` `0x1400a4710`, then `RenderInterface::RenderVertexData` `0x1400beec0`; indexed modes call extension `glDrawElementsBaseVertex`, while nonindexed mode calls imported `glDrawArrays`. Material texture binding can reach `glActiveTexture` and imported `glBindTexture`, and conditional texture creation reaches `glTexImage2D`/other upload APIs. These are the concrete model/image GL leaves for a renderable mesh Part, not proof that every layout resref has one. Other Part subclass slot targets and upload conditions are recorded in `geometry-and-draw-boundary.md`. REA `ev_741ec2c22c70e83928460f5256726e1bd890e80768e5a0a745f7ef9a6eb3f878`, `ev_26045c9fbebfea54e07821eae704552d1f4177b2b4f704faa25e0f6081d38729`.

**Text route.** `CGuiLabel::CGuiLabel` `0x1401e80b0` constructs `NewCAurString` `0x1400492f0`, which creates a `StringGob` with Gob-side vtable `0x140d81440`. The label's `AddToPanel` overloads `0x1401e8f60`/`0x1401e8e00` attach that string to the panel model: the StringGob interface vtable `0x140d81750` has `+0x8` → `StringGob::AttachToObject` adjustor `0x140047ce8` → body `0x140047ce0` and `+0x18` → `StringGob::AttachCornersToObjects` `0x140047b10`; the latter eventually calls `Gob::AttachToObject`. Successful attachment sets the StringGob's Scene to the panel model's Scene. Gob-side slot `+0x20` resolves to `StringGob::Render` `0x1400498a0`, which selects font texture/state, visits text lines and invokes `CAurFont::TextOut` `0x14004c870` for visible runs and optional caret text. `TextOut` obtains/commits vertex stream data and calls `RenderInterface::RenderVertexStreamData` `0x1400beed0`; that reaches imported `glDrawArrays` or `glDrawElements` according to stream index data. Conditional font texture creation/upload is described in `gui-presentation.md`. REA `ev_c678d4a6b86551c949966d8764115b85ffde9764f97dfa7e9f039345fdd93b86`, `ev_a64a3a77ab97821666c210eb2ebf8e1be942f482ab9fa936354981e9d289c863`, `ev_affb487bb8605f258fc11ae786dec9d0012cf0154c71af967515b6652d29724b`, `ev_bf4181e212ed94dd421ea808cd023c70cd36a5eac7b49efd69a5b4cac061a24e`, `ev_b57f63c614ffa54c7d83f09cc9504718f1d24a07a5417a4ed68ba1cd462f786c`, `ev_dc9db612f353b3e299b6890be9d883a25ebdc46987d53b1623b1296782b2eb06`, `ev_d48d788ea591d6f4c257237674ad87a57f1a635a3748ccc946cb8771653b9b15`, `ev_4002cd98130ddf0c2c5ba4642e30ad1a396d8a557df33c3d1074c2ad66cf4fb0`.

`UpdateScreen`'s posted-string overlay is a separate legacy text entry: `AurRenderStrings` → `AurPrintString` → `CAurFont::TextOut` or a `StringGob` route, then scene end and swap. This uses the same font stream/API boundary but is not a child of a panel GFF layout (`gui-presentation.md`).

## Remaining dynamic edges

The static tree does not identify which panels are active, every `Obj_ResRef` model/Part subtype, or which child widgets attach successfully to valid hookpoints in a given frame. Panel activation also invokes subclass virtual slots `+0x120`, `+0x60`, and `+0x100`; their per-class targets and any subsequent model mutations are not closed here. The alternate installed-BSP GUI scene branch crosses the shared Scene bucket tree and is not assigned a runtime frequency. No OS thread ownership or actual draw count follows from these static call edges.
