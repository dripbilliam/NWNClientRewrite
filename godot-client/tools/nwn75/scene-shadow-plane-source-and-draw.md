# NWN-75: shadow-plane light source and draw closure

Scope: installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This follows `Scene::RenderShadowPlanes` `0x1400d0350` beyond its [27 immediate direct-call sites](scene-optional-pass-callsite-census.md). State API and shader/stream implementations already mapped elsewhere are referenced rather than recounted.

## Admitted light and authored state

`Scene::RenderSinglePass` enters `Scene::RenderShadows` `0x1400d0ab0` only under `enableshadows`. Earlier `LightManager::GetShadowLights` `0x14007f840` selects and fades shadow lights: its mode-specific lists are held by the Scene at `+0x60/+0x68` and `+0x70/+0x78`, with the fade factor at each selected `PartLight+0xac`. [Lighting state](lighting-state-branch.md) records the selection gates and array publication. `RenderShadows` places the chosen PartLight pointer at Scene `+0x50` before the plane call. Its dynamic path walks `Scene+0x70/+0x78` in reverse and calls `RenderShadowPlanes` at `0x1400d0cb0` only while selected light radius `PartLight+0x74` is at most `1000`; a larger radius breaks that loop. Its static path uses the first pointer at `Scene+0x60` only when count `Scene+0x68` is positive, then calls at `0x1400d0d5d`. Both observed calls pass `8` as the stencil index; no other incoming code call was found. Evidence: `ev_13a6ac6ce4e119243b21b447647196262a1f0757f8c5b1db73898429db7c85b6`, `ev_4749a75cb0af55de42f3f1ef1de35bdba859902222863fa4534012e85c0d712d`.

The `PartLight` is created from a model light node. Its parsed `radius`, `shadowradius`, and `verticaldisplacement` controller families write instance offsets `+0x74`, `+0x7c`, and `+0x80`; pose updates supply world position `+0xb0..+0xb8`. The shadow-light selector supplies fade `+0xac`. These are the fields read by `RenderShadowPlanes` along with `shadowalpha`, Camera position/orientation and Scene `+0x198` height. See [model light source selection](model-light-source-selection.md) and [lighting state](lighting-state-branch.md). The exact authored values and runtime light population remain unobserved.

## Geometry and submission

`RenderShadowPlanes` chooses its radial input from positive `PartLight+0x7c`, otherwise `+0x74`. If light `+0x74` is at most `1000`, it computes a local plane radius from `sqrt(abs(selected_radius² - vertical_delta²))` and only proceeds when that result is positive. If `+0x74` exceeds `1000`, it uses Camera position/orientation and the selected radius for a directional plane; among the two observed callers this branch is reachable through the static path, since the dynamic caller breaks on greater-than-1000 radius. This describes code reachability, not evidence that such a light is present. Evidence: `ev_c71101097019c976c5da31c29a662dbbadcd8707d56a447c657129750b72d1f4`, `ev_13a6ac6ce4e119243b21b447647196262a1f0757f8c5b1db73898429db7c85b6`.

After the positive-radius gate, the pass sets stencil, blend and render-enable states through already mapped wrappers. It lazily looks up `vs_shadowplane`/`fs_shadowplane` through `RenderInterface::GetCustomShaderProgram` `0x1400bebf0` at `0x1400d0630`, stores the successful program in process global `0x14140af70`, and does no stream work when lookup returns null. A successful program is staged with `SetCustomShaderProgram` `0x1400bf0b0` at `0x1400d066d`. Shader first-use compilation/link and later uniform publication are mapped in [shader program branch](shader-program-branch.md). The two stream globals are similarly lazy and distinct: directional path `0x14140af78` requests `(4,0,5)` at `0x1400d068f`; local path `0x14140af80` requests `(11,0,5)` at `0x1400d0917`. `GetVertexStreamDataObjectTokenByAttributes` `0x1400bdaf0` reuses an exact-capacity/attribute match and only allocates on a miss. The middle argument zero specifies no element capacity. Evidence: Scene body above; stream manager `ev_3bdf3c95c2e4ea7932e5980e53d1350bc3d3d4fba5cc622e33a427b37e1dfe73`.

The directional branch takes Camera orientation, normalizes a vector, builds four packed color/position vertices with alpha `shadowalpha × PartLight+0xac`, commits count `4` at `0x1400d08e9`, and selects primitive `4`. The local branch builds one center plus ten perimeter vertices, sampling its trigonometric helpers at `0x1400d098f/0x1400d09a6` and scaling alpha by a radius factor; it commits count `11` at `0x1400d09db` and selects primitive `5`. Both paths call `RenderInterface::RenderVertexStreamData` `0x1400beed0` once at `0x1400d09f3`, then re-enable state `0xb`. The stream wrapper reaches `GLRender::RenderVertexStreamData` `0x1400b5c20` and imported `glDrawArrays` `0x1400b5d66` for these nonindexed streams. Buffer publication is through `CommitVertexData` → `UnlockPool`; GL driver behavior lies outside the binary. Evidence: Scene body above; GL draw `ev_faed7a96ea930f48e2170d7800f7dc1d4110c2b5267b35fe6813a21dee29899a`.

The direct math descendants in this branch are CPU leaves or CRT math: `normalize` `0x140230920` copies near-unit vectors, substitutes `(1,0,0)` for zero vectors, or uses square-root; the two trigonometric runtime bodies `0x140c7ac70/0x140c7a2b0` evaluate angle reduction and polynomial results, with exceptional/large-input helper calls. Their analyzed bodies make no GL call. The stencil/state wrappers and GL imports are in [shadow state APIs](scene-shadow-stencil-apis.md); no duplicate implementation tree is recorded here. Evidence: `ev_7dd6b588c6e49eb4d0c5676491c6f5cdc4bb0020de3094e38777a8a7490ad4b3`, `ev_d2e6afff7f7e5b9ae33d714142e6083c5816489fca96466f85fce22fe3355bb5`, `ev_5311826694994f0aec363efb39756244e5a3c3eadfaf56e848fee763a6c944b9`.

Scene `+0x198` is the Z component of its focus vector, and `+0x140` is the fog enable flag; their default, console and setter routes are in [focus to shadow plane](scene-focus-shadow-plane-source.md) and [fog state](scene-fog-state-source.md). Runtime focus values, indirect focus-setter callers and live light/branch frequency remain open. The static mapping establishes a maximum of one stream draw per admitted `RenderShadowPlanes` call; it does not establish frame cost.
