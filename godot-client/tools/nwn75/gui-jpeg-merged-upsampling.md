# Original JPEG merged upsampling and RGB output

Pinned `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This traces the bundled JPEG library's merged upsampling branch left open by [the baseline decoder supplement](gui-jpeg-baseline-decoder.md). The crucial caller gate is explicit: the normal file-backed `ImageReadJPG` route does **not** select this branch. [The ledger](gui-jpeg-merged-upsampling-ledger.json) records the conditional library edges and exact sites.

## Selection and caller reachability

Master decompression setup `0x14021eaf0` calls predicate `0x14021ef70` at `0x14021ec31` and, only if it returns true, calls `jinit_merged_upsampler` `0x14021f3e0` at `0x14021ecf3`. The predicate requires fancy upsampling off (`+0x60=0`), CCIR601 sampling off (`+0x16a=0`), YCbCr input (`+0x3c=3`), three source components (`+0x38=3`), RGB output (`+0x40=2`) with three output components (`+0x7c=3`), Y horizontal sampling 2 and vertical sampling 1 or 2, Cb/Cr horizontal and vertical sampling 1, and all three scaled DCT sizes equal to the output minimum. These values are read from the decompressor and its component table; unsupported layouts return false. Evidence predicate `ev_f47a8c76ce4dade1f0dbbaf4fe04bba8aa83bda03ce4281553787a2bbb99e771`, master `ev_027ff4cd124c82f9d91a5c49f963932a3b0c9450573f8d3beed86effd7cdf7d8`.

`ImageReadJPG` calls `jpeg_read_header` then `jpeg_start_decompress` without changing decoder output flags. Successful header read calls default initializer `0x140217cb0` at `0x1402182bd`, which writes `0x101` at `+0x60` (`0x140217e32`), setting fancy upsampling on. The merged predicate's first test therefore fails for this caller's normal path, so it chooses separate color conversion and generic upsampling. The merged library branch below describes what the pinned binary would do for a caller that clears fancy upsampling before master setup. No such setter is observed in `ImageReadJPG`; this supplement does not assert a reachable GUI asset/frame for the merged route. Evidence header `ev_c412a815200b48a5104d0b06f64aaafdce42978f6654a52ae581055665c13f93`, defaults `ev_ac63e240a12d8aa1f1f31346de9432d854bbe22caa80fc6aa9a612d8900b6684`, caller `ev_0247d39d9d07cd96331ad8062ed202eeda22bd217ca0feee96500e38c246a550`.

## Conditional library output

`jinit_merged_upsampler` allocates its controller and four 256-entry YCbCr conversion tables. It installs output callback `0x14021f560` and combined color routine `0x14021eff0` when the maximum vertical sampling factor is one. If that factor is two, it installs output callback `0x14021f5a0` and combined routine `0x14021f180`, plus a spare row buffer. These two CPU routines directly read Y, Cb and Cr samples, reuse each chroma value for two adjacent horizontal Y samples, apply conversion-table offsets and clamp through the sample-range table, and write RGB bytes to supplied output rows. The factor-two routine writes two Y rows per chroma row. Both inner routines have no decoder-descendant calls. Evidence initializer `ev_55f000db360ba196a1baa82dcbf0156982fc0a7d585b20aa4504715c9af4184a`, 1-row output `ev_b31cdf3a5cc0c0885300866444db6bb0cd36267642cce4922f8417ef077e3c46`, 2-row output `ev_e4ea32f4b05bcd74b259fde37752493803cd8913e4bf5f7e52df0be3825c34ff`, 1-row conversion `ev_99a6d550801463d3be4c2c518e09977240d2d35d224e5b449608ade56b8c65b4`, 2-row conversion `ev_af9a5507bd1308b50182413dd6dde133390e8b575ee03d45547d71650f60ac9f`.

At normal nonquantized output-pass start, post-controller `0x140220870` copies merged upsampler `+0x8` to post-controller `+0x8`. The merged controller has no context-row flag, so main-controller start `0x14021c590` selects `0x14021c4e0`. Its post call at `0x14021c554` reaches either `0x14021f560` or `0x14021f5a0`; the latter may cache one generated row if the caller provides space for only one and later copy it with `jcopy_sample_rows` at `0x14021f5f4`. The one-row and two-row output callbacks invoke their corresponding combined CPU routines at `0x14021f588` and `0x14021f658`. Coefficient and IDCT production before the post call is the separately mapped baseline or progressive branch. Evidence post start `ev_a3b52372724f7586ee57d7fc80eb1655cb5aa93f2c9d17de9e6533bdde5f7822`, main `ev_74fdb7d7b1975bed9a348e255709350eb593a9f8e7585f32def0329e8cb45301`.

The actual `ImageReadJPG` path still allocates its pixel block at `0x14022904f`, calls `jpeg_read_scanlines` with its row pointers at `0x140229080`, and returns the raster to `ImageRead` for the vertical flip at `0x140072fd0`. Those rows are produced by the separate generic route because fancy=true blocks merged selection. A different JPEG-library caller that satisfies the merged gates would have to supply its own output row pointers; that caller and its publication path are not established here. No GL call occurs inside these combined conversion loops.

## Remaining gates

The normal `ImageReadJPG` path statically excludes merged upsampling through fancy=true. Other callers of the bundled JPEG library, if any, must be checked independently for flag changes and runtime use. Quantized/raw output, arithmetic/lossless JPEG, alternate color spaces or sampling layouts, source suspension, and malformed-input errors are separate branches.
