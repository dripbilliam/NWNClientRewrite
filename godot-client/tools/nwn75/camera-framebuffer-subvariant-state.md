# NWN-75: framebuffer effect subvariant state

Pinned original `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This is a connected state continuation of [Scene::RenderSinglePass](render-single-pass.md) and [camera framebuffer effects](framebuffer-effects.md). The seven new direct callsites and the setter thunk are in `camera-framebuffer-subvariant-state-ledger.json`. It is static control flow, not a frame-cost measurement.

`Scene::RenderSinglePass` calls `Camera::DoFrameBufferEffects` `0x140057b20` for pre-water phase 0 at `0x1400d21ef` only under `mainscene && enableFBeffects`; it calls post-water phase 1 at `0x1400d2809` under `mainscene`, and the camera function itself returns without effect work when `enableFBeffects==0`. In phase 0 it enters the SSAO branch only when `m_nFramebufferEffectsEnabled & 1` is set. That branch lazily requests `vsFBSSAO`/`fsFBSSAO` and uses the subframe/texture operations described in the linked camera map; its three `RenderInterface::SetShaderParami(0,value)` sites set value 0 at `0x14005814e` before the first SSAO quad, 1 at `0x14005831b` before the next quad, and 2 at `0x140058519` before the final blend quad. In nonzero phase, the camera enters bloom only when `(m_nFramebufferEffectsEnabled >> 1) & 1` is set. It lazily requests `vsFBBLOOM`/`fsFBBLOOM`, then sets subvariant 0 at `0x14005866a` before its first quad. An admitted downscale loop sets 1 at `0x1400586f5` and 2 at `0x140058806` on its corresponding passes. The final blend sets 3 at `0x1400588b4` before drawing into subframe 0. The loop's execution count depends on `bloom_downscale_steps`; the static callsites do not give a runtime draw count. The decompiled body has no explicit nonnull shader-result check around these parameter setters, so the documented branch gates do not imply that a requested custom program was available. The GLRender body **unconditionally** increments shader-constant generation `0x1413d273c` and stores the supplied integer in `m_shaderConstantsi[index]`; index zero addresses `0x1413d26ec`. It has no immediate GL call and no equality check. Each admitted effect `RenderVertexData` joins the [VDO draw and program selection path](part-trimesh-draw.md). `GLRender::SetProgram` calls `SetUniforms` even when the selected program was already bound. `SetUniforms` revisits the shader-constant group when that program's cached `+0x4c` generation differs; within it, the `subvariant` uniform at program `+0x94` is sent through loader-resolved `glUniform1i` at `0x1400ba396` only if the location is valid and its cached integer at `+0x98` differs from `m_shaderConstantsi[0]`. Thus repeated setter calls can cause group checks, but the cached-value gate can suppress an API upload. The pointer `0x1414425f8=glUniform1i` is identified in [the GL pointer catalog](gl-extension-pointers.json), and the name `subvariant`/offset in [the uniform location map](shader-uniform-location-map.json).
