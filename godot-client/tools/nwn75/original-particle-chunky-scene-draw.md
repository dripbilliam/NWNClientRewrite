# Original Chunky particle attached-Gob draw route

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This follows the model Gob created for a Chunky particle from its source name through Scene membership and one concrete conditional model-draw route. It distinguishes emitter quad suppression from the attached Gob's ordinary geometry pass. Authored model contents and frame populations remain runtime boundaries.

## Source, object ownership and Scene attachment

A nonempty `MdlNodeEmitter+0x158` source `chunkName` selects `ChunkyParticle::ChunkyParticle` `0x1400602b0` in Fountain, Explosion, or Single creation branches; the subtype-specific gates are in [Fountain scheduling](original-particle-spawntype-time.md), [Explosion detonation](original-particle-explosion-detonation.md) and [Single lifetime](original-particle-single-lifecycle.md). `PartEmitter::Initialize` `0x140061d80` also tests this source byte and overwrites the emitter render pointer `+0x1b0` with `RenderNothing` `0x140064190` at `0x140061ef8`, regardless of Standard/Linked/MotionBlurred selection. It leaves the selected mode integer intact. Evidence initializer `ev_8196177995dbdc99839bcacb411d86473a8f877c6bf8291aea000762832be32d`.

Chunky construction calls base `Particle::initialize` at `0x140060316`, then passes the authored name at source `+0x158` to `NewCAurObject` `0x1400931f0` at `0x140060340`, with empty Gob name and no supplied stream. `NewCAurObject` resolves a named model through `FindModel` (one fallback or optional LOD names), constructs a Gob at `0x140093606`, and calls `CreateInstanceTreeR` at `0x140093645` for the base root and conditionally `0x140093677/0x1400936a9` for LOD roots. Which MdlNode/Part subtypes are present is model-content dependent. The constructor stores the resulting Gob pointer at `Particle+0x78` at `0x140060345`; if nonnull, it calls the Gob's virtual `+0x90=AttachToScene` at `0x140060362`, passing `currentscene`. `NewCAurObject` failure leaves no attached Gob. Evidence constructor `ev_a835c7c30c035c6d53c1f634d31e77e7825f252efc92bccc6a08a310d2e47917`, factory `ev_8e0b947d4d92de1b3222644deb68df1e15d569e05500363ea10323cd930e956b`.

`Gob::AttachToScene` `0x1400c5780` calls `Gob::SetScene` `0x140095250` at `0x1400c5784`. On a changed Scene pointer, `SetScene` removes old membership as needed, stores Scene at Gob `+0x88`, and invokes Scene virtual `+0x200=ChildAdd` `0x1400c5990` at `0x1400952c7` when the new Scene is nonnull. `Scene::ChildAdd` calls `SceneBSPAddGob` `0x1400dcf70` at `0x1400c59a7` only when the Gob has a model pointer `+0x68`, then appends the Gob to Scene `+0x130/+0x138`. With a Scene BSP, `SceneBSPAddGob` finds a fitting node by Gob position/bounding sphere and inserts the Gob if absent. This is Scene/BSP CPU membership, not particle quad rendering. Evidence attach `ev_688c1b08db11704be9a50f75c1e06431346e1558a5df8e79da8fb89505ab7c86`, SetScene `ev_643830a77c06dfc50804134d4969249c53b6633d7f12508994ddf59720aae7aa`, ChildAdd `ev_6773479203e34c4c3e037639badbf668573bac68a7c6117952d2d6e65a2a9bc2`, BSP add `ev_960a49865bd02c2670df0fdfbac5005255d2e8315f488fd885cc6897ee1c4a23`.

Fountain/Explosion reuse of a Chunky particle calls its virtual `+0x10=ChunkyParticle::initialize` `0x1400663d0`: base initialize at `0x1400663e9`, Gob reattach `+0x90` at `0x140066401`, Gob scale `+0x1b0` at `0x140066414`, and `impact` animation `+0x30` at `0x14006643f`. Expiry in `PartEmitter::chkParticleLife` removes it from live list, retains the particle in the reuse list, and detaches its Gob through virtual `+0x90` with null at `0x14006605a`. Single's zero-rate branch instead invokes the Chunky virtual destructor; `ChunkyParticle` destructor `0x140060cf0` invokes the attached Gob destructor at `0x140060d1a`, which reaches Scene removal and eventually frees the particle. These are distinct ownership paths; a recycled particle can retain its model Gob while detached. ## `RenderNothing` updates the attached Gob, not an emitter quad

In a Scene with a BSP, `Scene::Render` `0x1400cc730` calls `ManageSceneBSP` at `0x1400ccb38`, builds ordinary draw buckets at `0x1400ccdbe`, then calls Scene virtual `+0x210=RenderSinglePass` `0x1400d0f10` at `0x1400ccdc9`. `RenderSinglePass` calls Scene virtual `+0x1e0=DoEmitterBucket` `0x1400c7ae0` at `0x1400d27e6`, after its ordinary `RenderDrawBucket` calls, including bucket `4` at `0x1400d2754`. `DoEmitterBucket` invokes an eligible emitter's installed render callback `+0x1b0` at `0x1400c7dae` only with a positive effective live count. These original vtable slot targets are verified by the pinned Scene table `0x140d8dd30`. Evidence Scene `ev_8efee45b68ff722593854e051a36ecf8133863483336ba1b1e91e177c170aedb`, SinglePass `ev_02ace6727b08cd03cb9bd9a012c7c646766c92f3bd0cd79bb2b383726b80c4a0`, emitter bucket `ev_b4881207528882fb849869474dcd3a31c18cf9f00dad89280e126d85fcdd7ed3`.

`RenderNothing` `0x140064190` first requires owner/tile fade values to be at least `1` when present. Its debug-sphere option is separately gated. It loops live particles and, for each nonnull Gob at `Particle+0x78`, invokes Gob virtual `+0xb0=SetPosition` `0x140095210` at `0x140064297` with the particle position `+0x10..+0x18`. When emitter rotation `+0xbc` is nonzero and particle stop byte `+0x70` is zero, it computes an orientation from particle direction/angle and invokes Gob virtual `+0xb8=SetOrientation` `0x140094f80` at `0x140064346`. The two setters only copy values to Gob position `+0xa8..+0xb0` and quaternion `+0xb4..+0xc0`; neither calls Scene or GL. `RenderNothing` does **not** call `PartEmitter::RenderEmitter`, commit an emitter vertex stream or submit the particle quad. Optional `RenderBoundingSphere` is diagnostic GL work, separate from attached-model rendering. Evidence `RenderNothing` `ev_a979c6b8cb98277a05bdc0540623d05e97d8b4723e7f04ef580861ffec728692`, SetPosition `ev_dbbe391fc7d5fed18b0aabad8cae0c0b2ba5f4f71292fa52c78faf90e9fbb19c`, SetOrientation `ev_1829d7fab1e07d3bc4d36954999841675f4e0bde4138c21d827f9591167e5665`.

The pass order matters: `ManageSceneBSP`, bucket construction and every ordinary `RenderDrawBucket` call precede the `RenderNothing` pose writes in the same BSP `RenderSinglePass`. Those setters cannot change model draw calls already submitted in that pass. This is an order statement from static sites, not a measured one-frame visual delay; earlier Gob animation/pose writers and later render reentry remain content/runtime gates. The no-BSP `Scene::Render` branch instead invokes `RenderOnlyGobs` and does not call this emitter bucket in the observed branch.

## Separate ordinary model draw to conditional GL

For an attached Gob admitted into a BSP Scene, `ManageSceneBSP` `0x1400db320` traverses visible BSP nodes with callback `0x1400dc140` at `0x1400dba72`, then walks Scene Gobs and calls virtual `+0x2b8=IsInViewVolume` at `0x1400dbb0e`; admitted Gobs are appended to `_gobbucket`. `Scene::AddPartsToDrawBuckets` `0x1400c38f0` processes that bucket, calls `Gob::ProcessGob` at `0x1400c426e`, requires Gob visible flag `+0x1a4` and positive alpha `+0x108`, and passes root Part `Gob+0x90` to `AddPartsTreeToDrawBuckets` `0x1400c4620` at `0x1400c44ff`. That function recursively walks visible Parts, uses Part virtual `+0x58=AsPartTriMesh` at `0x1400c46a0` and adds accepted renderable triangle Parts to `DrawBucketManager` at `0x1400c47a6/0x1400c4801/0x1400c4879` according to material/type gates. The exact subtype mix and bucket types depend on the authored model. Evidence BSP `ev_3e8c979129e4069878975c423d7b4b3a20b360b7445a01bb16bd51221532027d`, bucket construction `ev_5e4853cf3f2ac16eddc2f1629d9693800f30c4b546f4b44f70b00fc074bdfbb0`, Part traversal `ev_7245333797a415fdd94c9cdf1b7512702927288fe071bae83702abdb27046e35`.

`Scene::RenderDrawBucket` `0x1400cd210` later reads a bucket item and invokes its Part virtual `+0xc8=Draw` at `0x1400cd8d1`. One constructor-backed candidate is `PartTriMesh::Draw` `0x1400a24c0`, which admits active/renderable/material/primitive data and chooses plain `RenderFlat` at `0x1400a261d` or bumpy/environment variants that converge on `RenderFlat` `0x1400a4710`. With a nonnull VDO at primitive `+0x58`, `RenderFlat` calls `RenderInterface::RenderVertexData` at `0x1400a4815`; thunk `0x1400beec0` reaches `GLRender::RenderVertexData` `0x1400b59b0`, whose indexed modes conditionally use `glDrawElementsBaseVertex` at `0x1400b5b35/0x1400b5b8e`, and whose nonindexed mode calls imported `glDrawArrays` at `0x1400b5bcb`. This is a **separate conditional GL route for attached model geometry**, through Scene Gob/Part buckets, not the emitter quad stream. Its full material/VDO gates are in [ordinary TriMesh draw](part-trimesh-draw.md). Evidence bucket `ev_a79e3b9d48678d00e937d48b7cfd390f667167b1d9917eb2e79df5ae2eeeb450`, TriMesh draw `ev_c71ed738e7b17f5a797049dd882453cd562f5d3a00b1397cff45724ce6f182f0`, flat `ev_d63ab790020cdd230625119645a3be9865a03bd0dd3ce29c3b8df6f9a9acd441`, GL `ev_8e9e440e5c5b0a364b9a6d1d9a76e16c1b4aa69d7c12cefc9a356392c92a273f`.

With no BSP, `Scene::RenderOnlyGobs` `0x1400cf9b0` walks Scene `+0x130/+0x138` and invokes Gob virtual `+0x20=Render` at `0x1400cfb50/0x1400cfbdf`; that enters the ordinary recursive Part Draw path, not the emitter quad stream. Which model Parts and callbacks render on either path is an explicit authored/runtime frontier. Model lookup failure, Scene attachment, expiry/reuse, visibility, alpha, LOD, material/VDO availability and actual GL execution are also open gates.
