# NWN-75: Shared material two-sided draw-state consumer

Pinned original `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This connects the previously mapped [`.mtr` lookup and parse](model-text-trimesh-tangent-pools.md), [bucket classification](bucket-classification.md), and [draw boundary](geometry-and-draw-boundary.md). The evidence is static; it establishes neither live material population nor measured cost.

On a shared-material cache miss, `SharedMaterial::GetSharedMaterial` `0x140083340` requests the named `.mtr` resource and passes its lines to `SharedMaterial::ParseField` `0x1400849a0`. The literal `twosided` key parses a Boolean into `SharedMaterial+0x1f1`; `volumetric` parses into `+0x1f8` (REA `ev_4887293af9d7cb85107e066a23405c548a2c8257f62cbd3f8899eb04e2d11333`). `Material::InitializeTextures` retains the shared-material pointer at `Material+0xd0` (REA `ev_e099f8f1f8a98443a95ad41b2b67202724559fa0b7e4cc2a585524f06b12d8e8`). Authored text, cache hit/miss and later Part admission remain conditional.

For static texture-keyed mesh and fade inputs, `Scene::AddPartsToDrawBuckets` `0x1400c38f0` reads `Material+0xd0`. At `0x1400c3c13` (mesh) and `0x1400c3dc7` (fade), nonzero `twosided` **and zero `volumetric`** choose variant `1` in `R9D`; otherwise variant `0`. The exact `AddPartToBucket` calls are `0x1400c3c5c` and `0x1400c3df4`, respectively (REA `ev_9b2776e75e9df7689deec134df0f62a5416d96a73218bc317ec5a36294648eb3`; instruction evidence `ev_42ee0257cf484527588c545d3590d4545e8fa4ed59f6bd539d38ad7d28e8f7e1`, `ev_c26b0866458c1a0f5fd466b8ea8b7ea929cc74f11fc8de30ce2d0f02405c9774`). Live Gob Parts use the same field gates at `0x1400c47c8/0x1400c47d1`; their main submission at `0x1400c4801` passes variant `1` under that condition (REA `ev_9e24461701831c9aebc02a0ef6ef07bce145ed378527c97ae94477cf3ad247bb`; exact instruction `ev_268de64344876def2829ecfec47aa1738e4e6bdacf8190ed813351b3f1ccfc39`). `DrawBucketManager::AddPartToBucket` `0x1400d75a0` indexes a retained list at `bucketType*3+variant` and appends one DrawItem. It does not itself draw or issue a GL state call (REA `ev_be929629581a2b9e85bcb28b997781374ebd3321a392e13ae1d3b0b4afcd79dc`).

`Scene::RenderDrawBucket` `0x1400cd210` traverses variants `0`, `1`, then `2` for the same bucket type. When it advances from `0` to a nonempty `1`, the direct `RenderInterface::Disable(3)` call at `0x1400cd6b0` disables culling for that variant. The wrapper reaches `GLRender::Disable`, whose enabled-state check can suppress a redundant `glDisable`; the call does not prove a driver transition every time. When it advances from `1` to a nonempty `2`, it calls `Enable(3)` at `0x1400cd6c1` and `SetCullFace(0)` at `0x1400cd6c8`. `GLRender::SetCullFace` indexes the facing table and invokes imported `glCullFace` without its own equality guard. Pinned PE bytes at table `0x140d8ad10` are `04 04 00 00 05 04 00 00`, so enum `0` is `GL_FRONT` (`0x404`) and enum `1` is `GL_BACK` (`0x405`). At final exit it restores culling and back-face selection through `Enable(3)` `0x1400cde16` and `SetCullFace(1)` `0x1400cde20`. REA draw loop `ev_9cb4fee5f7abb56a1fbee9e133c16b18e9b842aa3563ed95e15eafd0504d3500`; exact transition instructions `ev_bbe6cb6f8d8ca3702b93375c0ae1435fa189cd52847d87a988e3b4f1da20cc7f`, `ev_b1461c80b8e2688c85413f506910b73a4794f9a430270f2cfa4184d9d44fbb8a`, `ev_7558e558db863a777d96faddfcee423b784e60989c7066640561526e594e0c34`; GL facing setter `ev_33b1a2a7f9289dc7ca11bbe8a9cdee64eda61664bdecc531d337f22e0454558a`.

Thus an admitted `twosided` material chooses the **no-cull group** for its ordinary draw. It does not create a second draw item solely for that key. `volumetric` is a separate authored route: it takes precedence over this two-sided variant and explicitly emits an extra variant-`2` item before the main variant-`0` item, as detailed in [bucket classification](bucket-classification.md). Whether any such item reaches a visible draw, and whether the GL state cache actually changes at a particular group transition, requires runtime state.
