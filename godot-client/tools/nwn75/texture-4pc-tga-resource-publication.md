## 4PC source and data

`AurGetImageWrapper` `0x1400e5c60` tries the installed 16-bit callback if compressed selection fails or is excluded. `CAuroraInterface::Get16BitRaster` `0x1400f5460` tests resource types 4PC `0x80b` and TGA `3` through `CExoResMan::Exists` at `0x1400f54ce/0x1400f54f2`. Its branch chooses 4PC if 4PC wins the source-class order 2, 5, 3, 1; TGA at an earlier class makes this callback return null for later raster fallback. On selection it allocates a 0x30-byte `CAurora16BitTexture`, constructs it at `0x1400f5560`, loads at `0x1400f5570`, then writes width, height, float, format and a data pointer to the caller. A load failure calls the wrapper's deleting destructor at `0x1400f5584` and returns null. REA `ev_0dc1f85587b833f2f87c3f87ca723dab8624d51c39b5d2529aaa69c046e9b6ac`.

The wrapper constructor `0x1400f25c0` looks up a cached `CRes4PC` under type `0x80b`, constructs and registers one on a miss, and holds that resource at wrapper `+0x8`. Its `Load16BitTexture` `0x1400f29e0` calls `CRes::Demand` at `0x1400f29ed`. On successful demand it obtains the resource's `+0x68` data pointer, stamps the type `0x80b` and wrapper pointer in the preceding bytes, and sets wrapper loaded flag `+0x28`. `CRes4PC` constructor `0x1400f98a0` installs vtable `0x140d92a40`: slot `+0x20` is `OnResourceServiced` `0x1400f9a20`, which maps the demanded buffer `+0x20` to a 16-byte header at `+0x70` and pixel/data pointer `+0x68=buffer+0x10`. `Get4PCAttrib` reads the header's width, height, float and format fields; it and `Get4PCDataPtr` are CPU data leaves. The service body does not itself validate all size/format constraints. ## TGA source and CPU decode

The installed raster callback `CAuroraInterface::GetRaster` `0x1400f62d0` constructs `CAuroraTexture` at `0x1400f6342`; its constructor `0x1400f7dc0` gets or registers `CResTGA` under type `3`. `LoadTexture` at `0x1400f6356` demands the resource at `0x1400f81ed`, reads attributes/data, admits the supported 8/24/32-bit condition in its body, stamps type `3` and wrapper pointer **after** the pixel buffer, and sets wrapper loaded flag. An unsupported attribute or null data releases its demand. On success `GetRaster` returns dimensions, bytes per pixel and the data pointer; on failure it calls the deleting destructor at `0x1400f636a`. The service maps a resident header at `+0x88`, color-map start at `+0x78`, and pixel pointer at `+0x80`. Image types 1, 2 and 3 take the direct buffer path; types 9 and 10 call `ReadColorMappedRLETGA` `0x1401a4970` or `ReadUnmappedRLETGA` `0x1401a4ac0` at `0x1401a4879/0x1401a4812`. ## GPU handoff and ownership

Both callbacks return CPU pixels to `CAurTextureBasic::ConstructImage`/`BuildAndStoreTexture`. The existing [publication path](texture-publication-per-frame.md) maps `glImageBasic` and conditional `GLRender::CreateTexture`/cube and `glTexImage2D` or `glTexSubImage2D`; these callbacks do not submit GL work themselves. `FreeImage` calls installed `CAuroraInterface::ReleaseRaster` when the returned raster is callback-owned. A 4PC image uses the prefix before the data pointer to call `CAurora16BitTexture::Unload16BitTexture` `0x1400f2c10`; a TGA image uses the suffix after `width×height×components` to call `CAuroraTexture::UnloadTexture` `0x1400f86b0`. Each loaded wrapper clears its flag and calls `CRes::Release`; the wrapper deleting destructor follows. `CRes4PC::OnResourceFreed` `0x1400f9a00` clears header/data pointers. `CResTGA::OnResourceFreed` `0x1401a46e0` also frees the separately allocated RLE buffer when marked, then clears pointers/state. This CPU resource release is distinct from eventual GL texture-ID deletion.
