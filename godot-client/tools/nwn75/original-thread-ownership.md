# NWN-75: original render-related thread ownership

Status: partial. Installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This page records original-binary thread creation and known render-state producers. A static worker entry does not establish that its work executes during a particular frame or on the GL context thread.

`SDL_main` creates the original GL context and reaches the synchronous `Update` → client/GUI → Camera/Scene → GL calls → `SDL_GL_SwapWindow` path documented in [original render tree](original-render-tree.md). That call chain inherits its caller thread. Exact OS thread IDs and any context handoff require runtime evidence. A separate `CExoTimer` worker is proved below; it publishes cached clocks, not Scene/Gob animation.

The pinned PE has six direct E8 calls to `_Thrd_start` wrapper `0x140be690c`, found with `scan-rip-references.cjs`. Their containing bounds are from `.pdata` through `pe-function-range.cjs`:

`CExoTimersInternal` constructor `0x14016dd60` seeds cached timer fields and launches a `std::thread` through `_Thrd_start` at `0x14016deef` (REA `ev_187f2d55a0048ba27d2782c16da95db3ea12a6917c957279723f3d83eb13b878`). Its launch-pad vtable at `0x140d9db30` slot zero reaches `0x14016e1e0` and jumps to worker `0x14016e1f0` (bytes `ev_fbb2517d2f6c487bdee9fb3b252810c7212b4af013fb8457050ac26a1339656d`, worker `ev_70cd3db8df7af62c07e901199a8c7fe5f41ec359c1658890d3c662b41e9d2a19`). That worker names itself `CExoTimer`, loops refreshing cached tick, microsecond and wall-clock fields, and sleeps according to `g_nThreadedTimerResolution`. Destructor `0x14016e020` signals stop and joins (REA `ev_b274dc135587992c41e11a3f9474f7dcae371fd2fb2891f3b0bb7c79bf5ffc2f`). `GetMicrosecondTimer` `0x14016e0f0` reads its cached field when `g_bUseThreadedTimers` is enabled (REA `ev_0f3b4d2d5e182206bb295babc1457a6ae98eb03ee464a00a5d7a1dccaadd5052`). The pinned image defaults that flag to enabled and the resolution to 100; setting callbacks can change them. The [non-emitter animation supplement](original-scene-animation-nonemitter.md) links this clock read to the Scene animation delta. It does not move Gob/Part animation to the timer worker.

The generic task worker `Task::CExoTaskThread::Start` enters `ThreadFunc` `0x140672260` (REA `ev_a6766a4238a3aa9936102d97454a44d9ba7b49a929f449e40c2e82a8b11f62b8`, `ev_6c416e7c08a182f90bab3d6af31335966fbc4e3ddc1b3612bde2b83c5c2a4f80`). It pumps task groups through `Task::CExoTaskGroup::Pump` `0x14066ec90` and executes task virtual `+0x8` (`ev_be09bcfc2386bf2353187c40c469e6073c3dd9ec1a7e0e7ceb9c0afa5e72e4b2`). `SDL_main` reads `taskmanager.threadpool.max-size` and calls `Task::InitTaskManager` at `0x140046c6c` (key bytes `ev_67f171a812e327204630ce3c146b59448bad5613145118ae651d4b735839997b`, init `ev_3809f8d027992072bb69011048c271167195f7013ea2936625076f2c607775ca`). The bounded [task-pool ownership census](task-pool-ownership.md) traces the identified concrete enqueues through network address resolution and NWSync storage jobs; it finds no scene/model/texture/GL task producer among direct named callers. Virtual or inlined producers and runtime task choice remain open. The worker's own loop does not prove that geometry or animation runs there. Separately, the [NWSync startup handoff](nwsync-startup-handoff.md) follows its dedicated initialization worker and a conditional demand-time join to the Win32 wait boundary.

Open: identify any virtual or inlined task producers and downstream render-visible publication from NWSync, classify further thread APIs beyond the two direct-call censuses, and corroborate GL/main/worker OS thread identity and active branch frequency at runtime. The six-site census is bounded to direct rel32 references to `0x140be690c`, not all possible thread creation mechanisms.
