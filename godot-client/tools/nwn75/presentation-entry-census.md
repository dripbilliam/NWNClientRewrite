# NWN-75: original presentation entry census

Scope: installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This is a static census of direct references to the known window-swap chain in the original executable. It neither counts runtime presents nor excludes computed calls, external modules, or an unrecognized presentation API.

The [presentation entry ledger](presentation-entry-ledger.json) records the confirmed static edges and their open reachability conditions.

`RenderInterface::SwapBuffers` at `0x1400bf390` is a direct jump thunk to `GLRender::SwapBuffers` `0x1400bb640` (REA `ev_97be9829d6d4669e97876fa78afebb805ec5b1feb715de73f8f21c50e474e360`). The GLRender body calls `SDL_GL_SwapWindow` `0x140ab16b0` at `0x1400bb79a`; its rel32 field begins `0x1400bb79b`. The [SDL/Win32 swap boundary](sdl-swap-boundary.md) follows the built-in dynamic API and Windows video callback to imported `GDI32.DLL::SwapBuffers(HDC)`; external SDL dynamic API or another selected video backend remains conditional. GLRender subsequently calls `GLRender::ResetRenderStates` at `0x1400bb79f` (REA `ev_c11c50fe4c140466818d71bad2a1971fa61ffcdf3463d879a4fb5cb25d3058ec`). The reset's external GL state leaves are in [render-state boundaries](render-state-boundaries.md).

The byte scan of executable sections found precisely three direct references to the RenderInterface swap thunk, one conditional branch plus one jump-thunk edge to the GLRender swap body, and the one GLRender call to `SDL_GL_SwapWindow`. `scan-rip-references.cjs` reproduces the rel32 candidates for `0x1400bf390`, `0x1400bb640`, `0x140ab16b0`, `0x1400b6540`, and `0x1400bef10`; `pe-function-range.cjs` reproduces the three callsite ranges. The two extra candidates were checked against local instruction bytes: `0x1400b6540` begins `83 3d 49 84 1d 01 00 0f 84 f3 50 00 00 c3`, and `0x1400bef10` begins `e9` with the displacement to `0x1400b6540`. `GLRender::SwapBuffers` compares that same global `0x14128e990` to zero at `0x1400bb676`, sets `AL` from the equality test at `0x1400bb67c`, then stores the result back at `0x1400bb67f`. Thus its own entry toggles that state before the external swap call; the wrapper's zero gate reads a value the swap body changes. `scan-pointer-references.cjs` found no initialized 8-byte pointer to either wrapper or the known swap targets. That pointer scan does not rule out relative tables, runtime stores or external callers.

The pinned export directory at RVA `0x10d16a0` has 18,245 address and name entries. `inspect-pe-exports.cjs` resolves RVA `0xb6540` as `?RestoreFrontBuffer@GLRender@@CAXPEAUSDL_Window@@@Z` and RVA `0xbef10` as `?RestoreFrontBuffer@RenderInterface@@SAXPEAUSDL_Window@@@Z`. Their adjacent four-byte RVAs in the export address table are export metadata, not an internal caller. The [PE export format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#the-edata-section-image-only) defines these RVA/name/ordinal tables; the names and ordinals above come from the pinned executable bytes. A bounded byte-string search of executable/DLL files in the installed `bin/win32` directory found this decorated RenderInterface export name only in `nwmain.exe`; ordinal-only or out-of-directory callers are not excluded.

The exported `GLRender::cm_bFrontBufferActive` `.data` DWORD at `0x14128e990` initializes to `1` (`01 00 00 00`, file offset `0x128d590`). A complete executable-section rel32 scan with zero trailing bytes finds the two `GLRender::SwapBuffers` references at displacement fields `0x1400bb678/0x1400bb681`. A scan with one trailing immediate byte additionally finds `RestoreFrontBuffer`'s compare at `0x1400b6542`; its original bytes are `83 3d 49 84 1d 01 00`. This distinction matters because `scan-rip-references.cjs` ordinarily assumes the displacement ends the instruction. The observed swap entry toggles this state. The export name is `?cm_bFrontBufferActive@GLRender@@0HA` (ordinal 15638). This byte census does not exclude computed-address stores or external callers, and no internal route to `RestoreFrontBuffer` is proven.

The PE also exports `SDL_RenderPresent` at `0x140ab2d00`. The pinned executable-section rel32 and initialized 8-byte pointer scans find no direct application caller or pointer to that wrapper. It is a separate compiled SDL API surface, not a confirmed frame-present route in this application; dynamic API tables and external callers remain outside this bounded test.
