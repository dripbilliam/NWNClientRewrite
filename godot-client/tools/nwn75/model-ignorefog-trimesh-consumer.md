# NWN-75: authored `ignorefog` to TriMesh draw state

Pinned original `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. The [model command registration](model-render-command-startup-connectors.md) reaches `ignorefog` `0x1400a1630` only when the parsed MDL contains that admitted command. This note closes the field consumer at a TriMesh material draw. It is static source evidence, not a claim about a particular Arelith model or frame.

`Model::Model` `0x140087bc0` writes qword `0x01000000` at Model `+0x90` (`0x140087c96`), making byte `+0x93` equal to 1 on the pinned little-endian PE. `ignorefog` scans an integer and, only when it equals 1, writes zero to `currentmodel+0x93` at `0x1400a1653`. Other values leave the existing flag. `PartTriMesh::PartTriMesh` `0x140087fd0` initially sets `+0x9d` to 1 as part of a two-byte `0x0100` initialization at `+0x9c`. When its source `MaxTree` pointer at node `+0x58` has Model kind 2, it compares Model `+0x93` with 1 at `0x1400880f9` and stores that Boolean on the part at `+0x9d` (`0x140088103`). Thus the authored model setting is copied at TriMesh construction, rather than reread from the Model on every draw. Evidence: Model constructor `ev_487d22f518fd1fdc568161117ccde18e7565eb1ad86d8c70ad352245f1492ea2`, command `ev_1637ed298d05ddc95a35750315d747a738a373c685fc8084f450833339d97102`, TriMesh constructor `ev_5aca1021c29e62567fd952510b85a1db37b336878178ed4e952ab0dc0a480653`; individual instruction bytes are in the ledger.

The stored part flag can change later. `Gob::DisableFog` `0x14008ddb0` and `Gob::EnableFog` `0x14008ddf0` tail-jump to `PartSetFog` `0x140093a20` with false or true. `PartSetFog` asks each Part's virtual `+0x58` for a TriMesh view, writes that view's `+0x9d` when nonnull at `0x140093a40`, then recursively visits the Part's children in stored order. These explicit Gob operations would override the authored initial value on visited TriMeshes. Their observed incoming references are vtable data slots (`0x140d81620/628`, `0x140d830f8/100`, `0x140d88be0/be8`); this is a separate optional virtual entry, with no verified caller from the CRT-connected render path. A byte search also found `+0x1e0/+0x1e8` virtual calls in `Scene::RenderSinglePass`, but retained pseudocode calls those slots on `Scene::this`, so they do not connect the Gob override. Evidence `ev_048c6101c7d98229e56dfb811e08c496dbb720a07f28265ae849a8326aac9600`, `ev_ad23ce7f532845bdc5fbb66a85bb0d488ed8391a86e1eb51f5a0ca787dd98c82`, `ev_706b455761884d063a4358795661baa6ad64364a04d0783b0f5840a86086ad64`, `ev_be62db219ef3228680498d866cc221643bc961e0befe57d5e252f2fdd936e3cd`, `ev_02ace6727b08cd03cb9bd9a012c7c646766c92f3bd0cd79bb2b383726b80c4a0`.

The already mapped dynamic TriMesh Draw route selects `PartTriMesh::Mat` `0x1400a2f50` through the Part vtable. After material/texture/shader selection, Mat requires an owner flag at `Part+0x50 -> +0x18` to be zero, a nonnull `currentscene`, and Scene fog enable `+0x140 != 0`. It then reads the part `+0x9d` at `0x1400a31b2` (and again at `0x1400a31c7` on the true branch): value 1 calls `RenderInterface::Enable(2)` at `0x1400a31c2`, value 0 calls `RenderInterface::Disable(2)` at `0x1400a31d7`. The shared render-state and shader-uniform notes map those wrappers downstream. This conditional state choice adds no draw on its own. The separately mapped `MatStatic` `0x1400a3270` has no `+0x9d` read in its inspected body, so this specific consumer applies to the dynamic material route; do not silently generalize it to every static mesh.
