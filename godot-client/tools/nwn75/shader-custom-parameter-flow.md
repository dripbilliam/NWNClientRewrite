# Original custom shader parameter path

Pinned image: `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This supplement resolves the registered custom-parameter branch of `GLRender::SetUniforms` `0x1400b8380`; the wider fixed-uniform groups are in [shader uniform dirty gates](shader-uniform-dirty-gates.md). Exact branch and call sites are in [the ledger](shader-custom-parameter-flow-ledger.json). All observations here are static original-binary behavior.

## Input and registration

`SharedMaterial::ParseField` `0x1400849a0` accepts a `parameter` field and directly calls `Parse(char const*, MaterialParameter&)` at `0x140084d1a`. That parser `0x1400845e0` recognizes `float` and scans up to four `%f` values into `MaterialParameter+0x44..+0x50`; success requires at least one float. It writes type `0` at `+0x5c` and component count `sscanf_result − 2` at `+0x60`, so the accepted material-text float counts are **1, 2, 3, and 4**. Its `int` branch requires one `%d`, writes type `1`, one value at `+0x44`, and count `1`. A failed parse retains constructor type `2`. `Material::SetMaterialParam` `0x1400857e0` can reparse a formatted `oParam float` or `oParam int` value through the same parser at `0x140085988`; the float-count-one path extracts one word first. `Material::OverrideShaderParameterf` `0x1400844c0` replaces all four value slots for a matching type-0 name, and `OverrideShaderParameteri` `0x140084560` replaces the first slot for a matching type-1 name. These overrides do not alter the stored component count. After both custom shader variants exist, `SharedMaterial::Init` `0x1400838e0` calls `RenderInterface::GetCustomParameterToken` twice per parsed parameter, storing tokens in material fields `+0x54` and `+0x58`. The interface entry `0x1400bebe0` is a direct jump to `GLRender::GetCustomParameterToken` `0x1400b3500`. That function first matches an existing program record by parameter name. On a new name it copies the type and component count, calls the original `glGetUniformLocation` pointer `0x141442578`, logs a `-1` location, and initializes cached (`record+0x4c`) and pending (`record+0x5c`) payloads to zero for `count×4` bytes when type is 0, or one word each when type is 1. It appends a `0x6c`-byte record to program `+0x1ee8`, count `+0x1ef0`. The zeroing uses the count supplied by the parsed record; the token function itself does not show a separate `count<=4` guard. `SharedMaterial::BindCustomShader` `0x140082910`, `SharedMaterial::BindShaderParameters` `0x140082aa0`, and `Material::CheckAndBindCustomShader` `0x140082b80` are the complete pinned direct-call census of `RenderInterface::SetCustomParameterValuef` `0x1400bf090` and `SetCustomParameterValuei` `0x1400bf0a0`. They choose the variant's program pointer and token (`+0x1c0/+0x54` or `+0x1c8/+0x58`), dispatch only type 0 or 1, and pass material values at `+0x44`. The interface entries jump directly to `GLRender::SetCustomParameterValuef` `0x1400b6df0` and `SetCustomParameterValuei` `0x1400b6f00`. If the record location is `-1`, the setters return. The float setter accepts an unsigned-short count with no local four-component bound, but the established material parser supplies only 1–4. ## Program visit and CPU/GL leaves

At `0x1400ba4ba`, `SetUniforms` reads global generation `0x1413d2738`; if it equals the selected program's cached `+0x48`, branch `0x1400ba4c3` skips the entire custom array. Otherwise it stores the generation, requires count `+0x1ef0>0`, and iterates `0x6c` bytes per record. Type 0 at `0x1400ba4f7` uses `record+0x8` as an unsigned-short component count and calls original CRT `memcmp` `0x140c41f60` at `0x1400ba522` for `count×4` bytes, comparing cached `+0x4c` to pending `+0x5c`. Only a byte difference enters the upload branch. With location `record+4>=0`, count `1` calls the loaded `glUniform1f` pointer `0x1414425e8` at `0x1400ba53e`; **every other count** calls loaded `glUniform4fv` pointer `0x141442650` at `0x1400ba552` with `count=1` and pending pointer. This includes parser-admitted counts 2 and 3; there is no `glUniform2fv` or `glUniform3fv` selection in this branch. After the branch, `0x1400ba569` calls the original CRT copy routine `0x140c417f0` for `count×4` bytes into the cached payload, even when the location is negative. `0x140c417f0` is byte-copy/move code with small-size cases, not a GL boundary. Evidence: `SetUniforms` retained dossier `ev_1a4116233c92836c24653152acff91f84c48e7899cc3e2c69a0d2729deec3431`, `memcmp` `ev_af0eb64f87880145dd4eb8014c31758d4866282e380a850bb348a0089c018c3b`, copy `ev_16d3100b6105925aa7c5178516d0446689195bc8f7cda5c461a3a05c1ba14dda`, and the exact instruction IDs in the ledger. The GL pointer names are also indexed in [the original GL pointer catalog](gl-extension-pointers.json) and [uniform callsite catalog](shader-uniform-gl-callsites.json).

The **type-0 reset predicate** is instruction-level: `XORPS XMM10,XMM10` at `0x1400b86da` establishes zero; the post-copy loop loads each cached float through `[RBX-0x10]` at `0x1400ba580`, compares it with zero via `UCOMISS` at `0x1400ba585`, and writes zero to the corresponding pending component at `0x1400ba58d` if the value is nonzero **or unordered (NaN)**. Both `+0.0` and `-0.0` compare equal and skip the clear. Any clear sets a flag; after the record loop, `0x1400ba5c2` forces program `+0x48=-1` so a later visit can upload the cleared value. `memcmp` remains bitwise, whereas this reset decision is a float comparison. Evidence: exact instructions `ev_d220f29db5151196dd1ea4675154a0ad0aaeb742ca5ef9e5ce76f01e6b963783`, `ev_c120d3350b48f91271a5de59ec19e539eec1f16b2473d76f7d7b63097ff82f43`, `ev_44ca6df7428dd243226eb4629e63d571fe6fd30cdea49bd8da38c00e53b33308`, `ev_7d5c1cbfcdb01eb857c537cba978817b71739e824bcf9548f0b9cfd86f751bc3`, `ev_74ed98570da7e65233c8dc4adc10bf182f210766f0e5a6fb314bacf5682f3d60`, `ev_c339c5996fe6c4d499ee2c1ce57c879e14deecf3f56b17507fdd502553c61610`.

Type 1 at `0x1400ba612` compares pending integer `+0x5c` with cached `+0x4c`; on difference and valid location, `0x1400ba630` calls `glUniform1i` pointer `0x1414425f8`, then copies pending to cache. If that cached integer is nonzero, `0x1400ba650` clears pending and sets the same revisit flag. Other record types bypass both branches. ## Bounded frontier

The static path proves parser-admitted counts 1–4 and the GL call shape for each. The float setter and token function accept a raw unsigned-short count without a local upper-bound check; the behavior of nonmaterial or corrupted records with counts beyond four is outside this established path.

The global generation read at `0x1413d2738` has one exact-address Ghidra reference, the `SetUniforms` read at `0x1400ba4ba`. `GLRender::InitRenderSystem` `0x1400b3f60` and `GLRender::ReloadShaders` `0x1400b5110` each call `FUN_140c42060` (the original byte-fill routine) with base `0x1413d26f0`, fill byte zero and size `0x60`; the range includes `0x1413d2738`. The exact call sites are `0x1400b4120` and `0x1400b5371`. This establishes initialization/reload resets, not every later writer. `GLRender::SetShaderParami` `0x1400b7c90` writes a computed slot at `0x1413d26ec + index×4`, so index 19 could alias `0x1413d2738`. Its known in-image interface caller, `Camera::DoFrameBufferEffects` `0x140057b20`, supplies index zero at seven call sites. An exported/interface call with another index, or another indirect/containing-block write, remains possible. Thus the nonzero producer of this generation remains an explicit frontier.
