# NWN-75: original camera render entry

Status: partial original-binary branch map. The installed `nwmain.exe` has SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are image virtual addresses. Scene traversal and draw buckets are in separate scene documents. Static edges do not establish runtime frequency.

## Entry and conditional gates

`CGuiMan::UpdateAndRender` invokes camera vtable slot `+0x10` for registered and special scene views. The original `Camera` table resolves it to `Camera::RenderScene` `0x14005a5d0` (REA `ev_4393914dd018195bd1a10f8edf54a40ad4cff9b0c8d0e56fa03049d3137f7161`). If `Camera+0x90` has no scene, there is no scene render. Otherwise the function begins a scene, reads the viewport, optionally upscales it, prepares projection/view matrices and six frustum planes, sets depth range and shader-dependent camera data, then calls scene virtual slot `+0x18` at `0x14005b208`. The original `Scene` table resolves that slot to `Scene::Render` `0x1400cc730`. Afterwards it pops an optional upscale matrix, ends the scene, clears `CurrentCamera`, and restores an explicit viewport.

An explicit rectangle at camera `+0x4d8` through `+0x4e4` is rejected when wholly outside the screen, before the scene virtual call. A visible rectangle sets a clipped viewport and uses its aspect ratio. A full-viewport camera uses the existing GL viewport. FOV at `+0x4c8` selects orthographic projection when nonpositive or perspective projection when positive. The view transform uses camera position at `+0xb0` and orientation at `+0xbc`. Global shader parameters 8 and 9 gate additional camera-side data at `+0xe58` onward. These are observed conditional paths, not claims about every camera being active each frame.

`Camera::UpscaleViewport` `0x14005b860` returns false if GUI scale differs from 1.0 by less than 0.09. Otherwise it chooses scale, offsets and adjustment mode from the `sceneGUI...` name, with panel-geometry checks for selected names. Handled names include ordinary viewport, chat, inventory, character sheet, dialog, partybar, action queue and overlay. It can return false for unhandled names. Its camera virtual `+0x8` call at `0x14005bb10` resolves to `Camera::AsCAurObject` `0x1400577c0` through the pinned `Camera` vtable and returns `Camera+8`. The panel path at `0x14005bbf6` calls virtual `+0xc0` on the object pointer stored at `CGuiPanel+0x10`, rather than on the panel itself. For an original `Gob` object, its vtable slot resolves to `Gob::GetPosition` `0x140048530`, which reads position at `Gob+0xa8/+0xb0`; other possible object classes remain open. `CGuiPanel::SetPosition` independently invokes that same member's `+0xc0` slot. REA upscale `ev_c11fb07c5903f02e79a23d77acbfdc8865f646a5d0b252f3d88435a878ae8cc6`, camera bytes `ev_4eb84bc1d98cae6dee969fa614900a9171a7b0f99521c4ecb1142ab5cf01929d`, camera getter `ev_f742682307222bc52dd53f002a610702154b7b2e4c9917206ea78f372e6b7838`, panel callsite `ev_6e621512e9049981d06c395c561586062966d2531b80fa2271e172123b5d0d05`, Gob bytes `ev_15dd5e10911047e0f9099bb67a11928c97ae578a55fa4549a0802d3cab696213`, Gob getter `ev_ab5cc74dac75bb492d9943e8176af4b3b60be442a2ebf1931611043d6ee2b0d0`, panel setter `ev_714b8f7674692ac91f5710f342ce88eb82b3b038ffe2c926f2b73c796ad9e8dd`.

For `sceneGUI...` or orthographic cameras, `RenderScene` conditionally clears depth once via a global flag and sets a narrow depth range: selected named overlays/panels use `0.0–0.02`; other GUI scenes use `0.021–0.1`. The normal perspective branch sets `0.0–1.0` and resets that GUI-clear flag. Adjustment modes 1–7 push, reset, scale and translate the current matrix, then pop it after scene rendering.

## Matrix state reaches shader uniforms

The wider per-program generation groups are catalogued in [shader uniform dirty gates](shader-uniform-dirty-gates.md).

The camera selects matrix mode 0 for projection, `SetViewTransform` selects mode 1, and the camera selects mode 2 before its scene virtual call. The corresponding original CPU matrix-change counters are `0x1413d2748`, `0x1413d2744`, and `0x1413d2740`; mode 3 has `0x1413d274c`. The first three are read by `GLRender::SetUniforms` `0x1400b8380` at original instructions near `0x1400b83e2`, `0x1400b8413`, and `0x1400b8441`; mode 3 is read near `0x1400b86b4`. This function is called by `GLRender::SetProgram` `0x1400b7a40`, whether or not `glUseProgram` had to bind a different program. REA SetProgram `ev_c2fa9ed1743a63b47c3b92d6a2cd636bdebff3734eddc2913bdeac583cee5a97`; retained SetUniforms `ev_1a4116233c92836c24653152acff91f84c48e7899cc3e2c69a0d2729deec3431`.

`SetUniforms` compares each counter with a cached generation in the selected program (`PROG_FIXED+0x58` projection, `+0x54` view, `+0x50` model, `+0x5c` fourth matrix). On a mismatch it updates that cache and, if the corresponding uniform location is nonnegative, calls the original extension pointer `0x141442678` (`glUniformMatrix4fv`). The first three calls are at `0x1400b8406`, `0x1400b8434`, and `0x1400b8462`; the fourth is at `0x1400b86ce`. Combined and inverse matrix work is also gated by those dirty flags and valid locations. The location checks, cache fields, combined-matrix calls and fourth counter are visible in the first 5,200 UTF-16 units of the retained pseudocode; exact GL targets for all 129 computed calls in this large function are catalogued in [shader-uniform-gl-callsites.json](shader-uniform-gl-callsites.json) and [gl-extension-pointers.json](gl-extension-pointers.json). Therefore the camera writes CPU matrix state immediately, while GL matrix upload is deferred until a program is selected for rendering and the program's cached generations differ. This is a static control-flow statement; it does not establish how often a particular uniform location is present or a generation changes during gameplay.

The [camera entry ledger](camera-entry-ledger.json) records all 13 direct edges with exact instruction sites, including both `UpscaleViewport` calls, two `SetDepthRange` calls, the two `EndScene` exits, and both `SetProgram` tail jumps to `SetUniforms` (`0x1400b7a85/0x1400b7aff`). The sites were confirmed as decoded instructions in the pinned image; the complete outgoing reference sets are `ev_4e6edd5b82e426c0785a9603e46c09f86108db5096cd7217e15b83da526e1f3f` and `ev_cd009099e215db368541409bc0db6d037ac5c89f3fa8dccad3a29551f4233a63`.
