## Emitter alpha from source to stream

`Scene::DoEmitterBucket` `0x1400c7ae0` calls `PartEmitter::AnimateParticles` at `0x1400c7c94` only when the Scene is animating or the owner Gob is force animated. It queues emitters with positive live count, sorts by camera distance, and invokes each queued emitter's instance render function field `+0x1b0` at `0x1400c7dae`. `PartEmitter::Initialize` selects `RenderStandard` `0x1400643b0`, `RenderMotionBlurred` `0x140064180`, `RenderLinked` `0x140064170`, or `RenderNothing` `0x140064190`; the first three jump to shared `RenderEmitter` `0x140062900`. `RenderNothing` uses its separate attached-Gob route and does not produce this quad stream. Evidence Scene stage `ev_b4881207528882fb849869474dcd3a31c18cf9f00dad89280e126d85fcdd7ed3`, dispatch selection `ev_8196177995dbdc99839bcacb411d86473a8f877c6bf8291aea000762832be32d`.

In the active shared render body, the tile alpha source is emitter `+0x100`; if null, it falls back to owner Gob `+0x1a8`. `ProcessStaticParts` `0x1400cb520` writes its `TileData*` argument to `PartEmitter+0x100` at `0x1400cb828`, after the `AsPartEmitter` subtype and `ProcessTilePart` gates. `ProcessStaticObject` `0x1400cb4c0` writes the same `TileData*` argument to the owner Gob `+0x1a8` at `0x1400cb4ec`, closing the fallback source type. `Scene::SpawnTile` supplies the TileData and writes its position Z at `TileData+0x50`; the TileData constructor initializes fade `+0x70` to `1.0`. `ManageSceneBSP` `0x1400db320` copies each TileData's next fade `+0x74` to current fade `+0x70` for the Scene `+0x1a8` tile list before visibility traversal. Later in that function, `HandleFadingInBucket` `0x1400d9670` and `HandleFadingOutBucket` `0x1400d9ab0` use `DeltaT*4.0` to advance or reduce next fade `+0x74` for their selected TileData lists, with clamps to `1.0` and `0.0`; they also classify tile geometry into cap/fade buckets. This closes the observed per-frame fade producer for that Scene path, but an exhaustive writer census and runtime list population remain open. If neither TileData pointer exists, or the comparison `5.0 < emitter(+0x1e8) − selected TileData(+0x50)` fails, the factor is `1.0`. Otherwise it reads the selected TileData fade `+0x70`. A separate owner factor defaults to `1.0` and, with nonnull owner Gob `+0x50`, reads Gob `+0x108`, the alpha written by `Gob::SetColorShifting` `0x1400948d0`. The standalone named helper bodies `GetTileAlpha` and `GetGobAlpha` return these same factors; no direct call from `RenderEmitter` to them is present in its analyzed code. `RenderEmitter` multiplies the tile factor, owner factor and emitter alpha fields `+0x70` and, for authored lifetime alpha interpolation, `+0x6c`. It clamps the products to `[0,1]`, scales to an 8-bit channel, interpolates per live particle when the alpha-change gate is active, and packs the result into each generated vertex color at 0x18-byte stride. The same body can add lighting through `LightManager::GetEmitterLighting` at `0x140063092`, then calls `RenderInterface::RenderVertexStreamData` at `0x140064109`; that shared route reaches the GL draw boundary already mapped in the particle render document. This is a concrete per-emitter update/alpha/draw chain, with no extra named helper call at the alpha reads. The authored emitter mode, tile fade, owner color shift, positive live count and actual visible particles remain runtime gates.
