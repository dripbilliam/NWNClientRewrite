# NWN-75: tile reveal to static fog draw

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This joins a tile visibility state change to the Scene BSP fade clock and the static Part draw-state consumer. It is distinct from the general Scene fog range/color route in `scene-fog-state-source.md` and from camera geometry-fade planes.

`FUN_140850120` `0x140850120` only enters its change branch when Tile `+0x30` differs from the requested state. Under area flags `+8 & 3`, it calls `AuroraSetTileFoggedByWar` `0x1400a5070` at machine site `0x1408502c4` with Tile position `+8` and `requested_state==0`. It then stores the requested state at Tile `+0x30`. Saved original evidence `tools/native_parity/visibility/evidence/native-tile-reveal-owner-v1.json`, row `clientTileRevealSet850120`, `ev_032b1638998ac2c434a0a02c984a449a22b24be39ce96cbe292f8935fd00608a`. Its recorded analyzed callers are `0x1407b4f70`, `0x1407c95f0` and `0x1407dba70`; this note does not claim which one ran in a particular area.

`AuroraSetTileFoggedByWar` finds `mainscene`, performs a BSP search at the given position and uses the node's `+0x70` nodedata and its `+0x98` TileData pointer. It writes the boolean to TileData `+0xc4`; on a fogged (`true`) request it also writes zero to the float at `+0xc8` (decimal 200). Saved `native-tile-fog-callback-setter-v1.json`, record `tile_fog_actual_setter_evidence`, `ev_5f27f3de3a02971ab4909632a29b313f6b9d04e13bfa9c2b6c15150b2f0cc3c3`. The setter's nonnull BSP/TileData assumptions are visible in that body; a null-safe fallback is not shown.

On a visible BSP node, `FUN_1400dc140` reads the same nodedata `+0x98` TileData pointer. If it exists, its `+0xc8` float is below 1 and its `+0xc4` fogged byte is false, the callback advances `+0xc8` by `DeltaT*4`, capped at 1. It then calls `ProcessTriMeshParts` unless the debug AABB route is active. Saved callback `native-tile-fog-callback-setter-v1.json`, record `tile_fog_actual_callback_evidence`, `ev_45e32deb3c08e2049d65115dfbffa713fea199a454c49b479334e1e1653ddc01`. This is a conditional fade clock tied to BSP visibility, not an unconditional update of every area tile.

`ProcessStaticParts` stores the owning TileData `param_3` at each admitted static TriMesh Part `+0xa0` before Part publication. `Scene::RenderDrawBucket` reads that Part `+0xa0` pointer. For a nonnull TileData with fade `t=TileData+0xc8 < 1`, it enables fog and sends color `t² * Scene fog color`, start `t * Scene fog start`, and end `t * Scene fog end + 0.1` through `RenderInterface::SetFogModev/f` before the Part's virtual draw. The static draw body then calls `RenderInterface::SetCanDissolve` and the Part draw virtual. Saved `native-tile-fog-part-draw-selected-v1.json`: `ProcessStaticParts` `ev_37fb30c927647447004135ecdb127d880eb9d31c04a25f9f871c9c9dc4792731`, `Scene::RenderDrawBucket` `ev_05f4c923f9a05e41527720e54b2d50e38af2d28edb36f74e2d5a5e42af1c5b19`. The already mapped render-interface and Part leaves carry that conditional state toward the GL draw; this note does not infer its frame frequency or final pixel colors.

The resulting data edge is: changed Tile reveal state → area-gated `AuroraSetTileFoggedByWar` → BSP node TileData `+0xc4/+0xc8` → visible-node `DeltaT*4` recovery → static Part `+0xa0` → per-draw fog parameters. Remaining selectors are actual server/area reveal calls, area flags, BSP membership, node visibility, Part admission and whether a given draw has `t<1`. They need runtime or asset evidence; the static path alone does not show the effect occurring in Arelith.
