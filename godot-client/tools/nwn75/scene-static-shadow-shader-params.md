# NWN-75: static-shadow shader parameter producer

Pinned original `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This follows the static branch of [Scene shadow rendering](shadows-and-dynamic.md) and reuses the exact GLRender setter/consumer boundary in [dynamic-shadow shader parameters](scene-dynamic-shadow-shader-params.md). It records static control flow, not measured pass frequency or cost. New direct edges are in `scene-static-shadow-shader-params-ledger.json`.

`Scene::RenderStaticShadows` `0x1400d2ca0` is called by the shadow pass only when enabled shadows and its static-geometry branch admit it. The function requires `Scene+0x68` static-shadow-light count above zero and the first selected PartLight in `Scene+0x60` to equal the LightManager's current static shadow light at `LightManager+0x90`. It checks a separate cached `vs_shadowvol`/`fs_shadowvol` program pointer at `0x14140af28`, calling `RenderInterface::GetCustomShaderProgram` at `0x1400d2dc2` only while that pointer is null; a null result exits before the bucket loop. It prepares the light vector by a radius `<=1000` position/radius route or a directional route, disables culling and visits bucket 9 followed by bucket 10 with opposing stencil operations. REA `ev_9263c44a9da924e26c6d0a1587ffbee54b1eb615d49b71521ebdd1bba5c7cfea`.

For each nonnull item in those buckets, Part virtual `+0x80=AsPartShadow` must return a nonnull `PartShadow`, and its VDO at `+0xa0` must be nonnull. Only then the pass stages the cached program at `0x1400d2f7b`, calls `RenderInterface::SetShaderParamv4(0, light_vector)` at `0x1400d2f8e`, and calls `SetShaderParamf(1, z_clip)` at `0x1400d2fc2`. With no PartShadow projection pointer at `+0x80`, `z_clip=-20`; otherwise it is `min(projection+0x60,0)-0.1`. PartShadow virtual `+0xc8=Draw` follows at `0x1400d2fcd`, resolving through the constructor-backed table to `PartShadow::Draw` `0x1400a2490` and its already mapped VDO draw/API boundary. A nonnull VDO alone does not prove a nonzero element count or an eventual GL draw. Exact direct sites: `ev_376728c2240944986c9c66406594fa8facafb0f549b8274675de4bc2c14abc93`, `ev_97d3482ddb3b6d4125439a9bc5763fb7539c6c787451898d0a4ad202e5daafb5`; computed Draw site `ev_02ed387f0db54f0f6e5949cf06a738d43d2a80cac7ac02271aaec55221c4f53d`. The [PartShadow producer and lifetime](scene-partshadow-producer-lifetime.md) documents its subtype/source admission.

The two setters join the same original `GLRender::SetShaderParamv4` `0x1400b7cb0` and `SetShaderParamf` `0x1400b7c70` bodies as the dynamic-shadow item path. Each unconditional setter call advances generation `0x1413d273c` once and stores the vector or float. The next valid VDO draw selects a program and calls `GLRender::SetUniforms`, which revisits the shader-constant group if the selected program's cached `+0x4c` generation differs. A `projectionSource`/`projectionWorldZClip` GL upload still requires that uniform's valid location and a changed value in that program's cache. These static-shadow calls can therefore cause per-item CPU dirty-group checks without guaranteeing a `glUniform*` call. Consumer and pointer evidence is in [the dynamic-shadow continuation](scene-dynamic-shadow-shader-params.md) and [uniform gate map](shader-uniform-dirty-gates.md).
