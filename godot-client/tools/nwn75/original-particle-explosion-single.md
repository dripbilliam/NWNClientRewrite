## Common owner and render handoff

`MdlNodeEmitter::InternalCreateInstance` `0x1400621f0` installs the Explosion or Single PartEmitter vtable, stores the owner Gob at emitter `+0x50`, and initializes it. The Scene emitter stage `0x1400c7ae0` calls `PartEmitter::AnimateParticles` `0x140061210` only under Scene animating or owner Gob force-animated, and that method rejects tile fade states, computes the emitter pose, clamps delta to `0.5`, then invokes concrete virtual `+0x100`: `ExplosionEmitter::Update` `0x1400647c0` or `SingleEmitter::Update` `0x140065cd0`. An emitter with positive live count is sorted and receives its installed render callback at `0x1400c7dae` in the same inherited render call. A source name at `MdlNodeEmitter+0x158` selects `RenderNothing`, which moves attached model Gobs but emits no quad stream; otherwise Standard/Linked/MotionBlurred enter shared `RenderEmitter`, which conditionally commits packed vertices and calls `RenderVertexStreamData` → `GLRender::RenderVertexStreamData` → imported `glDrawArrays` for the nonindexed particle stream. The shared gates and GL API calls are in [particle rendering](original-particle-effect-render.md). ## Explosion: event edge, recycle, and burst

The factory registers the `Detonate` event callback `0x140061a30` on the supplied owner Gob at `0x1400622c7`; the callback only sets emitter byte `+0x108` to `1`. The PartEmitter constructor initializes that byte to `0`. `ExplosionEmitter::Update` first obtains owner adjusted scale, calls `chkParticleLife` at `0x14006482e`, updates previous positions for motion-blur mode `6`, advances rotation for each live particle, and invokes the installed movement callback `+0x170` at `0x140064949`. `chkParticleLife` walks live particles backward: while their clock is under lifespan, it advances clock; once expired, it removes them from live list `+0x188/+0x190`, appends them to reuse list `+0x130/+0x138` (growing capacity when needed), and, for a Chunky particle with an attached Gob, calls its `AttachToScene` virtual `+0x90` with null. That detaches the child Gob while preserving it for a later reuse. These are CPU particle, Scene membership and clock operations, with no GL call in Update. Evidence factory `ev_e9806c355853e25ce0b29fba8bd9035e6d113563e1d021a4effee3441c5add89`, Detonate `ev_62e63adcf051547b4dbecb64e768ec13383a69feb8df80fd7c24d7d012330b73`, constructor `ev_79437732e3dca6dd7bbc7156956fd5d4e067f8cd146357d6131acf6d1a9096fd`, Update `ev_41eacbf2486adc815c8e71b810e83f721043f80bb0bcd7dc6a346066af290416`, life `ev_6a316aab67a349f9829d86167385cb7733aaa9958720676629d2dc0a8e8cf9ce`.

When `+0x108` is set, integer-converted count from emitter `+0x74` is positive and latch `+0x1c8` is below `1`, Update optionally calls `WindManager::AddPointSourceWind` at `0x1400649bc` if source `+0xa4` is nonzero, then loops the count. Each iteration takes a particle from reuse list if available; otherwise it allocates a base `Particle` at `0x140064a85` when source model name `+0x158` is empty, or a `ChunkyParticle` at `0x140064a57` when nonempty. It calls the constructor-backed particle virtual `+0x10=initialize` at `0x140064a9e`, appends the particle to the live list at `0x140064aab`, then calls `chkRandom` at `0x140064ac6` for the authored random-atlas gate. New constructors themselves invoke base `Particle::initialize` before this second initialization; Chunky construction can create and attach a model Gob, and Chunky virtual reinitialization attaches it, scales it, and requests `impact` animation. At Update end, a true trigger sets latch `+0x1c8` to `1`, a false trigger clears it, and trigger byte `+0x108` is cleared. The exact event timing, authored count, model choice, reuse count and visible result remain runtime gates. ## Single: create once, advance, or destroy

`SingleEmitter::Update` tests `(int)emitter+0x74`. When zero, it removes its first live particle from the list and calls that particle's virtual destructor at `0x140065ef3`, then returns. Base Particle destructor slot `+0` points to `0x140060e50`; Chunky points to `0x140060cf0`. The latter destroys the attached Gob at `Particle+0x78` through its Gob virtual destructor before releasing the particle; the Gob destructor reaches Scene removal and Part/behavior teardown as mapped in [particle lifecycle](original-particle-effect-lifecycle.md). Unlike Explosion, Single does not call `chkParticleLife` or park this particle in the reuse array. Evidence Update `ev_362f7e8de70e775c790f65836a41761a209d7e748570b00ceabf8b4027943e70`, base slot `ev_42c21cedd4acbbabfc56add2f7ba4b9ab74df527d042102cb2ff432a265d7ddd`, Chunky slot `ev_e7e6095ca9907cf047dd59ec8a0e4fc4fb7a3616dd185a0e2914a3fba6bfcf6a`, destructors `ev_14f04387fcaebaa5d3e69ee710d166c5d5f91c4bf3bb053e95a70d876d8c9da3`, `ev_a263862a0470e20022159c8daf8dfe8fae70b9d2d9f1d14267cc920fe20b91b9`.

When enabled with zero live particles, Single allocates base Particle at `0x140065d5f` or Chunky at `0x140065d3a` under the same authored source-name gate, appends it at `0x140065d6b`, then tail-jumps to `chkRandom` at `0x140065d88`. It does **not** make Explosion/Fountain's subsequent virtual `initialize` call on this first-use path; the constructor has already initialized it, and the Chunky constructor attached its Gob. When enabled with a live particle, Single advances its clock `Particle+0x74`, wraps it to zero under its lifespan/source `+0x16c` gate, advances rotation, updates previous position for motion-blur mode `6`, then tail-jumps through movement callback `PartEmitter+0x170` at `0x140065ea4`. This movement path is absent on the first-use and disabled branches. It calls no GL API itself; a positive live count reaches the Scene render callback described above. Evidence Update `ev_362f7e8de70e775c790f65836a41761a209d7e748570b00ceabf8b4027943e70`, Particle constructor `ev_f4f36fcb70d25790540d91bfa65ddaa2576429752eca6b2df001b3d7b1f06b41`, Chunky constructor `ev_a835c7c30c035c6d53c1f634d31e77e7825f252efc92bccc6a08a310d2e47917`.

Explosion and Single differ in trigger and lifetime ownership: Explosion recycles expired particles and detaches model Gobs for reuse; Single destroys its live particle and attached Gob when disabled. Both inherit the Scene/render caller for this route. Authored subtype selection, event timing, object populations and GL visibility remain unproven at runtime.
