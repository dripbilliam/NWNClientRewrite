# Text Skin generated vertices and weight comparison

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. The [ledger](model-text-skin-vertex-dedup-ledger.json) expands the [text Skin postprocess](model-text-skin-animmesh.md) from `PartSkin::PostProcess` `0x1400df860` through the node's installed `+0xa0` callback and `MdlNodeSkin::InternalGenVertices` `0x1400df200` (REA generator `ev_7fe27dd2d5527878a6dc8584b82a06af7df9ccf1e275b52bc8f3ca19d96a5d17`). The generator is CPU instance construction before the conditional Skin stream pools; it contains no GL call or worker enqueue.

If the Skin node's face count at `+0xb8` is positive, the generator visits each face and its three corners. It selects indexed position, normal, optional texture coordinates, color, tangent and mirror data from the postprocess geometry at node `+0x278`, then allocates a `0x6c`-byte base `NodeVertex` candidate through constructor `0x1400aaa90` at `0x1400df3d9`. The face's authored weight index selects a 72-byte `SkinVertexWeight` from node `+0x2c8/+0x2d0`; an out-of-range index selects a zero-count local record. The candidate is compared against the prior generated `NodeVertex` list at postprocess `+0x90/+0x98` from its first element for each corner. The base comparison `NodeVertex::operator==` `0x1400ab270` at `0x1400df4a1` must pass before `SkinVertexWeight::operator==` `0x14008a4a0` at `0x1400df4bb` is called (base comparison REA `ev_44c76004558ff07dea1e4705530f6b4a03d5bfb661897019aca9a49e78c4cee5`; weight comparison REA `ev_77f9ce55053a27e5003e6a208d03fdcfc7bb2fd316a38e603132bbe1b39f9ec0`).

The weight comparator first requires the same entry count. For each of up to four entries, if the compared name pointers are non-null it uses case-insensitive `_stricmp`; when both names are null it compares the corresponding integer and float fields exactly. This describes the observed branches, not a semantic guarantee that all weight fields are compared on every named-entry route. A match frees the new NodeVertex and writes the old 16-bit index to the face. A miss grows the generated pointer list when needed, appends the candidate, and copies the weight record into a temporary deduplicated list. After all corners, that list replaces the node's `+0x2c8/+0x2d0` weight array. The caller then builds/fills the Skin index and weight pools as mapped in [text Skin and AnimMesh](model-text-skin-animmesh.md) and [model instance ownership](model-instance-branch.md).

This is a linear prior-vertex scan per face corner. Actual count, comparisons, weight naming, dedup outcomes, pool admission and execution time depend on authored content and runtime state. The decompiler's handling of invalid weight indices, allocation failures and 16-bit index overflow is not a correctness proof for malformed assets. No OS-thread identity is established by these static call edges.
