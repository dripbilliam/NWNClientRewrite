This is original-binary render-flow evidence; [the emitter render branch](original-particle-effect-render.md) and [alpha publication](original-particle-effect-alpha-publication.md) contain the shared descendants.

## Installed callbacks and ownership

The model-instanced `PartEmitter` owns the source `MdlNodeEmitter*` at `+0x8`, owner Gob at `+0x50`, live particle list at `+0x188/+0x190`, movement callback at `+0x170`, and render callback at `+0x1b0`. `PartEmitter::Initialize` `0x140061d80` stores `RenderStandard` `0x1400643b0` at `0x140061dc2`. The source's mode string at `MdlNodeEmitter+0xd8` sets mode `PartEmitter+0x1a8`: `Normal` gives `0`; world/local Z billboard gives `2/1`; `Linked` gives `3` and installs `RenderLinked` `0x140064170` at `0x140061ed8`; world Z/direction alignment gives `4/5`; `Motion_Blur` gives `6` and installs `RenderMotionBlurred` `0x140064180` at the same store. A nonempty authored source name at `MdlNodeEmitter+0x158` overrides any of these callbacks with `RenderNothing` `0x140064190` at `0x140061ef8`, while retaining the selected mode integer. The binary string bytes independently confirm `Normal`, `Linked`, and `Motion_Blur`. Lightning's subtype `Initialize` `0x140061d30` first calls the base initializer, then registers `_EmitterTarget` and clears `+0x1cc`; it does not replace the selected render callback. Evidence base `ev_8196177995dbdc99839bcacb411d86473a8f877c6bf8291aea000762832be32d`, Lightning `ev_32c154425f1ffedf227096ba7da18069f58e6b2e96e53a8a790e61f6f4175f34`, strings `ev_1c3171f5e68e57d72aad5006188359dad7525dbc6b06ac75e494555163a55b94`, `ev_3bea47d6f74107906335bb780c2f3303f05353d4cb5965635c9429c4d00490f9`, `ev_5a737d404673dbff038534abad44685d7ea95cd7fbd508d57eea6c1b817e90ed`.

`Scene::DoEmitterBucket` `0x1400c7ae0` inherits its caller's render thread. It calls `AnimateParticles` at `0x1400c7c94` only if Scene `IsAnimating` or owner Gob `IsForceAnimated`; `AnimateParticles` first rejects fading tile owners or emitter TileData, clamps `DeltaT` to `0.5`, derives the emitter world transform through Part `GetWorld`, then calls its constructor-backed subtype virtual `+0x100` (Fountain/Explosion/Single/Lightning). The Scene queues only emitters with positive live count, sorts them by squared camera distance, and invokes the installed `+0x1b0` callback at `0x1400c7dae`. These steps are sequential on the inherited render caller; authored subtype and live population are runtime variables. Evidence Scene `ev_b4881207528882fb849869474dcd3a31c18cf9f00dad89280e126d85fcdd7ed3`, animation `ev_ff99575ef698342f5a24d5144b760ebffc363ceb850792f77cdda4b6fe686c88`.

## Callback gates to CPU stream and GL

The Standard, MotionBlurred and Linked entrypoints are five-byte `E9` jump thunks to one `RenderEmitter` body `0x140062900` (original bytes `ev_681feccd88d02cf04b957162b976ae02e8306e07b43bec79ef80ad5caf603617`, `ev_bcca2568bb5ee70d06e02dc1323b377f516835862fac7256d1ac78410564b4f7`, `ev_6647d87f4b1ba1472f8148382f4e806b1f6dbcb56cd72d5ae323552ee414d466`; shared body `ev_34f8fbdda88642e9a5fcc853ff16fcb539af3e4923e97fbbca235e05c24b6605`). The body returns if the owner Gob's or emitter's TileData fade is below `1`, effective live count is zero, or emitter `+0xac` is zero. Linked mode uses `live−1` as its effective quad count, so one live particle is insufficient. Otherwise it may draw an optional diagnostic sphere, binds the emitter Material's textures at `0x140062adc`, chooses geometry using mode `+0x1a8`, applies depth/cull/blend state, and obtains a shared vertex stream sized for six vertices per effective particle. Mode `6` uses current and previous particle positions for motion blur; mode `3` uses consecutive particles for linked segments; the other modes use camera, world or emitter orientation, including mode `5` particle direction. The current TileData fade, owner color alpha, emitter lifetime alpha, tint/light, and atlas state feed packed 0x18-byte vertex records. Stream commit is at `0x140063ff5`; a missing shader program can still cause a return after this publication. The program is selected by blend mode and is cached in two globals after success. With a program, the function sets a shader parameter, binds it and any authored override, then calls `RenderInterface::RenderVertexStreamData` at `0x140064109` with `6*effective_live` vertices. That forwarding thunk reaches `GLRender::RenderVertexStreamData` `0x1400b5c20`, which sets VAO/program and conditionally calls imported `glDrawArrays` for the nonindexed stream (or `glDrawElements` if the stream carries an index buffer). The particle stream is created without an index buffer. Evidence shared body `ev_34f8fbdda88642e9a5fcc853ff16fcb539af3e4923e97fbbca235e05c24b6605`, forwarding `ev_eebcfb2e63d9940d0fdf01c2de8150cfcda589fde0e7d844a8be9b3a26969efb`, GL body `ev_f07bc8ffc5b8e28cb307462a960e15bf144503071ed421fe7b86612de920e47a`.

`RenderNothing` is a distinct body `0x140064190`. Its owner/tile fade gate suppresses work when either present TileData fade is below `1`; after admission it may draw a diagnostic sphere and, for each live particle with an attached Gob at `Particle+0x78`, calls Gob `SetPosition` at `0x140064297`. If emitter rotation `+0xbc` is nonzero and particle `+0x70` is not frozen, it also computes orientation and calls Gob `SetOrientation` at `0x140064346`. It does not create a particle vertex stream or call the particle GL draw. The attached Gob can later draw through Scene Gob/Part geometry after visibility and alpha gates; that route is linked in [particle rendering](original-particle-effect-render.md). Evidence `ev_a979c6b8cb98277a05bdc0540623d05e97d8b4723e7f04ef580861ffec728692`.

## Concrete per-frame Fountain spawn route

The factory installs the Fountain vtable; `AnimateParticles` virtual `+0x100` reaches `FountainEmitter::Update` `0x140064b30` when that subtype is installed. Update first ages/recycles live particles through `chkParticleLife` at `0x140064bd9`, updates previous particle positions in motion-blur mode `6`, advances live rotation, then invokes the per-instance movement callback `+0x170` at `0x140064cfa`. `Initialize` installs standard movement `0x140068010` by default; authored point-to-point flags at source `+0x174` select gravity `0x140067340` or Bezier `0x140066940`. Those callbacks can read Scene wind and perform Scene hit checks; they do not directly draw. Evidence Fountain `ev_8d49308bf3baade8551d571633fd403d485118bc9ddd9dc8cfd63cefb1b6e0cd`, callback installation `ev_8196177995dbdc99839bcacb411d86473a8f877c6bf8291aea000762832be32d`, standard `ev_7c630023378e591cda230f87e596ba613221990de48110da8fdb2128af6f4250`, gravity `ev_b89e0d72211d9d4e7768aea5eb40b92047d0ba7f139060c126976ba339a67256`, Bezier `ev_b8b1a4445d7a5d341b2fa52cb291ba35f6da9c9265fd6978da973a9f9d0696e7`.

For a positive effective emission rate `+0x74`, authored source `+0xb4==0` selects time accumulation in `PartEmitter+0x198`; once the reciprocal-rate threshold is met, the body emits its computed integer/modulo count and resets the accumulator. A nonzero source `+0xb4` selects traveled-distance emission: the body combines current/previous emitter pose and carry at `+0x164..+0x16c`, computes `int(distance*rate)` when enabled, distributes new particle positions along the traversed segment and retains residual distance. Each branch takes an expired particle from reuse list `+0x130/+0x138` if present; otherwise it allocates `Particle` at `0x140064ebb/0x1400651c9`, or, when authored model name `+0x158` is nonempty, `ChunkyParticle` at `0x140064e90/0x14006519b`. Newly allocated and reused particles receive virtual `+0x10=Particle::initialize` `0x140066450` or `ChunkyParticle::initialize` `0x1400663d0` (constructor-backed vtables `0x140d843c0/0x140d843e0`). Both constructors already call base `Particle::initialize` before this Fountain virtual call; the Chunky constructor also creates and attaches its model Gob between those calls. They are appended to live list `+0x188/+0x190`, then `chkRandom` may choose an authored atlas frame. Chunky construction can create and attach a separate model Gob, as documented in [particle lifecycle](original-particle-effect-lifecycle.md). This path is CPU particle state publication, followed by the Scene render callback above; neither update branch calls GL directly. Authoring, count, reuse availability and runtime mode remain open. Evidence Fountain `ev_8d49308bf3baade8551d571633fd403d485118bc9ddd9dc8cfd63cefb1b6e0cd`, Particle constructor `ev_f4f36fcb70d25790540d91bfa65ddaa2576429752eca6b2df001b3d7b1f06b41`, Chunky constructor `ev_a835c7c30c035c6d53c1f634d31e77e7825f252efc92bccc6a08a310d2e47917`, vtable slots `ev_a3c053cb861ec7f9899ded886084e4ee1c600427ee02902776ebde83727637d4`, `ev_f903d3a8193a42303801924f58f209a188b9db72fc0addf7e123ea1251eed2c3`.

The four callback choices and Fountain branches are statically bounded here. This does not prove which original assets install each mode or how often any path executes; those are runtime population questions. Shader, texture, geometry and GL descendants shared with other passes are linked rather than reclassified as emitter-only work.
