# NWN-75: tile AABB Part to conditional scene draw

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This closes the tile-specific connector that was absent between the authored `MdlNodeAABB` / `PartAABB` map and the visible-BSP debug draw map. Exact sites and evidence IDs are in `scene-aabb-tile-bsp-draw-connector-ledger.json`. It does not assert that a particular tile contains an AABB Part or that the debug flag is enabled at runtime.

## Instance and tile admission

`Scene::SpawnTile` `0x1400d41a0` first resolves a Model. In its direct-instance branch it calls `CreateInstanceTree` `0x14008da70` at `0x1400d43a6` and `PartInitMaterial` at `0x1400d43ed`; the alternative named `a` node branch calls `NewCAurObject` and uses its root Part. `MdlNodeAABBCreateInstance` `0x140092250`, reached by the model-node virtual instance slot, installs the `PartAABB` primary table `0x140d888d0`, as mapped in [model AABB payload](model-aabb-payload.md). `SpawnTile` passes the Part root to `CollapsePartTree` `0x1400c5b60` at `0x1400d4457`. The latter computes world transforms and appends root and accepted descendants to its Part list; a Gob-owned special `a` node is excluded from that collapsed list and restored to the Gob. Thus the Part list is conditional on the model and branch, not a claim that every authored AABB reaches the tile list. Evidence: `ev_0cdf2929555a1f88661105867841e26d91aadf548ff94fea7b7b57e660b9f172`, `ev_b01ee4552660b92d0906e3a7b02fb4cbfeefa77f7f3fb94f4bb68408237e1eac`.

`SpawnTile` calls `ProcessStaticParts` `0x1400cb520` at `0x1400d451c` before BSP insertion. For an AABB Part, its `+0x58=AsPartTriMesh` slot at table address `0x140d88928` points to the self-returning `0x14008c4e0`. The function assigns TileData to the TriMesh Part, computes its bounding box and uses the model node's `+0x224` classification. Class `2` moves the Part to TileData `+0x90` and class `4` to `+0xb0`; both remove it from the residual Part list. Other classes remain in that list only with positive face count `+0xb8` and vertex count `+0x284`; otherwise the function removes and destroys the Part. `SpawnTile` may additionally call `CombineParts` for an eligible Model, so precise post-combine subtype identity and runtime AABB occupancy are data dependent. The `ProcessTilePart` return value controls a separate non-TriMesh branch and does not bypass this TriMesh filter. Evidence: `ev_37fb30c927647447004135ecdb127d880eb9d31c04a25f9f871c9c9dc4792731`, `ev_9343e471dd968ef7264c21562e1dcdf52205b023f4fbe64794150d5ffd6a698f`, table bytes `ev_b09e178bc9daf999e8862612692449f9cee2d9ad90b5445eafe57e7af2f89f9e`.

`SpawnTile` passes the residual list and TileData to `SceneBSPAddTileData` `0x1400dd340` at `0x1400d474b`. With a nonnull Scene BSP, the function stores TileData at fitted node payload `+0x98`, loops the list and tests each Part's `+0x48=AsPartLight` before `+0x90=AsPartAABB`. The latter call at `0x1400dd44f` resolves to `PartAABB::AsPartAABB` `0x14008c3c0` for table `0x140d888d0`. A positive result fits the Part world position with radius zero at `0x1400dd46b` and **overwrites the single AABB pointer** at the fitted node payload `+0x90` at `0x1400dd474`; it does not append to the ordinary TriMesh list. When the Part's Model pointer is nonnull, `Model::AddRef` runs at `0x1400dd6f1`. The precise number of AABB Parts per tile and overwrite frequency are unmeasured. Evidence: `ev_4ab185511a1832552f2aab60acf7a36d2dfd7188a71056b6fc7eb5b2967e83c2`, exact subtype bytes `ev_31ddbc6d2651b90a06782f57813672b9a583806babf130919aa52fc043bebee8`.

## Frame and teardown

`ManageSceneBSP` supplies visible-node callback `FUN_1400dc140`. With a payload AABB pointer and current Scene `+0x1e0` enabled, the callback calls `AddPartToMeshBuckets` `0x1400d76e0` at `0x1400dc1c5`; when that flag is absent, it calls `ProcessTriMeshParts` for the ordinary TriMesh list instead. `AddPartToMeshBuckets` keys by material texture TID and appends the Part to `_meshbuckets` and `_meshshadowbucket`. The later `Scene::AddPartsToDrawBuckets` walk of `_meshbuckets` applies renderability, material, fade and bucket-classification gates before `DrawBucketManager::AddPartToBucket`. A surviving draw item reaches `Scene::RenderDrawBucket` Part virtual `+0xc8` at `0x1400cd8d1`; `PartAABB` table `+0xc8` is `PartAABB::Draw` `0x1400a1c70`. Its own current-Scene/`+0x1e0` check and mesh/face checks precede the paired vertex-stream GL draws. Existing [visible callback](scene-bsp-visible-callback.md), [bucket classification](bucket-classification.md) and [Part draw](part-draw-subclasses.md) maps cover those downstream bodies. The connector is conditional throughout; it is not a measured per-frame cost. Evidence: `ev_901383e0bdf24fe1d003abad9331df48ef421084ca94a06c5f73821df1e1e22b`, `ev_ec8551f3642f9e5fbbbb270937191abd6492e31acb4a055b9f77fdb1a2d16e32`, table bytes `ev_55b779e3f9c637171dc184003d18e65ea6fe5d3edaa0e0b5357aace52b0c0b2a`.

The Scene constructor sets `+0x1e0` to zero. `Scene::SetRenderAABB` `0x1400d3570` is the direct flag writer and primary Scene vtable slot at `0x140d8deb0`; REA reports no direct code caller. A virtual or external caller is therefore an explicit unresolved boundary. `Scene::DeleteTile` calls `SceneBSPRemoveTiledata` `0x1400ddc50` at `0x1400c7549`; that helper iterates TileData's surviving Part list, calls `SceneBSPRemovePart` at `0x1400ddcb8`, decrements nonnull Model refs, destroys Parts, destroys TileData and clears node payload `+0x98`. The AABB removal branch searches for the exact pointer and clears node payload `+0x90` only when it matches. The lifecycle of Parts diverted to TileData class `2` or `4` is outside this connector.
