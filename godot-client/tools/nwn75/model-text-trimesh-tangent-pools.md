# Text TriMesh tangent-basis and pool continuation

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. The [ledger](model-text-trimesh-tangent-pools-ledger.json) records exact callsites in `MdlNodeTriMesh::CalculateTangentSpaceBasis` `0x1400a6130` (REA `ev_87247071bebad3fd75fd90786ee5d63457a8792ff09c56e65f74c19edcc93043`). [Text TriMesh postprocess](model-text-trimesh-neighbor-indices.md) calls it at `0x1400a9b51` after index and vertex-data construction when face count is positive; it can also be reached from subtype postprocess. This is model-construction work with conditional resource and pool descendants, not an unconditional frame draw.

The function starts only when tangent pool handle `+0x2ac` is `0xffffffff`. It uses node render hint `+0x120` when nonzero. With a zero hint, it returns if one-shot lookup flag `+0x2c4` is already set; otherwise it gets the node material name, calls `SharedMaterial::GetSharedMaterial` `0x140083340` at `0x1400a61b3`, uses the shared material's hint `+0x14` when found (otherwise 1), and sets that flag. It proceeds only for hint 2 or 3, valid position `+0x280`, UV `+0x288` and normal `+0x298` pool handles, primitive mode `+0x270==3`, positive vertex count `+0x284`, and a positive first index-list count from `+0x248`. The checked first index-pool handle comes from `+0x258`. This gate links the `renderhint` and material-name source to tangent pool work.

`GetSharedMaterial` (REA `ev_3312dbef7fe0318db10e061df5d78fd92db41fdae304074e036c412c18f977a7`) returns null for an empty name, checks the shared-material table, and on a miss calls `AurResGet(name, ".mtr", ..., true)` at `0x1400833cd`. With data, it allocates a `0x200`-byte SharedMaterial, parses resource lines through `AurResGetNextLine`/`SharedMaterial::ParseField`, frees the resource, initializes the material and inserts it into the shared table. Thus the first tangent calculation can include a conditional synchronous resource lookup/parse. The provider behind `AurResGet` is mapped in [model instance](model-instance-branch.md), with source-kind archive/manifest descendants in the resource ledgers. The installed cache, authored material and active caller determine whether this branch executes.

On the admitted path, `CalculateTangentSpaceBasis` locks the first 16-bit index pool, requests two kind-0 pools at node `+0x2ac` (12 bytes per vertex tangent) and `+0x2b4` (four bytes per vertex sign), then locks position, UV and normal pools. It computes per-triangle tangent data and handedness from UV deltas, using a normal-derived fallback when the UV determinant is zero. It stages reusable CPU arrays and may split vertices when one vertex needs incompatible handedness. If splits are positive, it increases the 16-bit vertex count, resizes/relocks the five base/tangent/sign pools, copies source vertex attributes for each duplicate and rewrites affected 16-bit indices. Optional present color/UV/other attribute pools at `+0x28c/+0x290/+0x294/+0x29c` are likewise resized/copied. For a DanglyMesh it duplicates constraint entries; for a Skin it duplicates `0x48`-byte weight records and, when present, resizes/copies its two skin pools. It then orthogonalizes and normalizes tangents against normals. The function unlocks all admitted pools. Those unlocks enter the conditional shared pool-to-GL publication boundary in [geometry](geometry-and-draw-boundary.md). The function contains two `RequestPool`, 17 `LockPool`, 11 `ResizePool`, and 12 `UnlockPool` *static callsites*; the ledger lists every site, while branch gates mean a given invocation can execute only a subset. This is neither a runtime count nor evidence of repeated frame work.

The observed CPU data ownership is node pools and subtype lists plus reusable scratch arrays initialized under CRT thread guards. The caller's later position-pool scalar scan and temporary-array cleanup are in the [postprocess tail](model-text-trimesh-postprocess-tail.md). The shown body has no worker enqueue. Static analysis cannot establish its invoking OS thread, which material/cache path is active, how many vertices split, pool state, or whether a later Scene draw occurs.
