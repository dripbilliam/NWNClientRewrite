# NWN-75: original texture-controller runtime branch

Original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. The `.txi` [controller parser and registration](texture-controller-parser-registration.md) selects five of the six compiled controller tables; the [build-time `Init` dispatch](texture-controller-build-init.md) is separate from the draw-time `Control` route followed here. Static calls inherit the render caller's thread. No worker dispatch appears in these controller bodies.

Before the scene's texture use, `Scene::Render` calls `AurTextureMakeCurrent` `0x1400e8be0`. If `g_bIsSuspended` is false it resets construct/decode/GL image timers; unchanged anisotropy plus a nonempty pending texture count calls `AurTextureBuildAndStoreAll` `0x1400e6910`, while a changed anisotropy setting calls `AurTextureRefreshAll` `0x1400e8eb0`. It increments `texcurrentframe` on every invocation. The body has an optional connected-Tracy scope; neither texture build nor refresh is unconditional. REA `ev_7710c198e332b386a70fa12ca95cdef641f7a310f8160ac8e8b6899f5d354733`. The recursive build/refresh descendants remain open.

`Scene::Render` also lazily obtains the fallback environment map through `AurTextureGetFallbackEnvironmentMap` `0x1400e88e0`: only a null cached pointer enters `AurTextureGet("chrome1", ...)`, followed by reference-list maintenance, then stores the pointer for later calls (REA `ev_8eceedf95827aae15e846bb5dc82b5e04394ace3f135820132f5513101864a65`). `AurTextureGetReference` `0x1400e8b60` calls `AurTextureGet` twice, first for the named texture and then to wrap that result as a reference (REA `ev_75368d94af22e27b50b2177d95fe61232ce2fad1041ccdff4e4806e4f84764d8`). Their lookup, allocation and queue branches are in [texture acquisition](texture-acquisition.md); neither is a direct draw call.

`Material::LoadTextures` stores texture references in a `Material`. At draw time, the scene material route calls `CAurTexture::BindInUnit` `0x1400ea490`, which resolves a Basic texture, handles null/disabled texture cases, optionally calls Basic virtual `+0xe0=CAurTexture::IncrementTIDIndex` `0x1400ebd90` when an index argument is supplied, tests whether the texture is active, obtains its TID and binds it through `AurTextureBindTIDInUnit` `0x1400e6870`. It then retrieves the Basic texture's controller field `+0x38`. If nonnull and global `enabletexturecontrollers` is set, instruction `0x1400ea543` is a tail jump through controller vtable `+0x8=Control`; otherwise it returns. Thus controller CPU work and possible texture publication occur inside the texture bind branch, after the TID bind in this function. Evidence: REA `ev_e0255c509221b93994478aaab1e314d204ac1315f09e928262409ec4c80db5b5`; original instruction `JMP qword ptr [RAX + 0x8]` at `0x1400ea543`.

Six compiled controller vtables establish possible `+0x8` targets. The parser proves installation of the first five; Water requires an unproved producer:

| Controller table | Vtable | `Control` target | Admission and output observed in original body |
| --- | --- | --- | --- |
| Life | `0x140d90bf8` | `0x1400e1520` | Enabled and at least five `texcurrentframe` ticks since its last update; computes a neighborhood cellular image and calls Basic `+0xe8` to publish pixels. |
| Perlin | `0x140d90c30` | `0x1400e1890` | Enabled, once per texture frame; advances/interpolates Perlin images with `DeltaT`, converts a height channel when needed, then calls Basic `+0xe8`. |
| Arturo | `0x140d90580` | `0x1400e1100` | Enabled, `bindzero==0`, and accumulated `DeltaT` exceeds 0.03; frame guard then interpolates a generated image and calls Basic `+0xe8`. |
| Wave | `0x140d90548` | `0x1400e2720` | Enabled, once per texture frame; evolves a wave field, converts output when required and calls Basic `+0xe8`. |
| CycleTID | `0x140d905c0` | `0x1400e1470` | Enabled, once per texture frame; when accumulated time exceeds `1/frequency`, advances an index modulo texture grid dimensions and calls Basic `+0xe0`. |
| Water | `0x140d90510` | `0x1400e1b40` | Enabled, once per texture frame, with an additional every-other-update gate; evolves/blur-filters water image and calls Basic `+0xe8`. |

`CAurTextureBasic::ParseField` `0x1400ecf20` allocates Life and Perlin inline and directly calls Arturo, Wave and CycleTID constructors. It does not compare `water` or call the Water constructor. That constructor installs its table in compiled code but has no proved direct code caller. The original PE `+0x8` pointer values match the six `Control` addresses; see the [parser registration proof](texture-controller-parser-registration.md) for selector and callsite evidence.

Basic vtable `0x140d90d90` has `+0xe0=CAurTexture::IncrementTIDIndex` `0x1400ebd90` and `+0xe8=CAurTexture::glImage` `0x1400ee130`. The former writes the selected TID from the Basic texture's index table. The latter forwards generated pixel data to `CAurTextureBasic::glImageBasic` `0x1400ee1b0`, whose texture-creation/upload OpenGL descendants are mapped in `gui-presentation.md`. The controller bodies read Basic texture dimensions through virtual `+0x70/+0x78/+0x80` and use `texcurrentframe`/`DeltaT` gates as listed. Evidence: REA `ev_eddc90ee`, `ev_b2e85194`, `ev_6160db4e`, `ev_b69cdaa8`, `ev_8b379a46`, `ev_a6d2ab66`, `ev_725da3a7`, `ev_25fb5c6b`, original PE vtable bytes.

The branch ledger resolves 32 computed calls inside the six `Control` bodies against the original controller and Basic vtables. Besides the pixel publication and TID increment calls, these include Basic width, height, BPP, image, grid size and free-image getters, and controller `+0x28=TextureController::Distort` `0x1400e2c00` plus subtype `+0x30` image builders (`Arturo` `0x1400e0ce0`, `Perlin` `0x1400e0fa0`). These targets are recorded as identified descendants, not terminal boundaries; the image and distortion algorithms still require traversal. The 32 callsite rows are reproducible in `.cache/nwn75/append-controller-virtuals.ps1`; the ledger deduplicates eight previously recorded rows.

The shared `Distort` routine asks the Basic texture for BPP, width and height, grows a process-global scratch image when needed, then copies pixels from wrapped coordinates. Its two modes use either the input byte as a linear displacement or sine/cosine lookup values as angular displacement. It returns the scratch image to the caller, which may pass it through `Height2Channel` and then `glImage`. `Height2Channel` again reads the Basic dimensions/BPP and allocates a converted image; its CPU loop applies controller channel coefficients. The original callsites and helper edges are in the ledger. `Distort` REA `ev_29318373`; `Height2Channel` REA `ev_4d60eb50`; sine/cosine REA `ev_0f96a08d`/`ev_0bad006a`.

Arturo's `BuildArturoImage` `0x1400e0ce0` updates a wrapped neighbor field, injects CRT random variation at a selected coordinate and rotates three image buffers with copy helpers. Perlin's `BuildPerlinImage` `0x1400e0fa0` allocates octave images through `ImageBuildPerlin` `0x140071020`, samples each destination pixel through `ImageGetPerlinPixel` `0x140071dc0`, then frees the temporary octave buffers. `ImageBuildPerlin` draws from the CRT per-thread random state; `ImageGetPerlinPixel` interpolates octave values with `floorf`. The random helper at `0x140c7ed00` advances a CRT thread-local linear-congruential state and reaches `GetLastError`/`SetLastError` plus FLS setup on first use via `0x140ca98a0`. This establishes a per-thread state dependency inside the original image builders, without showing a separate controller worker. Evidence: REA `ev_57a0332b`, `ev_c46959c9`, `ev_7878eebb`, `ev_b34c5bc5`, `ev_95cdd088`, `ev_b8345eec`.

Life allocates/copies its cellular state and a temporary output image before `glImage`, then frees the output. Arturo and Perlin use `TextureController::Height2Channel` when their selected channel format requires it; Wave and Water also call it. Water additionally calls `ImageLowpassBlur` `0x140072510`; Arturo calls pure-arithmetic `FloatInterpolate` `0x1400e2f30`. These direct-call sites are now recorded in the branch ledger. The Water blur and Perlin/Arturo builder descendants are traced to CPU/CRT boundaries in [Water blur](texture-water-blur-leaf.md) and [controller image builders](texture-controller-image-builders.md). Evidence: REA `ev_66435409`, `ev_b47a2e35`, `ev_19551abd`, `ev_dfe1b008`, `ev_d8e4558a`, `ev_06ac2a72`.

The [image-transform continuation](texture-controller-distort-channel.md) follows `Distort`/`Height2Channel` through CPU/CRT boundaries, while [controller lifetime](texture-controller-lifetime.md) follows subtype state release on Basic texture destruction. Open boundaries include deeper CRT/math internals and exact dynamic frequency of each controller type in a live scene. The control family and its texture publication targets are address-backed; authored/runtime selection remains conditional.
