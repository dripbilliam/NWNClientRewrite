# NWN-75 native resource-key selection and object ownership

Pinned installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This is the resource-name/key selection stage before [resource demand](texture-resource-demand.md), with a concrete PLT texture constructor. It neither parses image bytes nor submits a draw.

`CAuroraLayeredTexture::CAuroraLayeredTexture` `0x1400f4040` requests resource type 6 through `CExoResMan::GetResObject` `0x140190840` at `0x1400f414b`. The general `CResHelper<CResPLT,6>::SetResRef` `0x1400f44e0` also calls it at `0x1400f45b5` when the nonempty name changes. `GetResObject` calls `GetKeyEntry` `0x14018ffb0`; an existing `CKeyTableEntry+0x18` `CRes` pointer is returned with its separate object-reference counter `CRes+0x34` incremented. A missing key or key without an instantiated resource returns null. The constructor or helper allocates a `CResPLT` and calls `SetResObject` `0x140194470` only for that null case. `SetResObject` resolves the key again, writes the new object to entry `+0x18` if empty, sets the object's entry pointer `+0x28`, object-reference count `+0x34` to 1 and copies key metadata into `CRes+0xc..+0x18`; an already populated entry is logged instead of replaced. `CRes::Demand` later obtains source bytes, and the [cache-lifetime continuation](resource-cache-reclamation.md) covers demand-count `+0x8` and buffer ownership. These counters and stages are distinct. `GetKeyEntry` first calls `GetOverride` `0x140190470` to resolve an optional resource-name override keyed by a lowercase `resref.extension` string. It then visits the manager's key-table pointer array `+0x18` in array order for `+0x20` table entries, skipping tables flagged inactive at `table+4`; the first `CExoKeyTable::FindKey` `0x14018ad70` match wins and publishes both the table and entry. A miss returns both outputs null; an optional reporting gate records the failed name/type, with exclusions for types `0x7e6`, `0x818` and `0x81e`. `FindKey` rejects an empty name or empty table, obtains a hash bucket from `CExoKeyTable::Hash` `0x14018b350`, then linearly probes `0x38`-byte entries with wraparound. Each candidate compares the resref and two-byte resource type; an empty slot or a full wrap is a miss. `Hash` folds up to 16 lowercased name bytes using the installed CRC32 table with resource type in each byte step and divides by table slot count. These are per-lookup CPU operations; their frame frequency depends on caller/cache state. The table-array order is produced by `CExoResMan::AddKeyTable` `0x14018e330`: after a successful `CExoKeyTable::BuildNewTable`, it inserts the new table before the first existing table with a lower numeric priority at `table+0x48`. Within the same million-wide priority band, it advances the new priority above conflicting existing values. `CExoResMan::SetupDefaultSearchPath` `0x1401947b0` is called by client initialization `0x1406e3c80` at `0x1406e4126`. Its direct default-table calls include `TEMPCLIENT:` priority 99,000,000 when client mode is below 2; `OVERRIDE:` 12,000,000; `OVERRIDELOCINSTALL:` 10,000,000; `HD0INSTALL:data/nwn_base_loc` 3,000,000; `nwn_retail` 2,000,000; and `nwn_base` 1,000,000. `SOURCEOVERRIDE:` at 11,000,000 is gated by `g_bRunningFromSources`; INI patch-list entries add `PATCH:` at 13,000,000 and `PATCHINSTALL:` at 5,000,000 when configured. Other vault, portrait, music, ambient and development tables also enter this array under their own gates. This establishes the installed default priority mechanism, not the complete runtime table list: modules, manifests, dynamic registrations and failed builds may change occupancy. When the PLT helper switches away from a prior nonempty name, it releases the old resource demand and calls `CExoResMan::ReleaseResObject` `0x140191380` at `0x1400f454f`. That decrements object-reference count when above one; on the final object reference with zero demands it may put the resource on the same pending-free list (unless already queued or an explicit caller flag returns early). It logs an attempted release with active demands. The queue, resource subtype freed hook and CPU buffer reclamation are in [cache lifetime](resource-cache-reclamation.md). **Boundary:** actual override entries, key-table ordering/content, resource type and whether an object or bytes are resident are runtime/asset choices. The constructed PLT path is one of many `GetResObject` direct callers; the source-class service and eventual GL image publication are linked from the existing resource and texture ledgers.
