# Text model controller key builders

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. The [ledger](model-text-controller-builders-ledger.json) continues the shared [base node](model-text-base-node-fields.md) and [TriMesh alpha/self-illumination](model-text-trimesh-fields.md) controller fields to their resource and CPU storage leaves. These builder functions are parse-time operations, not per-frame interpolation.

`AddGenericControllerSingle` `0x140098790` parses one `AurGenericKey` through `Parse` `0x1400a06a0`, appends a zero time and its parsed components to the node float list, then appends a 12-byte `NewController` descriptor with the passed destination offset to the controller list. Both arrays grow through `_realloc_base` as needed. When four components were parsed, it converts the first three plus the fourth angle into a normalized-axis quaternion, using Vector normalize, sine and cosine helpers. REA builder `ev_86839b288f0b74e74e6b21f739ed01cf9e0e6c9fa2ac21187af8dcf5b7365639`, element parser `ev_0e2b5f15bd3bca886922b0620b0dc040d52e4a3f40ec35f66dd6aae4f7988705`.

`AddGenericController` `0x140098570` and `AddBezierController` `0x140098340` first parse a temporary `AurGenericKey` list through `Parse<AurGenericKey>` `0x140096fa0`. They append key times and component words into the node float list and append a `NewController` descriptor to the controller list, growing both arrays as needed; Bezier sets its Bezier flag and derives its component layout from the parsed item count. They free the temporary list before return. REA generic `ev_d2f0d03bb59b9d52cd6f8c87421cfcd25a1753f6225e95e05dfbd4c8ce99c776`, Bezier `ev_15c3b1f86e79285af5a27e003837212c640fc1b1f9f51329f28703f1880bbb39`.

`Parse<AurGenericKey>` supports no-count lines through a trimmed `endlist`, a count with that many nonblank text lines, or a count plus marker with `0x2c × count` raw bytes through `AurResGetData` `0x14005de20`. Text lines arrive from `AurResGetNextLine` `0x14005dff0` and each is parsed into a 0x2c-byte key. The element parser scans up to ten floats, records the number parsed at key `+0x28`, and for exactly five floats converts an axis-angle input into a quaternion in place. Thus the text route performs CPU parsing and normalization, while the raw-data route copies serialized key bytes without calling the text element parser. REA list `ev_60cfaa7b0de7714f2c658e5ad144f79ba225322d46b90f9e0eff9ab7f5e1795a`, element `ev_0e2b5f15bd3bca886922b0620b0dc040d52e4a3f40ec35f66dd6aae4f7988705`.

These builders reach resource lines/raw-data reads, CRT allocation/copy/free and CPU math; none calls a render pool or GL API. Authored key counts, malformed input behavior, active controller selection and later animation evaluation remain conditional. Static code does not identify the invoking OS thread. Later evaluation and Part state are mapped in [non-emitter animation](original-scene-animation-nonemitter.md).
