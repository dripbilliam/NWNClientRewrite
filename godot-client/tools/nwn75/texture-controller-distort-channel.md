# NWN-75: original controller distortion and channel conversion

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This [ledger](texture-controller-distort-channel-ledger.json) closes the CPU image-transform route below [controller runtime](texture-controller-runtime.md). The original scene material bind calls controller `Control`; admitted `Control` bodies may use shared `TextureController::Distort` `0x1400e2c00` and `Height2Channel` `0x1400e3000` before their Basic `glImage` publication. The transform bodies inherit their caller's thread and contain no worker or graphics API call. Admission and publication remain in the parent map.

`Distort` obtains Basic BPP/width/height through virtual `+0x80/+0x70/+0x78`. If the required `width*height*BPP` bytes exceed process-global scratch capacity `0x14128edc4`, it frees the old pointer `0x14140b248`, allocates a larger array, and updates both globals. Otherwise it reuses the existing array. Controller `+0x18` selects a linear byte-offset mode or an angular mode. Both copy one BPP-sized source sample for each output pixel into the shared array, using wrapped coordinates. Angular mode looks up cosine and sine before copying. The routine returns the global scratch pointer. The three virtual getters and allocate/free/copy call sites are already in `branch-ledger.json`; the new ledger records the branch and terminal CPU output. REA `ev_9db7d34123e02b9613531663feb99da97cc66c010a7dd45f2a4e4193a2f855e2`.

Angular mode calls `cosineLUT` `0x14022fb10` and `sineLUT` `0x140231c20`. Each normally maps a bounded angle into a 32-entry float table. Angles outside ±2π first pass through CRT remainder helper `0x140c8f800` at `0x14022fb3c/0x140231c4c`; that helper has an exceptional-value branch into CRT math/error handling `0x140caea38` at `0x140c8fa8b`. This is a CPU math/CRT boundary, not texture upload. REA `ev_0bad006a2a268b1d60f724527245f618b5c07ede15278455a7c409c90c898888`, `ev_0f96a08def76cdfb318ef3f0e879acaea2759e7e33ddffb0377c1fad0bbbaa2c`, `ev_d206528108cc9dcd519153687969bb90083206d25ec430f84e9aa5fbb0b7d82a`.

`Height2Channel` gets Basic height/width/BPP through virtual `+0x78/+0x70/+0x80` and allocates `width*height*BPP` output bytes at `0x1400e305a`. For four-byte output, each input height byte becomes channels controlled by per-channel multipliers `this+0x28` and offsets `this+0x38`. Other positive BPP values follow a packed-nibble branch in the recovered loop. It returns the new buffer; the caller owns its eventual release. There are no other recovered calls in its complete body beyond the three getters and allocator, already listed in `branch-ledger.json`. REA `ev_466af851c99bf8863f0ad4ac32367f4cde29ca5671a4fe17bcb2bf17258a5a01`.

Runtime selectors remain controller mode/coefficients, image dimensions and format, scratch capacity/ownership, active authored controller, and actual `Control` admission. Static evidence does not establish concurrent access to the process-global scratch array or a live image format mix.
