## Frame consumer and GL boundary

`Scene::RenderSinglePass` calls `RenderPaths` `0x1400cfcb0` under the combined paths/personal-space gate; `RenderPaths` itself returns unless `renderpaths` is enabled. It stages render state and lazily gets a reusable nonindexed 32-vertex stream `(0x20,0,4)` even when Scene Gob count is zero. It scans **the full Scene Gob list** at `+0x130/+0x138`, not merely the earlier admitted draw bucket. For each Gob with positive scalar count `+0x150`, it divides by three and copies that many XYZ triplets from borrowed pointer `+0x158`. It flushes on 32 points through `CommitVertexData` `0x1400bd5d0` at `0x1400cfefa` and `RenderVertexStreamData` `0x1400beed0` at `0x1400cff10`, then seeds the next batch with the previous final point to preserve the strip. It commits/submits each positive-count Gob's remainder at `0x1400cff67/0x1400cff7d`. Primitive `2` maps through original table `0x140d8ad20` to OpenGL enum `3` (`GL_LINE_STRIP`); the nonindexed stream route reaches imported `glDrawArrays` at `0x1400b5d66`. Evidence: path body `ev_135eb54e67a0f14e4c99d0cc9f8e0685e7e88f145e7bae569ad06833fe903e74`, primitive table `ev_5593fb25f52fb07edc5e7621faf0a24eb23cd931759653bb21804778b864955a`, GL renderer `ev_faed7a96ea930f48e2170d7800f7dc1d4110c2b5267b35fe6813a21dee29899a`.

The final submission has no `point_count>=2` guard: a positive scalar count below three would submit zero vertices, and an exact 32-point multiple submits a final one-vertex remainder after reseeding. Both are ineffective line strips but still take the stream submission path. The static tree cannot establish whether such counts occur in a live area. Because collection updates only admitted Gobs while rendering scans all Scene Gobs, a stale borrowed path view on an unadmitted Gob is a possible dynamic lifecycle boundary; the analyzed path does not establish whether the Scene prevents it elsewhere.
