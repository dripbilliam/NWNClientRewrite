# Original legacy GUI registered-update descendants

Scope: installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This is an original-binary call tree, not a claim that every listed panel is active in one frame. Static callsite and table records are in [the registration census](legacy-register-update-callers.json) and [additional RTTI table candidates](legacy-gui-additional-update-vtables.json).

## List ownership and reachability

`CGuiObject::RegisterUpdate` `0x1401fb540` tests object flag `0x40`, appends the object to the GUI manager update list only when absent, and sets the flag. `UnRegisterUpdate` `0x1401fba80` removes it and clears the flag (REA `ev_7a6a19b3c84cd50e79def3015639417016ab68534519e9db6d0639d94f3ff845`, `ev_8f8f0ef310dc59147933842c0be8c5a693d4d1b9bf372b2410d40747379bb6d5`). `CGuiMan::UpdateAndRender` `0x1401f70e0` walks this list once per generation, calls each object's virtual slot `+0x58`, and unregisters on return `0x80000001` (REA `ev_e89c777fe9978d01554dbfdb34e21733672c56e4a3eb34090604337158400564`).

The exact incoming-reference census to RegisterUpdate has 267 references: 264 direct calls in 135 containing procedures, one internal branch, and two data references (REA `ev_d8e0b598f58bb00b1531799fed1dcef091ac06e012f9d6253d42dd924c3b78aa`). `CConnectServerStatusPanel` update `0x140715dd0` alone contains 58 direct callsites, commonly after changing a status text field (REA `ev_61695d4da06d6c3a1d2b813843deedc338005904d83a7fb47bd5c755f4450e1a`). Callsite count therefore cannot establish the number of live updated objects. The registration gate, panel activation and current runtime list contents remain data dependent.

The earlier [named-target table census](gui-update-vtables.json) identifies 207 primary vtables ending in five targets. A pinned PE MSVC RTTI scan found 32 further zero-offset table slots `+0x58` whose pointers lie in executable text. Thirty-one are plausible GUI/panel update targets; one `CGuiIcon` row is **rejected** because its `+0x58` points to `CArmorIcon::CreateCopyIconModel` `0x1401e3920`, an unrelated interface shape (REA `ev_eb348c28081e022e6b7be715aa6d9789f1d8b43a79efee7014f4f029e4b3e23b`). The remaining 31 are static candidates, not 31 proven registered classes or runtime invocations. Their constructor inheritance/registration and active-panel reachability are separate edges. In particular, the `CGuiAreaLoadscreen` constructor `0x140836f60` installs its table `0x140e4c0a8`, whose `+0x58` points to `0x140837a30` (REA constructor `ev_7857f863aa2e610142292f805b7df428b8813baa572e579c0aeb61478c0dbbdf`, table bytes `ev_8c23df0f88aff58d23ae9b46960895644f2aeca8f85ae87e49b0ea290d2fbbdf`).

## Posted text and event callback boundary

`StringGob::Render` `0x1400498a0` can animate and render a caller-attached `CAurObject*` via virtual `+0x28` and `+0x20`, then, when propagation is requested, invokes `Gob::DoEvent` for `propagaterender`. The attached object class and live event list are runtime dependent (REA `ev_d48d788ea591d6f4c257237674ad87a57f1a635a3748ccc946cb8771653b9b15`, `ev_454d4756647ffc9a42d34b6181f506a8b3af7b68003d37757b01d3323b3481de`). The [separate Gob callback census](original-gob-callback-census.md) identifies 26 static registration sites; `CAurBehaviorAttach` registers a `propagaterender` handler at `0x140053c9a` targeting `0x140056d80`, which may render an attached Gob. This establishes one concrete handler family but not the complete live handler set or attached model type.
