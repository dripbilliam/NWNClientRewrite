# Original ordinary TriMesh draw and GL submission

Pinned original `nwmain.exe` SHA-256: `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This is a control-flow map, not a live cost measurement. All immediate calls below have exact site-backed records in `branch-ledger.json`.

`PartTriMesh::Draw` `0x1400a24c0` returns when the Part is inactive, its model node is absent, the model's render field is zero, or both its primitive count and alternate primitive pointer are empty. The owner at Part `+0x50` selects virtual `+0xc0=PartTriMesh::Mat` at `0x1400a2512`; an ownerless Part selects `+0xf8=MatStatic` at `0x1400a251a`. It calls `MdlNode::AsMdlNodeTriMesh` at `0x1400a2524`, texture-matrix transform `+0x118` at `0x1400a252f`, then primitive `+0x30=VertexPrimitiveFlat::SetupArrays` at `0x1400a253f`. Mesh color/light fields select feature `0x11`. The material's `HasBumpyShinyMap` and `g_nEnableBumpyWater` select `RenderBumpyShiny` at `0x1400a25aa`; otherwise owner environment texture or `HasEnvMap` selects `RenderEnvironmentMapped` at `0x1400a25f6`; the remaining route calls `RenderFlat` at `0x1400a261d`. Each branch obtains primitive `+0x8=AsVertexPrimitiveFlat` and tail-jumps through Part `+0x120=RestoreTextureMatrix` after rendering (`0x1400a25bf`, `0x1400a2606`, `0x1400a262d`). This tail behavior is confirmed in the original assembly, not inferred only from decompiled control flow. REA `ev_c71ed738e7b17f5a797049dd882453cd562f5d3a00b1397cff45724ce6f182f0`.

`RenderBumpyShiny` `0x1400a4560` lazily gets the `vswater`/`fswater` custom program; if it cannot get that program, it returns before the draw. Otherwise it selects the program and calls `RenderFlat` at `0x1400a45ae`. REA `ev_5b5d099d6bcfd4ed22d0a998d4946593e540240b46461ff92361273f9b29b6d5`.

`RenderEnvironmentMapped` `0x1400a45c0` may skip environment staging when `AurTextureEnvMapDisabled` and the material texture format does not meet its two admitted format cases. Otherwise it chooses the owner's environment texture, the material's map, or the Scene environment fallback if the selected texture is null. It stages pixel shader ambient color using the Part alpha and optional owner color-shift alpha. The selected texture's virtual `IsCubeMap` decides unit `0xd` with feature `0x13` enabled, or unit `0xe` with that feature disabled; virtual `BindInUnit` performs the bind. It enables environment feature `0x12`, then calls `RenderFlat` at `0x1400a46ed`. REA `ev_5e4f1ae8af3209238519d29aab4da2fe87de0a12f8ffa3a94cfa3ebc5a7380cc`. The texture virtual targets are `CAurTexture::GetCompressionFormat` `0x1400eb7c0`, `IsCubeMap` `0x1400ec0d0`, and `BindInUnit` `0x1400ea490` in the pinned base/Basic vtables; their resource and GL descendants are mapped in [texture publication](texture-publication-per-frame.md) and [texture resource demand](texture-resource-demand.md).

Its ambient staging call at `0x1400a468c` reaches `RenderInterface::SetPixelShaderAmbientColor` `0x1400bf200`, a tail jump to `GLRender::SetPixelShaderAmbientColor` `0x1400b7990`. The GL body compares four cached components; only a changed value writes the color and increments dirty generation `DAT_1413d270c`. It has no immediate OpenGL call. [Shader uniform dirty gates](shader-uniform-dirty-gates.md) identifies that generation as the later `globalColor` publication input (`ev_4fa6e3b9170fd0a73bd5ca642540da5990f9b82f851bdac9a0192574a5d3a67a`, `ev_72d61220430a79625bef963b5c7a42ce05d325758f9084e587d0d6e93fbbe93b`).

`RenderFlat` `0x1400a4710` requires a nonnull VDO at primitive `+0x58`. It obtains the Part's render hint, sets it through RenderInterface, and may bind the Scene environment texture if feature `0x12` is off and Scene `+0x1e8` is present. A model flag can temporarily disable depth feature `5`. It queries the VDO item's element offset and size and calls `RenderInterface::RenderVertexData` at `0x1400a4815`, then restores depth feature when needed. REA `ev_d63ab790020cdd230625119645a3be9865a03bd0dd3ce29c3b8df6f9a9acd441`.

Five high-use direct children in this ordinary draw route are bounded CPU reads with no further calls or GL: `Material::HasEnvMap` `0x140083550` tests whether Material `+0x40` has a texture pointer (`ev_b8ad6bf5125708c6c5775e0df4869af159df541f68ad87c69f4271de14c80f83`); `PartTriMesh::GetRenderHint` `0x14008f800` reads the model-node and material hint fields (`ev_e677bdc7539cba01c19c74c9f7eea3ea7d381053a7533dde2fcabae7f96f6ecb`); `VertexDataObject::GetItemElementOffset` `0x1400bd810` and `GetItemElementSize` `0x1400bd820` read the indexed pair at VDO `+0x58` (`ev_8496cff2e3d13e8129ed44da01e0ab788157ccf713bdb1fdd7e2e2bfe4ad002e`, `ev_a320380f13f6eb8ef25cf05251e9c7327d939aa1268970b39af7ccdcf59f40a9`); `AurTextureEnvMapDisabled` `0x1400e7550` returns the global `CAurTextureBasic::m_bLowEndEnvMapEnabled` byte (`ev_7de6c10c840710edb6826bac5b245e15bd4c89ae13740daba1c8f07a831b6d53`). The last symbol's name and returned byte should be kept distinct from any assumed runtime setting value.

The GL draw body also reads `VertexDataObject::GetItemVertexOffset` `0x1400bd870` and `GetItemVertexSize` `0x1400bd880`. They return the indexed pair at VDO `+0x48`, with no children or GL; the parent body uses them to form the vertex range for the selected draw mode (`ev_50125fa6272906a00fe86aafd15e547dd68f3778a1b2d200e03ee1e188d37059`, `ev_a2fdd7fb1d5a1ae30e643200f555a4382e9592f2684acee7f2cf6666806f3fb4`).

The repeated primitive virtual subtype gate `VertexPrimitiveFlat::AsVertexPrimitiveFlat` `0x14008c520` returns `this` and has no children or GL. It is a bounded positive type check before the draw/texture-matrix branches (`ev_5b3dae1ce158e9aee0755a7c47468e209c9a0b0647c92d3990cb6d84a4088a9c`).

`RenderFlat`'s render-hint setter goes through `RenderInterface::SetRenderHint` `0x1400bf240`, a tail jump to `GLRender::SetRenderHint` `0x1400b7b10`, which only writes cached `m_nRenderHint` and makes no GL call. Its `IsEnabled` queries likewise tail-jump from `0x1400bee10` to `GLRender::IsEnabled` `0x1400b4200`, a bit read of `m_bEnabledStates`; that connector was already recorded. REA `ev_957b8d8b17ae9ee80aa5c90979e5b42714ad14add33d0a244be571f2d1917836`, `ev_779857a1c5eab3c11247a4f1c6f0bfb6181dc0871bd9388445e1192161b66efc`, `ev_a2a543e286b072750057a4bb1aa7603189bfe62fb7c34dfc2dfcdecd44154913`, `ev_8c0d34b70c9a7e5def2b6f37c416a71584cb0101c302cd2301fe15caebd5e679`.

`RenderInterface::RenderVertexData` `0x1400beec0` is a five-byte tail jump to `GLRender::RenderVertexData` `0x1400b59b0`. The GL body checks for a null VDO, sets the vertex data object, chooses a stock shader variant from VDO attribute bits and enabled state unless a custom program is selected, then calls `GLRender::SetProgram`. VDO mode `1` or `2` calls the loader-resolved `glDrawElementsBaseVertex` pointer `DAT_1414431f8` at `0x1400b5b35` or `0x1400b5b8e`; the other modes call imported `glDrawArrays` at `0x1400b5bcb`. Element and vertex offset/size getters run for the relevant mode and sentinel arguments. Afterward the method clears temporary enabled-state bits, custom program selection, and render hint. There is one GL draw API call per valid invocation; the VDO null branch draws nothing. REA wrapper `ev_bfd3d9699ee15a65fead46d18d80959d1535635bb391c43de834c65f39f0dbc3`, GL body `ev_8e9e440e5c5b0a364b9a6d1d9a76e16c1b4aa69d7c12cefc9a356392c92a273f`.

The immediate ordinary TriMesh chain reaches the external draw API. `VertexPrimitiveFlat::SetupArrays` and VDO attribute setup are mapped in [primitive/VDO preparation](primitive-vdo-preparation.md) and [projection-array preparation](projection-array-preparation.md); shader program, texture publication and resource-demand descendants remain separate linked branches.
