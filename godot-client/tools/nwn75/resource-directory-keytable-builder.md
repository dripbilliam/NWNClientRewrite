# NWN-75 native directory key-table builder

Pinned `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This continues a directory resource source from conditional default-path registration, [periodic storage watch](resource-periodic-storage-watch.md), or [TEMPCLIENT packet refresh](server-tempclient-resource-batch.md) through the concrete key-table entry builder. It is CPU/OS file enumeration and later resource lookup, not a draw.

`CExoKeyTable::BuildNewTable` `0x14018a690` copies its alias/path and resolves an alias path. For builder kind `2`, it stores priority at `+0x48`, kind `2` at `+0x20`, then calls `AddDirectoryContents` `0x140188450` at `0x14018a7bd`. Kinds `1`, `3` and `5` instead enter the separately mapped KEY, encapsulated archive and NWSync manifest providers. `AddDirectoryContents` calls `CExoBase::GetDirectoryAndWorkshopList` `0x140115080` at `0x1401884fc` with extension selector `0xffff`, allocates a hash table with `2 * returnedCount + 1` slots, then visits each returned name. `GetDirectoryAndWorkshopList` resolves the alias and calls `CExoBaseInternal::GetDirectoryList` `0x14015fa40` for the local directory at `0x140115193`. If `g_pSteam` exists, it asks `CSteam::GetWorkshopPathsForAlias` `0x1402043c0` at `0x1401151c4` and calls `GetDirectoryList` for each returned workshop directory at `0x140115366`. The workshop wrapper forwards to `CSteamInternal::GetWorkshopPathsForAlias` `0x140208310`, which derives a lowercased subdirectory from the alias prefix, checks candidate subscribed workshop paths with `FindFirstFileA`, and returns existing paths. The local and workshop scans are conditional on alias, Steam pointer and path data; their results are combined, not guaranteed populated. `CExoBaseInternal::GetDirectoryList` formats a `path\\*.extension` pattern, using `*` for the all-types selector in this builder. It enumerates via `FindFirstFileA`, `FindNextFileA`, `GetLastError` and `FindClose`; the file-list branch skips directory entries, while its separate directory-list branch can include directories other than `.`/`..`. The OS API and live filesystem are explicit leaves. For each listed name, `AddDirectoryContents` calls `GetResTypeFromFile` `0x140190b50` at `0x14018856f`, which takes the final extension and maps it with `CExoBase::GetResTypeFromExtension` `0x140115570` → `CExoBaseInternal::GetResTypeFromExtension` `0x1401602b0`. The internal helper scans its registered extension strings with `CompareNoCase` and returns the corresponding WORD type, or its fallback table entry when none matches. The directory builder skips the unknown `0xffff` type. It calls `GetResRefFromFile` `0x1401909f0` at `0x140188592`, skips an empty resref, then `AddKey` `0x140188f30` at `0x1401885da` with directory source ID, file index and priority. `AddKey` applies an optional table whitelist callback at `+0x60`, hashes name/type, linearly probes its allocated entries, skips duplicates, and records the source ID/name/type. The default `TEMPCLIENT:` registration passes a null whitelist; other directory registrations can supply one. Actual callback target and collisions depend on configured table and filenames. Later `GetKeyEntry` selects among priority-ordered tables and source services supply bytes for image/model publication, as mapped in [key selection](resource-key-selection-object-ownership.md) and [resource demand](texture-resource-demand.md). Three non-null default-path whitelist pointers have directly readable code despite Ghidra not recognizing separate procedure bodies at those addresses. `0x1401972c0` admits type `0x7df` (`LCVAULTINSTALL:` registration is one caller); `0x1401972d0` admits type `4` or `8` (`MUSICINSTALL:` is one caller); `0x1401972f0` admits type `3` or `0x7f1` (`PORTRAITSINSTALL:`). These predicates are decoded from the pinned instruction bytes, so they close those three default registrations without assigning a synthetic Ghidra function identity. `TEMPCLIENT:` uses a null callback. Other dynamic registrations can still supply a different pointer.
