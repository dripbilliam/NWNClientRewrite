# Original Nui movie widget route

Scope: installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. This connects the JSON `movieplayer` branch to its actual UI image draw and separates it from the direct movie presentation/swap route. It does not establish that a JSON movie window is open in any specific frame.

## Factory and owner

`Nui::JSON::LayoutableJ::Construct` `0x140741070` compares the type with `movieplayer` and calls `0x14095eb90` at `0x1407447a1`. The returned shared layout pointer is moved into the factory's output through `0x14071c1a0` (REA retained factory `ev_22c002c865997b52b6d2cdaa9b9b1462dd7d9fff367c19b2df563ac41a6bc4b0`, shared-pointer move `ev_ccb13ff0ea4517e7f8eaea1095b99a8c051a52375c0a6bed95d3ed6bbc6ee063`). The constructor chain `0x14095eb90` → `0x140954b90` → `0x140957090` allocates a shared `Nui::Layout::Widgets::MoviePlayer` object, installs its vtable `0x140e6e070`, constructs a `CExoMoviePlayer` member at widget `+0x6c0`, and retains dynamic play/overlay/size values (REA `ev_20a94f4af2ffc126094e02b127a26c41a9a48e7b7b10d9df12aaa6b184ada890`, `ev_c9a8285f881bd0012bb7b645b7f57cde00cd7be719c720bd23f336780a250e8b`, `ev_cecf9b8a4702f7e6fbee17d5a04dcd691fecfb8967ed225a9056016914040ff1`). The factory passes literal `1,0` for the constructor's play/loop parameters at this site; whether resource loading succeeds is data dependent.

`JsonWindow::Initialize` calls the layout factory and passes its result to `0x14074c0b0`. That installer stores an already-group layout at window `+0x108` with owner `+0x110`, or wraps the non-group movie widget in a `Nui::Layout::SingleGroup` through `0x14094b830`/`0x140952a10` before storing it (REA `ev_08892ea91c7365964949d8f7c8cdfbfdfaea1318f29de6fc52090111f1379116`, `ev_2f28694d29789d72db7d1c593570250dcb5a3d78b7908452ea8256ebe0f4801a`). This is a concrete attachment path for a JSON-created movie widget; it does not prove a live registered JSON window or a loaded movie asset.

`Nui::Window::RenderAll` `0x1406c4b20` walks the weak-window registry rooted at `0x141422c00`, under its UI and per-window lifetime/open gates. A surviving renderable window passes through `RenderWindow` `0x1406c5350` and virtual render `+0x60`. `JsonWindow` uses base `Nui::Window::Render` `0x1406c44e0`, which requires non-null content at `+0x108` and dispatches content `+0x20`. The SingleGroup content target `0x140950d90` invokes its virtual `+0x38`; pinned vtable `0x140e6ce58` resolves this slot to `0x140952960`, which calls `0x140951260` for child content traversal. That dispatches the movie child's `+0x20` target `0x14095b1a0` (REA registry `ev_fdd4a2429d1f0bc34d80bd3dadc79ae2cbe7531002b9758ca8a00086277d1cbe`, base render `ev_daabb01e3b637193b6eafc330825d4cbb65b3affd3c3ac9e9de6028146e8097b`, layout `ev_104ad9ce5af0baa8bf53b28ce0db33885362938c31cd06f9ecca6dd200fe470c`, slot bytes `ev_de8269f3ed639989898b684cd190ef9a01377fb5a7723f9bd7da039416d779ae`, child helper `ev_a7ae7bb6485055251853f051bda773edc7156159e38e437018d9f16393db0939`). The exact runtime registry contents, window visibility and child layout state remain open.

## Loaded and unloaded draw descendants

The movie widget content target `0x14095b1a0` checks `CExoMoviePlayer::IsLoaded` on its member. On success it calls wrapper `CExoMoviePlayer::UpdateMovie` `0x140232250` at `0x14095b492`, obtains the movie texture and emits a Nuklear kind-17 image command through `0x140a7db90` at `0x14095b50d`. Optional overlay controls emit kind 5 filled rectangles, kind 16 text and kind 2 lines. On failure it emits kind-16 text for `Movie failed to load` and does **not** call UpdateMovie or emit the video image (REA widget `ev_33c77e978b141241f1dd816751c87f4cb43f214c74dd06825b165408ec7d26af`, wrapper `ev_1871ed95ede910a77cf87f5c791e70dc66927ae76da8b47c38278b2836c17bfc`). Both cases enter the normal Nuklear converter/draw pass, which reaches imported `glDrawElements` for nonempty command geometry; numeric kind/GL mapping is in [GUI presentation](gui-presentation.md).

The [separate Nui image/WebM updater supplement](nui-image-webm-updater.md) identifies the wrapper's other caller, `0x140a93db0`: a shared image-descriptor helper with eight direct UI callsites, including JSON image and image-button widgets. Its WebM branch also constructs the movie player with a false direct-quad flag. The active resource and window remain data-dependent.

The wrapper `0x140232250` unconditionally delegates to `CExoMoviePlayerInternal::UpdateMovie` `0x140234210`. Its two direct caller sites are widget `0x14095b492` and another content helper `0x140a93dda` in `0x140a93db0` (REA incoming `ev_828f794a0434a136536926348bc624d1c06b92ec8a0cc2e8a0f3036c608ccd8c`, helper `ev_15badb524cfe90e3b241eecbeff2c5a5036046a59e75f00559d4b3cbed8e72ca`). The internal updater decodes video, conditionally uploads a frame by `RenderInterface::DirectCreateSubTexture` → imported `glTexSubImage2D`, and calls `ShowFrame` only when byte `internal+0x0` is nonzero (REA `ev_f8c4b2066951eb65fc05a0a66a5e5adedc4f54fc6fa08fd96f9d3ac62f9f0f2c`, GL upload `ev_a90dc9acfb64f5c54b5090f8f3e86571ca479767d70f93ff1a00921c55225207`).

The JSON movie constructor passes `false` to `CExoMoviePlayer::CExoMoviePlayer` `0x140231f50` at `0x140957090`. That wrapper forwards the boolean to the internal constructor `0x140232620`; `CExoMoviePlayerInternal::Initialize` `0x140233100` stores it at `internal+0x0`. Thus this constructor-backed Nui widget's updater takes the texture upload path but **does not call the direct `ShowFrame` quad** when that flag remains false. Its visible video is the Nuklear image command. REA constructor `ev_cecf9b8a4702f7e6fbee17d5a04dcd691fecfb8967ed225a9056016914040ff1`, wrapper `ev_ec5c488444bae999ee6f1b2001df396bcf9e0082d8247ca091d8d3f722199965`, internal `ev_522fb6b7d8c057851d54996fb52bb60e2453766e4e507b8f4b5d5e1e0843ef6d`, initialize `ev_75e671351d5655da928aceff74dddce28c8c8c05141b8e9f561df15637769919`.

The separate `CExoMoviePlayer::RenderFrame` wrapper `0x140232200` reaches `CExoMoviePlayerInternal::RenderFrame` `0x140233980` and swap under a non-null internal pointer. The Nui widget does **not** call that wrapper. Its pause click calls `CExoMoviePlayer::PauseToggle` `0x1402321f0` → internal pause state, not RenderFrame (REA `ev_5cc6baaa82bac36168da5a55a0c1f9167e15f4373aa0f4f7f2c3e932669877f5`, direct presentation path in [movie entry](movie-presentation-entry.md)).

## Direct movie mode gate and zero-result completion

The outer `Update` `0x1400448b0` uses helper `0x1406abc60` before both presentation sites. That helper returns whether the internal client at app-manager `+0x8` has a non-null `CExoMoviePlayer*` at `client+0x520` (REA outer `ev_3957e705c146df933c995e572aaf92eb3c23c4e0496ad434efca96649e1b9376`, gate `ev_79b23dec8f9c7e52019015b13fa3de89c27706bd266e080c5ee9c0ebd22d3248`). At the ordinary `RenderInterface::EndScene/SwapBuffers` site, a **zero** gate result permits the normal swap. At `0x1400450c8`, a later **nonzero** gate result calls `0x1406ac690` → `0x1406dea40` → direct movie RenderFrame wrapper. These are explicit tests of the same movie-pointer condition at their respective sites; they are not unconditional double presentation. A mutation of `client+0x520` between the two tests is not excluded by static code alone.

`0x1406dea40` reads that `+0x520` pointer again. If absent, it returns. If direct `RenderFrame` returns nonzero, it also returns. A **zero** result enters completion work: `0x1406e39f0` conditionally starts/resumes menu theme music, and `0x1406e4c20` destroys the movie object, clears `client+0x520`, and sets `g_pGuiMan+0x2c=1` (REA client `ev_e7fff9cdaf49cd4f56604194ef55213c1addbfe7703c8d926c7c55466b106c23`, music `ev_20ffd1cdaab7a69d00b8e7ea6b362a0e1578acfcf7d0af592acba90aea267a81`, teardown `ev_4d9fd001f7a4ab56cdf1d60884fea2870a380b3d2f336878f3903d66ae3944d4`). It then destroys optional owner `client+0x590`, clears flag `+0x58c` when set, and, if `client+0x208` is also non-null, calls `0x1407ba050` → `0x1407c25c0` with major/minor bytes `4,3` and zero payload. The latter reaches `CNetLayer::SendMessageToPlayer`; the exact protocol meaning and runtime recipient remain open (REA `ev_a5ecaca4228323f8edd668094228f9760be49ae97f501556cb6d21e10d36eed3`, `ev_2c368dee991431744dd1d3958e81c351a8a6a42d8063691a997a1297358ac612`). These are completion/music/network side effects, not extra GL draws in the zero-result body.
