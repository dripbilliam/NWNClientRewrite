# NWN-64 current accepted CPU particle audit

The retained source-heavy fixture `.cache/nwn64/accepted-shared_phase-d.json` has 1,750 sources, 960 configured far sources, 350 actor-clock sources and 42,000 actor-clock calls. It recorded a 3.605 ms mean native dispatch wall time. Its mean exclusive phases are 1.599 ms eligibility/clock, 0.602 ms simulation, 0.534 ms other loop, 0.262 ms admission, 0.261 ms geometry, 0.248 ms pose, 0.196 ms pack/sort and 0.014 ms counter summary. Within the eligibility/clock phase, the diagnostic reports 0.275 ms eligibility checks, 0.125 ms source checks and 0.666 ms actor clock boundary. These are profiled authored-source timings, not a current live Arelith run.

The normal production selection already enables native POD scene eligibility, bound setup, hot parameters, empty-clip skipping and borrowed resident text. `particle_presentation.hpp::frame()` short-circuits disabled emitters, fuses eligible/source-exists only when the engine's direct scene capability is active, and calls readiness only until its first success. The private animation snapshot removes repeated frame-local `animating` reads but its matched 360-input normal-client movement ABBA saved only about 0.032 ms in aggregate mean and regressed the quiet mean. It remains opt-in. The private canonical ModelRigs clock reader passed exact source-heavy state/packet/RNG tests, but same-binary timing drift obscured the gain against the accepted DLL; it remains unselected.

The current source calls the actor clock before `Step.advance()`. `Step.advance()` samples channels, reads current emitter/source poses and computes current radius before culling, then skips simulation when culled. Skipping clock, channel or pose work for the 960 far-source case would use stale animation/radius/transform inputs and could change admissions, callbacks, RNG and rendered effects. A frame cache shared across emitters can similarly miss external rig or Node3D edits between their calls. The direct scene ABI returns eligibility and source-existence flags, not the complete clock/pose state needed to make such a cache safe. No candidate is promoted from this audit.

Accepted DLL SHA256 remains `485741af15f0581a3c60c0f9a8ae738888eba08716c7a5c2c2d1bd550828963d`. No production or binary edits, build, graphical run or FPS measurement were made for this audit.

The next meaningful CPU candidate needs an engine-supported immutable per-frame pose/visibility witness or a proven canonical clock batch that can distinguish external edits between sources. Both require a separate correctness boundary and matched normal-client performance before promotion. The existing private clock reader is the closest already-verified candidate; test it under a quiet exclusive lease with accepted-binary bookends and original-source input matching before claiming a speedup.
