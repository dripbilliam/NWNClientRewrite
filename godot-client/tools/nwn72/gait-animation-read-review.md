# NWN-72 active gait animation read

`NetworkMotion.gait_speed()` previously read and converted `state.animation` for the creep predicate, then read and converted it again for the non-creep stride choice. It now keeps one unmasked integer local. The creep check still applies `& 65535`; the stride check still uses the unmasked value. There is no callback or mutation between the former two reads. This removes one Dictionary field read and one `int()` conversion for each active, non-creep gait evaluation. Inactive, invalid-clip and creep calls retain their prior early paths. The owner calls `gait_speed` during live pose animation selection (`systems/native_render/live_world.gd:661`) and local combat animation selection (`systems/local_connection.gd:1043`).

Only `systems/network_motion.gd` changed: SHA-256 `7b943610ba9765c8052e22fccdeaf2ca0e33f27eb86917db8ac44be5ab1d0762` → `bc6d3c8d26cd041a5f9977ac8f3357cd72b3102b7e2b9afa7060c0bd18176499`. The accepted Core E headless original-binary observation fixture `tests/network_motion_test.gd` passed 47,421 checks before and after, including 2,916 gait cases across animations 2, 3, 4, 78, 79, 84, 85, 86 and 87. The complete reports `.cache/nwn72/gait-control.json` and `gait-candidate.json` are byte-identical, both SHA-256 `b145ba8bc8e713045bfca6da60db348872fceac6013da4bcea03e9282721fea6` with zero failures. Both runs printed the same sandbox user-log and Windows root-certificate diagnostics; the fixture itself passed.

This is a small verified recurring work reduction, not a measured FPS or broad motion update improvement. No renderer, rig, combat-motion, engine or client launch file changed. The NWN-72 live busy-area CPU/FPS and effects acceptance gates remain open.
