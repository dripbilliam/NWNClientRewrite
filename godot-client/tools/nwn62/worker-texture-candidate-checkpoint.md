# NWN-62: opt-in worker texture creation checkpoint (2026-11-12)

The accepted runtime selection remains **off**. `nwn/private/worker_texture_creation=true` is a private project setting, gated additionally on a nonnull Forward+ RenderingDevice. With the setting absent, the existing main-thread texture path remains selected. The source adds a worker-side Image/`ImageTexture` sidecar in `raster_upload_preparation.gd`, forwards it through `asset_service.gd`, and validates/retains it on the main thread in `resource_pool.gd`. Scene consumers and cache ownership stay on the main thread. Each sidecar retains original-source bytes and a SHA-keyed packet; the main thread compares the packet with the actual raster record before using its texture. Invalid, missing or over-budget rows fall back to the original construction path. The worker memo uses weak texture references and coalesced in-flight requests, capped at 4,096 weak keys; no strong global GPU cache was added. The service permits at most four active workers and eight outstanding worker tasks, and each sidecar retains at most 16 MiB of prepared raster data. The ready pool is bounded at 16 MiB of counted CPU+texture bytes.

The Forward+ component used the accepted Core E binary on the NVIDIA RTX 5070 Ti. It passed worker-thread creation, main-thread texture use, GPU readback byte equality, one cache hit with the same texture object, and a deliberately changed source record with the same key falling back to main-thread creation and producing the changed pixels. The last component run also passed after the post-matrix mipmap-equality check. This is a local component result, not whole-scene visual acceptance. `worker_texture_component.gd` current SHA-256 is `6c390ccd0549ccbea51d2b52cbddad08f5320e41833ef9e9920cd8f918d29c63`.

## Profiler-on gate and speculative-work correction

An exact-source, profiler-on control/candidate pair at `.cache/nwn62/worker-texture-pair-b/staged.json` exposed 2,804 worker GPU texture builds for only 617 retained scene textures in one candidate run (the repeated diagnostic candidate built 2,751 for 615). The global worker memo had only 628/626 weak keys; most work was repeated after prior speculative textures lost their owners. The main pool did not report any `worker_textures_used` in these profiler-on runs, despite the earlier profiler-off matrix using 618/605. This route is scheduling-sensitive and the extra GPU work did not establish a frame benefit. One first pair had a 125.839 ms asset callback maximum versus 48.107 ms control; a second diagnostic pair had 43.261 ms candidate versus 49.442 ms control. The spike did not repeat. Completion phase logs show only 1–3 µs per logged sidecar admission; the long logged completions were consumer work. The `doortypes` completion was 42.346–48.889 ms of consumer work, consistent with the separately identified collision reindex. It cannot be charged to the texture sidecar.

The private worker option now records each attempted source key once per generation, capped at 4,096 keys. A lost speculative texture is not rebuilt for every later model result; actual later demand retains the normal main-thread fallback. The mutex still coalesces in-flight requests. A Forward+ RTX 5070 Ti component passed byte-exact texture readback, cache reuse, changed-source fallback, no redundant retry after releasing owners, and a fresh worker build after `RasterUpload.clear()`. It exited 0 from current root source `worker_texture_component.gd` SHA-256 `5ee284e5da98257543d3d34ad6f748e44889ba50d1edf7142e75e3cec6d4925b`. Accepted engine SHA-256 `753b3e188068efaf865bda3abd6322ebe44e3a98ef2f5d199c8af1a78624c98b`. Known sandbox shader-cache/root-certificate diagnostics remained.

The new pinned profiler-on ABBA original-scene matrix is `.cache/nwn62/worker-texture-pair-c/matrix-review.json`, SHA-256 `ef93277f28a5f4c49dc580ca520fff542884762505253add7b0e3e24b4ae81c8`. It verifies accepted engine, source/runtime, production camera/settings, 1,918 entities, 1,784/1,784 known base objects, ready collision, no scene/script errors and zero invalid texture packets in all four legs. Only `project.godot` selects the worker option. The candidate made exactly 626 worker GPU textures in each run, skipped 2,938/2,949 redundant repeat attempts, and recorded zero GPU failures. No worker-created texture was actually used by the scene in these profiler-on runs. The paired candidate-minus-control steady mean intervals were −0.207 and +0.195 ms (average −0.006 ms); p95 differences were −0.264 and +0.325 ms. Known-base completion was **418 and 1,307 ms later** in the two candidate legs. The first pair's texture-publication max was 25.971 ms candidate versus 8.372 ms control; the second was 5.393 versus 7.301 ms. This neither proves a stable FPS win nor passes the loading-latency gate. The strict driver still exits 1 for the known shader-cache and root-certificate diagnostics despite complete world verification.

**Decision:** keep `nwn/private/worker_texture_creation` default-off and private. The speculative-work correction removes measured redundant GPU creations when opted in, but does not justify promotion. `RasterUpload.clear()` currently has no production callsite, so its memo epoch persists across world scopes; later areas may use the correct main-thread fallback more often. Area-transition cost remains unmeasured. The expensive `doortypes` completion belongs to the collision-reindex work already tracked under NWN-62; the staged reindex remains a separate private candidate. Resume higher-impact publication work and leave NWN-62 In Progress.
