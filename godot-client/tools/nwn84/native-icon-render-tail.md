# Native item-icon render and texture tail

Scope: installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are image virtual addresses. Ghidra pseudocode is a machine-code analysis, not original source. This page records only original-binary behavior; the item selection and UI-owner branches are in `native-icon-flow.md`.

## Named texture replacement

Each `CreateCopyIconModel` variant constructs a `GUI_ICON*` `CAurObject` with `NewCAurObject` and invokes object virtual `+0x60` for a simple named texture replacement, or `+0x58` when a palette is supplied. Composite icons bind `gui_replace01`, `02`, and `03` in order. Layered and armor icons use the palette-aware call. Each replacement gets virtual `+0x80` with texture attributes `icons`. The four factory addresses and branch evidence are in [the presentation map](../nwn75/item-icon-presentation.md).

`NewCAurObject` uses the shared MDL resource route in [model-resource storage](../nwn75/model-resource-storage.md): `CAuroraInterface::GetResource` chooses `CAuroraModel::LoadModel`; `CRes::Demand` reuses resident bytes or reads from an installed archive, directory or NWSync manifest. The corresponding named image acquisition uses the resource-backed raster callback and texture build in [GUI resource demand/decoders](../nwn75/gui-resource-demand-decoders.md) and [scene texture acquisition](../nwn75/texture-acquisition.md). Actual source choice and first-use residency depend on the resource key and runtime cache state.

`CAuroraInterface` constructor `0x1400f4cf0` installs the active resource-backed callbacks for normal, layered, compressed and 16-bit raster requests and their release/header companions. This distinguishes the connected-game resource route from an earlier file-backed `ImageRead` callback state. REA `ev_ec9a35bff96bdcc0af6acceb8731b27395dd69cfca8f1f104f8d9c7aa0427406`.

For a layered image, the installed resource callback `CAuroraInterface::GetLayeredRaster` `0x1400f5d80` lowercases the requested name and searches a sorted `_m_lstLayeredTexture` list. A cached object is loaded/reused; otherwise it constructs `CAuroraLayeredTexture`, calls `LoadTexture` `0x1400f4440`, and inserts it on success. That load demands a `CResPLT`, validates PLT dimensions and layer count, then exposes its index bytes. The separate `CAurTextureBasic` scheme and conditional GPU palette publication turn those bytes into the bound texture. This is a second cache below the per-icon Gob and named `CAurTexture` caches. Ordinary raster `CAuroraInterface::GetRaster` `0x1400f62d0` constructs/loads `CAuroraTexture` through `CResTGA`; compressed/16-bit format callbacks have their own resource-priority paths. REA `ev_85c1695b8a7447f5bf772fb06951faab710d716cbbacddd0ee353612be004e83`, `ev_2a5f60570e40b098d4ae23c7b3cf207f844c16b8779b2926c142d6790154f8e3`, `ev_152fde58a838b504e8e8c07412addf97262fe6b8798592406d87f8b82d76eda2`, `ev_f4f1e0bf92e561036a6b9f84a02e17811601b0c3401b1e3e9f85b3cb38a042dd`.

For the `Gob` returned by `NewCAurObject`, virtual `+0x60` resolves to `Gob::ReplaceTexture` `0x140094040`. It walks the object's materials and calls `Material::ReplaceTexture` `0x1400853e0`, or `Material::Refresh` for a matching shared material. `Material::ReplaceTexture` calls `AurTextureGetReference` when the material's texture is null, or `AurTextureReplaceSingleReference` for an existing texture. These are named resource/reference updates, not an icon-specific bitmap bake. REA `ev_59b8751a40cd0006e68a4a9f9e01cb9dc0b2d914617ad2be9800dbc11c21856b`, `ev_b5bc92df3a82a7d3050f86871a6b9e93b1b6300f3778f13e0b2ef1146347401b`.

Virtual `+0x80` resolves to `Gob::SetTextureAttributes` `0x1400957e0`. It finds matching named textures and calls `AurTextureSetAttributes` `0x1400e9880` for each. That function initializes the underlying `CAurTextureBasic` with the `icons` attribute and deduplicates/enqueues it in `_RefreshTextures`. This is still before texture publication. REA `ev_52d27052904bac56ee47f85cd5b7d58031d2671eee32acc9b50100c5401b31fc`, `ev_81706fc74647873c909c52bd1b8e9b6add4212e64e01f7bb04aa1ca3a9840278`.

Palette-aware model virtual `+0x58` resolves to the other `Gob::ReplaceTexture` overload `0x1400941e0`. It gathers the model's materials, expands the supplied 16-bit palette entries to 32-bit values, and calls `Material::ReplaceTexturePLT` `0x140085610` for each selected part. That material method first checks the replacement resref exists as resource type 6, loads a shared texture array when present, then replaces an existing texture reference or sets layered state. The layered state stores up to 15 scheme entries and queues the texture for refresh. The material also retains the palette count and normalized values (`entry / 1792.0`). The reference replacement uses `AurTextureGet` and tracks texture references; it is not a per-icon CPU compositing step. REA `ev_aacad02e5fff305d49c4ada0d58e251e7e9dafb05735d64995a46ae136a93f6b`, `ev_50c735d91230bd59541b406b4a6873161feced00c42999776879e723600ecb72`, `ev_b37ab1d28ebb0d4c86f123009b964f36670ff49589a1acac8f91371af60916b5`, `ev_3fe249521ecf5e40e0cee0226b081b657eb95322096010124a60d2ce59d3346b`, `ev_e320aac2c019d109ac08cd6205753c051c116eaa6e74d18a7775b4e23b683e23`.

## Attachment and draw

The verified inventory control caller `0x14087f640` obtains its item icon, copies it, calls `CGuiIcon::GetIconModel`, then invokes model virtual `+0x98` with the inventory control model as parent. It calls `RepositionModel` `0x140882b70` to place the attached icon at the grid cell. `Gob` virtual `+0x98` resolves to `Gob::AttachToObject` `0x14008c540`: it chooses the parent's root or named part, creates an attachment behavior, then calls `Gob::SetScene` with the parent's scene pointer. `Gob::SetScene` `0x140095250` removes the object from an old scene if needed, stores the new scene, and invokes its add-object slot. This is a retained object in a GUI scene, not a CPU raster converted into a new UI texture. REA `ev_490485584d57445bf54c28ac8e09d898a983fbaa94b82197fb3895e6d63dc7c1`, `ev_941df7c54ed4bbf33fbdc51a478097ed7c45100f313d90c7b675d565470eb697`, `ev_119c4d798471c072350e79d3579629dd4009ae0408b157f00a7ace9417003cb9`, `ev_b195cae81e8290aca80dc063168a76525aebb83f4b65adc680004093440bcef4`.

The [GUI render pass](../nwn75/gui-presentation.md) establishes that `CGuiMan::UpdateAndRender` `0x1401f70e0` iterates registered GUI scene views and invokes their cameras. The [legacy GUI draw ownership trace](../nwn75/legacy-gui-draw-ownership.md) follows the scene camera through Gob/Part model draw to conditional GL array/element calls. The [texture acquisition trace](../nwn75/texture-acquisition.md) establishes that `AurTextureGet` first looks up a named texture in its registry; a miss creates a Basic texture and queues it. `AurTextureBuildAndStoreAll` processes pending textures during the scene render path, with conditional image decoding and GL upload. These generic leaves are connected to the item icon by the named replacement and scene-attachment edges above. They do not prove the runtime latency of a first unseen icon.

The no-BSP GUI scene target `Scene::RenderOnlyGobs` `0x1400cf9b0` walks its stored Gob array `+0x130` in index order and invokes virtual `+0x20` for each. Ordinary GUI scene names disable nearest-light setup; `sceneGUI_guiModelView` and `sceneGUI_Viewport_Compass` take the separate lighting branch. `Gob` virtual `+0x20` is `Gob::Render` `0x1400a4280`, which applies the Gob transform and traverses its Part tree through `Gob::PartDraw`; drawable mesh parts reach `RenderInterface::RenderVertexData` and GL draw calls as mapped in the shared GUI trace. `GobRenderLast` `0x14008fa20`, used in a drag path, removes and readds a Gob through Scene virtual slots `+0x208/+0x200`, which changes its array order. REA `ev_13916b7382c586af44aa639f3b605478dd4f729adbe1e6746cbeaa394197ef18`, `ev_77439f92ad3967b5a8bfc93386d7bb44717a6ef361231bdf0f537eda94b8ccf2`, `ev_758fa9b0d2ebc6e0108f486f871a8ef96705c7e7900824caf4d7f8288a495d29`.

`CAurTextureBasic::ConstructImage` `0x1400eac60` shows the precise palette branch. With scheme data and no usable ordinary raster it calls `AurGetLayeredRaster`, marks image kind 4, and retains the PLT index image. With `g_bGeneratePLTOnGPU == 0`, it instead calls `ImageDecode` with the master palette and scheme to make RGBA on the CPU. With GPU generation enabled, [palette publication](../nwn75/texture-gpu-plt-publication.md) uses the shared palette, shader and FBO to make a destination texture. These are original resource-format branches feeding the same GUI Gob draw, not competing icon renderers. The ordinary image path goes through `LoadImageA` `0x1400ec570` → `AurGetImageWrapper` `0x1400e5c60`, which tries allowed compressed texture data, then 16-bit image, then ordinary raster. REA `ev_69e3e2579e6c438fb6ed552e2bdd99610fba09be27af261b39e2ef35cf00a918`, `ev_3c2a719c481ea678658a08426a1c418713c6d8eb887b8926b6471e7fc35e97c9`.

`CSceneView::CSceneView` `0x1401f37f0` creates its `sceneGUI...` scene and `cameraGUI...` camera, sets camera clip distances to **81.92** and **757.76**, position to `(0, 0, 742.4)`, view angle to zero, and scene ambient to `(1, 1, 1)`. The constants are pinned float bytes at `0x140db1a2c/30/34`; `Camera::SetPosition` `0x14005b6f0`, `SetClipDist` `0x14005b440`, and `SetViewAngle` `0x14005b800` give the field meaning. At zero view angle, `Camera::RenderScene` `0x14005a5d0` chooses `SetOrthoTransform` with height equal to viewport pixel height times `0.01` model units and width scaled by aspect. This establishes the original 100-pixel-per-model-unit GUI projection before any panel-specific camera or viewport change. ## Observed cache and open edges

`CGuiIcon::GetIconModel` `0x1401e4310` returns the model pointer at icon `+0x30` when present. On a miss it invokes virtual `CreateCopyIconModel`, stores the result, and returns it. `GetSmallIconModel` `0x1401e43b0` caches a separate model at `+0x38`. `PurgeIcon` `0x1401e4630` and `PurgeSmallIcon` `0x1401e4660` destroy and clear the respective model. This per-icon model cache is separate from the named texture registry. REA `ev_3f141fcb72cf18762ec54081aa388bb9c16ae92d9413dfcef9fe9a6eca8f901e`, `ev_3f247bde8ab7ae849fc03156ccc92916ae8347fd98692130763848d1dc98d95c`, `ev_39ed8b0fdae5423a293bdd429c14d19166b2a1fa8754abea43a7b40aa3f430e5`, `ev_2067e1c9bfeccf26a7d0843fd76dce8b2a2390a7cb683081a0c8e94a1b0f4b4`.

The [connected server override route](../nwn75/server-resource-override-refresh.md) can change later resource-key selection. Its major `0x34`, minor-1, type-`0x7d1` branch fans one override across raster, compressed, PLT and model resource types, refreshes matching shared materials and named textures, and can rebuild matching quickbar icons. Minor 4 has explicit texture/model/palette bulk invalidation masks. A model or texture cache key that ignores the active resource generation would therefore differ from the original's invalidation behavior. These branches run only for their matching server messages.

The exact texture binding lifetime across server overrides, icon attachment and cleanup in non-inventory controls, and runtime first-use latency remain open. Static call paths do not establish that all named textures are resident before a UI opens.
