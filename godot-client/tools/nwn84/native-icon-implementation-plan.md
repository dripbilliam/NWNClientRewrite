# NWN-84: retained native-style item icon implementation plan

Status: design only, 2026-11-14. No client source changed by this plan. It applies to **item** icons in inventory/equipment, quickbar, barter/store, and item examine. The original-binary facts are in [native icon flow](native-icon-flow.md), [render and texture tail](native-icon-render-tail.md), [GUI presentation](../nwn75/gui-presentation.md), and [legacy GUI draw ownership](../nwn75/legacy-gui-draw-ownership.md). The current client consumer map is [client icon consumers](client-icon-consumers.md). Those maps retain explicit open edges; this document must not be treated as proof of full visual parity.

## Method to preserve

The original selects a flat, composite, layered or armor `CGuiIcon` from item/base-item data. On demand, it creates a `GUI_ICON*` model for normal or small presentation, replaces named `gui_replaceNN` materials with item TGA/PLT resources, gives them the `icons` texture attributes, caches the model in the icon object, attaches its Gob to a GUI control model, and positions it in that panel's 3D GUI scene. The GUI manager renders registered panel scenes with their cameras. Texture names have a shared registry and conditional first-use publication. The normal item path has no per-icon render-to-image/readback/reupload step.

In Godot, the closest compatible path is a retained 3D scene **per active native GUI panel**, with all of that panel's item icons as live model instances. Godot's root viewport already has the world camera; [Godot supports one active 3D camera per Viewport](https://docs.godotengine.org/en/stable/tutorials/rendering/viewports.html). A `SubViewport` plus its live `ViewportTexture` can provide the second camera and composite the panel scene without CPU readback. [Godot requires a SubViewport to be displayed through a container or ViewportTexture](https://docs.godotengine.org/en/stable/classes/class_subviewport.html). This is a Godot bridge, **not** the original binary's direct backbuffer GUI pass. The bridge's cost and alpha/order correctness need measurement. One viewport per icon would recreate the failed serial path and is excluded.

## One item-icon service and one production path

1. Keep `ItemIcon.plan/select` as the item-data decoder, but verify its class, normal/small choice, texture replacement order, palette fields, fallback rules and overrides against the full native ledger. Do not add a blanket installed-icon preload. A valid NWSync override is valid even if absent from the installed 372 item-template census.
2. Separate `NativeItemIcons.request(item, ...)` from its unrelated `request_model(...)` GUI-art API. The item service resolves a plan and source revision, requests the model bundle through `AssetService`, and publishes a **prepared model/material descriptor**, not `Texture2D`. The existing `request_model` use by other UI art remains independent; no item silently falls back to its bitmap output.
3. Cache immutable MDL geometry, parsed template, resolved raster/PLT texture and material by content/source identity and palette scheme. Keep a distinct mutable model instance per visible item/control binding. A shared mesh/material resource may be used by many instances; a single Node3D cannot be parented to multiple slots. Retire unused slot instances, and retain only bounded shared assets according to actual references. Missing or corrupt *active* source data yields an explicit icon error, not an alternate raster icon.
4. Use one global **whole item-icon system** switch for rollback during acceptance. In native mode all item consumers use the retained scene API; in legacy mode all item consumers use the preserved raster API. Do not mix per-item or per-family paths, and do not promote native mode until every supported native item family and the four surfaces pass. The old code can remain in a separate implementation for an explicit rollback, without being invoked in native mode.

The new completion contract should return `key`, source generation, prepared descriptor or error. `ready(key)` means textures/materials and the model instance needed by the current visible panel are ready; it must not mean a disk prework PNG is resident. Source identity should include the active archive/NWSync override and palette inputs. The current `request()` key hashes only the icon plan, while `AssetService` knows bundle/source digests; ensure an override or resource invalidation cannot reuse a stale key/material. Verify the catalog's active precedence and refresh notifications before choosing the exact key shape.

## Panel-scene owner

Create a reusable panel 3D host owned by each native item-icon surface: inventory/equipment/store and container windows (including simultaneous alternate inventory windows), quickbar, barter, and item examine. If multiple controls share one actual native panel, share one host; do not allocate a viewport per row, slot or icon. Each host owns a transparent `SubViewport`, one orthographic `Camera3D`, a Node3D root and one live viewport presentation Control that is placed among that panel's art at the corresponding GUI depth. It creates/reparents/frees child icon model instances as item bindings change. A panel close disables its viewport update and retires all slot bindings; reopening can reuse immutable assets.

The native `CSceneView` constructor uses a camera at `(0, 0, 742.4)`, clip distances `81.92/757.76`, zero view angle, and white scene ambient. `Camera::RenderScene` selects an orthographic projection whose model-unit height is viewport pixel height × `0.01`. The native inventory `RepositionModel` likewise uses `0.01` model units per pixel. Godot's existing private icon raster projects the converted X/Z geometry with a camera down negative Y; that is a converter convention, not the original engine's axis convention. Verify per-panel viewport mapping at 1.0 through 1.9 UI scale and the ultrawide window size. Do not use `SubViewport` image bounds to recenter each icon; position the retained model using the native control anchor, model origin and template geometry.

The host receives a binding `(panel, slot/control, item key, view/target revision, icon presentation kind)`. It computes the control anchor from its **current** transform, updates the model transform when the panel moves, changes scale, scrolls, pages, or resizes, and rejects completions from retired views. A fresh visible row must have its model before the panel's existing art-admission gate opens. A changed count/disabled state can update text/alpha without reconstructing unchanged geometry, matching the native grid branches. Normal and small model families must be distinct cache entries. Micro is only admitted where the native caller is actually established.

## Draw order, clipping and alpha gates

`Control.clip_contents` clips **CanvasItem children**, not a separate 3D viewport's meshes ([Godot Control](https://docs.godotengine.org/en/stable/classes/class_control.html)). The mapped native item attachment functions do not issue per-icon clip calls; the legacy camera has a viewport, and its GL leaf calls `glViewport`, with no confirmed legacy icon `glScissor` call. Implement the native camera/panel viewport and item visibility/page ownership first. Do not invent a per-slot shader clip: multi-cell icons can cross slot boundaries. If a local parity fixture demonstrates additional native clipping, trace its owner before adding a matching bound. A per-*panel* live viewport is the compositing boundary; never use a per-icon image capture.

Panel stacking matters. The original has a CSceneView/camera per panel and the GUI manager renders registered views in order, plus overlay views. A Godot `ViewportTexture` Control must be inserted at the corresponding point between panel background, item art, labels/stack count and borders; a single global full-screen icon layer cannot automatically interleave with every current 2D panel/modal layer. Test simultaneous inventory, barter, examine and quickbar, overlapping/dragged windows, hover/disabled alpha, tooltip/menu, modal cover, and resize. If one live panel texture cannot reproduce native order without moving more GUI art into the panel scene, treat that as an implementation requirement, not an accepted visual difference.

The original uses named texture replacement (`gui_replaceNN`), `icons` sampler attributes, and a palette-aware material route with conditional GPU PLT publication. Reuse existing decoded raster/PLT data only if it produces the same resource selection, palette, UV, blending, tint and alpha. The current `AssetService` `gui-icon-v1` worker resolves the model and `icon_textures`; its PLT path currently colorizes on CPU. Confirm output parity and the original option/gate before deciding whether a Godot GPU PLT publication equivalent is needed. Preserve template mesh and composite layer depth/order rather than flattening 2D layers by hand.

## Surface-specific binding and retirement

| Surface | Required binding behavior |
| --- | --- |
| Inventory, equipment, backpack, container, merchant | Bind by `view_serial` and `entryId` after `native_inventory.refresh` resolves item plans. `server_inventory.render` reuses matching buttons but may free and recreate rows on movement/page changes. The panel host owns icons by entry, follows the real `native_icon_center`, honors repository clipping and alternate-window ownership, and removes stale icons on view/page/close. The separate `inventory-icon` network PNG message must not supply an item in native mode. |
| Quickbar | Use the original small icon model family: ordinary item assignment `0x140867760` invokes small-model helper `0x14086baa0` and binds it to the button Gob. Native page switch `0x140859a60` removes and reattaches 12 existing GUI button objects, preserving their icon Gobs; server updates can clear or repopulate any of the 36 bindings. Bind by `(quickbarId, slot index)` after current `server_quickbar.render`, which currently recreates visible buttons. Reposition on page, GUI scale and window movement; gate late completion by current view. Keep non-item shortcut art in its existing system. The `quickbar-icon` PNG message must not replace a native item model. |
| Barter/store | Use the shared inventory item model rules with each barter grid's own panel host/clip and `native_barter_slot` center. Bind by current item id/side and retire on trade state, scroll and close. Test both player and NPC panels. |
| Item examine | Bind only the current `(targetId, revision)` to its native icon model. Native `CGuiExamineItem` target update `0x140899d70` uses the normal model for width below 3 and the small model otherwise, attaches it to the panel Gob, and transforms it. The current `image_bounds` footprint calculation is a raster-placement workaround and cannot be assumed to be that transform. Retire on target/type/revision change. Non-item portrait images are separate. |

Drag previews are a fifth presentation of a *currently bound item*, not a reason to bake a permanent icon texture. The native drag trace attaches the icon Gob to an overlay owner and removes it on drop. Move or clone a retained icon instance into an explicit drag GUI scene for the drag lifetime, following the actual native ownership and z order once that edge is fully mapped. Godot's current `TextureRect` previews in `inventory_slot.gd` and `native_barter_slot.gd` are tied to the raster path and must not remain active in native mode.

## Acceptance and measurements

1. Finish the bounded GUI viewport/depth audit before production source changes. Quickbar page/server update, store/barter shared-grid routes, examine attachment, texture override refresh, and the absence of an observed per-icon clip call in mapped owners are now documented. Record remaining runtime-dependent unknowns in the native ledgers. Compare the whole item chain, not just `CreateCopyIconModel`.
2. Headless source/plan tests: all 192 existing item-oracle cases, every installed item template family, normal/small model names, six armor layers, composite order, PLT palette, resource override/revision, invalid/corrupt active resource handling and cache retirement. A test should prove a native-mode item never enters `draw_icon`, `frame_rendered`, `get_image()` or `ImageTexture.create_from_image()`.
3. Local graphical tests: first unseen items appear before panel admission in inventory, quickbar, barter and examine; compare native screenshots for flat/composite/layered/armor with distinct palette rows and tall/odd UVs; verify clipping, alpha, count labels, z order and drag at the user's 3440-wide setup and representative UI scales. Keep NWSync custom resources in scope.
4. Matched performance test only after pausing concurrent ticket work: control and candidate with identical route/settings, cold and warm item panels. Report admission delay, CPU icon preparation, GPU render/composite cost, frame time and FPS separately. The expected work removal is one per-icon viewport draw, GPU-to-CPU readback and ImageTexture reupload per cache miss; the per-panel live viewport(s) add recurring composition work and must be measured.
5. Arelith acceptance: first inventory open, page switch, equipment, item shortcut, barter, examine, drag, server override and reconnect. Keep whole-system legacy switch available until user accepts visual parity and performance. A source-only result or an installed-template census cannot close NWN-84.

## Explicit unknowns

- Native ordinary quickbar item assignment, page switch, item examine, and store/barter shared-grid updates are mapped. Untraced alternate GUI event handlers remain bounded unknowns.
- Native panel viewport/depth behavior in every inventory/examine configuration and overlap with the current 2D layout are not yet fully pinned. The panel SubViewport composition is a proposed Godot bridge, not observed native code.
- Installed assets do not bound Arelith NWSync overrides. No arbitrary model shape should be rejected solely because an installed-template probe did not contain it.
- Static native code does not quantify first-use cache residency, original icon latency, or whether a specific item takes GPU PLT generation. Those require a controlled runtime capture or matched acceptance check.
