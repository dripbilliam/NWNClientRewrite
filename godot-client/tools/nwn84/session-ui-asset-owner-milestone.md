# NWN-84 session UI image ownership, first slice

The resolved `ResourceCatalog` now owns completed raster, GUI model, and item-composite `Texture2D` objects with their exact bounds. `native_ui_art` and `native_item_icons` reuse them across screen-owner closure and reopening. The catalog's ordered binding identities scope the owner; a mounted-source change detaches it, and `release_ui_assets()` explicitly closes it. Ordinary catalog forks are payload readers and cannot acquire the GPU owner; normal UI consumers use the published catalog. Exact model keys still include clip, overrides, turn, layer, poses, and render region. Item keys still derive from the received item plan and tables. Errors remain in each producer's existing error path and are also recorded by the owner for inspection.

The manual disk preloader sets `assets.prework_write=true`. Its icon renderer neither consumes nor retains images through this owner, preserving its one-image-at-a-time GPU release policy. No startup population or all-assets readiness claim is made by this slice.

## Admission and lifetime design for the next slice

- **Installed-content startup:** `native_pregame_menu.gd:catalog_ready` is the gate. The full resolved installed catalog must be mounted before an exhaustive pregame cohort is constructed. Its complete, failure-free decoded and GPU-ready result must precede `source_ready.emit` and the first page starts. The pregame catalog owner remains through menu reopen and is released at application shutdown.
- **Post-NWSync content:** `native_live_world.gd:receive("setup")` has the fully mounted server catalog after `catalog_loader.completed`. Its complete server-specific cohort must finish before `gameplay_ui.configure` and the `catalog-ready` ACK. The session catalog owner is explicitly released on connection reset after UI owners close. Area transition within the same connection retains it.
- **Runtime item/action variants:** server item parts, colors, gender, spell/action rows, and generated poses can be unknown at installed startup. Their keys join a content-arrival cohort after authoritative data arrives; its associated screen remains noninteractive until its complete set is GPU ready or shows a concrete missing/corrupt error. A static GUI GFF/model-prefix scan cannot seal these cohorts.

The owner is a residency foundation. Completing NWN-84 still requires exhaustive resolved manifest construction, per-screen cohort sealing, screen admission wiring, explicit reset wiring, cold/warm memory and startup receipts, and graphical verification. The existing manual prebake's 3,819 images are a partial historical corpus and are not an all-assets manifest.

| [GUI resource demand](../nwn75/gui-resource-demand-decoders.md) follows `CRes::Demand` `0x14018f300` through manager source selectors 1/2/3/5, including manifest service, then conditional decode/release. A same-name pregame texture from a different catalog cannot be assumed equivalent. Native source selectors support this precedence concern; the exact client ACK gate comes from current source, not the binary. |
| [Texture acquisition](../nwn75/texture-acquisition.md) traces `_RefreshTextures` → `AurTextureBuildAndStoreAll` `0x1400e6910` → Basic image build/`glImageBasic` → GL upload, which can occur during `Scene::Render`. [GUI presentation](../nwn75/gui-presentation.md) traces active GUI update/render and later Nuklear/overlay work. | `native_ui_art` and `native_item_icons` previously published `Texture2D` only at first request and released owner dictionaries on close; the new catalog owner retains completed textures and bounds. | Readiness must mean an actual completed texture, with failures separately counted. The owner removes repeat first-use work after the first completion; it does not yet move the first completion ahead of interaction or cover fonts. |
| [Texture acquisition](../nwn75/texture-acquisition.md) also traces an anisotropy-change `AurTextureRefreshAll` route that rebuilds texture state. | The Godot owner holds `Texture2D` references; it has no explicit renderer-reset or preference-change invalidation yet. | The future graphical gate must check settings changes and renderer restarts. Native refresh behavior does not prove Godot residency across device loss. |

The native map leaves active panel population, exact authored `Obj_ResRef` variants, runtime NUI callback content, and per-frame frequency conditional or uncharted. Dynamic item/action cohorts therefore require client-side arrival records and their own screen gate; they cannot be inferred complete from the binary's static call tree.
