# NWN-84 UI/icon cohort sources and honest admission gates

Read-only planning checkpoint. The resident `Texture2D` owner is a separate first slice; this note does not treat its populated keys, the historical disk prebake, or a resource-name scan as a complete preload.

## Key identity and source stack

`systems/native_data/session_catalog.gd:prepare` mounts install keys, Workshop HAKs, server archives, NWSync manifests, portraits and override directories in priority order, then calls `ResourceCatalog.build_resource_index()` before publishing the catalog. `ResourceCatalog.resource_names(type)` and `raster_location(name)` are therefore candidates for enumeration and exact precedence. A manifest row needs the winning layer `binding_identity`, resource name/type, source digest or failure, and the **consumer request descriptor**. A resource name alone is insufficient: `native_item_icons.gd:model_key` includes clip, overrides, turn, replacement layer, poses and render region; its item-composite key hashes `item_icon.gd:plan(item,tables,gender)`. Bitmap fonts use a font-name key, while explicit TTF includes resource and pixel height. The pregame and server catalogs are separate scope identities even when names match.

## Installed-content pregame cohort

The source boundary is `native_pregame_menu.gd:catalog_ready`, before `source_ready.emit` and before `pre_main`/`options_pregame` page starts. Its `source_ready` subscribers configure the server browser and original character chooser in `native_session_world.gd`. These producers must all declare keys before a **pregame all-assets** cohort may seal:

| Producer | Known source and request forms | Remaining dynamic membership |
| --- | --- | --- |
| Entry pages | `native_entry_menu_frame.gd` requests GFF `pre_main`, `options_pregame`, `pre_multiplayer` and `okcancelpanel`, then recursively requests every nonempty `Obj_ResRef` model. `native_gui_painter.gd` binds static model images and button clips `up/hilite/down/disabled`, or checkbox clips `uncheckedup/uncheckeddown/disabled/checkedup/checkeddown` with exact overrides. | Visibility and page state change which clips are drawn, but every declared clip must be included. Authored layout references may be missing/corrupt and must fail explicitly. |
| Browser and prejoin dialogs | `native_server_browser.gd` requests `serverlist_panel`, `serverlist_page1/3/4` and `gamespyrooms` 2DA; `native_direct_connect.gd` requests `directconnect`; `native_player_profile.gd` requests `multi_login` and `okpanel`; `native_server_filters.gd` requests `serverlist_filt`; `native_server_details.gd` requests `srv_srvdetails` and `gamespyrooms`. Their recursive model discovery and painter binds use the same variant key rules. | Server row text/data arrives later, but layout art and fonts are installed-content keys. Any icon derived from a server response belongs to an arrival cohort. |
| Character chooser and options | `native_character_lobby.gd` requests `pre_playmod`; `native_key_settings.gd` requests `options_key_pnl/page`; `native_video_options.gd` requests `options_vidmodes`. The chooser requests `ctl_pre_btn_char` clips; source painter captures other control variants. | Portraits and character appearance/replacement models are known only from local/server records; they need a record-arrival cohort. |
| Fonts | GFF `Obj_Caption.AurString_Font` from every above document; explicit pregame status `fnt_galahad14`; `native_bitmap_fonts.gd` demands type-2022 metadata plus resolved atlas, or type-2074 resource for `ttf <name> <height>`. | Font creation includes `FontFile` and atlas publication. The current disk prebake adds some `fnt_` names and `ttf fnt_default 14`, but is not proof that every consumer font was requested. |

`ui_prebake_plan.gd:discover` is useful seed evidence: it walks all type-2047 GUI GFF references and six model prefixes, but explicitly omits exact generated poses/replacement textures. Its historical 3,819 saved images were not held live. Exhaustive pregame membership requires a producer registry for every page/dialog/chooser and font owner, not just this scanner.

## Post-NWSync server-content cohort

The source boundary is `native_live_world.gd:receive("setup")`, after `SessionCatalog.completed` provides the fully mounted server stack. It constructs `gameplay_ui` and sends `catalog-ready` afterward. The static cohort must register all server-resolved GUI documents/model variants and fonts before the associated chooser/gameplay screens become interactive; it cannot seal from catalog names alone. Important producers:

| Producer | Source and exact key family | Data that may arrive after setup |
| --- | --- | --- |
| Game UI frames | `native_gameplay_ui.gd:configure` creates inventory, desktop, chat, conversation, mouse cursor, barter, examine, creation, loading, and NUI owners. Their `native_gui_painter`/`native_ui_art` calls include static names, button clips, region crops, authored replacement textures and generated poses. `native_scrollbar.gd`, `native_status_bar.gd`, `native_conversation_frame.gd`, `native_journal_frame.gd` create descriptor-specific pose keys. | Scroll position, progress/time and text flow can make new pose arrays after setup. They need a bounded screen/state cohort unless a finite state generator is proven. |
| Item, inventory, barter and examine | `native_item_icons.gd:request` calls `item_icon.gd:plan` from received item `baseItem`, parts, colors, properties, gender and 2DA `baseitems/capart/parts_robe/cloakmodel/iprp_spells`, then `select` chooses actual model and PLT/raster layers by catalog precedence. `native_inventory`, `native_barter`, `native_examine_frame` are consumers. | Item instances and palettes arrive with server/character state; enumerating all hypothetical combinations at setup is not a finite proven cohort. Seal a received-item cohort before its inventory/barter/examine screen presents. |
| Spells, feats, actions, effects, radial, quickbar | `native_gameplay_ui.gd` requests startup tables including `spells`, `feat`, `skills`, `effecticons`, `actions`, `domains`, `iprp_spells`; `native_game_desktop`, chooser classes, `native_effect_icon`, `server_action_queue` and `server_radial` bind row or packet icon names. Radial and equipment placeholder models also use `gui_replace01` overrides. | Available rows depend on server state, class/level, quickbar and action packets. Cohort membership must be captured from the resolved rows/packet before these screens or controls become interactive. |
| Portraits and loading | `native_portrait_chooser` uses sized portrait resource selection from the catalog; `native_nameplate_mesh` binds picture variants; `native_loading_screen` requests `pnl_loadscreen` with `gui_replace01` area-name image. | Character records and next area identity arrive after setup. Their exact portrait or loading replacement key requires a record/area-arrival cohort. |
| Fonts and NUI skin | `native_ui_skin.gd` requests `nui_skin` type 2076, then its declared fonts and image rasters; `native_bitmap_fonts.gd` and `native_popup_fonts.gd` produce `FontFile`/atlas outputs for GUI, chat, nameplates, popups and script floaties. Explicit source names include `fnt_galahad14`, `ttf fnt_default 14`, `ttf fnt_default_hr 16`, and `ttf fnt_maintext 17`; GFF captions supply additional names. | `server_nui.gd` also receives runtime NUI skin/font/resource transfers, and `native_nui.gd` resolves image names/regions from window packets. These transfers are not known at setup and require a window/transfer cohort. |

## Smallest honest completion gate

1. Each applicable producer registers **all** request descriptors for a named cohort and reports `enumeration_complete` only after its required GFF, 2DA, character, item, area or NUI input is available. A cohort cannot be marked complete while a producer is unregistered, a required source is pending, or a dynamic input is merely assumed absent.
2. Seal the installed pregame cohort after all pregame producers above have enumerated; admit the first main/menu interaction only after every required exact key has a completed `Texture2D` or `FontFile` (and any required UI model geometry), no pending GPU publication, and no unresolved failure. Keep the loading/status surface visible while waiting; show concrete missing/corrupt keys on failure.
3. Seal the server static cohort only after the final NWSync catalog plus required UI tables/layouts are ready. Its gate belongs before character chooser or gameplay presentation. Delaying `catalog-ready` itself requires a protocol check: later server packets may be needed for dynamic cohorts, so the static gate must never wait for item/action/area/NUI packets that the ACK releases.
4. For each dynamic received item/action/portrait/area/NUI window, form a separate arrival cohort from the *actual received data*, seal it, and gate that screen/control before interaction. An unbounded generated pose or unknown server icon remains explicitly `unresolved` until its generator declares a finite set or supplies the current exact key. No lazy missing-key fallback may be counted as all-assets completion.
5. Record expected, completed, failed and pending counts by source scope and screen, winning binding identity, texture/font bytes, and startup/post-NWSync latency. NWN-84 is complete only when every producer above is registered and cold/warm/reopen/area/reconnect visual acceptance shows no first-use read, decode or upload for admitted UI.

The [NWN-75 native GUI map](../nwn75/legacy-gui-draw-ownership.md) proves conditional panel activation reads GFF `Obj_ResRef` models before its scene/Gob/Part draw; [resource demand](../nwn75/gui-resource-demand-decoders.md) proves conditional source service, and [texture acquisition](../nwn75/texture-acquisition.md) proves named reuse versus pending texture build/upload during render. These support exact resolved descriptors and GPU-ready gates. They do **not** prove native preloads every UI asset, enumerate current client runtime item/NUI variants, or establish the client's `catalog-ready` protocol timing.
