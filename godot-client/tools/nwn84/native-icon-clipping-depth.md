# Native item-icon clipping and depth boundary

Scope: installed `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are image virtual addresses. This is a bounded static map of the **legacy 3D GUI Gob path** for item icons, not the separate Nuklear numeric-command UI. It distinguishes a confirmed camera viewport from an unproven per-control clip.

## Icon to scene

Inventory grid `0x14087f640` obtains the cached icon model, attaches its Gob to the inventory control model with Gob virtual `+0x98`, then calls `RepositionModel` `0x140882b70`. That helper maps the grid position and icon dimensions through 33-pixel cells at `0.01` model unit per pixel. Equipped slots `0x14087f320`, ordinary quickbar helper `0x14086baa0`, and item examine target update `0x140899d70` also attach icon Gobs to their control or panel model. The mapped attachment functions contain **no explicit icon clip/scissor operation**. Evidence: [item-icon flow](native-icon-flow.md), `ev_af34a9adade103cd4172b6daebfb7b27ec52e90025cf2f8ce054a684a6cfc725`, `ev_941df7c54ed4bbf33fbdc51a478097ed7c45100f313d90c7b675d565470eb697`, `ev_2ae6a6c48e844162860ec070504bf3a2c067a80e1d48cfcd4c833c2efe8a7971`, `ev_cbae4e87117bff70fa2367cf9d5db7123b38d79ccd904fabd4c274606413fa25`.

Gob `+0x98` is `Gob::AttachToObject` `0x14008c540`. It attaches to the parent root or named part, then `Gob::SetScene` `0x140095250` propagates the parent's GUI scene. Ordinary panel activation creates a `CSceneView` and attaches its root Gob to that scene; `CGuiMan::UpdateAndRender` invokes the registered view camera. Thus an item icon follows its control model into a **retained GUI scene**, rather than receiving an independently rasterized icon texture. Evidence: [render tail](native-icon-render-tail.md), `ev_119c4d798471c072350e79d3579629dd4009ae0408b157f00a7ace9417003cb9`, `ev_b195cae81e8290aca80dc063168a76525aebb83f4b65adc680004093440bcef4`; [legacy GUI ownership](../nwn75/legacy-gui-draw-ownership.md), `ev_643830a77c06dfc50804134d4969249c53b6633d7f12508994ddf59720aae7aa`.

## Viewport and clipping

`CSceneView` constructor `0x1401f37f0` creates a GUI scene/camera, sets camera clip distances **81.92–757.76**, camera position `(0,0,742.4)`, view angle zero, and ambient `(1,1,1)`. `Camera::RenderScene` `0x14005a5d0` uses an orthographic projection at `0.01` model unit per viewport pixel for zero view angle. An explicit camera rectangle at `+0x4d8..+0x4e4` is rejected if wholly offscreen; a visible rectangle is clipped to the screen and passed to the viewport setter. A full-viewport camera uses the current viewport. `GLRender::SetViewPortLight` `0x1400bb290` clamps to screen and calls **`glViewport`**, not `glScissor`. Evidence: [render tail](native-icon-render-tail.md), `ev_f6193f4a8a66fe1a8d0b22e673f243f887c3cb29d5daad26e394a06d69f032c2`, `ev_78f457c4276dbd9d464acb2775a8f55015ed1eaa29087ce42357960cbae3923d`; [camera entry](../nwn75/camera-entry.md), `ev_4393914dd018195bd1a10f8edf54a40ad4cff9b0c8d0e56fa03049d3137f7161`, `ev_bf5c2adaae67af892766c2397a88c98cc4f340f82ac707722a8a2fc752dab6e6`.

`CGuiViewport` can own a separate GUI scene/camera, register or unregister its view, and set a camera viewport. A `CAurBehaviorSubwindow` path can update that camera viewport from attached part corners (`CGuiViewport::SetViewportAttached` `0x1401f0560` → `GuiAttachViewport` `0x140203400` → `CAurBehaviorSubwindow::Control` `0x140202af0`; `CGuiViewport::SetViewport` `0x1401f0520` → `Camera::SetViewPort` `0x14005b810`). These are **possible panel/subwindow mechanisms**, not proof that inventory, quickbar, or examine item controls instantiate a dedicated child viewport. Evidence: [GUI presentation](../nwn75/gui-presentation.md), `ev_c549ad3d21cd22585bb22be15bf2cd6524a5853bb5b3b2862fcb1ddd10cb0f81`; [subwindow behavior](../nwn75/original-scene-animation-nonemitter.md), `ev_bf27f744500842286091d13dccd43a2e8a11a8698bd022a35d415c961e3ee744`.

The concrete `CPanelInventory` constructor `0x140854e60` installs its vtable, loads `INV_PANEL`, sets the repository model `INV_BOX_10X6`, and attaches that repository to the panel root through `CGuiObject::AddToPanel`. It also constructs a separate `INV_CONTAINER` panel with an `ItemGrid`. Its analyzed direct callee list contains no `CGuiViewport` constructor or setter. The other direct `CGuiViewport` constructor callers identified by Ghidra are chat, journal, character sheet, spellbook, map, party bar and other panels; no inventory, quickbar, or examine constructor is identified among those direct callers. This supports ordinary panel-scene ownership for item icons while leaving indirect later viewport creation open. REA `ev_638de05afd264eaf9b75b78a05a00b3b80608ce10b5f64fcabdd69f2cee9f8ca`, `ev_8958553c18a435fc5d1cd867de8f6108f44b32193154298526ed2ff39a94dbd4`.

The known `glScissor` call in this binary's mapped UI work belongs to Nuklear draw `0x140a71760`, whose command loop sets it before `glDrawElements`. The legacy Gob scene path above is not that command loop. The mapped attachment, camera viewport, and no-BSP draw bodies provide **no confirmed per-item scissor**; an indirect state change or untraced panel-specific route remains possible. Evidence: [GUI presentation](../nwn75/gui-presentation.md), `ev_6b5e1be5df3d0ec1c19e05d9f5114d2a9453a5c0bd89c9f09f1a3012d4826278`; root's GL import reference census (only computed `glScissor` callsite `0x140a71d8e` in Nuklear plus import table). `glViewport` and projection clip scene geometry to the camera's view volume; they do not by themselves establish clipping to each inventory slot or scroll region.

## Depth, order, and alpha

For `sceneGUI...` or orthographic cameras, `Camera::RenderScene` conditionally clears depth once through a global gate and sets a narrow depth range: selected overlays/panels use **0.0–0.02**, other GUI scenes **0.021–0.1**. The perspective branch uses 0.0–1.0 and resets that GUI-clear gate. Evidence: [camera entry](../nwn75/camera-entry.md), `ev_4393914dd018195bd1a10f8edf54a40ad4cff9b0c8d0e56fa03049d3137f7161`, `ev_cd2ca7419cdd12192b2db03cf0a17659898d3d1fd441a1fd4eacf2dbf8b8dba0`.

With no BSP, `Scene::RenderOnlyGobs` `0x1400cf9b0` walks Scene Gob array `+0x130` in stored order, calling Gob virtual `+0x20=Gob::Render` `0x1400a4280`. `Gob::PartDraw` `0x1400a3440` tests each Part visibility byte, applies its transform, draws, then recursively visits child Parts in stored order. Installed composite and armor `GUI_ICON` templates use parent-chained Parts with successive local depth offsets near `+0.03` and `+0.01`; those depths and material alpha/depth state can affect the visible result even where meshes are locally planar. A drag path's `GobRenderLast` `0x14008fa20` removes and readds a Gob through scene slots, changing array order. Inventory's disabled item path uses alpha **0.4** versus **1.0** normally. Evidence: [render tail](native-icon-render-tail.md), `ev_13916b7382c586af44aa639f3b605478dd4f729adbe1e6746cbeaa394197ef18`, `ev_77439f92ad3967b5a8bfc93386d7bb44717a6ef361231bdf0f537eda94b8ccf2`, `ev_758fa9b0d2ebc6e0108f486f871a8ef96705c7e7900824caf4d7f8288a495d29`; [no-BSP Gob trace](../nwn75/scene-no-bsp-sky-gob.md), `ev_5080b9fb6725bb9ac451460297aad6160dfc13a6af388d001037368a792d5233`; [template geometry](icon-template-geometry.md); inventory evidence `ev_af34a9adade103cd4172b6daebfb7b27ec52e90025cf2f8ce054a684a6cfc725`.

This establishes **traversal order**, not a complete final pixel-order rule: depth test/write, transparency, culling, texture attributes, and any later scene mutation can change which layer wins. Panel activation initializes its Scene BSP pointer null, so the mapped ordinary GUI route takes no-BSP rendering unless another path later installs a BSP. The conditional BSP branch enters `Scene::RenderSinglePass` and buckets rather than this simple Gob array walk. Evidence: [legacy GUI ownership](../nwn75/legacy-gui-draw-ownership.md), `ev_4393914dd018195bd1a10f8edf54a40ad4cff9b0c8d0e56fa03049d3137f7161`; [geometry and draw boundary](../nwn75/geometry-and-draw-boundary.md).

## Remaining native questions

1. Whether later indirect code creates a child `CGuiViewport`/Subwindow clip for inventory, quickbar, barter, or examine. The verified inventory constructor uses direct panel attachment and has no direct viewport constructor call; exact camera rectangle at each live UI scale remains runtime-dependent.
2. Whether scroll/repository boundaries are enforced through a child camera, geometric visibility, or another late panel operation; no per-slot clip has been proven.
3. The exact item-template material depth test/write, blend, cull and alpha behavior at the GL draw leaf, including overlap with neighboring control models and text.
4. Runtime no-BSP versus BSP choice and depth-clear history for the actual active panels.

The original-binary analysis call for a fresh independent `Camera::RenderScene` decompilation exceeded the private Ghidra import window and was stopped. This note uses the linked prior REA evidence and explicitly leaves those four edges open; it makes no FPS or visual-parity claim.
