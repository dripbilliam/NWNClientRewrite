# NWN-84: current client item-icon consumers

Read-only map, 2026-11-14. This describes the current code; it is not a proposed renderer. The native binary's complete icon flow is being mapped separately before implementation resumes.

## One source, four item consumers

`NativeInventory.configure()` creates one `NativeItemIcons` instance and shares it with the desktop, barter, and examine owners. All original item icons in those four surfaces call `icons.request(item, tables, gender)`. The request plans/selects the original item model and named replacement layers, asks `AssetService` for the model bundle, then currently renders the model in a private orthographic `SubViewport`. After the render fence, `frame_rendered()` reads the GPU image and uploads an `ImageTexture`; it publishes `textures[key]`, `image_bounds[key]`, and `completed(key, texture, error)`. The session UI owner retains the resulting texture under `item` and the digest key. See `systems/native_item_icons.gd` (`request`, `draw_icon`, `frame_rendered`, `finish`).

The item key is a digest of the icon plan, so a future direct model owner must preserve plan identity, selected override precedence, failure state, and stale-request protection. The present `completed` signal and texture dictionary are the binding contract for all four consumers. `request_model()` on the same class renders **other GUI art**; it is not an item request.

## Other GUI icon art

`native_party_frame.gd` draws portraits from original raster resources and state/frame GUI models via `NativeUiArt.request_model`; it never calls `icons.request(item)`. `server_radial.gd` draws action icons through `NativeUiArt` raster binding and some GUI models for circles, arrows, and submenu previews; it also never calls `icons.request(item)`. These are outside the four native item-icon consumers. Their GUI models share the existing renderer implementation, so replacing *all* GUI model art would be a separate, larger scope.

## Shared 3D scene placement contract to resolve from native flow

The present UI is 2D `Control` geometry. A native-equivalent icon Gob attached to a shared orthographic 3D GUI scene needs a projection that maps each control's screen/local center, model footprint, clipping region, draw order, and window movement to the 3D attachment. Inventory and barter icons also need scroll/page clipping; quickbar needs hook placement; examine needs its original bounds offset. If the host is a single viewport-sized 3D layer, these are layout updates for attached models, not per-icon image captures. The remaining native-flow questions are the exact camera orientation/scale, model-parent transform, depth/culling, replacement texture and UV behavior, and whether clipping follows parent GUI controls.

No source consumer edits are retained from this audit. No FPS measurement was run.
