# Native inventory item-icon timing boundary

Target: installed `nwmain.exe`, SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses below are image virtual addresses. This note distinguishes the proven construction path from the unresolved timing of offscreen backpack pages. It makes no measured-latency claim.

## Proven chain

1. `CNWItem::UpdateIcons` `0x14083f6f0` selects a flat, composite, layered or armor `CGuiIcon` and stores it at item `+0x238`. The constructors store icon description data and do not themselves decode/upload pixels. Both equipped-slot refresh `0x14087f320` and grid refresh `0x14087f640` reach this update. Evidence: [native icon flow](native-icon-flow.md), `ev_4d222a6b2b39bef78897f04743935db82f0202aecb3958a3b9f9bd3721a1a506`, `ev_dfc320a60dea1b93a97b4491636e04cf7cb4766517347c813b16616b850ad060`.
2. Grid refresh `0x14087f640` copies the item icon, calls normal `CGuiIcon::GetIconModel` `0x1401e4310`, attaches its Gob to the inventory control, and positions it at the grid cell. `GetIconModel` returns the cached Gob at icon `+0x30`, or calls the virtual model factory on a miss and saves the result. The same-item/same-count grid case reuses the existing model. Evidence: [native icon flow](native-icon-flow.md), `ev_af34a9adade103cd4172b6daebfb7b27ec52e90025cf2f8ce054a684a6cfc725`, `ev_3531cb17263ce2d4efdf85b3f2fd561a730a8a7b24e2bab56102a43495551ecd`.
3. A factory miss creates an original `GUI_ICON*` model, performs named `gui_replace01..NN` texture/PLT replacement and assigns the `icons` layer. `NewCAurObject` can demand model bytes through `CAuroraInterface::GetResource`/`CRes::Demand`; named raster and PLT callbacks have their own resource caches. Actual reads/decode/upload depend on resource residency. Evidence: [native render tail](native-icon-render-tail.md), [item presentation](../nwn75/item-icon-presentation.md).
4. The original inventory window open body `0x140857cd0` has a direct call at `0x140857dfc` to owner refresh `0x140856fa0`. The existing controlled replay of that body records `refreshOwner` on an open branch, but stubs the refresh itself, so it does **not** establish which item pages it populates. Evidence: `scripts/inspect-native-inventory-window.py`, `backups/animations/native-inventory-window-observations-v1.json`; the direct rel32 site was checked against pinned `.text` bytes with `scan-rip-references.cjs` and belongs to PE `.pdata` function `[0x140857cd0,0x140857e4e)`.
5. Pinned `.text` direct-call bytes also show two inventory-panel callsites into grid placement `0x14087f640`: calls at `0x1408569a9` and `0x140856ce5`, inside PE `.pdata` ranges `[0x140856740,0x1408569d7)` and `[0x1408569e0,0x140856e30)`. Generic wrapper `0x14087f970` tail-jumps to the same grid placement at `0x14087f98c` and has other callers. These bytes establish eligible callers, not when each caller runs or which page its item belongs to. The direct-call byte scan is reproducible with `node godot-client/tools/nwn75/scan-rip-references.cjs <pinned nwmain.exe> 0x14087f640 0x14087f970 0x140856fa0` and PE bounds with `pe-function-range.cjs`.

## Offscreen-page and first-use conclusion

The verified path is **lazy at the Gob-model level**: item icon metadata can exist at `+0x238` without a built `+0x30` model; the grid's first `GetIconModel` miss creates it, and later reuse returns the cached Gob. The mapped functions contain no all-icons startup preload. They do not prove that every offscreen backpack page is attached/refreshed on inventory open, nor that a first page visit must create or load its model. The `CGuiMultiPageMultiInvbox` page-population and item-update callers still need a bounded call trace or runtime observation. Texture/model source caches can also be warm from unrelated use.

Consequently, the client's closed-inventory preparation of every replicated item's **model/texture bundle** is a latency optimization with the same original resources and a single retained renderer, but **native timing parity for that preparation is unproven**. It does not justify claiming the original prewarms all pages. If strict scheduling parity is required, keep this choice behind the current opt-in backend until native page-population timing is settled.

REA Ghidra was opened on the matching executable for this pass. `search_procedures`, `analyze_function(0x14087f970)`, and one `inspect_native_instruction(0x14087f640)` each stalled for over 30 seconds without a receipt and were cancelled. The prior ledger evidence and pinned direct-call bytes above are the available proof; no conclusion was inferred from an incomplete Ghidra query.
