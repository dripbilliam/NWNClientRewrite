# NWN-84 `pre_main+okcancelpanel` completion cohort

This first admission gate covers only the original `pre_main` page and its constructed, initially hidden `okcancelpanel` exit confirmation. It does not claim the whole pregame/browser/character/gameplay asset inventory is ready.

`native_entry_menu_frame.gd` already requests both type-2047 GUI documents and recursively requests every nonempty `Obj_ResRef` model before it marks layout ready. Once both layouts and models are parsed, `build()` creates the static images, button clips and caption labels for the page and confirmation. `cohort_snapshot()` now enumerates those constructed targets: model count, every `TextureRect` exact GUI model key, every button-style clip/override key, and every bound `AurString_Font`. The newly tagged static image key matches the actual `art.bind(..., model=true, clip="")` descriptor. A ready cohort has all images/textures and fonts applied, no missing model, no pending key and no failure. The existing page visibility and input admission continue to use `art_ready()`, now backed by this complete scoped snapshot.

Failures from GFF/model preparation, `native_ui_art.failed`, or `native_bitmap_fonts.failed` stop admission and name the exact image/font key. `native_pregame_menu.refresh` shows the active page's error; it does not leave a corrupt asset behind an indefinite “Preparing menu resources…” label. Unrelated painter jobs cannot hold this page. The receipt scope is explicitly `pre_main+okcancelpanel`. `options_pregame` retains its prior `art_ready()` admission rule until its separate installed-content cohort is tested.
