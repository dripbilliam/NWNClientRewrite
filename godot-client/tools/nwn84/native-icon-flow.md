# Native item icon flow ledger

Scope: `nwmain.exe` SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are image virtual addresses. `Verified` means the named edge appears in Ghidra pseudocode/assembly; it does not imply every runtime branch has been observed. This ledger covers item icon selection through GUI ownership. The GUI scene/camera/texture/draw tail is being mapped separately. Unresolved edges are listed at the end rather than inferred from missing direct call references.

## Flow

```text
CNWItem item and base-item/part data
  -> CNWItem::UpdateIcons (0x14083f6f0)
  -> item+0x238: one CGuiIcon / CCompositeIcon / CLayeredIcon / CArmorIcon
  -> virtual CreateCopyIconModel (normal), CreateCopySmallIconModel (small),
     or CreateCopyMicroIconModel (micro)
  -> NewCAurObject(GUI_ICON template)
  -> replace gui_replace01..NN with item texture/PLT; assign "icons" layer
  -> CAurObject/Gob attached to GUI control's 3D model
  -> GUI scene render (separate render-chain ledger)
```

### Resource and installed-template coverage

The native server-resource override handler `0x1407ab2f0` can add/remove resource overrides. Type `0x7d1` fans the override across types including model and PLT, then refreshes shared material/texture caches. It can call quickbar icon refresh `0x14085fda0`. Thus an installed-asset census is a baseline, not a complete set for a connected NWSync server. Evidence: `tools/nwn75/server-resource-override-refresh.md` and `ev_37757f2819fa72a5d8e721ac08c673a2dbf278ea43b4839484ff45e22ec0830f`.

Installed NWN root plus `Prelude.nwm` currently exposes 376 `gui_icon_*` MDLs: 120 `#x#L/LC`, 240 `#x#R/S/RC/SC`, 12 `ARMR#L/S`, and four special templates. All 372 item templates decode with a real PLT replacement layer under the current `gui-icon-v1` probe; the 126 normal templates contain 259 local render meshes, and the full 372 contain 760. Their local render meshes are planar, but some parent transforms translate X/Y or rotate Z; many UVs are cropped and 13 extend slightly outside the U range. The 19 templates used in 188 valid installed item-oracle cases are represented. Full source, geometry and UV evidence is in [icon-template-geometry.md](icon-template-geometry.md); the ignored diagnostic is `.cache/nwn84_icon_geometry_all.gd` with report `.cache/nwn84-icon-geometry-all.json`. This **does not** establish geometry of NWSync/mod overrides and does not change the native 3D Gob draw requirement.

## Unresolved edges and parity requirements

1. **Small/micro use sites:** normal quickbar and wide examine item use small models; subclass small creators and `GetSmallIconModel` are verified. `CreateCopyMicroIconModel` has a character-creation callsite; item use of micro remains unproven.
2. **Store/barter alternate events:** the two mapped server update handlers, panel constructors/destructors and barter drop share the generic grid attach/cleanup path. An exhaustive proof of every subclass-specific event branch is not established; the current dispatch boundary is `CGuiStoreInvBox`/`CGuiBarterInvBox`/`CGuiMultiPageMultiInvbox` methods outside `0x1407b4b80`, `0x1407b4620`, and `0x14097e120`.
3. **Server overrides and dynamic assets:** connected server can replace model/texture/PLT resources after startup. The installed template probe and item-oracle cases do not bound these variants. Exact live resource precedence and invalidation must be preserved.
4. **Clipping and render tail:** no explicit per-icon clip operation appears in the mapped inventory placement, quickbar assignment, or examine update functions. Whether clipping is applied by GUI controls, the scene view, or the render pipeline remains unresolved. The separate render-chain ledger must link 3D GUI scene view/camera/projection, texture cache/draw, depth and both normal no-BSP and conditional BSP render branches from these attached Gobs before claiming full native parity.

For the current client consumer map and differences, see `client-icon-consumers.md`. This file is an evidence ledger, not a promotion claim.
