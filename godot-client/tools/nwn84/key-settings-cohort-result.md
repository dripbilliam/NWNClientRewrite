# NWN-84 key-settings artwork admission

The original key-settings page previously exposed its Controls action after GFF/model layout and key binding readiness, while its page images, button poses, fonts or scrollbar could still be pending. `NativeKeySettings` now requests the five checked row-button poses before first opening, checks only its own constructed controls and original asset models, and emits artwork readiness once the page is complete. Both pregame and in-game parent menus wait for that signal, and direct early Controls actions are rejected. The pregame Video action now also waits for the existing Video artwork gate; its prior layout-only enablement could admit a click before `show_page()` accepted it.

Official Godot 4.7.2 OpenGL checks used the installed original game on an unfocused secondary display. The in-game key-settings interaction suite passed 32/32 (`.cache/nwn84-key-input-graphic-root-c.json`); the pregame menu/navigation suite passed 27/27 (`.cache/nwn84-pregame-key-graphic-root-b.json`). Temporary display-position copies of the existing suites were removed after the checks. The canonical key-settings fixture now waits for the binding owner before asserting that the parent action is enabled; the canonical pregame fixture waits for both key and Video artwork readiness.

The headless full-UI key-settings run timed out with many unrelated GUI requests pending and is not counted as a pass. The OpenGL checks establish local navigation and admission, not complete all-menu/icon residency, original-client pixel parity, RAM/VRAM or FPS. NWN-84 remains In Progress for the remaining UI cohorts and full startup acceptance.
