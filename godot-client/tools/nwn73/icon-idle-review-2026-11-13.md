# NWN-73 idle icon owner callback

The pre-edit `systems/native_item_icons.gd` SHA-256 was `70cd84a2466f2144b3d2b4bbd30479f9b110ad61682ecb97e52b0209dc55d607`; the candidate is `afc8db5fb8ceabd84fa85d5a685d8992a8db2703294485f0f4f024dff0004393`. This is a small main-thread callback reduction, not a claim of new parallel speed or FPS improvement.

Every `NativeItemIcons` owner previously ran `_process` every frame. Its frame body calls `pump_models()` to admit deferred worker requests and, if no draw is active, publishes one completed icon from `queue`. In the idle state both arrays are empty, so the callback performed profile timing plus an empty pump. The candidate starts with processing disabled, wakes whenever `request_model()` leaves deferred work or `prepared()` queues a draw, and sleeps when both queues drain. `AssetService` owns its own worker completion `_process` and independently wakes on pending/running tasks; item `request()` still uses that service. No worker count, icon key, texture, rendering or publication order changed.

The focused headless `tools/nwn73/icon-idle-test.gd` passed 14 checks with the pinned existing Godot executable. It covers initial/configured idle state, immediate admission, full worker queue, later drain, a request re-enqueued inside admission, prepared result waking draw publication, active viewport wait, a follow-on queued draw, and close. `git diff --check` passed. The engine emitted only the existing isolated user-log/root-certificate errors; the fixture itself reported zero failures. The first draft's gate missed the draw queue; it was corrected before handoff and the expanded gate passed.

While a draw is active with no queued follow-on, the main owner may sleep. Completion is delivered by the render-thread compositor fence (`icon_viewport_drawn`) or the independent `RenderingServer.frame_post_draw` signal, both wired in `draw_icon` and both calling `frame_rendered`. Neither path requires the owner `_process`. If another completed draw is queued while the viewport waits, `prepared` enables processing; it remains enabled until the queue drains. There is no `_process` timeout/watchdog in the original code, so sleeping does not remove one.

Remaining gate: a graphical icon run should check actual up/down/hilite pixels, completion ordering and teardown with the production renderer when the coordinator grants an exclusive visual lease. This patch does not satisfy NWN-73's matched FPS/hitch acceptance by itself.
