# NWN-73 preview worker current-source gate, 2026-11-12

No production worker route was merged. The accepted `preview_drive` still calls `DrivePreview.path` synchronously with `drive_collision.query_preview`. `prepare_worker_preview` and `worker_preview_current` have no production call sites, so `--drive-preview-surface-cache=on` cannot engage. The accepted DLL and all production files remain unchanged.

The private whole-preview proposal at `.cache/nwn73/preview-worker-a` has exact-path component parity on 74 original WOKs (300 checks), synthetic in-place WOK/door invalidation checks (21), and keyboard token checks (16). These are proposal-source results, not current production engagement. In the four original-WOK component cases, 90/122-face synchronous OFF main time was roughly 5.7/5.0 ms; worker ON snapshot plus start was roughly 1.5/1.5 ms and later admission roughly 0.8–0.9 ms. Immediate-join path latency was roughly 10 ms ON versus 5–6 ms OFF. The component fixture did not model a live keyboard/click stream.

The private recorded-input headless OFF/ON replay (`.cache/nwn73/preview-entry-a/review.md`) contains 360 inputs: 349 drives, six stops and five turns. It contains **no click/walk input**, so an ordered keyboard/click oracle is absent. The ON leg submitted/completed/admitted 35/35/8 workers, rejected 14 stale poses and 13 superseded serials, took 31 busy synchronous fallbacks, and ended at controlled distance 91.793266 rather than OFF 91.817070. Both legs accepted all input operations, but they did not establish exact local movement parity. The ON `snapshot_ms=973.516` aggregate includes 283 first-clear immediate requests and is not isolated copy time.

The private proposal publishes `motion.preview(id, async_plan, null)` before the path returns and later publishes another preview on admission. The accepted route publishes one preview after the complete path. That changes when path, orientation and correction observers see movement; an input token only rejects stale results and cannot undo the earlier publication. In the current `native_live_world.gd`, clicking ground calls `keyboard.stop()` then sends a walk command, while keyboard predicts through `world.preview_drive`. Correct cancellation must include that order, area generation, actor lifetime, in-place WOK edits, and newer keyboard requests. The existing capture omits click events, and the old ON replay already failed controlled-distance parity. A production-reaching worker cannot be justified by the current evidence.

`DrivePreview.path` is an adaptive collision search: probe points in the fraction and side-search loops depend on prior clear results. `query_preview` already collects one bounded geometry view for its repeated probes. Offloading only a probe then joining on the same call would add thread cost and preserve no useful overlap; offloading the entire path produced the rejected latency and stale-result rate. No narrower substantial independent phase is proven. Keep NWN-73 In Progress and the flag default off.
