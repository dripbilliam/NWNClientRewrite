# NWN-83 installed-character worn-cloak reproduction

`cloak-original-character-replay.gd` used the normal `CreatureStream` → `ActorInstance` render path in Godot 4.7.2 Compatibility, on an unfocused secondary display. It mounted the original installed game read-only at `C:/Users/Niflheim/Desktop/Tools/Local Tools/FullDecomp/NwnRootInstall`. The source was installed `data/lcv/monk.bic`, SHA-256 `77b605ab223b074ae5144f2538ad2068a3740ad1c832235cb1c99a64b831504b`. Its original equipment slots were 2, 4, 8 and **64**. Slot 64 already holds base item 80, model part 1, matching installed `baseitems.2da` ModelType 1 and `cloakmodel.2da` row 1, Plain (MODEL 1, TEXTURE 1). Only the control removes slot 64. This is a genuinely equipped installed character, not a synthetic cloak addition. The [BIC census](../../.cache/nwn83-cloak-bic-census-a.json) found two slot-64 characters among 40 installed BICs; `shifter.bic` has model part 3, GreatCloak.

The [report](../../.cache/nwn83-cloak-original-c.json) exited 0 with no fixture failures. Both actors published through the current creature stream. They have the **same model names and mesh count**, with no additional worn-cloak piece. Neither reported unattached equipment. The two saved back-view images are [without cloak](../../.cache/nwn83-cloak-original-c-original-character-no-cloak.png) and [equipped Plain cloak](../../.cache/nwn83-cloak-original-c-original-character-plain-cloak.png). Both visibly render the original character (421/422 sampled colors); the equipped view still shows the same silhouette. The images are not byte identical, so pixel equality is explicitly a diagnostic, not the acceptance condition; separate actor instances can differ in rendered pixels.

The omission is source-backed. `systems/native_data/bic_visual.gd` projects equipped items into the appearance payload. `systems/native_data/creature_appearance.gd:33,75-84` reads slot 64 and `cloakmodel.2da` solely for HIDEWING/HIDETAIL conditions; it never emits a worn-cloak part. `systems/native_render/creature_stream.gd:162-177` turns appearance parts and attachments into pieces; `equipment()` at lines 147-158 adds right/left weapons and a helmet, with no cloak. `systems/native_render/actor_instance.gd:80,88-110` installs only supplied pieces. The generic item path's `gi_cloak01` at `systems/native_data/item_appearance.gd:33` does not supply a worn character attachment.

The baseline reproduction did not change production files. It identified `systems/native_data/creature_appearance.gd` and `systems/native_render/creature_stream.gd` as the likely production owners. The native rule search and coordinator's subsequent candidate validation are recorded below. No FPS or live Arelith result is claimed.

## Native rule and current candidate checkpoint

After the baseline, the pinned native `nwmain.exe` (SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`) was inspected through Ghidra. Function `0x140976b40` reads `cloakmodel.2da` MODEL and TEXTURE from the equipped cloak row, formats each as `cloak_%03u`, and combines `P` + gender + race + phenotype + `_` + model suffix for the MDL resref. The direct format-string xrefs are `0x140977288` and `0x1409774f4` (REA evidence `ev_a90578267a49d9f9e35fc661c11bac73df4d085050bc1aa5ffd27cfbe19abdaf`); function dossier `ev_24bb40b8dd3fcb7eac4846178274987d916a6f4835ec1bbb7ce1aa9daa91eda4`. It passes the separate texture resref and ten tagged color words to the slot `0xf3` model creation route, then reads ENVMAP and the HIDEWING/HIDETAIL/HIDESHOL/HIDESHOR fields. The exact native body transform and origin of those ten appearance color values remain open. The installed catalog has `pfh0_cloak_001` MDL and `cloak_001` PLT, as recorded in `.cache/nwn83-cloak-catalog-b.json`. A standalone current-service/template test `.cache/nwn83-cloak-model-c.json` publishes one drawable mesh with original PLT pixels; without palette options, the service rejects `cloak_001` as an unavailable raster.
