The ON snapshot reports a nominal 713-instance reduction, not a measured draw-call reduction.

`static_scenery_batches.gd` accepts only opaque or alpha-scissor material (`_unsupported_reason`, lines 38-53); blended and dynamic per-tile fog remain on the original source path. The merged owner preserves the source Node, visibility/layers, original material/light/collision owners, and suppresses only its RenderingServer draw instance. The installed scene selected the same `ttu01__ref` model environment in every leg. Each leg had one active point shadow out of five eligible lights, with the same focus origin and selected light. These are owner-state checks plus a sampled view, not an isolated shadow/fog pixel oracle. Alpha-scissor and individual blended/fade exemplars still need close visual inspection in an original scene.

All four reports have the same picking census: 530 bound meshes, 806 colliders (584 target, 222 walkmesh), 87 entities, zero missing bindings. This proves that the merge did not remove those owners; it does not assert every ray result. The small existing Vulkan fixture recorded 52/52 checks, byte-identical 640×360 individual/merged images, source hit equality, shadow-light teardown, withdrawal and retirement (`tools/nwn77/static-world-draw-grouping-preflight.md`). That fixture predates the current one-lookup source-ID enrollment edit, whose output semantics are unchanged.

## Saved-image comparison

I inspected the four `native.ready.png` and four `native.png` screenshots. The same-camera original view has no obvious absent wall/ground surface, transparency, fog or lighting change. `tools/nwn77/compare-saved-images.ps1` compares all six OFF/OFF, ON/ON and cross-mode pairs over the 3200×950 world crop; output is `.cache/nwn77/static-visual-a/pixel-pairs.json` (SHA-256 `61d4a03e6ac60b09a1b54726b4e22be9879ba164498311df84ca3b9ed6903fe1`). Same-mode differences establish temporal/rendering noise. A stricter four-image filter counts a pixel only when both within-mode RGB sums are ≤8 and the average cross-mode RGB sum is >24. It finds 983/3,040,000 candidate mode-specific pixels in the ready images and 701/3,040,000 in the later images; report `.cache/nwn77/static-visual-a/pixel-pairs.mode.json` (SHA-256 `6e784773070a075a2818d64e6292d17944c1741396a2bfb45f58214c7dd5a6a9`). These sparse pixels are not classified to a surface or cause. The original-scene images are **not pixel-identical**, and this check does not prove full visual parity.

## Transition gate

`world_retirement` reports zero released/retired worlds in all four legs. The saved replay therefore never exercised an area transition. `tests/native_static_scenery_merge_test.gd` tests owner clear, withdrawal and stale-worker retirement on a small authored fixture, but it does not call `AreaStream.open_network_area` for a second original area. `tests/native_world_transitions_test.gd` requires a live server transition door and a potentially 35-second authority wait; it is not a short deterministic replay fixture. No existing short replay with static merge and a real area change was found under `tools/` or `tests/`. The missing acceptance is a pinned two-area replay or live transition that verifies old source draws/worker results retire and the new area's eligible/suppressed counts, picking and appearance settle correctly. I did not launch a full client or measure FPS.
