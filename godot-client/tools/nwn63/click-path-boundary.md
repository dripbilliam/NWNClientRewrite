# NWN-63 click movement source boundary

`systems/world_input.gd:57-64` retains the latest left-button press and point. On the next eligible pointer step, it calls `registry.pick` and invokes `action(hit)` once (`:71-104`); UI blocking clears the pending press, and focus loss clears it (`:144-149`). The live owner binds this action to `world_action` at both creation sites (`native_live_world.gd:160,469`). The owner is recreated on area transition.

`world_action` checks loading/UI, current world readiness and target eligibility, then converts ground `hit.position` into a `walk` command, stops held keyboard motion and calls `send(base)` (`native_live_world.gd:810-839`). `keyboard.stop` only ends the current prediction and optionally emits a stop (`systems/native_keyboard.gd:117-126`). Keyboard setup separately binds `predict=world.preview_drive` (`native_live_world.gd:168,478`); the expensive `query_preview` and `planner.path` calls are only in that keyboard preview entry (`systems/native_render/live_world.gd:358-388`). Thus click-to-walk has a ray-pick/command route and does not invoke the local preview solver. No click code was changed, and no preview reduction is claimed for click movement. This is a static source finding, not a live-server timing result.
