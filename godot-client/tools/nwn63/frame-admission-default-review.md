# NWN-63 native keyboard frame admission default

Current working source `native_live_world.gd` now calls `set_frame_input_admission` with a default-true `nwn/private/keyboard_frame_admission` setting at both keyboard creation sites (initial world and area transition). `project.godot` does not override that setting. An explicit false setting retains the previous immediate OS-event route for rollback. The shared preview solver, synchronous programmatic key API and click route are unchanged. Working source SHA-256 after this two-line change: `372ee7b93d58babd2187da383aac47600f2a7ce5b2625f9bdbfa53fa848aec92`.

The exact frame-admission logic in `systems/native_keyboard.gd` was already tested as the private candidate. The original-client coordinator drains key events before one held-key scheduling tick. The prior graphical original-scene ABBA burst gate had 119 previews/120 packets per default-off leg versus 60 previews/61 packets per admission-on leg, and burst median 12.108 to 10.4705 ms with p95 13.0825 to 11.231 ms. Whole ten-second steady mean changed only about 0.121 ms; this is a burst-work reduction, not an accepted broad FPS gain. See `.cache/nwn63/frame-input-live-graphics-e/abba-review-b.json` SHA-256 `fc12815b344c7bfc13e88bd6827af2b644660c98b74b6c864fe21df01ed053b5`.

The current keyboard class also contains later async-preview token/completion support and an idle-flush fast return. The latter avoids an empty-frame `update_input()`/`stop()` and its cancellation-generation churn. The current-source engine gate `tools/nwn63/keyboard_frame_gate_test.gd` passed 16/16 checks, including an actual OS W echo burst reduced from two previews to one, 250/500 ms cadence, immediate release, reentrant input and actor-scope cancellation. The existing private graphical candidate checks cover request/ACK sequence, partial path resend and door/creature changes between admission and flush. No new graphical/FPS run was launched for the default and idle edits. They do not solve click-to-move or a single expensive collision search. Keep NWN-63 In Progress for live keyboard/click acceptance and measured normal-client preview tails before declaring the ticket complete.
