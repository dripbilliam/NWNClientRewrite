## Already selected: settled admission plan

The active entry `native_live_world.gd:6` instantiates `live_world_pending_appearances.gd`, which extends `live_world_support.gd`, which extends `live_world_quiescent_candidate.gd`, which extends the authoritative `live_world.gd`. The quiescent layer checks an exact empty plan, then validates that each desired appearance key is installed or failed before returning an empty plan on subsequent unchanged frames. It invalidates on full/delta receive, explicit instance removal, scope and lifetime changes; the sparse pending-ID layer retains only unresolved IDs during active preparation. Thus the measured stable-frame full-registry planning scan is already addressed in the active client. Reimplementing the same skip in `live_world.gd` would duplicate policy.

The existing correctness report `reports/native-world-quiescent-v3.json` passed 236 checks, including 2,001-object settled frames, exact-key replacements, failures, possession, removal and reentrant invalidation. `reports/native-world-quiescent-evidence-v1.json` recorded an instrumented dense-scene World callback mean of 1.813/1.792 ms for two baseline runs and 0.237/0.231 ms for candidate cold/warm runs. This establishes a scoped owner CPU reduction. Its own `unprofiledConclusion` says no matched FPS gain was established; the capture's postprocess fixture was also incomplete. The source pins in that report differ from the current workspace, so it is historical evidence of the approach, not a current-build benchmark.
