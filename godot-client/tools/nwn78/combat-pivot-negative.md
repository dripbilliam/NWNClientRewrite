# NWN-78 current combat pivot duplication bound, 2026-11-12

The current `systems/combat_animation.gd` SHA256 `d80611b55704feba5aab282fe4dd4d8b4082228c86ad0c2b889b1587e97f980a` matches the NWN-61 original-scene production pin. `LiveWorld.apply_pose()` calls `CombatEngine.base_frame()` for each admitted creature, which refreshes its actor position and trigonometric orientation from the Node3D pivot. Later in the same world callback, `CombatEngine.update()` enumerates all actors and repeats that refresh. This is genuinely duplicated for creatures that receive `base_frame()` before `update()` and whose pivots remain unchanged between those calls.

An actual headless SceneTree component with 32 and 128 creature actors, all with valid rig states and pivots, bounded the second refresh. Its optimistic candidate suppressed that entire refresh without a guard and retained final actor/animation state in 16 checks. ABBA medians for 128 actors were 466/427/423/463 microseconds per frame (control/candidate/candidate/control), an upper bound of roughly 38–40 microseconds per 128 actors. The 32-actor case saved roughly 6–9 microseconds. This is a small component saving, not an FPS result or a direct dense original-asset count.

The optimistic suppression is unsafe: external pivot or actor edits between `base_frame()` and `update()` would be overwritten by the original second refresh. A private copy of the current engine stamped each `base_frame()` position, rotation, and actor orientation, then skipped refresh only if the pivot and actor still matched. The fixture edited a pivot's position/rotation and an actor's position/orientation between the two calls. All 16 final-state checks passed, but ABBA medians **regressed**: 128 actors 472/501/501/462 microseconds; 32 actors 117/125/123/114 microseconds. Stamping and checking consumed more than the refresh saved.

The tested candidate is rejected. No production source was edited. The private fixture and candidate are `tools/nwn78/combat_pivot_component.gd` and `tools/nwn78/combat_animation_pivot_candidate.gd`; raw reports are `combat-pivot-component-a.json` and `combat-pivot-component-b.json` in this directory. The original second refresh remains necessary under current external-edit semantics. A future change would need a cheaper reliable transform/actor dirty signal or an ownership contract that proves no intervening edits.
