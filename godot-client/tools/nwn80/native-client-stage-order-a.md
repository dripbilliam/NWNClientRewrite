## First implementation milestone

Add a **diagnostic-only, generation-scoped ordered event trace** to an isolated client selection for: area accepted, definition ready, each model request/completion, each tile index published, full-registry boundary start/end, controlled instance installed, first visible world and first input enabled. Include cache hit and cold/warm/transition labels. Pair it with native debugger/trace observations of tile index/model resref visits, selected-creature publication and first usable input for the same area. Compare order and readiness before changing `refresh_priority` or publication. A candidate correction must preserve resource precedence, snapshot message order, cancellation and full population, and measure first playable plus known-base completion. The saved client F pair illustrates why a shorter pack tail alone is insufficient: its candidate removed a large pack tail but usually added loading time.

No source edit or loading/FPS claim follows from this table. Cold versus warm native cache branches, native first-input gate, and timing at original tile/creature boundaries remain unmeasured.
