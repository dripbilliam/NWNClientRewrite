The pinned native edge is now closed through saved decompilation. `ProcessStaticParts` stores the own `TileData*` on each TriMesh Part at `Part+0xa0`, diverts class `2` into that TileData's `+0x90` Part list and class `4` into its `+0xb0` list; class `1` stays in the residual list at `+0x30`. `Scene::SpawnTile` finds neighboring TileData and copies each class-`4` Part pointer from the originating `+0xb0` list to the neighbor's `+0xa0` list in both directions. `ProcessTriMeshParts` visits a visible BSP node's residual Parts: class `1` and a matching geometry-fade mode read the Part's TileData, test camera fade-plane coordinates and TileData state, then add that TileData uniquely to `fadinginbucket` or `fadingoutbucket`. `Scene::ManageSceneBSP` runs the fade handlers after visible-node traversal. The handlers append the active TileData's own `+0x90` Parts and its neighbor `+0xa0` Parts (the latter gated by the Part owner's fade at `>=1`) to the cap list while TileData fade is `<=1` and `!=1`. `AddPartsToDrawBuckets` still requires each Part to be renderable before bucket `7`; `RenderSinglePass` draws bucket `7` after static transparent bucket `1`, before dynamic geometry. Thus class `2` supplies own-tile caps and class `4` supplies neighbor caps, but the census is not a live cap draw count. The client parser preserves `native_tilefade`, and `systems/native_render/model_instance.gd` retains physical part metadata in `native_mesh_source`. `model_template.gd` and `area_stream.gd` publish ordinary tile mesh instances. `native_scene_visibility.gd` handles network tile fog and object perception; it does not supply the native camera/BSP fading-node state. `camera_controller.gd` updates the view pose but does not derive native fade planes. The current Forward+ renderer combines scene opaque and transparent lists, so a material priority alone cannot establish bucket `7` between static transparency and dynamic opaque geometry.

**Implementation boundary:** Add a generation-scoped opt-in tile-fade state owner only after the exact camera plane coefficients and active original setting are established. At tile publication, enroll class-`1` residual meshes and class-`2` own/class-`4` neighboring cap meshes from `native_mesh_source`; link neighboring tiles in original `SpawnTile` order. Update visibility/fade membership from camera and authored state, and retire it with the area. A renderer pass or equivalent scene split must place cap draw after static transparent and before dynamic geometry. Do not create always-on duplicate caps or drive them from network tile-fog updates.

**Focused original-asset acceptance:** Use a recorded `udcitydist1a` tile containing the relevant class-`1` fade geometry and class-`2`/`4` special parts, an overlapping static translucent surface and a dynamic actor. At fixed camera-follow poses before, during and after an obstacle fade, compare visible caps, opacity, overlap and pass order with the original client; then reset/transition the area and assert no old cap survives. The opt-in tile publication lane itself also needs an original-area visual order/transition check before becoming default. FPS is outside NWN-80 acceptance.
