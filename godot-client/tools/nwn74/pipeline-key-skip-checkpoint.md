# NWN-74 private pipeline-key arithmetic gate, 2026-11-12

The two latest live Arelith Tracy captures expose `draw_cpu` but no inner Forward+ spans. Their active-window render-thread means are 4.275 ms control and 4.084 ms candidate, with unequal routes; these are context, not an intervention result. The prior settled original-scene census measured about 3,054 Forward+ draws/frame, 189 pipeline lookups and 2,865 hash-based pipeline reuses. It measured 0.80 ms in the Forward+ draw list. Reuse is only an upper bound on exact key matches.

The accepted Forward+ source (SHA-256 `fe8b102c6742d12f8a51a7312bfa8b72596277ee7d2f429fce5c97d6e03846dd`) hashes an 11-field pipeline key on every draw, including the reuse branch. `prepare-pipeline-key-skip.cjs` created a **private** one-translation-unit candidate at `.cache/nwn74/pipeline-key-skip-a/render_forward_clustered.cpp` (SHA-256 `e4489af813158fd061fe8413331080fb540ce2e640ef1491f5ead4857b49106c`). It compares the exact 11 hash input fields with the last successfully selected key and reuses its hash when the shader and key match. Hash collisions retain the old hash-based branch behavior. The accepted engine source, executable and client remain unchanged.

`pipeline-key-skip-oracle.cjs` checks that all 11 fields are compared in hash order and simulates 214 draws, individual field changes, shader changes, failed first-pipeline attempts and forced hash collisions. Decisions, lookups and binds match the old path. In the normal synthetic stream, hash calls fall from 215 to 16; with forced collisions, 215 to 114. This is a source/state oracle, not rendered output or a real-scene count.

`pipeline-key-cpu-bench.cpp` compiles standalone with MSVC `/O2`. Its 3,054-draw synthetic loop, best of five 1,500-frame rounds, measured 9.185 to 2.222 ns/draw for runs of 16 repeated keys, 8.239 to 4.833 ns/draw for runs of two, and 7.945 to 9.341 ns/draw for all unique keys (old to candidate). At the favorable 16-repeat setting, the arithmetic saving is about **0.021 ms/frame**. This is too small against the 0.80 ms draw list and 4 ms live render-thread lane, and the unique-key case regresses. No actual-scene exact-key count or full-engine timing is available. This candidate remains private and is **not recommended for promotion** without a measured inner phase and a stronger net benefit.

Checks: `node --check` and the source oracle passed; the standalone MSVC compile/run passed; the accepted source hash remains pinned. No engine build, FPS benchmark, graphical test or normal-client A/B was run. NWN-74 remains In Progress. A useful next gate needs inner phase timing at `_fill_instance_data`, `_fill_render_list`, sort, `_render_list_template`, shadow prep and draw-graph submission in the same busy scene, with state counts and a matched client pair only after a larger exact-work candidate is found.
