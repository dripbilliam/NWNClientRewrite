# NWN-74 bounded draw-thread source audit, 2026-11-13

This is a read-only follow-up after the vertex-array cache failed to show a repeatable whole-frame gain. The accepted Forward+ source `render_forward_clustered.cpp` remains SHA-256 `fe8b102c6742d12f8a51a7312bfa8b72596277ee7d2f429fce5c97d6e03846dd`. No engine/client source, binary, rendering settings or FPS measurement changed.

The saved original-scene probe has 3,054 Forward+ draws/frame, a 0.78–0.80 ms draw-list template, 0.29 ms `_pre_opaque_render`, 0.15 ms `_fill_render_list`, 0.09 ms sorts and 0.07 ms `_fill_instance_data`. These are nested or separate spans and cannot be added to the live Arelith `draw_cpu` mean of 5.30 ms, which came from a different scene. The saved draw census already shows 2,865/3,054 pipeline reuses, 747 material uniform binds and only 11 transform binds. The existing warm shader vertex-input-mask cache, pipeline/bind guards and prior failed vertex-cache experiment rule out those apparent duplicates as a quick follow-up.

I inspected `_pre_opaque_render` and `_fill_render_list` in the pinned source. The former classifies each shadow light and calls `light_get_type(base)` twice for a non-directional light. Hoisting that getter into one local enum would remove at most one call per non-directional shadow, roughly six shadow lights in the saved scene, far below the previously removed 791 material marks/frame that showed no repeatable FPS gain. The same function deliberately renders cube, directional and positional shadows through distinct passes, then updates light/decal buffers, cluster data and optional effects. Removing one pass from those counts would change visible coverage. `_fill_render_list` computes camera-relative depth, fade and LOD distances with different semantics; it also mutates flags, GI offsets and motion state by pass. Those are not interchangeable duplicate calculations. Its `_update_dirty_geometry_instances()` call already drains an empty list cheaply and checks pipeline dirty state before regenerating any pipeline.

No short, safe same-frame guard with meaningful measured work remains in these examined spans. A new production edit on this evidence would add maintenance without a credible reduction. The next NWN-74 gate is a count-only inner operation census on the same busy scene for shadow preparation, `RendererSceneCull` visibility admission and RenderingDevice submission, followed by a private change only when a repeated idempotent operation and its cost are actually measured. Do not infer FPS from this audit. NWN-74 stays In Progress.
