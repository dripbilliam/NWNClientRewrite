# Native map and journal

Status: **partial native multiplayer presentation verified locally**. The
complete migration and moving-world performance goal remain active. No Arelith
connection or original-client modification occurred.

## Native behavior

The quickbar exposes Map (M) and Journal (J). Both are independent draggable
windows, can remain open together, retain their last positions on reopening,
and participate in the existing window stacking. Outside clicks, WASD and
middle-mouse camera input continue to reach the world.

`tools/map-service.mjs` reads actual area tile placements, the installed SET's
ImageMap2D references, replicated exploration, server waypoint map notes and
received player map notes. It reuses the unchanged original-derived
`presentMapPin`, `playerMapPosition` and `mapPlayerHeading` helpers. Only tile
state exactly 1 is revealed; no local visibility/exploration is calculated.
Disabled, removed and unexplored pins stay hidden. Delayed pin-name resolution
cannot publish a superseded exploration/pin snapshot.

The isolated v27 staging helper reuses `NativeUiAssets.mapTileSkin` and original
CTL_ICON_AREAMAP/CTL_MAP_PIN/CTL_MAP_XMARKER resources. It rasterizes each unique
tile/quarter-turn and normal/hover/down/player control art; Godot receives PNGs
with original bounds and performs native drawing. Four bounded art jobs run in
parallel. Closing, area/control/world changes and late results are scoped to
the private map view. Art retirement waits for pending jobs. This reuses the
existing resource backend; Godot owns the visible map, menus and frame loop.
Zoom is 8/16/32/64 pixels per tile, initially the original 16; scroll clipping
avoids drawing offscreen tile artwork. Pin hit testing shows the supplied note,
and the player's original projection/heading follows real movement.

`tools/journal-service.mjs` sends the existing typed native journal open/close
subscription and projects canonical journal state into Quests, Completed,
Notes and Messages. Received localized titles/descriptions, custom/name
tokens and byte RGB controls pass through the existing text parser to explicit
native rich spans. Server completion/removal changes category membership.
Empty loaded categories and pending server data remain distinct. Private view
handles gate category changes; late text and close acknowledgements cannot
overwrite a reset/reopened window. It does not execute local quest logic.

## Shared cleanup correction

The previous short-run leak was traced to `server_inventory.gd`: setup created
an AC Label without parenting it until the first inventory render. A client
that never opened inventory left this blank native Label orphaned, retaining
font/theme resources and associated textures. It is now parented to equipment
during setup, and normal rendering/reset already preserves that owned child.

The old failures remain: map/journal v1 and `native-map-journal-cleanup-v1`
pass behavior checks but fail final lifecycle acceptance. The diagnostic traced
the blank, unscripted orphan Label. Standalone authored texture/cursor cases
exit cleanly and did not reproduce it. The attempted delayed shutdown from the
earlier milestone was ineffective and was removed. The actual correction is
ownership at creation, not forced freeing arbitrary orphan nodes.

**`native-dialogue-cleanup-fixed-v1.json`** now passes all 16 original short
dialogue/examine checks and exits cleanly **without opening inventory**. The
final map/journal and level-up regressions likewise have no leak/error output.
The stricter host acceptance still checks terminal output and rejects leaked
RIDs/ObjectDB instances or unsuccessful native exit codes.
