# Native server-vault reference transfers

Both native43/3 reference variants now complete real owned-server A→B→A:
account-vault source17 and base-server-vault source2. Godot performs initial
server selection through its native lobby, then the existing protocol owner
logs into each destination using the exact transferred reference. No local BIC
is selected or uploaded. Normal-client transfer adoption remains disabled until
cross-server NWSync/content changes are verified. Full multiplayer migration and
performance acceptance remain incomplete. No online game server was queried or
connected.

## Implementation and isolation

`tools/vault-handoff-fixture.mjs` creates two fresh external temporary profiles
from the existing hash-verified authored GodotHandA1/B1 modules. Their
servervault folders are junctions to a single fresh external test vault, matching
the authoritative shared-vault setup needed by reference transfers. All roots,
profile paths, module hashes, junction targets and loopback ports are checked
before use. The server helper manages only the exact installed binary and exact
owned profiles. No recursive cleanup traverses a junction or other profile.

The seeded character is generated by the replacement creator using installed
rules: a new level1 Wizard named Native Vault Handoff, reference `native_hand`.
Original art is referenced only. Generated BICs remain outside the workspace.
Source17 uses the private account subdirectory; source2 uses the base vault.
Neither account identifiers nor CD-key material are exposed to Godot or reports.

`tools/seed-vault-handoff.cjs` reads the existing protected CD key privately,
creates the authored seed before server startup, hashes it, verifies that the
protected settings file is unchanged, disposes its login identity and exits.
It creates no game session or game-server connection. The live host verifies
the seed length/SHA256 before using an existing seed. Missing, tampered, foreign
or wrong-source seeds are refused. Its older dynamic seeding path remains useful
for account-vault-only tests; base-vault fixtures must be preseeded because the
server builds its resource index at startup.

Only the explicit `--portal-handoff-smoke --portal-vault-fixture=<fixture>`
regression path selects the authored reference automatically. Native normal
startup and public-server selection retain their existing behavior. The test
host records only wire major/minor/length and whether each Play packet equals
the canonical reference request; no raw credential or BIC payload is logged.

The common presentation gate now handles rigid-only actors as well as skins.
The new branch requires the native import inventory to report zero skin meshes,
positive rigid meshes and no import failures, plus actual controlled-actor
walk/run clips, advancing clocks and changed local parts. Skinned models still
require measured vertex deformation. This corrects a test assumption rather
than substituting a still character or NPC animation for player locomotion.

## Reproduction and retained failures

Create an unused fixture report with
`node godot-client/tools/create-vault-handoff-fixture.mjs --report=vault-handoff-fixtures-vN.json --source=17`
(or `--source=2`). Run `tools/seed-vault-handoff.ps1 -Fixture <name>` before
`tools/vault-handoff-server.ps1 -Action Start -Fixture <name>`. Then run
`test-handoff.ps1 -Scenario vault -FixtureReport <name> -Report <unused.json>`.
Ports5121/5122 must be free or already owned by those exact test profiles; never
replace an unrelated server. Stop only those exact profiles afterwards and
restore the ordinary owned GodotFeedback1 server. The editor is preserved.

Account-vault v1 joined and animated, but the old generic movement gate demanded
GPU skin deformation even though the new character contained only rigid meshes.
That failed report is retained; the corrected gate additionally requires actual
controlled locomotion and an independently reported rigid-only import inventory.
Account v2 subsequently passed, and v3 verifies the finalized preseeded pipeline.

The first base-vault run seeded after server startup and advertised zero choices;
it reached its deadline and remains failed. The startup log had zero entries in
the SERVERVAULT resource table. Preseeding before startup resolves it in v2.
Static original evidence is consistent: original client hash
`3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`,
retained `rea-server-vault-charlist-send.json`, function0x1404d1260, enumerates
the base `SERVERVAULT:` alias by resource type2015. This is static evidence,
not a claim that the entire original sender was emulated. Installed server hash
`98951511ae7d06a251355f12d4f3e4b96269a2414fa3058e641afd70098690f6`
is checked before launches. Originals and their running processes are unmodified.

Initial launcher attempts also exposed a case-insensitive PowerShell parameter
collision; it was corrected before any client launch. A subsequent text edit
briefly duplicated the launcher; parsing was checked after removing the duplicate.
Neither attempt connected to a server or is counted as a successful test.

The preserved editor prevents clean FPS benchmarking. Sparse-fixture counters
are not complete moving-world60FPS evidence. NWSync changes across server
transfers, public-server acceptance, broader NUI/rendering/weather and remaining
migration work are still open. Online game-server tests remain prohibited until
the user returns and reauthorizes them.
