# Rig resource loading, inheritance, and instance binding

The stock evidence here covers the pinned Windows `nwmain.exe` with SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Addresses are preferred PE virtual addresses. The source cohorts differ in architecture. Stock retains parsed `Model` and `Animation` trees and constructs mutable `Gob` and `Part` instances that refer to those trees. The client prepares portable model and clip data on workers, then constructs mutable Godot scene nodes, tracks, and playback owners on the main thread. A resource hit, a prepared-model hit, and a bound-track hit therefore refer to different stages. ## Stock request and parse

1. The creature vtable selector `+0xf0` resolves to `CNWCCreature::LoadModel` `0x140802cc0` from the constructor-installed table `0x140e474e8`. It is an admission/rebuild method. The runtime callsite distribution has not been measured. The scene-model route through `NewCAurObject` `0x1400931f0` has named and explicit-stream branches. [Creature ingress](../../godot-client/tools/stock-render-tree/creature-model-load-virtual-source.md) · [Scene instance branch](../../godot-client/tools/stock-render-tree/model-instance-branch.md)
2. `FindModel` `0x140098cd0` rejects null/`NULL`, then binary-searches the live, case-insensitive Model table. A hit returns the existing tree without resource demand or parsing. A miss calls the named `IODispatcher::ReadSync` `0x140079f70` through `0x140098ecf` and temporarily installs the top-level whitelist and `currentmodel`. The explicit `_iobuf*` route instead reaches `LoadModel` `0x1400a0130` and `ReadSync(_iobuf*)` `0x140079e40`. Its parsed result can be destroyed after it finds an existing same-name Model. This explicit-stream behavior is separate from the original named hit. [Name and resource gate](../../godot-client/tools/stock-render-tree/model-name-parser-tree.md#name-and-resource-gate) · [Explicit stream branch](../../godot-client/tools/stock-render-tree/model-instance-branch.md)
3. Named requests resolve through `AurResGet` `0x14005dbc0` and its constructor-installed `CAuroraInterface::GetResource` callback `0x1400f63d0`. Its MDL wrapper `CAuroraModel::LoadModel` `0x1400f4a70` demands `CResMDL` through `CRes::Demand` `0x14018f300` and `CExoResMan::Demand` `0x14018ef90`. The resource manager can reuse resident bytes or service storage class 1 (resource file), 2 (encapsulated), 3 (directory), or 5 (manifest). Named `AurResGet` permits CRT file fallback only on callers with the fallback argument set. The byte and wrapper lifetimes are independent from the parsed Model pointer table. [Resource and storage map](../../godot-client/tools/stock-render-tree/model-resource-storage.md) · [Wrapper teardown](../../godot-client/tools/stock-render-tree/aurora-layered-model-cache-retirement.md)
4. `0x140079a80` checks the first byte after a four-byte read. Binary data goes through `0x140079d50`, which copies the principal block and optional raw geometry block before `0x140079f90` builds the `0x110` Model. The parser retains its supermodel through `FindModel` and an added reference, builds each `0xe8` Animation from the offset table, and invokes the same typed constructor `0x14007abe0` for clip roots and physical geometry. `0x14007b6c0` rebuilds child and controller arrays and relocates serialized controller destinations into live Part field offsets. It preserves key counts, data offsets, component/mode bytes and authored omission of channels. Subtype vertex and skin data cross CPU render-pool request/lock/copy/unlock paths. 5. Text data is probed, released, and then read again by `dofile` with local fallback disabled. `FuncInterp` matches registered command holders under the whitelist. `newmodel` constructs the typed Model, `setsupermodel` binds the parent, and `beginmodelgeom` imports a named child hierarchy and synchronizes IDs to the supermodel where present. `newanim` constructs each clip tree, post-processes it, and synchronizes it to the owning physical tree. `ParseNode` dispatches `+0x8` typed field parsers and `+0x10` post-processing. ## Stock inheritance and binding

The original retains its parents as Models. The binary parser adds a reference after the named lookup. Text `setsupermodel` `0x1400a19c0` drops the old reference, stores the name at Model `+0xd0`, then stores and retains the resolved Model at `+0xa8`. Text `newanim` `0x1400a17f0` adds one locally authored pointer to the owner's `+0x98` animation list and updates count `+0xa0`. The imported clip's post-process can trim it to its authored animation root and clear ancestor controllers. `SynchronizeTree` uses names to bind the text trees to compatible node IDs. Animation runtime consumes matching Part IDs in those trees. The stock binary path consumes the compiled node identity in its typed constructor. [Text commands](../../godot-client/tools/stock-render-tree/model-text-other-command-holders.md#model-state-and-typed-descendants) · [Hierarchy and render-visible output](../../godot-client/tools/stock-render-tree/original-scene-animation-nonemitter.md) · [Construction and transition evidence](../native-pipeline-comparison.md#omitted-properties-in-clip-transitions)

The selected `Animation*` stays on the native run. `Gob::PlayAnimation` `0x140052580` invokes the same animation-lookup leaf `0x140050f80` at `0x1400527a1` and `0x1400527bc` for the optional Gob Model `+0x80` and fallback Model `+0x68`. It calls `FindAnimScale` `0x140050ed0` at `0x140052895`, then stores its factor at `AnimRun+0x20`. The scale helper searches each Model's local animation pointers, multiplying each traversed descendant Model's `+0xcc` only until it locates the exact pointer and follows parent `+0xa8` when needed. That factor is used for live position sampling. It preserves one shared parent curve for multiple child scales and has no effect on playback speed. Its long-list search may reorder pointers, which matters when testing lookup order and makes the registry itself distinct from immutable curve values. ## Stock instance publication and lifetime

The creature loader can adopt an existing pending animation base from creature `+0x3e0`, retiring its old base, or construct one of six known owners when creature `+0x78` is empty. Model-kind values `0/1/2/3/4/11` call `CNWCAnimBase`, `Head`, `Wield`, `HeadWield`, `Parts`, and `TW` at `0x140802f16/0x140802f68/0x140802fa6/0x140802fd5/0x140803004/0x140802f41`. The owners keep the Gob at `+0xc8` and expose it through their model interface. This dispatch explains why one creature can have different setup and playback responsibilities. The mapped named request path calls a synchronous loader from its caller. The binary separately has async I/O methods for other consumers. ## Client request, preparation, and handoff

1. `CreatureStream` prepares appearance tables and body, equipment, and reference descriptors. It groups requests within the stream by a piece key that includes relevant appearance options, then calls `AssetService.request` for `2002`, decoder `actor-model`, with relevant-node selection. Owners such as a placeable or GUI icon have distinct decoder and preparation routes. The catalog selects a mounted winning source and gives each worker a reader fork with generation-bound source and cache ownership. [Creature planning and request](../../godot-client/systems/native_render/creature_stream.gd#L191) · [Catalog forks](../../godot-client/systems/native_data/resource_catalog.gd#L86) · [Request and jobs](../../godot-client/systems/native_data/asset_service.gd#L89)
2. The worker's installed KEY name fast path runs before resource read and source digest. It can return a prepared bundle on a valid catalog-scoped named alias. Other cohorts resolve bytes, hash them, then check a content/options preparation key and optionally checked disk prework. The worker's separate decoded tier coalesces unfinished jobs by source and parser identity, retains frozen model node and controller storage, and hands out private owners for the model fields that get edited. The worker still deep-copies ordinary prepared bundles on cache retrieval. [Named and content lookup](../../godot-client/systems/native_data/asset_service.gd#L126) · [Immutable source and working model copy](../../godot-client/systems/native_data/asset_service.gd#L530) · [Preparation store copy policy](../../godot-client/systems/native_data/preparation_store.gd#L54)
3. `actor_data_serial` handles the binary/ASCII actor result. It filters transform and emitter tracks to relevant names, retains a source-chain identity, requests and recursively loads parent `2002` resources, and rejects cycles or depth ≥16. `inherited_clips` applies exact-name local override selection, copies clip/track records, aliases the parent-root name to the child name, and applies descendant position scale. For packed tracks it records scale without expanding coordinates or copying the raw controller pool. Own clip and inherited clip events, unsupported fields and root metadata stay available. Resource options such as palettes, substitutions, and absent texture resolution have their own identity and correctness guards. [Source-chain and projection](../../godot-client/systems/native_data/asset_service.gd#L422) · [Rig asset](../../godot-client/systems/native_data/actor_model.gd#L416)
4. `rig_data` reads or builds a source-chain-keyed prepared rig dictionary. `ActorModel.rig_asset` prepares default transforms, lowercased physical-name/row bindings, supplied clip keys/pools and authored event rows. It derives the controlled-property union and clip index once per prepared cohort. The separate opt-in `--shared-animation-preparation=true` partition includes source-chain and selected-view identity. Its lifetime is separate from ordinary decoded-source coalescing and the resource pool's GPU resources. [Rig data variants](../../godot-client/systems/native_data/asset_service.gd#L502) · [Selective partition](../../godot-client/systems/native_data/shared_animation_preparation.gd)
5. Completed pieces feed an `ActorInstance`. The instance builds the private part hierarchy and inferred attachment mapping while pulling immutable geometry, textures and materials from the shared pool. The staged path steps preparation and publishes a complete actor, retaining previous scene state until commit or cancellation. `RigConstruction` maps the part hierarchy to normal `Node3D` owners or an optional `Skeleton3D` branch, binds meshes and skin data, resolves each model asset, and commits the hierarchy and initial sample. Each animated model creates a private `AnimationPlayer` and an `AnimationLibrary`. The indexed and lazy clip route uses the prepared union and binds relative NodePaths at first use, creating an `Animation` with actor-owned paths, transitions, loop mode and clock. Packed, byte-exact templates serve normal transform keys and normalized arrays serve packed Bezier keys. Those caches leave physical part/application state private. Deletion retires actor presentation and worker leases; the session pool can retain reusable render resources over travel.
