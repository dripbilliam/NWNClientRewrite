# Rig pose consumers and retirement

This lane begins after animation controllers produce a local pose. The stock addresses are virtual addresses in the pinned Windows x64 `nwmain.exe`, SHA-256 `3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`. Source links for NWNAnalog describe the ordinary Node3D rig unless they explicitly name an alternate. The stock map establishes ordering and ownership. The cited performance captures provide separate evidence about runtime cost.

## Stock pose to frame

```text
Gob / current LOD root Part
  local translation, orientation, scale and subtype fields
  ├─ Part::GetWorld → parent Parts → adjusted Gob transform
  │    ├─ attachment behavior and dependency propagation
  │    ├─ moving BSP Parts and emitter preparation
  │    └─ lighting, independent view/camera and specialized Part users
  ├─ admitted Gob → active root → recursive Part matrix stack → draw bucket
  │    ├─ rigid mesh → current primitive matrix and draw
  │    ├─ admitted Skin draw → GatherBones → palette → GPU skin draw
  │    └─ AnimMesh, DanglyMesh, light and reference continuations
  ├─ caster/light admission → eligible Part shadow projection
  └─ owner expiry or replacement → detach callbacks and Scene membership
       → destroy Parts and primitives → Model refcount and pool release
```

### Local fields, hierarchy and bounds

- A Part stores local position at `+0x10`, quaternion at `+0x1c`, parent at `+0x48`, and owner Gob at `+0x50`. `Part::GetWorld` `0x14008f870` returns local fields directly on the ownerless branch. The owned branch ascends the parent chain and combines adjusted Gob scale, position and rotation. The original composes this result on demand. The BSP routine `ManageSceneBSP` calls this operation at `0x1400db808` for moving Parts and compares the current placement before relocating membership. [Part and Gob position rules](../../godot-client/tools/stock-render-tree/original-scene-animation-nonemitter.md#hierarchy-control-and-render-visible-output) · [Moving BSP](../../godot-client/tools/stock-render-tree/scene-bsp-frame-maintenance.md)
- `Gob::GetMinimumSphere` `0x14008ee60` refreshes bounds during construction and at admitted animation visits under the observed modulo-five gate. `Part::GetMinimumSphere` `0x14008ef40` recursively combines child spheres using the child local transforms. `PartTriMesh::GetMinimumSphere` `0x14008f250` adds the eligible mesh's authored bounds. The Gob then stores scaled center and radius. The animated root can still be changed by LOD before draw. [Original bounds call and subtype tables](../../godot-client/tools/stock-render-tree/original-scene-animation-nonemitter.md#scene-gob-and-part-order) · [LOD and publication](../../godot-client/tools/stock-render-tree/gob-lod-scene-publication.md)
- On the BSP route `0x1400db320` populates the visible Gob bucket and updates LOD. `Scene::AddPartsToDrawBuckets` `0x1400c38f0` processes the visible candidate, then requires Gob geometry and positive visual alpha before sending its active root to `Scene::AddPartsTreeToDrawBuckets` `0x1400c4620` at `0x1400c44ff`. That traversal applies each admitted Part's local transform and scale to its matrix stack, walks children in stored order, publishes the current matrix into the primitive, and selects material buckets. `Scene::RenderDrawBucket` `0x1400cd8d1` dispatches the Part draw. The no-BSP and separately rendered Gobs use `Gob::Render` `0x1400a4280` and `Gob::PartDraw`. [BSP and draw dispatch](../../godot-client/tools/stock-render-tree/geometry-and-draw-boundary.md) · [Direct Gob and sky route](../../godot-client/tools/stock-render-tree/scene-no-bsp-sky-gob.md)

### Equipment, authored references and attached Gobs

- `Gob::AttachToObject` `0x14008c540` resolves a root or named Part and admits base, translate, rotate, no-orientation and GUI-scale behaviors. The behavior stores the live referenced Part and owns callback registrations on the target Gob. `CAurBehaviorAttach::Control` `0x140054cb0` reads that Part through `GetWorld` at `0x140054db4`. Position, Scene, color, illumination and view callbacks can propagate along attachment links. The immediate render route raises `propagaterender` after its own draw when its caller requests it. `PropagateRender` `0x140056d80` can call the attached object's `Control(0)` and `Render(true)`, enabling attachment traversal. This legacy route can repeat pose reads at rendering boundaries. [Attachment behavior and render reentry](../../godot-client/tools/stock-render-tree/original-propagaterender-attachment-reentry.md)
- For the conditional skinned-head branch, head setup `0x14099b1c0` calls `ContainsSkinnedMeshes` `0x14008d110`. On success it uses a root attachment and opts into synchronized animation. The ordinary branch uses the named `head_g` hook. The eligible BSP collector walks the attachment parents and calls `SynchronizeHierarchies` `0x1400d4d80` at `0x1400c43b5` when the original child Gob's synchronization byte is set. The helper copies local position and quaternion and matches descendants by model-node ID. The sibling scan can find multiple matches. Binding a rigid item to a hook and copying a skinned attachment's posed hierarchy are distinct operations. [Skinned head synchronization](../../godot-client/tools/stock-render-tree/scene-attached-gob-animation-sync.md)
- `CreateReferenceObjects` `0x14008db90` can build and attach a child Gob directly from an authored Reference Part. It owns the referenced Gob pointer. Reattachment, missing reference and reference-Part destruction travel through the separate typed continuation. A Camera anchored to a Part can consume the resulting Gob pose through `Camera::RenderScene` `0x14005a5d0` and its view transform call `0x14005ae0a`. [Reference creation and reattachment](../../godot-client/tools/stock-render-tree/model-compiled-reference-reattachment.md) · [Camera payload and active view](../../godot-client/tools/stock-render-tree/model-camera-payload.md)

### Skin palette, other Part types and render services

- Skin enters the Scene as a Part under a model Gob. The Skin vtable `0x140d88438` resolves draw slot `+0xc8` to `PartSkin::Draw` `0x1400deb40`. After renderability and material admission, `RenderSkinned` `0x1400e0410` conditionally runs postprocessing for retained temporary data, rejects zero vertices, resets process-global gathered-list counts while retaining capacity, and walks the ancestor chain to seed the inverse transform. At `0x1400e061d`, `GatherBones` starts from the highest reached Part and gathers a pose relative to the Skin. [Skin-to-Scene draw bridge](../../godot-client/tools/stock-render-tree/scene-partskin-gob-draw-connector.md) · [Gathered list lifetime](../../godot-client/tools/stock-render-tree/scene-skin-bone-list-lifetime.md)
- `ExecuteSkinGPU` `0x1400deb90` maps up to 64 authored slots to gathered poses, skips invalid slots, and stops at the second accepted zero index. It combines inverse bind transforms, builds matrices, publishes them through `SetBoneMatrix` at `0x1400dee43`, then draws with skinning enabled. `GLRender::SetBoneMatrix` `0x1400b6950` writes the transposed slot and advances the palette generation on each admitted write. Later per-program comparison determines whether to upload through the highest changed slot. Geometry deforms on the GPU. The bone gather and matrix assembly are CPU work tied to an admitted Skin draw, and the input palettes use retained shared scratch. [Skin palette assembly](../../godot-client/tools/stock-render-tree/scene-skin-palette-matrix-publication.md) · [GL uniform gates](../../godot-client/tools/stock-render-tree/shader-uniform-dirty-gates.md)
- AnimMesh and DanglyMesh are distinct from ordinary Skin, with their own animated geometry and publication routes. They cannot be counted as additional bone-palette writes. Light Parts feed inherited draw color or furnish world position to the light owner. An Emitter Part samples its world pose at `0x14006132d/0x14006145e` before the subtype update at `0x1400615bf`. That pose can still be needed when its owning Gob has no admitted color mesh. [Animated mesh and lifetimes](../../godot-client/tools/stock-render-tree/original-scene-animation-nonemitter.md#skin-pose-draw-and-lifecycle) · [Dangly vertex publication](../../godot-client/tools/stock-render-tree/dangly-animation-dynamic-publication.md) · [Original emitter transform and simulation](../../godot-client/tools/stock-render-tree/animation-and-emitter.md)
- The stock volume-shadow route begins from visible Gobs and applies caster, distance and light admission before walking Parts. `Gob::PartVolumeProject` `0x1400a3550` checks and bypasses Skin and AnimMesh in its local mesh projection branch at `0x1400a3692/0x1400a36a0`. Other routes include separately prepared projections, shadow-light geometry and attached shadow blobs. These select different coverage from a Godot/CX depth map containing skinned mesh proxies. [Volume projection gates](../../godot-client/tools/stock-render-tree/scene-shadow-part-volume-project.md) · [Shadow pass selection](../../godot-client/tools/stock-render-tree/shadows-and-dynamic.md#shadow-pass-selection) · [Attached blob](../../godot-client/tools/stock-render-tree/scene-shadow-blob-model-lifecycle.md)

### Stock retirement

The Gob's deleting slot `0x14008a850` calls `Gob::~Gob` `0x1400889c0`. The destruction route raises `Dying`, clears animation/behavior state, detaches its Scene, destroys its Part trees and releases corresponding Model references. `CAurBehaviorAttach::~CAurBehaviorAttach` `0x140054390` deregisters the saved target callback handles. PartReference deletion can recursively destroy the owned referenced Gob. TriMesh/skin primitive cleanup releases per-instance objects and VDO items. Model-node pools are shared ownership and reach the deeper buffer release only behind last-reference and pool ownership/residency gates. The Scene destructor's separate Repack path can compact surviving VDO ranges and publish backing ranges. ## NWNAnalog consumers

1. **Root and local pose.** `LiveWorld.apply_poses` normally visits network-motion owners, with area initialization or input changes handling static transforms. `apply_pose` skips equal root-transform writes. `RigConstruction._node` builds a parented Node3D for each physical Part on the ordinary route. `_mesh` reparents a rigid MeshInstance to its actual Part and applies its local bind. `ModelRigs._update` advances the local tracks, reapplies only changed manual overrides and emits serial-validated cues. World transforms are evaluated and invalidated through Godot's scene graph. This also enables consumers other than the color viewport to read the transform, including pick anchors and visibility services. [Root pose admission](../../godot-client/systems/native_render/live_world.gd#L634) · [Rig graph and mesh attachment](../../godot-client/systems/native_render/rig_construction.gd#L42) · [Animation to manual writes and cues](../../godot-client/systems/model_rigs.gd#L672)
2. **Equipment and references.** Rigid mesh parenting handles ordinary Part-local clothing and rigid pieces whose physical hierarchy represents their hook. Explicit attachments in the rig entry are synchronized after animation and cues. `ModelRigs.sync_attachments` resolves the enrolled internal or external anchor, validates lifetime, derives the orientation/scale by flags, and writes only when the held node's current world transform differs. This equality check retains correction if another owner edited the held node. `visual_model.gd` also invokes synchronization immediately when attaching or reorienting a reference. This is a different producer from the ordinary pose tick and protects newly changed references. Stock attachment controls and the conditional skinned-head hierarchy copy offer different timing and scope from Godot's graph plus explicit rows. [Ordinary and explicit attachments](../../godot-client/systems/native_render/actor_instance.gd#L81) · [Rig synchronization](../../godot-client/systems/model_rigs.gd#L193) · [Reference reattachment](../../godot-client/systems/visual_model.gd#L96)
3. **Default skin setup and update.** Only a rig with nonempty `entry.skins` enters this path. `ModelRigs._skin` builds a separate Skeleton3D with authored palette slots 0–63 and unweighted identity slot 64. No parents are set on this palette skeleton. It derives inverse binds, rebuilds the Skin ArrayMesh and assigns it and the bind to the MeshInstance. The source worker can supply packed upload arrays for supported geometry. Skin weight/material interpretation and exact slot order remain part of the binding contract. The tick then builds a second rigid unit-scale composition from the Node3D hierarchy, in physical parent order and **once per rig**, and uses each skin's inverse mesh-part transform to calculate its palette poses. It reads live Skeleton3D components to elide equal writes and uses a combined setter where enabled. It still scans the slots and calls `force_update_all_bone_transforms` once per skin even if every setter was skipped. The registered Skin is consumed by Godot's rendering backend. This route uses GPU geometry deformation, with GDScript and engine CPU work supplying the pose. [Palette setup and upload](../../godot-client/systems/model_rigs.gd#L537) · [Rigid gather and palette publication](../../godot-client/systems/model_rigs.gd#L731)
4. **Native publisher and skeletal alternative.** The default launcher selects `standard`. The `verified-native` selection checks the exact engine, bundle proof and kernel before adding `--rig-skin-publisher=native` and `--skeleton-force-pass=once`. `configured_native_skin_publisher` also requires the `NwnRigSkinPublisher` class. This alternate runs on the ordinary Node3D graph. It validates a binding and distinguishes complete publication, an untouched script path and partial continuation, preserving reentrant callbacks without replaying committed rows. The custom publisher still walks rigid nodes, writes every processed slot, and forces once per skin, explicitly preserving the synchronous boundary. The source checked here uses native setter calls in place of GDScript crossings and performs one full skeleton pass when the separate `once` engine setting is active. The distinct `SkeletalRigs` alternate requires `skeleton=true`, uses one Skeleton3D with physical bones and parents, and binds tracks to skeleton paths. It creates BoneAttachment nodes on demand, shares the clip clock and retains special geometry binds. [Launcher defaults](../../godot-client/systems/native_data/client_feature_registry.json#L6) · [Verified-runtime gates](../../godot-client/tools/native-performance-runtime.cjs#L11) · [Script bridge and continuation](../../godot-client/systems/model_rigs.gd#L115) · [Custom publisher's slot and force loop](../../godot-client/tools/nwn65/engine-v2/modules/nwn_particle_snapshot/rig_skin_publisher.cpp#L97) · [Skeletal branch](../../godot-client/native_live_world.gd#L140) · [Skeletal attachment accessors](../../godot-client/systems/native_render/skeletal_rigs.gd)
5. **Downstream pose consumers.** Rigid MeshInstance nodes register their transforms with Godot. Skinned instances consume their Skeleton3D palette. NWNAnalog's CX shadow views mirror eligible caster geometry into separate depth scenarios. Rigid actor ShadowMesh nodes notify change consumers. Skinned and other meshes have separate polled coverage and the skinned proxy attaches to `skeleton_updated`. Source mesh, material, transform, visibility and skeleton updates have distinct gates. Actor-particle owners read current anchor transforms, while target-driven emitters can read another Node's pose. Suppressing publication solely because the main camera culls the actor would omit some shadow, picking, attachment, particle or auxiliary-view consumers. [Actor shadow notification](../../godot-client/systems/native_render/actor_shadow_mesh.gd) · [Moving caster reconciliation](../../godot-client/systems/native_render/cx_directional_depth.gd#L313) · [Skinned proxy listener](../../godot-client/systems/native_render/cx_directional_depth.gd#L449) · [Emitter pose sources](../../godot-client/systems/native_render/particle_emitter.gd#L262) · [Depth capture coverage comparison](../render-flow-measurement-ledger.md#live-cx-caster-admission-and-capture-scheduling)
6. **Removal and retirement.** Appearance/lifetime replacement enters `LiveWorld.retire_replaced_lifetime`, fences stale jobs, then removes the visual instance. `remove_instance` invalidates draw and collision, notifies listeners and calls `ActorInstance.retire`. This cancels unfinished installs, disconnects rig/emitter listeners, drops the skin publisher and any explicit native playback owners through `ModelRigs.forget_entity`, clears instance registries and queues the Node tree for destruction. An actor can retain shared CPU-only decoded graphs briefly for deferred release. Area retirement budgets object and tile release in batches and keeps CPU-only release separate from scene disposal. Shared render pools can retain model resources beyond one actor. [Lifetime fencing](../../godot-client/systems/native_render/live_world.gd#L411) · [Removal and release](../../godot-client/systems/native_render/live_world.gd#L612) · [Actor retirement](../../godot-client/systems/native_render/actor_instance.gd#L538) · [Rig retirement](../../godot-client/systems/model_rigs.gd#L182) · [Area retirement budget](../../godot-client/systems/native_render/live_world.gd#L223)

## Remaining boundaries

- The stock model's runtime Skin population, LOD, callback reentry, pose rebuild count, shadow coverage and draw-time palette frequency have no matched per-frame counter set for the local captured room. Static callability and subtype identities establish the branches here.
- The default-client no-skin room isolates the ordinary animation path. A Skin-heavy case is needed to compare lookup, rigid compose, palette slot read/restore, force signals and GPU upload. Installed Godot and custom publisher source versions matter for the exact scan and signal counts.
- No indexed proof yet establishes that the same skinned pose can be used by every view at the same evaluation boundary. External edits, manual overrides, callbacks, effect anchors, LOD/root change and reparenting can invalidate a previously usable pose.
