# Characters and progression

Creation and level-up use the active base/server 2DA and TLK resources. Pregame artwork must not substitute stock rules for the admitted server's rules. Preserve physical row IDs, byte widths, package choices and original proposal semantics.

## Creation

Native source controls, recommendations, private drafts, appearance/voice preview and typed BIC construction are integrated. Fighter and Wizard have scoped original-server create/save/reconnect evidence. Cleric creation is accepted; a retained reconnect failed on IPC before fresh export, not on a demonstrated class/domain mismatch.

Cached custom Warlock control/BIC and package cases do not establish current custom-server admission. Cover base caster types, domains, schools, companions, recommendations, rejection, vault policy and reconnect before claiming full creation.

Keep proposal state private. Cancel retires pending preparation and stale callbacks; it cannot pretend to undo a transaction already submitted to the server. Validate detached output in the actual writer and compare saved/exported fields against received results. Never predict a server HP normalization to make a test pass.

## Existing characters

Local/server/Workshop discovery, aliases, previews and scoped Delete actions are implemented. Unusual filenames, duplicate aliases, disk failures, DM vaults and full chooser state/input coverage remain.

Existing-character Customize is still unavailable. Its preservation layer is groundwork, separate from the functioning first-level creator's Appearance/Information flow. Implement portrait/appearance/information editing, cancel/back, atomic storage, catalog refresh and original-server admission of the saved copy.

## Level-up

Private class preparation, recommendations, native HP/RNG ownership, spell counters and reply correlation have implemented checkpoints. Later base-rule evidence covers Wizard advancement, Fighter multiclassing, Cleric new-class and Sorcerer progression. Domain/School Recommended and pending-submit Cancel are implemented fixes, not new missing work.

Complete active-server/custom class paths, no-scroll and spontaneous books, domains/schools, companions at legal levels, higher-level variants and original visual/input acceptance. The draft must not change live character state until actual authority confirms it.
